两台电脑的 React（React for Two Computers） ｜ Overreacted, Dan Abramov ｜ 文章 ｜ https://overreacted.io/react-for-two-computers/

Dan Abramov 的一篇超长文章，用一种循序渐进、几乎像寓言的方式，从零推导出 React 服务端组件背后的思想，而不直接提及它的名字，直到最后才揭晓。

他从一个思想实验开始：设想有两台计算机，一台是你的（客户端），一台是我的（服务器），我们要一起完成一次计算。他先用"标签"和"函数调用"的类比展开：一段程序可以写成函数调用的嵌套，也可以写成一棵由标签组成的树；标签就像一个尚未执行的函数调用，可以被传递、延迟，或者在另一台电脑上执行。于是他区分两类东西：一类是在服务器上就能马上算完的"组件"，比如读取数据库、文件后生成一段 UI 描述；另一类是必须交给客户端、在用户的浏览器里运行才有意义的"原语"，比如需要状态和交互的按钮。

文章一步步推演：如果把整个程序看成一棵标签树，服务器可以先展开所有属于它的部分，把结果连同"这些部分请客户端来渲染"的引用一起序列化成 JSON 发过去；客户端拿到后，再在本地执行剩下的部分。这样，程序跨越两台电脑运行，但写起来仍然像一个整体：服务器部分可以直接访问数据，客户端部分负责交互，二者之间通过 props 自然传递数据，而传给客户端的必须是可序列化的值或者对客户端代码的引用。他还讨论了怎么在服务器端引用客户端代码，也就是用一个指令把模块标记为"在另一边"，以及为何这种模型让数据加载和交互可以组合在一起，而不是割裂成 API 加前端两套。

最后他点明，这一切正是 React 服务端组件，以及 'use server'、'use client' 两个指令的由来：它们是两台电脑之间的门。他建议想实际体验又不想用框架的人试试 Parcel 新推出的服务端组件支持。
