Lauren Tan XAi Grokbot ｜ 59:41 ｜ https://youtu.be/Cmoh-yR-usA

一场线上直播分享，由主持人 Colin 串场、穿插观众提问，主讲人是 Cursor 工程师 Lauren Tan（推特名 "potatoe"）。她此前在 Meta 的 React 团队做 React Compiler，更早在 Netflix 当过技术负责人和两年工程经理，此时刚加入 Cursor 五个月，录制前一天团队刚发布了 GrokBot。她讲的是自己如何一步步爬上对编程 agent 的"信任曲线"：从紧盯一两个 agent 的每条输出，到如今早上醒来已有约 20 个 agent 自动合并的 PR，她直接在主干上审。上个月她合入了约 1000 个 PR，这个月才到 12 号就快 800 个了。她自嘲"听起来像 slop 工匠，但保证不是"，并坦然承认大家有理由质疑代码质量。

她的出发点是管理经验：不信任下属的经理只能微观管理，人成了瓶颈，也就没法并行，用 agent 也一样。第一步是验证，让 agent 像用户一样真正运行应用、抓 CPU trace 和堆快照、开模拟器。这不能保证代码写得好，但至少能保证写得对。她讲了入职第一周的经历：本来要去云端 agent 团队，因为懂 React，被临时拉去抢救一周后就要上线的 agent 窗口的性能。她自己看火焰图，把截图和 trace 发给 agent，agent 每次都自信地说"找到元凶了"，结果都不是。于是她做的第一个技能，就是让 agent 通过 Chrome DevTools 协议控制应用（agent 窗口的内部代号是 Glass）。光能控制还不够，agent 不知道某个功能在界面上怎么找，所以她又配了一份"功能地图"，写清每个功能的入口、子功能、快捷键和 DOM 选择器。这样即使 Slack 里的反馈只有一张截图加"？？？"，agent 也能找到并复现。这些技能后来汇成了她的插件 PStack，名字是对 YC CEO Garry Tan 的 GStack 的玩笑（两人同姓但没有亲戚关系）；插件里带有生成和维护验证技能的工具。

PStack 是一点点长出来的。她早期像"后座司机"一样逐条看 agent 的工具调用，发现它根本没读相关代码就下结论，于是写了"别猜，去查代码，多用子 agent"之类的技能。她说技能就是一份 Markdown，好比给一个代码能力很强、但毫无业务背景的新员工写入职指南；高质量的 token 能把模型"拉到更聪明的潜在空间"。维护技能靠评测（eval），她把它当作"agent 的单元测试"：由协调 agent 先定评分标准，再派生一批子 agent 去执行，目录名特意取得让子 agent 察觉不到自己在被测试，因为 agent 一旦知道就会改变行为；再用另一个模型当裁判交叉核验，并且跨多个模型测试；最后用 /loop 一直"爬山"到满分。她的验证技能本身也是这样迭代出来的。她把工程师比作主厨：不必亲手做每道菜，但要负责设计整个厨房。关于从哪里起步，她建议先在本地观察 agent，建立信任后再上云端。云端 agent 加上验证技能能惠及整个团队，例如自动化 agent "Benny" 会接收 bug 报告，在自己的云端电脑上运行 Cursor 并复现，还能确认问题已在主干修复，只差发一个新版本。她提醒，信任还没建立就开上百个 agent，只会白白烧 token。

第三部分是她"为重写正名"。她认为有完善护栏的老项目反而适合 agent，因为大公司那套"为能力最弱的工程师设计"的框架、约定和权限同样能约束 agent，况且 Meta 那样的代码库本来就有"人类 slop"。风险最大的是靠氛围编程起家的新项目，GrokBot 正是这样：原型阶段没人读代码，agent 一直抄最方便的近路，代码库逐渐失控。她花了 600 多个 PR，把 GrokBot 重构到一个代号叫 Dune 的严格架构上，可以理解为"给 Electron 应用用、专为 agent 设计的 Next.js"。CI 检查多到"人写代码很烦，但 agent 会吸收掉这些烦"：禁用 React 的 useEffect；禁止写代码注释，因为 agent 爱把"Lauren 说过别这样"之类当成永久规则写进去；主进程和渲染进程分在不同目录，CI 检查依赖图，防止重活误入渲染线程、打破每帧 16 毫秒的预算（agent 窗口至今还为此反复出现性能回退）；每个功能集中在一个目录里。核心原则是"最短路径就是最好路径"，既然 agent 爱抄近路，就让近路等于正路。约束有强弱之分：架构约定、CI、lint、编译器诊断是硬约束，会让 CI 变红，所以 Rust 这类严格的编译器很有吸引力；规则、技能、Bugbot 和代码风格指南是软约束，agent 会忘，只能叠加使用，单靠它们"代码库迟早变垃圾"。每次想在 PR 里留评论纠正，都应该当成坏味道，把它变成一条硬规则，甚至从根本上消除这类问题。她不设 PR 大小上限，从几十行到上千行都有，但会让 agent 拆成原子化的小 PR，因为 git 历史本身就是丰富的上下文，也方便回滚。

问答里有人问 token 成本。她承认自己在 AI 实验室，token 不限量，但认为这笔前期投入的 ROI 是正的：过去她一个人要花几年才能搭好这样的框架、完成重构，现在用 token 就能做到，而且约束到位之后，较小的模型也能写好代码。她顺带提到当天发布的 Grok 4.6，每 token 价格与 4.5 相同，智能更高，并说 Cursor 和 SpaceX AI 追求的是成本与智能的最优平衡，而不是最大的模型。最后被问到产品团队怎么跟上这种速度，她说 GrokBot 是非技术人群的"Cursor 时刻"：界面像 iMessage，每个 agent 有自己的名字、像一个同事，PM 可以让 agent 汇总她昨晚做了什么；PM 和设计师也在直接提交修复，她审查后往往"完美，直接批准"，这也证明 Dune 的严格约束经得起考验。
