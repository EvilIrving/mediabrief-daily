## 引言

CSS Grid 是 CSS 语言中最了不起的部分之一。它给了我们一大堆新工具，可以用来创建精巧而流畅的布局。

它也*出人意料地复杂*。我花了相当长的时间才真正熟练掌握 CSS Grid！

在这篇教程里，我会分享自己学习 CSS Grid 过程中那些最大的 💡 恍然大悟时刻。你会学到这种布局模式的基础知识，并看到如何用它做一些相当酷的事情。✨

**浏览器支持情况？**

CSS Grid 是 CSS 中构建布局最现代的工具，但它并不算"最前沿"。所有主流浏览器支持它已经将近十年了！

根据 caniuse，CSS Grid [约 96% 的用户都能用](https://caniuse.com/css-grid)。这是*非常好*的浏览器支持；作为参照，Flexbox 的支持率也只高出大约 0.5%！

## 心智模型

CSS 由几种不同的[布局算法](https://www.joshwcomeau.com/css/understanding-layout-algorithms/)组成，每一种都为不同类型的用户界面而设计。默认的布局算法 Flow 布局是为数字文档设计的；Table 布局是为表格数据设计的；Flexbox 是为沿单一轴线分布元素而设计的。

CSS Grid 是最新、最强大的布局算法。它*极其*强大：我们可以用它构建复杂的布局，根据多种约束条件流畅地自适应。

在我看来，CSS Grid 最不同寻常的地方在于，网格的*结构*——行和列——是**完全在 CSS 中定义的：**

（交互演示：一个网格父元素，其中的网格子元素为 <Header>、<Nav>、<Main>、<Footer>，可切换"显示透视"。）

在 CSS Grid 中，单个 DOM 节点被细分为行和列。在本教程中，我们用虚线标出行和列，但实际上它们是不可见的。

*这真的很奇怪！*在其他所有布局模式中，要创建这样的隔间，唯一的办法是添加更多 DOM 节点。比如在 Table 布局中，每一行用一个 `<tr>` 创建，行内的每个单元格用 `<td>` 或 `<th>` 创建：

```
<table>
  <tbody>
    <!-- 第一行 -->
    <tr>
      <!-- 第一行中的单元格 -->
      <td></td>
      <td></td>
      <td></td>
    </tr>

    <!-- 第二行 -->
    <tr>
      <!-- 第二行中的单元格 -->
      <td></td>
      <td></td>
      <td></td>
    </tr>
  </tbody>
</table>
```

与 Table 布局不同，CSS Grid 让我们完全在 CSS 内部管理布局。我们可以随心所欲地切分容器，创建出网格子元素可以作为锚点的隔间。

## 网格流

我们通过 `display` 属性启用 Grid 布局模式：

```
.wrapper {
  display: grid;
}
```

默认情况下，CSS Grid 使用单列，并根据子元素的数量按需创建行。这被称为*隐式网格*，因为我们没有显式定义任何结构。

它的工作方式如下：

（交互演示：子元素数量：3，可切换"显示透视"。）

隐式网格是动态的；行会根据子元素的数量增加或删除。每个子元素拥有自己的一行。

默认情况下，网格父元素的高度由其子元素决定，它会动态地伸缩。有意思的是，这甚至不是"CSS Grid"的特性；网格*父元素*仍然在使用 Flow 布局，而 Flow 布局中的块级元素会在垂直方向上增长以容纳其内容。只有*子元素*是用 Grid 布局排列的。

但如果我们给网格一个固定高度呢？这种情况下，总面积会被划分成大小相等的行：

## 构建网格

默认情况下，CSS Grid 会创建单列布局。我们可以用 `grid-template-columns` 属性指定列：

（代码演练场）

```
<style>
  .parent {
    display: grid;
    grid-template-columns: 25% 75%;
  }
</style>

<div class="parent">
  <div class="child">1</div>
  <div class="child">2</div>
</div>
```

**为清晰起见添加了虚线**

在上面的演练场以及整篇教程中，我用虚线来显示列与行之间的分隔。在 CSS Grid 中，这些线是不可见的，也无法让它们显示出来。

我在这里用了一点 ✨*博客魔法*✨，用伪元素伪造了这些线。如果你想看看是怎么做的，可以切换到 **CSS** 标签页。

通过给 `grid-template-columns` 传入两个值 `25%` 和 `75%`，我是在告诉 CSS Grid 算法把元素切成两列。

列可以用任何合法的 [CSS <length-percentage> 值](https://developer.mozilla.org/en-US/docs/Web/CSS/length-percentage)来定义，包括像素、rem、视口单位等等。此外，我们还获得了一个新单位，`fr` 单位：

（代码演练场）

```
<style>
  .parent {
    display: grid;
    grid-template-columns: 1fr 3fr;
  }
</style>

<div class="parent">
  <div class="child">1</div>
  <div class="child">2</div>
</div>
```

`fr` 代表"fraction"（份数）。在这个例子中，我们是说第一列占 1 份空间，第二列占 3 份空间。也就是说总共有 4 份空间，这就成了分母。第一列占用可用空间的 ¼，第二列占用 ¾。

`fr` 单位给 CSS Grid 带来了 Flexbox 式的灵活性。百分比和 `<length>` 值会形成硬性约束，而 `fr` 列可以根据需要自由伸缩，以容纳其内容。

**试着缩小这个容器，看看区别：**

（交互演示：单位可选 fr 或 %，容器宽度：100%。演示中有一只表情惊讶的可爱小幽灵 3D 插图。）

在这个场景中，第一列里有一只可爱的小幽灵，它被显式设定了 55px 的宽度。但如果列太窄、装不下它怎么办？

*   基于百分比的列是刚性的，所以幽灵图片会*溢出*，跑到列外面去。
*   基于 `fr` 的列是灵活的，所以列不会缩到小于其最小内容尺寸，哪怕这意味着打破比例。

更准确地说：`fr` 单位分配的是*多余*的空间。首先，列宽会根据其内容计算出来。如果还有剩余空间，再根据 `fr` 值来分配。这和我在 [Flexbox 交互式指南](https://www.joshwcomeau.com/css/interactive-guide-to-flexbox/)里讨论过的 `flex-grow` 非常相似。

总的来说，这种灵活性是好事。百分比太死板了。

`gap` 就是一个绝佳的例子。`gap` 是一个神奇的 CSS 属性，它会在网格内所有的列和行之间加上固定大小的间距。

看看在百分比和份数之间切换时会发生什么：

（交互演示：单位可选"份数"或"百分比"。）

注意到使用基于百分比的列时，内容溢出到网格父元素外面了吗？这是因为百分比是根据网格的*总*面积计算的。两列占满了父元素内容区的 100%，而且不允许收缩。当我们加上 16px 的 `gap` 时，列别无选择，只能溢出容器。

相比之下，`fr` 单位是根据*多余*空间计算的。在这个例子中，多余空间因为 `gap` 而减少了 16px，CSS Grid 算法会把剩余的空间分配给两个网格列。

**`gap` 与 `grid-gap`**

CSS Grid 刚推出时，用的是 `grid-gap` 属性来在列和行之间添加间距。不过很快，社区就意识到 Flexbox 里要是也有这个功能就*太棒了*。于是这个属性被改了一个更通用的名字：`gap`。

如今，`grid-gap` 已被标记为弃用，浏览器把它作为 `gap` 的别名。两个属性的作用完全相同，浏览器支持度也几乎一样，[大约 95%](https://caniuse.com/?search=grid-gap)。（注：你得回到 2017—2018 年，才能找到只实现了 `grid-gap` 而没有实现 `gap` 的浏览器，在当前用户中占比不到 0.1%。）

### 隐式行与显式行

如果我们往一个两列网格里放超过两个子元素，会怎样？

我们试试看：

（代码演练场）

```
<style>
  .parent {
    display: grid;
    grid-template-columns: 1fr 3fr;
  }
</style>

<div class="parent">
  <div class="child">1</div>
  <div class="child">2</div>
  <div class="child">3</div>
</div>
```

有意思！网格多出了第二行。网格算法要确保每个子元素都有自己的网格单元格，为了达到这个目标，它会按需生成新行。当元素数量不固定（比如照片网格）、我们希望网格自动扩展时，这很方便。

但在其他情况下，我们希望显式定义行，以创建特定的布局。可以用 `grid-template-rows` 属性做到：

（代码演练场）

```
<style>
  .parent {
    display: grid;
    grid-template-columns: 1fr 3fr;
    grid-template-rows: 5rem 1fr;
  }
</style>

<div class="parent">
  <div class="child"></div>
  <div class="child"></div>
  <div class="child"></div>
  <div class="child"></div>
</div>
```

通过同时定义 `grid-template-rows` 和 `grid-template-columns`，我们就创建了一个显式网格。这非常适合构建页面布局，比如本教程开头的"圣杯"布局。（注："圣杯"是早期 Web 时代对最常见布局的称呼：页头、侧边栏、主内容区和页脚。）

### repeat 辅助函数

假设我们在做一个日历：

（演示：一个从 1 到 31 编号的日期列表。）

CSS Grid 很适合做这类东西。我们可以把它构建成一个 7 列的网格，每列占 1 份空间：

```
.calendar {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr 1fr 1fr 1fr 1fr;
}
```

这样*能用*，但要一个个数那些 `1fr` 有点烦人。想象一下如果有 50 列！

```
.calendar {
  display: grid;
  grid-template-columns: repeat(7, 1fr);
```

## 分配子元素

默认情况下，CSS Grid 算法会把每个子元素分配到第一个空着的网格单元格，很像工匠在浴室地面上铺瓷砖。

**不过很酷的一点是：**我们可以把元素分配到任何我们想要的单元格！子元素甚至可以跨越多行或多列。

下面是一个交互演示，展示其工作方式。*点击/按住并拖动*，即可把一个子元素放进网格。（注：如果你没有使用鼠标或触屏之类的指针设备，也提供了基于键盘的控制方式，详见下方的"帮助"界面。）

（交互演示，可关闭声音、重置。）

```
.parent {
  display: grid;
  grid-template-columns:
    repeat(4, 1fr);
  grid-template-rows:
    repeat(4, 1fr);
}

.child {
  

}
```

`grid-row` 和 `grid-column` 属性让我们指定网格子元素应该占据哪条（或哪几条）轨道。如果希望子元素只占一行或一列，可以用它的编号来指定。`grid-column: 3` 会把子元素分配到第三列。

网格子元素也可以横跨多行或多列。其语法用斜杠来划分起点和终点：

```
.child {
  grid-column: 1 / 4;
}
```

乍一看，这像个分数 ¼。但在 CSS 中，斜杠字符不是用来做除法的，而是用来分隔几组值。在这里，它让我们能在一条声明中同时设置起始列和结束列。

它本质上是下面写法的简写：

```
.child {
  grid-column-start: 1;
  grid-column-end: 4;
}
```

**这里有个隐蔽的坑：**我们提供的数字是基于列的*线*，而不是列的索引。

用图来解释最容易理解：

（示意图：一个 4 列网格，列线编号 1 到 5，行线编号 1 到 4；一个子元素从第 1 条列线跨到第 4 条，从第 2 条行线跨到第 4 条。）

令人困惑的是，一个 4 列的网格实际上有 *5* 条列线。当我们把子元素分配到网格中时，是用这些线来锚定它的。如果想让子元素横跨前 3 列，它需要从第 1 条线开始，到第 4 条线结束。

**负数线号**

在英语这样从左到右书写的语言中，我们从左往右数列。但借助负数线号，我们也可以*反方向*、从右往左数。

```
.child {
  /* 放在从右数第 2 列： */
  grid-column: -2;
}
```

真正酷的是，我们可以混用正数和负数。看看这个：

（交互演示：列数：3。）

注意，即使我们根本没改 `grid-column` 的分配，子元素也横跨了网格的整个宽度！

我们在这里表达的是：子元素应该从第一条列线跨到最后一条列线。无论有多少列，这条好用的声明都能按预期工作。

你可以在我的博文[《用 CSS Grid 实现全出血布局》](https://www.joshwcomeau.com/css/full-bleed/)里看到这个技巧的实际用例。

### 跨越多行/多列

在上面的例子中，我们用 `grid-column` 和 `grid-row` 为网格子元素选择具体位置。当我们确切知道子元素该放在哪里时，这很有用；但在其他情况下，我们会希望更动态一些。

例如，也许我们希望网格子元素自然地填满网格，但希望*某些*子元素横跨多列：

（示意图：一个 4 列网格，其中大部分格子是灰色方块，个别黄色方块横跨两列。）

在这个例子中，大多数网格子元素（用灰色方块表示）各占一个网格单元格，但我们希望*特色*子元素（用黄色方块表示）是双倍宽，横跨*两*列。

我们*可以*给每个子元素指定具体的行列位置来解决，但这听起来很繁琐，尤其是当网格由动态数据生成时！相反，我们可以对特色子元素使用特殊的 `span` 关键字：

```
.grid {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  grid-template-rows: repeat(3, 1fr);
}
.featured.child {
  grid-column: span 2;
}
```

下面是一个可实时编辑的演练场，展示这个功能：

（代码演练场）

```
<style>
  .grid {
    display: grid;
    grid-template-columns: repeat(4, 1fr);
    grid-template-rows: repeat(3, 1fr);
  }

  .featured.child {
    grid-column: span 2;
  }
</style>

<div class="grid">
  <div class="child"></div>
  <div class="child"></div>
  <div class="featured child"></div>
  <div class="child"></div>
  <div class="featured child"></div>
  <div class="child"></div>
  <div class="child"></div>
</div>
```

**特色子元素位置别扭？**

在上面的例子里，两个特色子元素碰巧*没有*被分配到第四列，也就是最后一列。如果我们把一个两列宽的子元素放在最后一列，会怎样？

我们试试看：

（代码演练场）

```
<style>
  .featured.child {
    grid-column: span 2;
  }
</style>

<div class="grid">
  <div class="child">1</div>
  <div class="child">2</div>
  <div class="child">3</div>
  <!--
    第 4 列中的一个特色子元素：
  -->
  <div class="featured child">4</div>
  <div class="child">5</div>
  <div class="child">6</div>
</div>
```

特色子元素在最后一列放不下，结果被挤到了下一行，第一行最后一个单元格留下了一个空位。

**对于这种情况，CSS Grid 有个巧妙的技巧。**如果子元素的*顺序*并不重要，我们可以让浏览器把子元素塞到任何放得下的地方。看看这个：

（代码演练场）

```
<style>
  .grid {
    grid-auto-flow: row dense;
  }

  .featured.child {
    grid-column: span 2;
  }
</style>

<div class="grid">
  <div class="child">1</div>
  <div class="child">2</div>
  <div class="child">3</div>
  <div class="featured child">4</div>
  <div class="child">5</div>
  <div class="child">6</div>
</div>
```

`grid-auto-flow` 属性有点超出本教程的范围，但本质上它就是为这类情况设计的：在动态分配不同尺寸的子元素时，避免网格中留下空洞。在这个例子中，它发现第五个子元素*能*放进第四个网格单元格，于是把它提上来，挪到了特色子元素前面。

### 网格区域

好了，现在来聊聊 CSS Grid 最酷的部分之一。😄

假设我们要构建这样一个布局：

（示意图：左侧是 Sidebar，右侧上方是 Header、下方是 Main；列宽为 2fr 和 5fr，行高为 50px 和 1fr。）

用目前学到的知识，我们可以这样构建它：

```
.grid {
  display: grid;
  grid-template-columns: 2fr 5fr;
  grid-template-rows: 50px 1fr;
}

.sidebar {
  grid-column: 1;
  grid-row: 1 / 3;
}
.header {
  grid-column: 2;
  grid-row: 1;
}
.main {
  grid-column: 2;
  grid-row: 2;
}
```

这样能用，但还有一种更顺手的方法：*网格区域*。

它看起来是这样的：

（交互演示：可选择网格区域 sidebar、header、main，对应 Header、Main、Sidebar。）

和之前一样，我们用 `grid-template-columns` 和 `grid-template-rows` 定义网格结构。但接着，有这样一条奇特的声明：

```
.parent {
  grid-template-areas:
    'sidebar header'
    'sidebar main';
}
```

**它的工作原理是这样的：**我们在描画想要创建的网格，几乎就像在做 ASCII 艺术。（注：ASCII 艺术是用印刷字符拼成的图画，在命令行计算时代很流行。）每一行代表网格的一行，每个词是我们给网格中某一块起的名字。看出来它在视觉上有点像这个网格了吗？

然后，我们不再用 `grid-column` 和 `grid-row` 来分配子元素，而是用 `grid-area` 来分配！

当我们希望某个区域跨越多行或多列时，可以在模板中重复这个区域的名字。在这个例子中，"sidebar"区域横跨两行，所以我们在第一列的两个单元格里都写了 `sidebar`。

**该用区域，还是行/列？**在构建这种显式布局时，我非常喜欢用区域。它让我能给网格分配赋予语义，而不是使用难以理解的行列编号。话虽如此，区域最适合行列数量固定的网格。对于隐式网格，`grid-column` 和 `grid-row` 可能更有用。

### 照顾键盘用户

在网格分配方面有个大坑：**Tab 键顺序仍然基于 *DOM 位置*，而不是网格位置。**

用例子来解释会更容易。在这个演练场里，我放了一组按钮，并用 CSS Grid 排列它们：

（代码演练场）

```
<div class="wrapper">
  <button class="btn one">
    One
  </button>
  <button class="btn four">
    Four
  </button>
  <button class="btn six">
    Six
  </button>
  <button class="btn two">
    Two
  </button>
  <button class="btn five">
    Five
  </button>
  <button class="btn three">
    Three
  </button>
</div>
```

在"结果"面板中，按钮看起来是按顺序排列的：从左到右、从上到下读，就是从一到六。

**如果你使用的设备有键盘，试着用 Tab 键在这些按钮之间切换。**做法是点击左上角的第一个按钮（"One"），然后按 Tab 键逐个移动到下一个按钮。

你应该会看到类似这样的情况：

[视频 2](https://www.joshwcomeau.com/images/interactive-guide-to-grid/tab-order.mp4)

从用户的角度看，焦点轮廓在页面上毫无规律地乱跳。这是因为按钮是按照它们在 DOM 中出现的顺序获得焦点的。

要解决这个问题，我们应该在 DOM 中重新排列网格子元素，使其与视觉顺序一致，这样我就能从左到右、从上到下依次 Tab 切换。（注：这甚至对阿拉伯语、希伯来语这类从右到左书写的语言也能正确工作；在这些语言中 CSS Grid 的列会镜像翻转，第 1 列在右边而不是左边。因此同样的 DOM 顺序适用于所有语言。）

**`reading-order` CSS 属性**

CSS 工作组知道这是 CSS Grid 的一个问题。必须让 DOM 顺序和视觉顺序一致，多少违背了能把子元素分配到特定网格单元格的初衷！

为了解决这个问题，最近引入了一对新属性：`reading-flow` 和 `reading-order`。`reading-flow` 让我们可以根据指定的布局覆盖默认的 Tab 顺序（例如 `reading-flow: grid-order` 或 `reading-flow: flex-flow`），而 `reading-order` 让我们可以为每个元素单独指定 Tab 顺序，就像 HTML 中 `tabIndex` 属性的作用域版本。

在我写下这段文字的 2026 年 5 月，这些属性[只在 Chrome 和 Edge 中可用](https://caniuse.com/wf-reading-flow)，浏览器支持率约为 67%。希望将来有更多浏览器支持这个属性！在此之前，我建议修改标记，让源码顺序与视觉顺序一致。

## 对齐

在目前看到的所有例子中，列和行都会拉伸以填满整个网格容器。但不一定非得这样！

例如，假设我们定义两列，每列宽 90px。只要网格父元素宽于 180px，末尾就会有一些空白区域：

（示意图：C1、C2 两列，箭头标出剩余的空间。）

我们可以用 `justify-content` 属性来控制列的分布：

（交互演示：justify-content 可选 start、center、end、space-between、space-around、space-evenly，列为 C1、C2，可切换"显示透视"。）

如果你熟悉 Flexbox 布局算法，这可能会让你感觉很熟悉。CSS Grid 建立在最早随 Flexbox 引入的对齐属性之上，并更进一步。

**最大的区别在于，我们对齐的是*列*，而不是元素本身。**本质上，`justify-content` 让我们安排网格的隔间，随心所欲地把它们分布在网格中。

如果我们想在列*内部*对齐元素本身，可以使用 `justify-items` 属性：

（交互演示：justify-content 为 start（默认），justify-items 为 stretch（默认），列为 C1、C2，元素为 One、Two、Three、Four。）

当我们把一个 DOM 节点丢进网格父元素时，默认行为是让它横跨整列拉伸，就像 Flow 布局中的 `<div>` 会水平拉伸以填满其容器一样。但借助 `justify-items`，我们可以调整这种行为。

这很有用，因为它让我们能打破列的刚性对称。当我们把 `justify-items` 设为 `stretch` 以外的值时，子元素会缩回由其内容决定的默认宽度。这样一来，同一列中的元素就可以有不同的宽度。

我们甚至可以用 `justify-self` 属性控制*某个特定*网格子元素的对齐：

（交互演示：justify-content 为 start（默认），justify-self 为 stretch（默认），列为 C1、C2，元素为 One、Two、Three、Four。）

`justify-items` 设置在网格父元素上，控制*所有*网格子元素的对齐；而 `justify-self` 设置在子元素上。我们可以把 `justify-items` 看作为所有网格子元素设置 `justify-self` 默认值的一种方式。

### 对齐行

到目前为止，我们讨论的都是如何在*水平*方向上对齐东西。CSS Grid 还提供了另一组属性，用于在*垂直*方向上对齐：

（交互演示：justify-content 为 start，justify-items 为 stretch，新增 align-content 为 start、align-items 为 stretch；行为 R1、R2，列为 C1、C2，元素为 One、Two、Three、Four。）

`align-content` 类似于 `justify-content`，但它作用于行而不是列。同样，`align-items` 类似于 `justify-items`，但它处理的是元素在其网格区域内的*垂直*对齐，而不是水平对齐。

再进一步拆解：

*   `justify`——处理*列*。
*   `align`——处理*行*。
*   `content`——处理*网格结构*。
*   `items`——处理网格结构中的 *DOM 节点*。

最后，除了 `justify-self`，我们还有 `align-self`。这个属性控制单个网格元素在其单元格内的垂直位置。

### 两行居中技巧

最后还有一样东西想给你看。这是我最喜欢的 CSS Grid 小技巧之一。

只用两个 CSS 属性，我们就能让子元素在容器中水平和垂直都居中：

（交互演示：place-content 可选 start、center、end；行 R1、列 C1，子元素 Child，可切换"显示透视"。）

`place-content` 属性是一个简写，它是下面写法的语法糖：

```
.parent {
  justify-content: center;
  align-content: center;
}
```

正如我们学到的，`justify-content` 控制列的位置，`align-content` 控制行的位置。在这种情况下，我们有一个只有一个子元素的隐式网格，所以最终得到的是一个 1×1 的网格。`place-content: center` 把行和列都推到了中央。

在现代 CSS 中，让一个 div 居中的方法有很多，但这是我所知道的唯一一种只需要两条 CSS 声明的方法！
