https://surma.dev/things/webgpu/

Surma 自称图形方面经验不多，用 WebGL 一直不顺手。别人都说 WebGPU 的样板代码比 WebGL 还多，他真上手后的结论却是：样板量差不多，API 用起来顺手得多。这篇长文想让 Web 开发者入门 WebGPU，但刻意不讲图形渲染，只讲用它调用 GPU 的通用算力（GPGPU）。他也说明，目标是能“有效”使用，而不是“高效”使用。

他先解释为什么需要新 API。WebGL 基本就是 OpenGL ES 2.0 加一层薄封装，而 OpenGL 的设计围绕一个内部的全局状态对象：调用顺序极其关键，写库和抽象时必须小心保存、恢复各种指针，出错时往往只得到一块黑色画布。在他看来，这正是大家宁可用 ThreeJS 的原因。做通用计算时，WebGL 1 要把数据编码成纹理、算完再编码回去；WebGL 2 的 Transform Feedback 好一些，但 Safari 直到 2021 年 9 月才支持。与此同时，原生领域已经有了 Vulkan、Metal、DirectX 12 这些更底层的新一代 API，适应 GPU 无处不在、多线程以及提前做验证的需求。WebGPU 不照搬其中任何一个，而是自成一套抽象，既符合 Web 习惯，又能架在各家原生 API 之上，由 W3C 联合各大浏览器厂商标准化。

接着他按代码顺序讲解核心概念。适配器是操作系统原生图形 API 到 WebGPU 的转换层，逻辑设备则让每个网页都像独占 GPU。默认设备只提供所有 GPU 的“最低公分母”能力，比如缓冲区上限是 1GiB，而他的显卡能支持 4GiB。这样做的好处是程序几乎在哪儿都能跑，需要时也可以按 adapter.limits 申请更高的上限。管线必须显式声明，分渲染管线和计算管线两种。他把渲染管线看作计算管线的一种特化，但也承认这在历史上是倒过来的，而且两者在硬件上是不同的电路。着色器用 WGSL 编写，语法像 Rust 和 GLSL 的混合，浏览器会把它编译成 HLSL、MSL 或 SPIR-V。

理解 @workgroup_size 需要先了解 GPU 架构。他以 Intel 的公开文档为例：最底层的执行单元（EU）里有 7 个步调一致的 SIMT 核心，执行同一条指令、处理不同的数据。所以分支和长短不一的循环会让所有核心陪着空转。访存要等几百个时钟周期，于是每个 EU 都被超额分配工作，一等待就切换到别的工作项，以牺牲单个任务的延迟来换取整体吞吐量。多个 EU 组成 SubSlice，共享约 64KiB 的本地内存，需要同步的工作只能在同一个 SubSlice 内完成。WebGPU 把工作负载建模为三维网格，再切成工作组。三维形状本意是提高缓存局部性，但实际硬件上 64 和 8×8 几乎没有差别，这个概念已有些过时。工作组大小还受 device.limits 中各维度上限和乘积上限的约束。至于取多大，他转述 Corentin 的建议：除非清楚目标 GPU 或负载有特殊需要，否则就用 64。命令通过 CommandEncoder 和 PassEncoder 编码后提交到队列。所有状态都经由通道编码器显式传递，这正好取代了 OpenGL 的全局状态。

文章最繁琐的部分是数据交换。缓冲区要通过绑定组布局预先声明类型（storage、read-only-storage、uniform），以便 GPU 提前优化。由于 GPU 显存为了吞吐量与核心紧密集成，主机无法直接读写。读回结果时，得先把数据复制到可映射的暂存缓冲区，再用 mapAsync 和 getMappedRange 取出，并用 slice 复制一份，因为取消映射后原来的 ArrayBuffer 就会失效。写入则可以直接用 device.queue.writeBuffer，由它选择最高效的路径。他还提醒了两个坑。一是过量调度：调用次数向上取整到 64 的倍数，越界写入会被钳制到数组最后一个元素，造成脏数据，所以着色器里要用 arrayLength 提前返回。二是内存对齐：Ball 结构体中 f32 半径之后跟着 vec2，而 vec2 要求 8 字节对齐，因此会被插入 4 字节填充，JavaScript 端按每个球 6 个浮点数来排布才能对上。

演示是用 GPU 模拟大量小球的移动与碰撞，再用 Canvas2D 画出来。碰撞检测采用最朴素的两两比较，也没做任何优化，在 M1 MacBook Air 上也能跑到约 2500 个球仍保持 60fps，而这时的瓶颈其实是 Canvas2D 绘图。关掉渲染后，16 毫秒帧预算内大约能模拟 14000 个球。

最后谈现状。当时 WebGPU 只能在 Chrome 和 Firefox 中通过开关标志启用，Safari 技术预览版里还没有。规范仍在变动，比如属性语法从 [[stage(compute)]] 改成了 @compute，endPass() 改名为 end()，所以还要预期会有破坏性变更。他的结论是，跨过学习曲线后，用 JavaScript 驱动大规模并行计算的感觉非常强大。他还提到，用 Rust 实现的 wgpu 能让同一套 API 在浏览器外原生运行或编译成 WebAssembly，Deno 正是借助它成为第一个内置 WebGPU 的运行时；遇到问题可以去 WebGPU 的 Matrix 频道求助。
