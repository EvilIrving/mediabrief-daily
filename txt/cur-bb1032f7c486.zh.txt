Satya Nadella：如果是这样，我甚至会说，每家公司基本上都同时拥有人力资本和 token 资本。如果每家公司都有 token 资本和人力资本，那么 token 资本可以是一个嵌入了你自身知识的开放权重模型。这是一种方式。它也可以存在于上下文层里。你甚至可以使用多个闭源模型，收集自己使用这些闭源模型的运行轨迹，再利用这些轨迹，为自己训练一个小模型、一个开放权重模型，保留这些方式的组合。看 Copilot，无论 GitHub Copilot 还是 Copilot，它们都被设计成多模型系统。我甚至会说，也许等到我们下次交谈时，所有人都会说，重点已经不在开放还是封闭了，人人都有一个模型系统。它甚至从一个决策引擎开始，用来决定什么任务使用什么模型。然后，我的上下文、记忆和行动空间，独立于任何单一模型。否则，你就被完全锁定了。

Satya Nadella：没错。你的观察是对的，这很有意思。我甚至会说，如果你是一家银行，就应该看看，那些试图在这个生态里走到前沿的软件公司，是怎么做的。它们没有交出控制权。从某种意义上说，银行也应该这样做，这样才有杠杆。比如，我们所做的，也就是我们称为 IQ 层的东西，是把 Copilot 和 GitHub Copilot 底下的执行框架拿了出来。

Gergely Orosz：对。

Satya Nadella：把它变成了一等功能。现在你可以在 Foundry 里把它作为托管服务使用，直接获得这个执行框架。假设你在构建一个供应链系统，可以从我们的框架开始，基本上作为一个开放的……你也可以把 Pi 或其他开源执行框架带进来。不过，你也可以直接把它当作托管服务：微软经过实战检验、我们自己也在使用的执行框架，就在那里。然后，你可以使用 Foundry 里的所有模型。这样，你有了执行框架，可以把多个模型当作端点使用；你还有一个完全分离的上下文层，记忆和上下文是你自己的。我认为，我们现在就有了一个模型系统。哦，还有包括所有插件、技能和连接器的行动空间，它们也都独立出来，不是只有某个给定模型能看到。

Satya Nadella：我认为，一种很好的、经典的中间层平台，即使在模型优先的开发方式下，也正在形成，让你不会被困住。而且，你可以对一切做评测。你可以说，我有一套评测，我的私有评测会更加重要。所有这些公开基准当然很好，但你需要针对自己真正关心的结果，拥有自己的私有评测。然后，在你的强化学习环境里，看这些模型的实际表现，持续优化。其实，我看到客户往往先用一个前沿模型，然后说，好，我拿到了所有这些运行轨迹。现在我要转换一下：这是一个确定性的工作流，我并不需要等下一个大模型发布，而是要优化成本。我放进一个 MAI Flash 模型，用这些轨迹对它做微调，就搞定了。这些事你都可以在 Foundry 里做。我想，这类工作将越来越普遍。

Gergely Orosz：你可能只是坐在一颗滴答作响的定时炸弹上。

Satya Nadella：这里有很多事。比如思维链，天哪，思维链不能是 neuralese 那样的模型内部语言，它必须是人类语言，必须可以审计，必须以不可篡改的方式记录下来。并不是只有预训练或强化学习阶段才会出事，在测试时计算阶段，也可能发生问题，因为它们可能钻奖励机制的空子。因此，你必须在运行时建立相当多的保障措施。我把它称为信任架构：确保你可以把模型和智能体当作内部风险来处理，对其进行监控，建立可观测性，等等，同时确保你能掌控自己的学习循环。
