大型神经网络是近来许多 AI 进展的核心，但训练它们是一项艰巨的工程与研究挑战，需要协调一整个 GPU 集群来执行同一个同步计算。随着集群和模型规模不断增长，机器学习从业者发展出了越来越多样的技术，把模型训练并行化到许多 GPU 上。乍一看，理解这些并行技术似乎令人望而生畏，但只要对计算的结构做少数几个假设，这些技术就会变得清晰得多——到那时，你不过是在把不透明的比特从 A 搬到 B，就像网络交换机搬运数据包一样。

训练神经网络是一个迭代过程。在每次迭代中，我们先对一批数据做一次前向传播，穿过模型的各个层，为批中每个训练样本计算输出。然后再做一次反向传播穿过各层，通过计算关于每个参数的梯度，传递每个参数对最终输出的影响程度。这一批的平均梯度、参数以及每个参数的一些优化状态，被交给一个优化算法（例如 Adam），由它计算出下一次迭代的参数（在你的数据上应当表现略好）以及新的逐参数优化状态。随着训练在一批批数据上迭代，模型逐渐演化，输出越来越准确。

各种并行技术沿不同维度切分这一训练过程，包括：

* 数据并行——在不同 GPU 上运行批次的不同子集；

* 流水线并行——在不同 GPU 上运行模型的不同层；

* 张量并行——把单个运算（比如一次矩阵乘法）的数学拆开，分到多个 GPU 上；

* 混合专家——每个样本只由每一层的一小部分来处理。

（本文假设你使用 GPU 训练神经网络，但同样的思路也适用于使用任何其他神经网络加速器的人。）

## 数据并行

数据并行训练是指把同一组参数复制到多个 GPU（通常称为"worker"）上，并给每个 GPU 分配不同的样本同时处理。仅靠数据并行，仍然要求模型能装进单个 GPU 的显存，但它让你能利用许多 GPU 的算力，代价是要存储参数的许多份重复拷贝。话虽如此，也有一些策略可以增加 GPU 可用的有效内存，例如在两次使用之间把参数临时卸载到 CPU 内存。

每个数据并行 worker 更新自己那份参数拷贝时，它们需要相互协调，确保每个 worker 的参数始终保持一致。最简单的做法是在 worker 之间引入阻塞式通信：（1）在每个 worker 上独立计算梯度；（2）在各 worker 之间对梯度取平均；（3）在每个 worker 上独立计算出相同的新参数。第（2）步是一次阻塞式求平均，需要传输相当多的数据（与 worker 数量乘以参数规模成正比），这可能损害训练吞吐量。有各种异步同步方案可以消除这一开销，但它们会损害学习效率；实践中，人们通常还是坚持使用同步方法。

## 流水线并行

在流水线并行训练中，我们把模型按顺序切成若干块，分布到各个 GPU 上。每个 GPU 只持有一部分参数，因此同一个模型在每个 GPU 上消耗的显存按比例减少。

把一个大模型切成由连续层组成的块很直接。然而，各层的输入与输出之间存在顺序依赖，因此朴素的实现可能导致大量空闲时间：一个 worker 要等待上一台机器的输出作为自己的输入。这些等待的时间块被称为"气泡"（bubble），浪费了这些空闲机器本可以完成的计算。

朴素流水线并行设置示意图：模型按层被纵向切成 4 个分区。Worker 1 持有网络第一层（最靠近输入）的参数，而 worker 4 持有第 4 层（最靠近输出）。"F"、"B"、"U"分别代表前向、反向和更新操作，下标表示该操作在哪个 worker 上运行。由于顺序依赖，数据一次只由一个 worker 处理，导致出现大段空闲的"气泡"。

我们可以借用数据并行的思路来降低气泡的代价：让每个 worker 一次只处理一部分数据元素，从而巧妙地让新的计算与等待时间重叠。核心思想是把一个批次拆成多个微批次（microbatch）；每个微批次的处理时间按比例更短，而每个 worker 一旦拿到下一个微批次就立刻开始处理，从而加快流水线的执行。只要微批次足够多，worker 在大部分时间里都能被充分利用，只在一步的开始和结束处留下极小的气泡。梯度在各微批次之间取平均，而参数更新只在所有微批次都完成后才进行。

模型被切分到的 worker 数量通常称为"流水线深度"（pipeline depth）。

在前向传播中，worker 只需把自己那块层的输出（称为激活值）发给下一个 worker；在反向传播中，它只需把这些激活值上的梯度发回上一个 worker。如何调度这些传播、如何在微批次之间聚合梯度，存在很大的设计空间。GPipe 让每个 worker 连续地处理前向和反向传播，然后在最后同步地聚合来自多个微批次的梯度。PipeDream 则调度每个 worker 交替处理前向和反向传播。

## 张量并行

流水线并行按层"纵向"切分模型。也可以在一层之内"横向"切分某些运算，这通常称为张量并行训练。对许多现代模型（例如 Transformer）而言，计算瓶颈在于把一个激活批次矩阵与一个大权重矩阵相乘。矩阵乘法可以看作行与列两两之间的点积；可以在不同 GPU 上计算相互独立的点积，也可以在不同 GPU 上计算每个点积的一部分再把结果相加。无论哪种策略，我们都可以把权重矩阵切成大小均等的"分片"（shard），把每个分片放在不同的 GPU 上，用该分片计算整个矩阵乘积中相应的部分，之后再通过通信把结果合并起来。

一个例子是 Megatron-LM，它把 Transformer 自注意力层和 MLP 层中的矩阵乘法并行化。PTD-P 同时使用张量、数据和流水线并行；它的流水线调度给每个设备分配多个不连续的层，以更多的网络通信为代价减少气泡开销。

有时，网络的输入可以沿某个维度并行化，该维度上的并行计算量相对于跨设备通信量很高。序列并行就是这样一种思路：把输入序列按时间切分成多个子样本，让计算以更细粒度的样本进行，从而按比例降低峰值内存消耗。

## 混合专家（MoE）

在混合专家（MoE）方法中，对任何一个输入，只用网络的一小部分来计算输出。一种做法是准备许多组权重，网络在推理时可以通过门控机制选择使用哪一组。这样能在不增加计算成本的情况下拥有多得多的参数。每组权重被称为"专家"，希望网络能学会把专门化的计算和技能分配给每个专家。不同的专家可以放在不同的 GPU 上，这为扩大一个模型所用的 GPU 数量提供了清晰的途径。

## 其他节省内存的设计

还有许多其他计算策略，能让训练越来越大的神经网络变得更可行。例如：

* 计算梯度时，你需要保存原始激活值，这会消耗大量设备内存。检查点（checkpointing，也称激活重计算）只存储一部分激活值，在反向传播时即时重新计算中间的那些。这样能节省大量内存，计算代价至多是额外一次完整的前向传播。还可以通过选择性激活重计算在计算与内存成本之间持续权衡，即对那些存储代价相对较高、但重新计算代价较低的激活子集做检查点。

* 混合精度训练是指用较低精度的数值（最常见的是 FP16）来训练模型。现代加速器使用低精度数值能达到高得多的 FLOP 数，而且还能节省设备内存。只要处理得当，得到的模型几乎不会损失精度。

* 卸载（offloading）是指把暂时不用的数据临时卸载到 CPU 或在不同设备之间转移，需要时再读回来。朴素的实现会大大拖慢训练，但成熟的实现会预取数据，使设备永远不必等待。这一思路的一个实现是 ZeRO，它把参数、梯度和优化器状态切分到所有可用硬件上，并在需要时再将其实体化。

* 内存高效的优化器被提出来，用于减少优化器维护的运行状态所占用的内存，例如 Adafactor。

* 压缩也可以用于存储网络中的中间结果。例如，Gist 压缩为反向传播而保存的激活值；DALL·E 在同步梯度之前先对其进行压缩。
