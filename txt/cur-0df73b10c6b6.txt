用了 10 年 AntD 之后，聊聊 UI 库的下一个十年 ｜ AsyncTalk ｜ 14分钟 ｜ https://www.ximalaya.com/sound/976830930

这是 AsyncTalk 主播的一期单人节目，讨论前端 UI 组件库的演变与未来。他把 UI 组件分成两个时代：2015 年前后到前几年，以 AntD 为代表的组件库追求开箱即用和交付速度，竞争的是功能多寡和 API 简单程度；之后兴起的 Headless 组件（以 shadcn 为代表）受 Tailwind 的 design system 理念和 React Server Component 推动，关心的是"做对的事"。

他肯定 AntD 上手快、文档和生态成熟，但列出几条硬伤：以 Tooltip 为例，trigger 与 content 混在 children 里，语义不清；几乎全是 Client Component，不适合 Server Component 时代；全局 CSS 无法 tree shaking、样式互相打架；getPopupContainer 挂载点和 z-index 冲突；DOM 结构是黑盒，改样式等于和框架作者打架，ConfigProvider 收效有限。shadcn 把组件复制进项目由你拥有，无障碍属性完备、可任意改、对 RSC 友好、没有升级负担，代价是要先懂 Tailwind、API 拆得更细、代码量和心智负担更大。

他自己的倾向是第三条路：AI 让写代码的成本大降，加上 Floating UI 等 Headless 库已经成熟，用 AI 生成自有组件库只需半小时左右，能兼顾品牌一致、性能和自由演进。结论是一次性的内部后台照用 AntD 或 Material UI 无妨，稍大、看重正确性和 AI 友好的项目，宜基于 shadcn 或直接让 AI 生成自己的 UI 库。
