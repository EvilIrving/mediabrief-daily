在使用 MCP 的系统里，有宿主（host）、客户端（client），还有服务器（server）。宿主是面向终端用户的应用。比如说这是我的代码编辑器，我的编辑器底层会以某种方式用到 MCP 的东西。我在写代码，在“氛围编程”（vibe coding），对吧？我提出各种请求，它就会在 IDE 里以某种方式交互，让事情发生。这就是宿主，也就是终端用户应用。客户端位于宿主应用内部，是一个 MCP 客户端，意思是它可能是一个库，懂得怎么做 MCP 的那些事。打个比方，在 Python 里我可以导入 requests 包，它知道怎么和 Web 服务器来回执行 HTTP 调用。你可以把 MCP 客户端想成类似的东西，它住在你的应用里，懂得怎么和 MCP 服务器而不是 Web 服务器来回通信。然后服务器就是你从客户端去访问的那些外部程序、工具或资源，它们通过这种标准化的 API 暴露工具、资源和提示词。所以这是一个客户端-服务器架构：客户端在宿主里，宿主是终端用户应用；另一边是服务器，也就是 MCP 服务器。

我们待会儿再细聊 MCP 服务器做什么，但你可以这样理解：客户端负责调用工具、请求资源、请求提示词或提示词格式、模板；MCP 服务器负责暴露这些工具、资源和提示词。这样说能理解吗，Chris？
