Anthropic 工程师讲 Claude Managed Agents：从 API 到托管智能体 ｜ X @Grow_withAI（Anthropic 闪电演讲） ｜ 11:52 ｜ https://x.com/Grow_withAI/status/2115062331227226349

一位 Anthropic 产品工程师（负责针对特定任务改进模型、搭建智能体运行框架、帮大客户落地智能体用例）讲构建智能体的接口如何演变，最终到新产品 Claude Managed Agents。

演变分三步。第一步是 Messages API：只有 token 进、token 出，智能体循环、上下文管理、工具执行、会话状态与恢复、鉴权、可观测性、自定义工具逻辑都要开发者自己做。第二步是 Claude Code 及由它封装成的 Claude Agent SDK：提供智能体循环和运行框架、上下文管理、内置工具执行、沙箱和文件系统，但托管与扩容、会话状态、可观测性等仍要自己管，上线还有大量工作。第三步是 Claude Managed Agents：开发者只带任务、智能体配置和自定义工具逻辑，Anthropic 负责运行框架、工具运行时与沙箱、会话状态持久化和检查点、鉴权与凭据保险库、托管扩容和可观测性；底层仍是 token 进出。他说客户常常几小时做出原型、却要几周才能上线，这正是它要解决的问题，并推荐从它入手。

它有三种核心资源：智能体（模型、提示词、工具、MCP 服务器、技能，有版本且不可变，可迭代和回滚）；环境（容器、网络边界、允许访问的主机）；会话（用前两者启动）。智能体循环在服务端运行，合上电脑也继续跑。关键架构变化是把“大脑”（模型与循环）和“双手”（工具与沙箱）分离：以前二者在同一容器，每次启动延迟高且单点故障；现在沙箱只在需要时启动，扩容更快、延迟更低、可靠性更高。

示例来自他在 Code with Claude 大会的工作坊（GitHub Anthropic 组织下的 CWC workshops 仓库）：结账服务报错高于基线时，用一个 SRE 智能体排查。步骤是写一小段代码定义工具、模型和名字（可让 Claude 代写），定义容器网络边界并获得唯一 ID，上传日志文件和技能，再用智能体 ID 和环境启动会话，智能体在真实沙箱里用 grep、glob 找根因。这些代码就是生产级的，满意后用同一 ID 和环境直接放进产品，扩展能力内置。会话通过事件通信：云端发来智能体动作的事件，开发者发事件回去控制方向（他提醒 API 细节可能变动）；对话存在云端，可一条命令列出所有会话。

其他功能：层级式子智能体/多智能体；记忆；“做梦”（从对话记录中学习、形成技能、改进记忆库）；Outcomes（像 Ralph Wiggum 循环那样反复迭代产出）；Vaults 安全存放凭据；MCP、webhook、权限策略、中断；控制台里用纯文本描述即可生成生产级配置的智能体构建器；像 cron 一样的定时和触发式智能体（如每天凌晨 1 点运行、早上 8 点发每日摘要）。
