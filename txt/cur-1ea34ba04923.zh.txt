# 1. 多头注意力（MHA）

自注意力让每个 token 都能查看序列中其他可见的 token，为它们分配权重，并用这些权重构建输入的一个新的、感知上下文的表示。

多头注意力（MHA）是这一思想的标准 Transformer 版本。它用不同的可学习投影并行运行多个自注意力头，然后把它们的输出合并成一个更丰富的表示。

下面几节先旋风式地讲解自注意力，以便解释 MHA。这更多是一个快速概览，为分组查询注意力、滑动窗口注意力等相关注意力概念做铺垫。如果你对更长、更详细的自注意力讲解感兴趣，可能会喜欢我那篇更长的文章《理解并编写 LLM 中的自注意力、多头注意力、因果注意力和交叉注意力》。

**示例架构**

GPT-2、OLMo 2 7B 和 OLMo 3 7B

## 1.2 历史花絮：注意力为何被发明

注意力早于 Transformer 和 MHA。它的直接背景是用于翻译的编码器-解码器 RNN。

在那些较早的系统中，编码器 RNN 会逐个 token 读取源句子，并把它压缩成一串隐藏状态，或者在最简单的版本中压缩成一个最终状态。然后解码器 RNN 必须从这个有限的摘要中生成目标句子。这对短而简单的情况有效，但一旦生成下一个输出词所需的相关信息位于输入句子的其他位置，就会形成明显的瓶颈。

简而言之，局限在于隐藏状态无法存储无限多的信息或上下文，而有时直接回看完整的输入序列会很有用。

下面的翻译例子展示了这种思路的一个局限。例如，当模型过于把问题当作逐词映射时，一个句子可能保留了许多局部合理的用词，却仍然是一个失败的翻译。（上方面板展示了一个夸张的例子：我们逐词翻译句子，结果句子的语法显然是错的。）实际上，正确的下一个词取决于句子层面的结构，以及在这一步哪些较早的源词重要。当然，用 RNN 仍然可以把这句话翻译好，但如前所述，由于隐藏状态只能存储有限的信息，它在更长的序列或知识检索任务上会很吃力。

下一张图更直接地展示了这种变化。当解码器生成一个输出 token 时，它不应被局限于一条压缩过的记忆路径，而应该能够直接回溯到更相关的输入 token。

Transformer 保留了上述加入注意力的 RNN 的核心思想，但去掉了循环。在经典论文《Attention Is All You Need》中，注意力本身成为了主要的序列处理机制（而不再只是 RNN 编码器-解码器的一部分）。

在 Transformer 中，这一机制被称为自注意力：序列中的每个 token 计算对所有其他 token 的权重，并用这些权重把来自那些 token 的信息混合成一个新的表示。多头注意力就是把同一机制并行运行多次。

## 1.3 带掩码的注意力矩阵

对于一个包含 `T` 个 token 的序列，注意力需要为每个 token 计算一行权重，因此总体上得到一个 `T x T` 的矩阵。

每一行回答一个简单的问题：在更新这个 token 时，每个可见 token 应该有多重要？在仅解码器的 LLM 中，未来位置会被掩码屏蔽，这就是下图中矩阵右上部分呈灰色的原因。

自注意力从根本上说就是在因果掩码下学习这些 token 到 token 的权重模式，然后用它们构建感知上下文的 token 表示。

## 1.4 自注意力的内部机制

下一张图展示了 Transformer 如何从输入嵌入 `X` 计算注意力矩阵（`A`），然后用它生成变换后的输入（`Z`）。

这里的 `Q`、`K` 和 `V` 分别代表查询（query）、键（key）和值（value）。一个 token 的查询代表这个 token 在寻找什么，键代表每个 token 提供什么用于匹配，而值代表注意力权重算出后被混合进输出的信息。

步骤如下：

- `Wq`、`Wk` 和 `Wv` 是权重矩阵，把输入嵌入投影为 `Q`、`K` 和 `V`
- `QK^T` 产生原始的 token 到 token 相关性分数
- softmax 把这些分数转换为上一节讨论的归一化注意力矩阵 `A`
- 把 `A` 应用到 `V` 上，产生输出矩阵 `Z`

注意，注意力矩阵并不是一个单独手写的对象。它由 `Q`、`K` 和 softmax 自然产生。

下一张图展示了与上一张相同的概念，但注意力矩阵的计算被隐藏在“缩放点积注意力”方框里，而且我们只对一个输入 token 而不是所有输入 token 进行计算。这是为了展示单头自注意力的紧凑形式，以便在下一节扩展到多头注意力。

## 1.5 从单头到多头注意力

一组 `Wq/Wk/Wv` 矩阵给我们一个注意力头，也就是一个注意力矩阵和一个输出矩阵 `Z`。（这一概念在上一节已有图示。）

多头注意力只是用不同的可学习投影矩阵并行运行多个这样的头。

这很有用，因为不同的头可以专门处理不同的 token 关系。一个头可能专注于短距离的局部依赖，另一个专注于更宽泛的语义联系，还有一个专注于位置或句法结构。

# 2. 分组查询注意力（GQA）

分组查询注意力是从标准 MHA 衍生出的注意力变体。它由 Joshua Ainslie 等人在 2023 年的论文《GQA：从多头检查点训练通用多查询 Transformer 模型》中提出。

它不是给每个查询头配备自己的键和值，而是让多个查询头共享同一组键值投影。这让 KV 缓存便宜得多（主要是减少内存），同时又不会对整体解码器方案改动太多。

**示例架构**

稠密模型：Llama 3 8B、Qwen3 4B、Gemma 3 27B、Mistral Small 3.1 24B、SmolLM3 3B 和 Tiny Aya 3.35B。

稀疏模型（混合专家）：Llama 4 Maverick、Qwen3 235B-A22B、Step 3.5 Flash 196B 和 Sarvam 30B。

## 2.1 GQA 为何流行起来

在我的架构比较文章中，我把 GQA 描述为经典多头注意力（MHA）的新标准替代品。原因在于，标准 MHA 给每个头都配备自己的键和值，这从建模角度看更优，但一旦在推理时必须把所有这些状态保存在 KV 缓存中，代价就很高。

在 GQA 中，我们保留较多的查询头，但减少键值头的数量，让多个查询共享它们。这降低了参数量和 KV 缓存的数据流量，又不需要像稍后要讨论的多头潜在注意力（MLA）那样做大幅的实现改动。

在实践中，对于那些想要比 MHA 更便宜、又比 MLA 这类较新的重度压缩方案更易实现的实验室来说，这让它成为并一直是非常受欢迎的选择。

## 2.2 GQA 的内存节省

GQA 能大幅节省 KV 存储，因为每层保留的键值头越少，每个 token 需要缓存的状态就越少。这就是 GQA 随序列长度增长而变得更有用的原因。

GQA 也是一个谱系。如果一路减少到只有一个共享的 K/V 组，我们实际上就进入了多查询注意力的范畴，它更便宜，但可能更明显地损害建模质量。最佳点通常在多查询注意力（1 个共享组）和 MHA（K/V 组数等于查询数）之间的某处，在那里缓存节省很大，而相对于 MHA 的建模性能下降仍然有限。

## 2.3 为什么 GQA 在 2026 年依然重要

MLA 等更先进的变体正变得流行，因为它们能在相同的 KV 效率水平下提供更好的建模性能（例如 DeepSeek-V2 论文的消融研究中所讨论的），但它们也涉及更复杂的实现和更复杂的注意力栈。

GQA 依然有吸引力，因为它稳健、更容易实现，也更容易训练（根据我的经验，需要调的超参数更少）。

这就是为什么一些较新的发布在这方面仍刻意保持经典。例如，在我的《春季架构》一文中，我提到 MiniMax M2.5 和 Nanbeige 4.1 是保持非常经典的模型，只用分组查询注意力，没有叠加其他效率技巧。Sarvam 也是一个特别有用的对照：30B 模型保留了经典 GQA，而 105B 版本改用了 MLA。

# 3. 多头潜在注意力（MLA）

多头潜在注意力（MLA）背后的动机与分组查询注意力（GQA）相似。两者都是减少 KV 缓存内存需求的方案。GQA 与 MLA 的区别在于：MLA 通过压缩存储的内容来缩小缓存，而不是通过共享头来减少存储的 K/V 数量。

MLA 最初在 DeepSeek-V2 论文中提出，后来成为 DeepSeek 时代极具标志性的理念（尤其是在 DeepSeek-V3 和 R1 之后）。它比 GQA 更难实现、更难部署，但如今一旦模型规模和上下文长度大到缓存流量开始占主导，它也往往更有吸引力，因为在相同的内存削减比例下，它能保持更好的建模性能（后文详述）。

**示例架构**

DeepSeek V3、Kimi K2、GLM-5、Ling 2.5、Mistral Large 3 和 Sarvam 105B

## 3.1 是压缩，而不是共享

MLA 不像 MHA 和 GQA 那样缓存全分辨率的键和值张量，而是存储一个潜在表示，并在需要时重建可用的状态。本质上，它是一种嵌入在注意力内部的缓存压缩策略，如上图所示。

## 3.2 MLA 的消融研究

DeepSeek-V2 论文提供了一些消融实验，其中 GQA 在建模性能上看起来不如 MHA，而 MLA 的表现要好得多，经过仔细调优甚至可以超过 MHA。这比“它（也）能省内存”有力得多。

换句话说，MLA 之所以是 DeepSeek 偏爱的注意力机制，不只是因为它高效，还因为它看起来是一种在大规模下能保持质量的效率改进。（不过同行也告诉我，MLA 只在一定规模以上才效果好。对于较小的模型，比如小于 1000 亿参数的，GQA 似乎效果更好，或者至少更容易调好。）

## 3.3 MLA 在 DeepSeek 之后如何扩散

在 V2 中引入之后，DeepSeek V3/R1、V3.1 等让这种设计成为常态，它开始出现在第二波架构中。Kimi K2 沿用了 DeepSeek 的方案并将其扩大规模。GLM-5 采用了 MLA，同时搭配 DeepSeek 稀疏注意力（来自 DeepSeek V3.2）。Ling 2.5 把 MLA 与线性注意力混合架构配对。Sarvam 发布了两个模型，其中 30B 模型保留了经典 GQA，105B 模型改用了 MLA。

最后这一对特别有用，因为它把技术复杂度的讨论放到了一边。也就是说，Sarvam 团队两种变体都实现了，并刻意选择一个用 GQA、另一个用 MLA。所以在某种意义上，这让 MLA 不那么像一个理论上的替代方案，而更像是模型家族扩大规模时一条具体的架构升级路径。

# 4. 滑动窗口注意力（SWA）

滑动窗口注意力通过限制每个位置能关注的前序 token 数量，来降低长上下文推理的内存和计算成本。每个 token 不再关注整个前缀，而只关注其位置周围固定窗口内的最近 token。由于注意力被限制在局部 token 邻域内，这种机制常被称为局部注意力。

一些架构把这些局部层与偶尔出现的全局注意力层结合起来，让信息仍然能在整个序列中传播。

**示例架构**

Gemma 3 27B、OLMo 3 32B、小米 MiMo-V2-Flash、Arcee Trinity、Step 3.5 Flash 和 Tiny Aya

## 4.1 以 Gemma 3 为参照

Gemma 3 仍是近期最清晰的 SWA 例子之一，因为很容易把它和 Gemma 2 做比较。Gemma 2 已经使用了混合注意力设置，局部层与全局层比例为 1:1，窗口为 4096 个 token。Gemma 3 更进一步，把比例提高到 5:1，并把窗口缩小到 1024。

关键发现并不是局部注意力更便宜，因为这早已为人所知。Gemma 3 消融研究中更有意思的收获是：更激进地使用它，似乎只会轻微损害建模性能。

## 4.2 比例与窗口大小

在实践中，说一个模型“使用 SWA”并不意味着它只依赖 SWA。通常重要的是局部与全局层的排列模式和注意力窗口大小。例如：

- Gemma 3 和小米采用 5:1 的局部对全局模式。
- OLMo 3 和 Arcee Trinity 采用 3:1 的模式。
- 小米还使用了 128 的窗口大小，比 Gemma 的 1024 小得多，因此也激进得多。

SWA 本质上是一个可以调得更激进或更保守的旋钮。

## 4.3 SWA 与 GQA 结合

SWA 经常与 GQA 一同出现，因为这两种思路解决的是同一个推理问题的不同部分。SWA 减少局部层需要考虑的上下文量。GQA 减少每个 token 贡献给缓存的键值状态量。

这就是为什么许多近期的稠密模型同时使用两者，而不是把它们当作二选一。Gemma 3 在这里又是一个很好的参照，因为它在同一个架构中结合了滑动窗口注意力和分组查询注意力。

# 5. DeepSeek 稀疏注意力（DSA）

DeepSeek 稀疏注意力是 DeepSeek V3.2 系列中出现的架构变化之一，后来又出现在 GLM-5 中。

具体来说，DeepSeek V3.2 把它与多头潜在注意力（MLA）结合使用，而 GLM-5 出于相同的大致原因采用了同样的组合，即在上下文长度变大时降低推理成本。

**示例架构**

DeepSeek V3.2 和 GLM-5

## 5.1 相对于滑动窗口注意力的变化

在滑动窗口注意力中，当前 token 不关注完整前缀，而只关注一个固定的局部窗口。这与 DeepSeek 稀疏注意力背后的总体思路相同，后者中每个 token 也只关注前序 token 的一个子集。

然而，被选中的 token 并不是由固定宽度的局部窗口决定的。相反，DeepSeek 稀疏注意力使用一种学习得到的稀疏模式。简而言之，它采用“索引器 + 选择器”的设置：一个闪电索引器（lightning indexer）计算相关性分数，一个 token 选择器只保留一小部分高分的历史位置。

选择 token 子集的方式是它与滑动窗口注意力的主要区别。滑动窗口注意力把局部性写死了。DeepSeek 稀疏注意力仍然把注意力限制在一个子集上，但让模型自己决定哪些先前的 token 值得回看。

## 5.2 DeepSeek 稀疏注意力与 MLA

DeepSeek V3.2 同时使用多头潜在注意力（MLA）和 DeepSeek 稀疏注意力。MLA 通过压缩存储的内容来降低 KV 缓存成本。DeepSeek 稀疏注意力则减少模型需要回看的先前上下文的量。换句话说，一个优化缓存表示，另一个优化建立在缓存之上的注意力模式。

稀疏模式并不是随机的。第一阶段是闪电索引器，它为每个新的查询 token 给先前的 token 打分。它使用 MLA 压缩后的 token 表示，在先前上下文上计算一个学习得到的相似度分数，让模型能够对哪些较早位置值得回看进行排序。

第二阶段是 token 选择器。它只保留一个较小的高分子集，例如 top-`k` 个历史位置，并把这个子集转化为稀疏注意力掩码。所以要点在于，DeepSeek 稀疏注意力并没有把稀疏模式写死，而是学习保留哪些历史 token。

DeepSeek 稀疏注意力相对较新，实现起来也相对复杂，这就是为什么它还没有像分组查询注意力（GQA）那样被广泛采用。

# 6. 门控注意力

门控注意力最好理解为一种改进的全注意力块，而不是一个独立的注意力家族。

它通常出现在混合架构中——这些架构仍然保留偶尔出现的全注意力层用于精确的内容检索——并在一个原本熟悉的缩放点积注意力块之上增加了一些面向稳定性的改动。

## 6.1 门控注意力出现在哪里

Qwen3-Next 和 Qwen3.5 架构表明，近期的混合架构（下一节介绍）并没有在所有地方都替换掉注意力，而是用更便宜的替代方案替换大多数注意力层，并在栈中保留较少数量的全注意力层。

这些保留下来的全注意力层，正是门控注意力通常出现的地方。Qwen3-Next 和 Qwen3.5 把它与 Gated DeltaNet 以 3:1 的模式一同使用。

不过撇开混合架构不谈，Trinity 在一个更传统的注意力栈中使用了相关的门控思路，如上图所示。

## 6.2 门控注意力与标准注意力的对比

Qwen 风格混合架构或 Trinity（不是混合架构）中的门控注意力块，本质上就是标准缩放点积注意力加上几处改动。在最初的门控注意力论文中，这些改动被呈现为一种让混合栈中保留的全注意力层表现得更可预测的方法。

这个块看起来仍像标准（全）注意力，但它增加了：

1. 一个输出门，在注意力结果加回残差之前对其进行缩放；
2. 一种零中心的 QK-Norm 变体，取代 q 和 k 上的标准 RMSNorm；
3. 部分 RoPE（旋转位置编码）。

这些并不是 MLA 或线性注意力那种级别的改动，只是在一个原本熟悉的注意力块上施加的稳定性和控制性改动。

# 7. 混合注意力

混合注意力是一种更宽泛的设计模式，而不是某个具体的单一机制。总体思路是保留类 Transformer 的栈，但把大多数昂贵的全注意力层替换为更便宜的线性或状态空间序列模块。

动机是长上下文效率。全注意力随序列长度呈平方增长，所以一旦模型转向 128k、256k 或 100 万 token 这样的上下文，注意力的内存和计算就会变得足够昂贵，以至于在大多数层中使用更便宜的序列模块、只保留较少的较重检索层开始变得更合理。（不过请注意，这会带来一点建模性能上的取舍。）

在 Qwen3-Next 中，这种模式表现为 Gated DeltaNet 与门控注意力块的 3:1 混合。Gated DeltaNet 也与 Mamba-2 密切相关（例如可参见论文《门控 Delta 网络：用 Delta 规则改进 Mamba2》），这一机制可以理解为 DeltaNet 风格的快速权重更新与 Mamba 风格门控的结合。后来的架构保留了同样的总体思路，但换用了其他轻量级序列混合器，比如 Kimi Delta Attention、Lightning Attention 或标准 Mamba-2。

## 7.1 Qwen3-Next 中的 Gated DeltaNet

据我所知，第一个采用混合注意力的、接近旗舰级的知名 LLM 是 2025 年的 Qwen3-Next。它并没有完全去掉注意力，而是把三个 Gated DeltaNet 块与一个门控注意力块混合在一起。

在这里，轻量级的 Gated DeltaNet 块承担了大部分长上下文工作，让内存增长比全注意力平缓得多。较重的门控注意力层之所以保留，是因为 DeltaNet 在基于内容的检索上不够精确。

在 Gated DeltaNet 块内部，模型计算查询、键、值向量以及两个可学习的门（α、β）。它不形成通常的 token 到 token 注意力矩阵，而是用 delta 规则更新写入一个小型快速权重记忆。粗略地说，这个记忆存储了过往信息的一个压缩的滚动摘要，而门控制添加多少新信息、保留多少先前状态。

这使得 Gated DeltaNet 成为一种线性注意力或循环式的机制，而不只是对 MHA 的又一次微调。与 Mamba-2 的密切联系在于，两者都属于线性时间的门控序列模型家族，但 Gated DeltaNet 使用 DeltaNet 风格的快速权重记忆更新，而不是 Mamba 的状态空间更新。

Qwen3.5 把之前 Qwen3-Next 的混合架构搬进了 Qwen 的主力旗舰系列，这是一个有意思的举动。这基本上表明混合策略是成功的，未来我们可能会看到更多采用这种架构的模型。

## 7.2 Kimi Linear 与改进的 Delta 注意力

Kimi Linear 保留了同样宽泛的 Transformer 骨架和同样的 3:1 模式，但对配方的两半都做了改动。

在轻量级一侧，Kimi Delta Attention 是对 Gated DeltaNet 的改进。Qwen3-Next 为每个头使用一个标量门来控制记忆衰减，而 Kimi 使用通道级门控，对记忆更新的控制更精细。在较重的一侧，Kimi 用门控 MLA 层取代了 Qwen3-Next 的门控注意力层。

所以，它仍然是与 Qwen3-Next 和 Qwen3.5 相同的宽泛模式，但两种成分都（略有）变化。也就是说，大多数层仍由更便宜的线性类机制处理，并且仍保留周期性的较重层以提供更强的检索能力。

## 7.3 Ling 2.5 与 Lightning Attention

Ling 2.5 展示了轻量级一侧的另一种替换。Ling 没有用 Gated DeltaNet，而是使用了一种稍简单的循环线性注意力变体，叫 Lightning Attention。在较重的一侧，它保留了 DeepSeek 的 MLA。

大部分序列混合发生在更便宜的线性注意力块中，同时保留较少的较重层以维持更强的检索能力。区别在于，具体的轻量级机制现在是 Lightning Attention，而不是 DeltaNet 或 Kimi Delta Attention。

Ling 2.5 更瞄准长上下文效率，而不是绝对的基准领先。据 Ling 团队称，它在 32k token 时比 Kimi K2 快得多，这正是这些混合架构所追求的实际回报。

## Nemotron 与 Mamba-2

Nemotron 把这种模式推得离 Transformer 基线更远。Nemotron 3 Nano 是一种 Mamba-Transformer 混合架构，它把 Mamba-2 序列建模块与稀疏 MoE 层交错排列，只在一小部分层中使用自注意力。

这是上面讨论的同一基本取舍的更极端版本。在这里，轻量级序列模块是 Mamba-2 状态空间块，而不是 DeltaNet 风格的快速权重更新，但基本取舍是相似的。

更大的 Nemotron 3 Super 保留了 Mamba-2 混合注意力方案，并增加了其他面向效率的改动，比如潜在 MoE 和用于推测解码的共享权重多 token 预测（MTP）。

# 结论

当然，文献中还有许多（大多是小众的）注意力变体，我在这里没有涉及。本文的重点是那些目前在最先进的（开源权重）模型中使用的变体。

特别是，我期待（1）看到全新的 Mamba-3 层被整合进上述混合架构（取代 Gated DeltaNet），以及（2）注意力残差得到普遍使用。

在实践中，你可能也想知道目前“最好”的架构是什么。这很难回答，因为没有公开实验在相同的训练数据等条件下训练不同的架构。

因此，我们目前只能回答，对于给定问题，最好的（已训练好的）模型选择是什么。在我看来，混合架构仍是新鲜事物，主要卖点是（长上下文）效率，而不仅仅是建模性能。因此，我认为它们非常适合智能体场景（比如 OpenClaw）。

就我个人而言，我认为混合架构的问题还在于推理栈尚未充分优化，我发现在本地运行 LLM 时，使用更经典的设置（比如采用分组查询注意力的 GPT-OSS）能获得更高的 token/秒吞吐量。

无论如何，我很好奇 DeepSeek V4 会带来什么，因为在最近两年里，DeepSeek 一直是相当可靠的潮流引领者。
