几乎所有服务都需要默认的硬性预算上限 ｜ Simon Willison ｜ 文章 ｜ https://simonwillison.net/2026/Oct/3/default-hard-budget-caps/

Simon Willison 的一篇短文，呼吁按用量计费的服务和 API 都提供"默认的硬性预算上限"：超过每月 X 美元就直接切断、返回错误。只发警告邮件的软上限不够用。

他的理由是：编程 agent 和个人 agent（套了一层不那么吓人界面的编程 agent）让人很容易做出能干活的代码，而这些代码可能调用付费 API、部署托管应用、用掉按量计费的存储和算力。没人想半夜收到一封预算警告，醒来发现失控的服务又烧掉了几百甚至几千美元。有人反对说企业不希望应用因为超预算而报错，他认为多数企业和个人宁愿报错，也不想收到一万多美元的意外账单。所以硬上限应该是默认的，想冒险的人可以主动勾选"移除预算上限，超支费用由我承担"。

他最想看到的是 AWS，因为很多人出于合理的恐惧不敢拿 AWS 做个人项目，也有人没料到而被狠狠坑过。结果 AWS 几周前（9 月 16 日）真的推出了月度花费上限，达到上限项目就暂停到月底，目前只对部分客户开放；Google Cloud 7 月也推出了类似的 Spend Caps，看起来正在成为趋势。他最后希望 agent 也能帮忙：优先推荐有硬性预算上限的服务商，并提醒新手别把应用部署在可能让他们陷入麻烦的无上限服务上。
