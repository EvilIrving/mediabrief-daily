OpenAI and Codex with Thibault Sottiaux and Ed Bayes ｜ Software Engineering Daily ｜ 50分钟 ｜ https://softwareengineeringdaily.com/podcasts/openai-and-codex-with-thibault-sottiaux-and-ed-bayes/

本期 Software Engineering Daily 由 Kevin Ball（KBall）主持，嘉宾是 OpenAI Codex 的工程负责人 Thibault Sottiaux（Tibo）和产品设计师 Ed Bayes。节目录于 GPT-5.2 发布次日，围绕 Codex 的构建方式、模型与 harness 的协同演化、沙箱安全、内部使用方式、多智能体前景以及非技术用户展开。

两位嘉宾的核心论点是：智能体不只是模型，而是模型加上工具、上下文处理和推理方式构成的整体。Tibo 把 harness 比作大脑之外的"身体"，决定智能体如何作用于世界，而且必须安全地作用。Codex 最早是云端版，每个任务跑在独立虚拟机里，底层是 Kata Containers；后来推出 CLI 和 VS Code 扩展时，仍坚持"默认安全"，限制网络和文件系统访问。他们承认频繁的命令审批会让体验别扭，Ed 介绍的折中是让用户切换智能体模式和只读模式，并对已批准的命令做细粒度控制、写入配置。

关于模型，KBall 问到 GPT-5.1 与 GPT-5.1-Codex 的区别，并提到在 Cursor 里纯 5.1 反而更好用。Tibo 解释，Codex 系列是与 harness 协同训练的，在 Codex 环境里更得心应手；5.1-Codex-Max 融入了几项研究突破，能更持久地工作，用的 token 更少、成本更低。衡量标准是单位时间或单位成本能创造多少经济价值，所以模型选择器只保留少数几个选项，并给出默认推荐。他强调 harness 要刻意保持简单，本质就是一个 for 循环加若干工具调用，否则短期内的过度优化会跟不上模型能力的跃升。CLI 完全开源，系统提示词就在仓库里。GPT-5.2 在 GDPval 上提升超过 20%，延迟和算力离用户多远也因此更加关键。

内部使用方面，OpenAI 的每个 PR 都经过 Codex 审查，Tibo 称之为离不开的安全网。文案和市场团队自己改定价文字，设计师从贴 Figma 静态图变成贴可交互原型。Codex 还接入了 Slack 和 Linear，可以在讨论串里 @ 它直接起任务。Tibo 认为代码生成"几乎已经解决"，瓶颈正转向审查、部署、值班和规划，其中部署和值班风险大、难以放进沙箱，仍是开放问题。Sora 和 Atlas 都是几个人驾驭一串智能体就搭出了大块代码库的例子；Ed 也提到，Deep Research 这样触达海量用户的产品，团队只有一名 PM、一名设计师和几名工程师、研究员。

KBall 分享了自己的工作流：先让智能体为子系统写一份带文件链接的"地图"文档，做上下文压缩；再列出几种方案、互相辩论；然后写实现计划、拆成测试。Tibo 认为这类"菜谱"正说明产品应保持开放，引入有主张的框架要谨慎。他还说，团队如今很少写"如何运作"的文档，新人直接靠 Codex 探索代码库，文档更多记录"为什么"。被问到 hooks 时，他说还在讨论，眼下的重点是构建能让智能体连续工作一天甚至一周的原语，并预言 2026 年会出现稳健的多智能体网络；Ed 补充 Codex SDK 已经可用。Ed 关注的设计难题是：任务从一分钟变成十小时、又有多个智能体并行时，用户如何掌握全局、不必频繁切换上下文，以及非程序员的第一次上手体验。

谈到智能体的未来角色，KBall 指出，过去亲手写代码同时也在更新开发者对系统和用户问题的心智模型；生成代码的工作委派出去以后，这种理解从哪里来？Tibo 认为，智能体将来要做的远不止写代码：它应当知道你在乎什么，主动告诉你代码库怎么变了、用户怎么看产品，参与规划、构思和理解用户反馈。到那时代码生成也许只占它工作的一小部分。Ed 用 ChatGPT 作类比：最初只是一问一答，智能体时代的交互则更像把一项要花时间、需要协调的大任务交给同事。在非技术用户方面，Tibo 说最好的编程智能体终究是通用智能体，已经有人用 Codex 做数据分析、编辑表格和市场调研，不过团队眼下仍把专业软件工程放在第一位。Ed 讲了设计团队团建的例子：会写代码的同事挨个帮大家装好 npm、上手 CLI 和扩展，起初觉得终端吓人的人，现在写代码越来越多。

结尾两人都劝听众保持好奇，重新审视两年前还有效的老办法。Tibo 认为现在是遇到问题的最好时代；Ed 则感慨，设计师独自就能做出比线上产品更好的原型，角色边界正在模糊。
