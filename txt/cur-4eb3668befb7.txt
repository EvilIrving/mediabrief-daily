Gas Town, Beads, and the Rise of Agentic Development with Steve Yegge ｜ Software Engineering Daily ｜ 68分钟 ｜ https://softwareengineeringdaily.com/podcasts/gas-town-beads-and-the-rise-of-agentic-development-with-steve-yegge/

本期 Software Engineering Daily 由 Mento 工程副总裁 Kevin Ball（KBall）主持，嘉宾是写了 40 年代码、以博客吐槽文闻名的业内老兵 Steve Yegge。两人围绕他最近打造的 Beads 和 Gas Town，讨论 AI 编程从聊天辅助走向多智能体编排的过程，以及这对开发者心智、团队协作和整个行业意味着什么。Steve 整体极度乐观，KBall 认同大方向，但不断追问人如何跟得上。

Steve 先回顾了几个转折点：ChatGPT 3.5 能写出像样的 Emacs Lisp 函数，让他第一次觉得"悬浮摩托虽然老坠毁，但比走路快"；GPT-4o 能一字不差地复现千行文件并只改一个字符，等于能编辑世界上大多数源文件；Sonnet 3.7 带来 Claude Code；Opus 4.5 则让 Gas Town 得以运转。他的概括是"聊天把提问放进循环，Claude Code 把聊天放进循环，Gas Town 把 Claude Code 放进循环"。他认为 Anthropic 的发布间隔已从四个月缩到两个月，唱反调的人只看前后三个月，看到的是导数而不是那条陡峭的曲线；在他眼里，Opus 4.5 是砸进池塘的那块大石头，人们开始意识到模型其实已经不需要再变聪明了。KBall 也说，自 Sonnet 3.5 起，即使再也不出新模型，软件工程也已经永远改变，只是当时能啃下的任务块还小，必须先拆分，而现在这座山大了很多；他还引用 antirez 的话：再手写代码已经没有意义。

关于 Beads，Steve 说它本质上是给智能体用的任务追踪器，但有三个关键特性：任务以图的形式组织，可以用 SQL 查询，并且整本账记在 Git 里。Claude 参与了设计，加入了"discovered-from"这类人类想不到的边，方便追溯工作是怎么展开的。智能体有了它就不再推卸责任，看到问题会顺手记一个 bead，积压的 bead 又能直接分派给别的智能体去做、去审查，于是 Beads 成了一种通过 Git 联邦化、不需要中心服务的共享记忆。他坦承最初把 JSONL 和 SQLite 硬拼在一起，合并冲突不断，下一版会改用老同事 Tim Sehn 创办的 Git 式数据库 Dolt。Dolt 本身就是 Git 原生的数据库，可以嵌入 Go 程序，换上它以后三方合并、同步命令和守护进程都可以去掉，冲突也能细到按字段来解决。已经有贡献者在 Beads 上加了键值存储，他因此说 Beads 正在变成智能体的数据平面。他也承认现在的代码是氛围编程写出来的，代码审查落后了一个月，但测试全部通过，用户也一直在用。

谈到规格说明和上下文，Steve 转述 Anthropic 内部的两派：一派把任务切到最小、用完即弃，以控制成本和性能；另一派把上下文塞满，让模型知道"为什么"。Gas Town 的 polecat 对应前者，负责已经规格清楚的流水线式工作；crew 对应后者，用来做需要深度思考的设计。他的实用技巧是顺着模型喜欢清单和验收标准的特点写启动和收尾提示词，比如"让飞机着陆"，让智能体在上下文耗尽前也能把收尾做完。收尾时要清理分支、stash、没合并的工作和没关闭的 bead，下次启动时再检查一遍，因为模型很擅长勾清单，却经常忘掉收尾。两人还顺带比较了各家模型：Steve 调侃 GPT 不会写代码，KBall 说 GPT-5.2 在某些风格的代码上很有效，只是慢得多，两人都认为它写 UI 很差，Gemini 3 据说在这方面接近 Claude。他建议先手动练熟这些，再去驾驭一群智能体。

Gas Town 本身是一个编排器。Steve 用"程序员的八个阶段"解释它的由来：信任来自可预测性，信任越高耐心越低，于是开的智能体越来越多，个人问题变成了团队问题。他借用 Jeffrey Emanuel 的邮件机制，给智能体分配身份、收件箱和镇长、polecat 等角色，看到镇长训斥越权的"喷嚏精"，也见过一个蜂群一下清空了 30 个 bug。他认为邮件之所以好用，是因为它在训练数据里存在得最久，模型就像穿惯了一条旧牛仔裤。他的原则是"永远不要看它们干活"，只处理已经完成的那些，要么带它们补完收尾，要么和它们讨论新的设计。Anthropic 认为 Gas Town 的不少角色只是在绕开模型的缺陷，所以他预计它会逐渐扁平成两三层结构。12 月 28 日它第一次"编译了自己"，像自举编译器一样进入自托管，他两天后就发布了，整套角色阵容、神话设定、主题歌和 Nano Banana 生成的插图一起登场，这一下把讨论的奥弗顿之窗挪动了一大截。

KBall 最关心人怎样维持对系统的心智模型。他自己同时管着三到五个智能体，还要带一个团队，团队里每个人手下又各有一批智能体，跟上所有人的进度越来越难。Steve 认为关键不在语法细节，而在功能规格：要像技术型产品经理或超级技术负责人那样，不断向模型追问、定期审查、积极砍掉没用的功能。他用核潜艇的复杂度反驳"不看代码就不理解代码"的说法，又引用 Peter Norvig"能把整个问题装在脑子里"的回答。速度带来新的协作危机，他的两个朋友各跑 20 个智能体，嫌同事"落后两小时、错过了六个决定"。在他看来，每个人都成了带团队的经理，软技能和沟通变得至关重要。说到质量，他认为那只是一种选择：他有位顶尖工程师朋友靠逐一审查达到了更高的质量，Beads 的测试代码也比业务代码多，验证和确认成了新的关卡，合并则是新的瓶颈。Gas Town 为此专门设了一个精炼厂角色负责重做合并。他也提醒，资深工程师受益更多，因为他们一眼就能看出好坏；Gas Town 至今仍很不稳定，他曾一次杀掉 320 个各占约 1GB 内存的 Claude Code 实例，所以不建议拿它给普通用户做产品。

展望行业，Steve 预测绩效评估和招聘都会被打乱，业务团队会自己写软件，工作会变得零工化、机动化，传统规划会被淘汰，"活的软件"本身就成了规格说明；编程会像 RTS 游戏和老虎机一样让人上瘾，而他认为这能让所有人都参与进来。KBall 坦言自己在机场宁可憋着也不愿离开刚启动的智能体。Steve 则把这种状态比作《刺客信条》里派间谍出任务：总有一个智能体在等你，人很快就会进入这种平衡。他认为只要把知识工作都拆成 bead、匹配给世界上所有人，软件开发就会被民主化。最后他首次抛出一个"热力学"判断：在 AI 吞噬软件的时代，能帮模型节省 token 的基础设施才能活下来，比如 Serena、Dolt、Kafka，而且要像 Notion 那样主动让模型学会使用自己。KBall 补充说，他还举了 Anthropic 分析模型做乘法的研究为例：模型先靠模式匹配猜出大概的数，再查表确定个位，绕了很大的弯，所以只要有更省的工具，懒惰的模型就会去用。独有的数据和访问权限同样重要，Steve 承认这只是必要条件、不是充分条件。他又设想，两年后手机上可能只剩一个 Claude，人们会越来越依赖 AI，别的应用只有提供 Claude 给不了的东西才能留下来，比如精心设计的游戏、它拿不到的数据，或者大量真人聚在一起的产品。KBall 评论说他描述的未来一半是乌托邦，一半是反乌托邦。Steve 以重读阿瑟·克拉克作答。他最后警告，单一的全球支付或社交通道会走向数字封建和监控，AI 是人类面前的十字路口，今年社会对 AI 的反弹会前所未有。
