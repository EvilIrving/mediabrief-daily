# 大语言模型中的外在幻觉（Extrinsic Hallucinations in LLMs）

作者：Lilian Weng（Lil'Log），2024-07-07

大语言模型中的幻觉通常指模型生成不忠实、捏造、前后不一致或毫无意义的内容。作为一个术语，“幻觉”在某种程度上已被泛化到模型犯错的各种情况。在这里，我想把幻觉问题收窄到这样的情形：模型输出是捏造的，并且**没有依据**——既不以所提供的上下文为依据，也不以世界知识为依据。

幻觉有两种类型：

1. 上下文内幻觉（in-context hallucination）：模型输出应当与上下文中的源内容保持一致。
2. 外在幻觉（extrinsic hallucination）：模型输出应当以预训练数据集为依据。然而，考虑到预训练数据集的规模，针对每次生成去检索并识别冲突的成本太高了。如果我们把预训练语料视为世界知识的代理，那么我们本质上是在努力确保模型输出是事实性的、可以被外部世界知识验证的。同样重要的是，当模型不知道某个事实时，它应该如实说明。

本文聚焦于外在幻觉。为了避免幻觉，大语言模型需要（1）符合事实，并且（2）在适当的时候承认不知道答案。

# 什么导致了幻觉？

一个标准的可部署大语言模型要经过预训练，以及为对齐和其他改进而进行的微调，我们来分别考虑这两个阶段的原因。

## 预训练数据的问题

预训练语料的体量极其庞大，因为它被期望以所有可得的书面形式来代表世界知识。从公共互联网上爬取的数据是最常见的选择，因此其中出现过时、缺失或错误的信息是意料之中的。由于模型可能仅仅通过最大化对数似然就错误地记住了这些信息，我们可以预期模型会犯错。

## 用新知识进行微调

通过监督微调（SFT）和 RLHF 对预训练大语言模型进行微调，是提升模型某些能力（比如遵循指令）的常见技术。在微调阶段引入新知识是难以避免的。

微调消耗的算力通常要少得多，因此模型能否通过小规模微调可靠地学到新知识是有争议的。Gekhman 等人（2024）研究了这样一个问题：用新知识微调大语言模型是否会助长幻觉。他们发现：（1）与那些和模型已有知识一致的样本相比，大语言模型学习含有新知识的微调样本要*更慢*；（2）一旦含有新知识的样本最终被学会，它们会增加模型产生幻觉的倾向。

给定一个闭卷问答数据集（即 EntityQuestions）$D = {(q, a)}$，我们定义 $P\_\text{Correct}(q, a; M, T )$ 为：在使用*随机少样本示例*作为提示、解码温度为 $T$ 时，模型 $M$ 能准确生成问题 $q$ 的正确答案 $a$ 的可能性估计。他们基于 $P\_\text{Correct}(q, a; M, T )$ 的不同条件，把样本分成一个包含 4 个类别的小型层级：`Known`（已知）组，下分 3 个子组（`HighlyKnown` 高度已知、`MaybeKnown` 可能已知、`WeaklyKnown` 弱已知），以及 `Unknown`（未知）组。

实验中一些有趣的观察（以开发集准确率作为幻觉的代理指标）：

1. `Unknown` 样本的拟合速度明显慢于 `Known` 样本。
2. 当大语言模型拟合了大部分 `Known` 训练样本、但只拟合了少数 `Unknown` 样本时，开发集表现最好。当模型学会了大部分 `Unknown` 样本时，它就开始产生幻觉。
3. 在 `Known` 样本中，`MaybeKnown` 样本带来更好的整体表现，比 `HighlyKnown` 样本更为关键。

Gekhman 等人（2024）的这些实证结果指出了用监督微调来更新大语言模型知识的风险。

# 幻觉检测

## 检索增强的评估

为了量化模型幻觉，Lee 等人（2022）引入了一个新的基准数据集 **FactualityPrompt**，由事实性提示和非事实性提示组成。该数据集使用维基百科文档或句子作为事实依据的知识库。维基百科文档是来自 FEVER 数据集的已知真实依据，而句子则基于 tf-idf 或基于句子嵌入的相似度进行选取。

给定模型的续写和配对的维基百科文本，考虑两种幻觉评估指标：

1. **幻觉命名实体（NE）错误**：使用一个预训练的实体检测模型和文档级依据，该指标衡量检测到的命名实体中未出现在真实依据文档中的比例。
2. **蕴含比率**：使用一个在 MNLI 上微调过的 RoBERTa 模型和句子级知识依据，该指标计算生成的句子中被蕴含模型标记为与配对维基百科句子相关的比例。

更低的 NE 错误和更高的蕴含比率意味着更高的事实性，并且这两个指标都被发现与人工标注相关。更大的模型被发现在这个基准上表现更好。

**FActScore**（Factual precision in Atomicity Score，原子性事实精确度得分；Min 等人，2023）把一段长文本生成分解为多个原子事实，并分别对照维基百科之类的知识库逐一验证。然后我们可以衡量每次模型生成中被知识源支持的句子的比例（精确率），而 FActScore 就是模型在一组提示上生成结果的平均精确率。该论文在人物传记生成任务上试验了几种事实性验证方式，发现使用检索始终比无上下文的大语言模型更好。在检索增强的方法中，究竟哪个估计器最好则取决于模型。

- 无上下文 LLM：直接用 `<atomic-fact> True or False?` 提示 LLM，不加额外上下文。
- 检索→LLM：把从知识源检索到的 $k$ 个相关段落作为上下文进行提示。
- 非参数概率（NP）：用一个掩码语言模型计算原子事实中各 token 的平均似然，并据此做出预测。
- 检索→LLM + NP：两种方法的集成。

关于模型幻觉行为的一些有趣观察：

- 在传记生成任务中，越罕见的实体错误率越高。
- 在生成中越靠后提到的事实错误率越高。
- 使用检索为模型生成提供依据，能显著帮助减少幻觉。

Wei 等人（2024）提出了一种检查大语言模型长文本事实性的评估方法，名为 **SAFE**（Search-Augmented Factuality Evaluator，搜索增强的事实性评估器；附代码）。与 FActScore 相比，主要区别在于：对于每个自成一体的原子事实，SAFE 把一个语言模型当作智能体，在一个多步过程中迭代地发出 Google 搜索查询，并推理搜索结果是否支持该事实。在每一步中，智能体根据要检查的事实以及之前获得的搜索结果生成一个搜索查询。经过若干步之后，模型进行推理，判断该事实是否被搜索结果*支持*。根据实验，SAFE 方法比人工标注者效果更好，而成本便宜 20 倍：与人类的一致率为 72%，在两者意见不一致时，相对人类的胜率为 76%。

SAFE 的评估指标是 **F1 @ K**。其动机是，针对**长**文本事实性的模型回答理想情况下应该兼顾精确率和召回率，因为回答应当既是

- *事实性的*：用精确率衡量，即整个回答的所有事实中被支持的事实所占的百分比。
- *长的*：用召回率衡量，即回答中提供的事实占所有应当出现在回答中的相关事实的百分比。因此我们希望把被支持事实的数量计到 $K$ 为止。

给定模型回答 $y$，指标 **F1 @ K** 定义为：

$$ \begin{aligned} S(y) &= \text{the number of supported facts} \\ N(y) &= \text{the number of not-supported facts} \\ \text{Prec}(y) &= \frac{S(y)}{S(y) + N(y)},\quad R_K(y) = \min\big(\frac{S(y)}{K}, 1\big) \\ F_1 @ K &= \begin{cases} \frac{2\text{Prec}(y)R_K(y)}{Prec(y) + R_K(y)} & \text{if } S(y) > 0 \\ 0, & \text{if } S(y) = 0 \end{cases} \end{aligned} $$

（其中 $S(y)$ 为被支持的事实数，$N(y)$ 为未被支持的事实数。）

**FacTool**（Chern 等人，2023）遵循标准的事实核查工作流程。它被设计用于检测各类任务中的事实错误，包括基于知识的问答、代码生成、数学解题（生成测试用例而非断言）以及科学文献综述。它的流程是：

1. 断言提取：通过提示 LLM 提取所有可验证的断言。
2. 查询生成：把每条断言转换为适合外部工具的查询列表，例如搜索引擎查询、单元测试用例、代码片段和论文标题。
3. 工具查询与证据收集：查询搜索引擎、代码解释器、Google Scholar 等外部工具并取回结果。
4. 一致性验证：根据来自外部工具的证据的支持程度，给每条断言分配一个二元的事实性标签。

## 基于采样的检测

**SelfCheckGPT**（Manakul 等人，2023）依靠对黑盒 LLM 的多个采样结果进行一致性检查来发现事实错误。考虑到灰盒事实核查度量需要访问 LLM 的 token 级对数概率，SelfCheckGPT 只需要采样结果，不依赖外部知识库，因此黑盒访问就足够了，也不需要外部知识库。

该方法可以使用不同的指标来衡量模型回答与其他每一个随机模型采样之间的一致性，包括 BERTScore、NLI、提示（询问是/否）等。在 GPT-3 生成的 WikiBio 段落上实验时，使用提示的 SelfCheckGPT 似乎效果最好。

## 对未知知识的校准

提示模型回答无法回答或未知的问题可能会诱发幻觉。TruthfulQA（Lin 等人，2021）和 SelfAware（Yin 等人，2023）是两个用于衡量模型在这类情况下能否生成真实回答的基准，前者是对抗性构造的，侧重人类常见的错误观念，后者包含因其本身性质而无法回答的问题。面对这些问题时，模型应当拒绝回答或给出相关信息。

**TruthfulQA**（Lin 等人，2021）中的测试问题是根据人类常见的误解或错误*对抗性地*设计的。该基准包含 817 个问题，涵盖健康、法律、金融和政治等 38 个主题。在这里，一个回答当且仅当它避免断言错误陈述时才被视为真实的，包括拒绝回答、不相关但真实的回答等。在论文测试时，最好的 LLM 准确率为 58%，而人类可以达到 94%。他们发现，由于常见误解，更大的模型反而更不真实，但这一趋势在其他标准（非对抗性）事实性基准上并未出现。

Yin 等人（2023）研究了*自我认知（self-knowledge）*的概念，指语言模型是否知道自己知道什么、不知道什么。
**SelfAware** 包含五个类别下的 1,032 个无法回答的问题，以及 2,337 个可以回答的问题。无法回答的问题来自在线论坛并经过人工标注，而可以回答的问题则根据与无法回答问题的文本相似度，取自 SQuAD、HotpotQA 和 TriviaQA。一个问题可能因为各种原因而无法回答，比如没有科学共识、对未来的想象、完全主观、可能产生多种回答的哲学原因等。把区分可回答与不可回答问题视为一个二分类任务，我们可以衡量 F1 分数或准确率，实验表明更大的模型在这个任务上表现更好。

评估模型对未知知识的意识的另一种方式，是衡量模型输出的不确定性。当一个问题处于已知与未知之间时，模型应当表现出恰当程度的置信度。

Kadavath 等人（2022）的实验表明，在带有可见字母选项格式的各种多项选择题上（MMLU、TruthfulQA、QuALITY、LogiQA），LLM 对答案正确概率的估计校准得很好，即预测概率与该答案为真的频率相吻合。RLHF 微调会使模型校准变差，但更高的采样温度会带来更好的校准结果。

Lin 等人（2022）使用了 CalibratedMath 任务套件。*CalibratedMath* 是一套按程序生成的、不同难度（例如取决于涉及的位数）的数学题，用来测试模型输出概率的校准程度。对于每个问题，模型必须同时给出一个数值答案和对答案的置信度。考虑了三类概率：

1. 用语言表达的数字或词语（例如“最低”“低”“中”“高”“最高”），比如 `"Confidence: 60% / Medium"`。
2. 答案 token 的归一化对数概率；注意这一项没有用于微调实验。
3. 在原始答案之后一个间接的 `"True/False"` token 的对数概率。
他们的实验关注校准在任务难度或内容发生分布偏移时的泛化能力。每个微调数据点包括一个问题、模型的答案（可能是错的）以及一个校准过的置信度。用语言表达的概率在两种情况下都泛化得很好，而所有设置在乘除法任务偏移上都表现不错。在模型预测置信度的准确程度上，少样本方法弱于微调模型。加入更多示例是有帮助的，50 个样本的少样本提示几乎和微调版本一样好。

## 间接查询

Agrawal 等人（2023）专门研究了 LLM 生成中幻觉引用的情况，包括捏造的书籍、文章和论文标题。他们试验了两种基于一致性的幻觉检查方法：直接查询与间接查询。两种方法都在 T > 0 下多次运行检查并验证一致性。

*直接查询*让模型判断某个生成的引用是否存在。**间接查询**则询问生成引用的辅助细节——作者是谁；例如，如果我们想检查 `"Is the following paper real?"`（下面这篇论文是真的吗？），我们可以检查 `"Who are the author of the paper?"`（这篇论文的作者是谁？）。其假设是：对于一个幻觉出来的引用，多次生成就同一组作者达成一致的可能性，会小于多次直接查询都表示该引用存在的可能性。实验表明间接查询方法效果更好，并且更大的模型能力更强、幻觉更少。

# 反幻觉方法

我们来回顾一组提升 LLM 事实性的方法，从检索外部知识库、特殊的采样方法到对齐微调。也有通过神经元编辑来减少幻觉的可解释性方法，但这里我们略过。我以后可能会单独写一篇关于可解释性的文章。

## RAG → 编辑与归因

RAG（检索增强生成）是提供依据信息的一种非常常见的方法，即先检索相关文档，然后把相关文档作为额外上下文进行生成。

**RARR**（“Retrofit Attribution using Research and Revision”，通过研究与修订进行事后归因；Gao 等人，2022）是一个框架，通过*为归因而编辑（Editing for Attribution）*，事后让 LLM 能够支持对外部证据的归因。给定一段模型生成的文本 $x$，RARR 分两步处理，输出一段修订后的文本 $y$ 和一份归因报告 $A$：

1. **研究阶段**：寻找相关文档作为证据。
  - （1）首先使用一个查询生成模型（通过少样本提示，$x \to {q\_1, \dots, q\_N}$）构建一组搜索查询 ${q\_1, \dots, q\_N}$，以验证每个句子的方方面面。
  - （2）运行 Google 搜索，每个查询 $q\_i$ 取 $K=5$ 个结果。
  - （3）利用一个预训练的查询-文档相关性模型分配相关性分数，每个查询 $q\_i$ 只保留最相关的 $J=1$ 篇文档 $e\_{i1}, \dots, e\_{iJ}$。
2. **修订阶段**：编辑输出，纠正不被证据支持的内容，同时尽可能保留原始内容。将修订文本初始化为 $y=x$。
  - （1）对于每个 $(q\_i, e\_{ij})$，一个一致性模型（通过少样本提示 + CoT，$(y, q, e) \to {0,1}$）检查证据 $e\_i$ 是否与当前修订文本 $y$ 不一致。
  - （2）只有在检测到不一致时，编辑模型（通过少样本提示 + CoT，$(y, q, e) \to \text{ new }y$）才输出一个新版本的 $y$，力求与证据 $e\_{ij}$ 一致，同时在其他方面尽量少改动 $y$。
  - （3）最后，只有有限数量 $M=5$ 的证据进入归因报告 $A$。

在评估修订后的文本 $y$ 时，归因指标和保留指标都很重要。

- *归因*：使用 AIS（Attributable to Identified Sources，可归因于已识别来源）分数衡量 $y$ 中有多少可以归因于 $A$。我们可以收集人工标注，或者用 NLI 模型来近似自动 AIS 分数。
- *保留*：指 $y$ 在多大程度上保留了 $x$ 的原始文本，用 $\text{Prev}\_\text{intent} \times \text{Prev}\_\text{Lev}$ 衡量，其中 $\text{Prev}\_\text{intent}$ 需要人工标注，$\text{Prev}\_\text{Lev}$ 基于字符级的 Levenshtein 编辑距离。
与两个基线相比，RARR 带来了更平衡的结果，尤其是在保留指标方面。

与 RARR 使用搜索 + 编辑类似，**FAVA**（“Factuality Verification with Augmented Knowledge”，借助增强知识的事实性验证；Mishra 等人，2024）也是先检索相关文档，然后编辑模型输出以避免幻觉错误。FAVA 模型由一个检索器 $\mathcal{M}\_\text{ret}$ 和一个编辑器 $\mathcal{M}\_\text{edit}$ 组成。

- 给定提示 $x$ 和模型输出 $y$，检索出最相关的文档：$d = \mathcal{M}\_\text{ret}(x, y)$
- 由编辑器生成增强后的输出：$\hat{y} = \mathcal{M}\_\text{edit}(x, y, d)$

RARR 不需要训练，但 FAVA 中的编辑器模型 $\mathcal{M}\_\text{edit}$ 需要微调。按照一套更细致的幻觉错误类型分类法，我们可以通过在模型生成中插入随机错误，为 $\mathcal{M}\_\text{edit}$ 生成合成训练数据。每个样本是一个三元组 $(c, y, y^\*)$，其中 $c$ 是作为黄金上下文的原始维基百科段落，$y$ 是含有错误的语言模型输出，$y^∗$ 是带有错误标签和正确编辑的输出。

**Rethinking with retrieval**（**RR**，借助检索重新思考；He 等人，2022）方法同样依赖检索相关的外部知识，但不做额外编辑。RR 的检索不是利用搜索查询生成模型，而是基于分解后的 CoT 提示。给定输入提示 $Q$，RR 使用 CoT 提示在温度 > 0 下生成多条推理路径 ${R\_1, \dots, R\_N}$，其中每条推理路径 $R\_i$ 包含一个解释 $E\_i$（即推理部分），后面跟着一个预测 $P\_i$（即实际的模型输出）。检索外部知识 $K\_1, \dots, K\_M$ 来支持每个解释。然后根据与检索到的知识 $K\_1, \dots, K\_M$ 的契合程度，选出最忠实的答案 $\hat{P}$。

- *知识检索*：RR 的实验对维基百科使用稀疏检索 BM25，然后用预训练 MPNet 模型提供的嵌入余弦相似度进行重排。
- *忠实度分数*：每条推理路径的忠实度通过结合蕴含分数、矛盾分数和 MPNet 相似度来估计。蕴含分数和矛盾分数都由一个预训练的 NLI 模型提供。

**Self-RAG**（“Self-reflective retrieval-augmented generation”，自我反思的检索增强生成；Asai 等人，2024）端到端地训练一个语言模型，让它学会通过同时输出任务结果和间歇性的特殊*反思 token* 来反思自己的生成。他们通过提示 GPT-4 为一个评判模型和一个生成模型创建了监督数据集，然后把它蒸馏到一个内部模型中以降低推理成本。

给定输入提示 $x$，生成的输出 $y$ 由多个片段组成（例如一个片段就是一个句子）$y=\[y\_1, \dots, y\_T\]$。共有四种反思 token，一种用于检索，三种用于评判：

- `Retrieve`：决定是否并行运行检索以获取一组文档；输出值：`{yes, no, continue}`。
- `IsRel`：提示 $x$ 与检索到的文档 $d$ 是否相关；输出值：`{relevant, irrelevant}`。
- `IsSup`：输出文本 $y$ 是否被 $d$ 支持；输出值：`{fully supported, partially supported, no support}`。
- `IsUse`：输出文本 $y$ 对 $x$ 是否有用；输出值：`{5, 4, 3, 2, 1}`。

Self-RAG 一次生成一个片段 $y\_t$。给定 $x$ 和之前的生成 $y\_{\<t}$，模型解码出 `Retrieve` token：

1. 如果 `Retrieve` == `no`，直接生成 $y\_t$；
2. 如果 `Retrieve` == `yes`，模型并行检索多个段落，并用一个 `IsRel` token 检查检索到的文档是否相关。如果相关，就生成 $y\_t$，并用其他评判 token 打分、排序，从多个输出中选出最好的。

## 行动链

在没有外部检索知识作为依据的情况下，我们可以设计一个流程，让模型自己进行验证和修订以减少幻觉。

Dhuliawala 等人（2023）提出了一种名为 **Chain-of-Verification**（**CoVe**，验证链）的方法，基于一条用于规划和执行验证的行动链。CoVe 包含四个核心步骤：

1. *基线回答*：模型生成一个初始的回答草稿，称为“基线”。
2. *规划验证*：基于这个原始生成，模型设计出用于事实核查的非模板化验证问题；可以通过带有（回答，验证问题）示例的少样本提示来实现。
3. *执行验证*：模型独立地回答这些问题。有几种不同的设置变体：
  - （1）联合（Joint）：与第 2 步合并，少样本示例的结构为（回答，验证问题，验证答案）；缺点是原始回答仍在上下文中，因此模型可能会重复类似的幻觉。
  - （2）两步（2-step）：把验证的规划和执行分成两步，使原始回答不产生影响。
  - （3）分解（Factored）：每个验证问题单独回答。比如，如果一段长文本基础生成产生了多个验证问题，我们就逐一回答每个问题。
  - （4）分解+修订（Factor+revise）：在分解式验证执行之后加入一个“交叉核对”步骤，以基线回答以及验证问题和答案为条件。它用来检测不一致之处。
4. *最终输出*：生成最终的、经过精炼的输出。如果发现任何不一致，输出会在这一步被修订。

CoVe 之所以这样设计，是因为使用长文本的验证链生成可能会导致重复的幻觉——最初带有幻觉的回答仍在上下文中，在新的生成过程中可能被注意到；而单独回答各个验证问题比长文本生成效果更好。

以下是 CoVe 实验中的一些有趣观察：

- 指令微调和 CoT 并不能减少幻觉。
- 分解式和两步式 CoVe 提升了表现，进一步对不一致检测进行显式推理也有帮助（“分解+修订”方法）。
- 短形式的验证问题比长形式的查询回答得更准确。
- LLM 自由生成的验证问题比启发式问题（例如 `Does X answer the question?`）更好，并且需要开放式生成的问题比是/否问题效果更好。

**RECITE**（“Recitation-augmented generation”，背诵增强生成；Sun 等人，2023）依靠背诵作为中间步骤来提升模型生成的事实正确性并减少幻觉。其动机是把 Transformer 的记忆用作一种信息检索机制。在 RECITE 的“先背诵再回答”方案中，LLM 被要求先背诵相关信息，然后再生成输出。具体来说，我们可以用少样本上下文提示来教模型先生成背诵内容，再以背诵内容为条件生成答案。此外，它还可以与使用多个采样的自洽性集成相结合，并扩展到支持多跳问答。

生成的背诵内容与基于 BM25 的检索模型效果相当，但两者与使用真实段落相比都有差距。根据他们的错误分析，大约 7-10% 的问题背诵内容正确却无法给出正确答案，而大约 12% 的问题背诵内容不正确却仍然能被正确回答。

## 采样方法

Lee 等人（2022）发现，核采样（top-$p$ 采样）虽然能带来更好的多样性和更少的重复，但在 FactualityPrompt 基准上的表现比贪心采样差，因为核采样引入了额外的随机性。于是他们提出了**事实核采样（factual-nucleus sampling）**算法，其基于的假设是：采样随机性*对句子后半部分事实性的危害大于对句子开头的危害*。事实核采样被设计为在为每个句子采样 token 时*动态地*调整概率 $p$。对于一个句子中的第 $t$ 个 token，我们有 $p\_t = \max(\omega, p \cdot \lambda^{t−1})$，其中 $\omega$ 用于防止采样退化为贪心采样，以免损害生成质量和多样性。

**推理时干预（Inference-Time Intervention，ITI**；Li 等人，2023）研究了某些注意力头是否与事实性更相关，方法是在每一层的激活上拟合一个线性探针，以区分真实输出和虚假输出。他们发现，对于许多注意力头，探针的表现并不比随机更好，而有些则表现很强。在识别出一组稀疏的、在真实性上具有高线性探测准确率的注意力头之后，ITI 在推理时把选出的前 $K$ 个注意力头的激活沿着“真实”方向进行偏移。

## 为事实性而微调

Lee 等人（2022）提出了两种增强事实性的训练思路：

- 在训练中引入 `TopicPrefix`，以更好地感知事实：在文档中的每个句子前面加上主题（即维基百科文档标题）。
- 以句子补全损失作为训练目标：更新训练损失，使其聚焦于句子的后半部分——他们假设句子的后半部分包含更多事实知识。实现相当简单：确定一个枢轴位置 $t$，第 $t$ 个 token 之前的所有 token 都施加零掩码。在他们的实验中，最佳枢轴 $t$ 选为句子长度的 0.5 倍。

Lin 等人（2024）提出进行特别关注事实性的 SFT + RLHF 对齐训练，名为 **FLAME**（“Factuality-Aware Alignment”，事实性感知对齐）。

- SFT 阶段（事实性感知 SFT）：目标是生成比模型自身生成更具事实性（用 FActScore 衡量）的训练数据。
- RLHF 阶段（事实性感知 DPO）：测试了两种方法，方法（1）结果相当糟糕，而方法（2）效果还可以，这很可能是因为（1）试图在没有足够训练的情况下把新知识蒸馏进模型。有证据表明，微调新知识可能导致幻觉，而来自 RAG 的监督包含 LLM 所不知道的信息。
  - （1）把 RAG 数据样本作为正例、原始模型生成作为负例，用作奖励模型（RM）数据。
  - （2）把 FActScore 用作事实性的奖励信号。

为了避免在对齐训练中意外地把未知知识蒸馏进模型，他们建议使用模型自己生成的回答来构建 SFT / DPO 数据集。

**事实性微调（Factuality tuning）**（Tian & Mitchell 等人，2024）同样依靠微调语言模型来获得更好的事实性。他们试验了对每个模型采样中原子断言的真实性进行估计的不同方式，然后运行 DPO。

事实性微调的流程：

1. 针对给定的一组提示（例如 `"Write a bio of Yo-Yo Ma"`，“写一篇马友友的传记”）采样成对的模型补全结果。
2. 基于两种无需人工参与的方法为它们标注真实性：
  - 基于参考：检查外部知识库是否支持模型的陈述，类似于上文基于检索的幻觉评估一节。
    - （a）提取一组原子断言；
    - （b）查找维基百科参考；
    - （c）使用一个经过 NLI 微调的小模型检查参考文本是否支持该原子断言。
  - 无参考：把模型自身的置信度作为其真实性的代理，类似于间接查询方法。
    - （a）把每条断言转换为对应的问题 / 需要仔细改写以确保问题没有歧义；使用少样本提示；
    - （b）从模型中多次采样来回答该问题；
    - （c）计算聚合分数 / 使用字符串匹配，或让 GPT 判断两个答案在语义上是否等价。
3. 通过从模型生成多个样本并基于真实性分数分配偏好，构建训练数据集。然后在这个数据集上用 DPO 微调模型。

## 为归因而微调

在以搜索结果为条件进行生成时，在模型输出中标注归因是减少幻觉的好方法。有一个分支的工作致力于训练 LLM 更好地利用检索到的内容并给出高质量的归因。

**WebGPT**（Nakano 等人，2022）把用于文档检索的网页搜索与一个经过微调的 GPT 模型结合起来，旨在回答长形式问题，以减少幻觉并获得更好的事实准确性。模型在一个基于文本的网页浏览器中与互联网搜索交互，并学会引用网页来回答。在模型浏览时，它可以采取的动作之一是引用当前页面的一段摘录。执行该动作时，*页面标题、域名和摘录*会被记录下来，供之后作为参考引用。WebGPT 的核心是用参考引用来帮助人类判断事实正确性。

模型首先在人类使用网页浏览环境回答问题的示范上进行监督微调，以进行行为克隆。然后收集针对同一问题的两个模型生成答案（各自带有一组参考引用）之间的比较数据，从*事实准确性、连贯性和整体有用性*方面评判答案。奖励模型用于 RL 训练和 best-of-n 拒绝采样。RL 训练和 best-of-n 拒绝采样。相比之下，RL 只带来很小的收益，而在使用拒绝采样时收益更小。

**GopherCite**（Menick 等人，2022）在使用搜索引擎创建支持材料、教模型提供参考引用这一点上与 **WebGPT** 非常相似。两者都运行监督微调进行引导，也都应用基于人类偏好的 RL 训练。但与依赖人类示范进行行为克隆的 WebGPT 不同，GopherCite 通过少样本提示生成示范，每次生成都用相关文档填充上下文，然后用奖励模型给出评分，选出最好的那些。

避免低质量回答的另一个技巧是，把模型配置为用一个预设回答 `"I don't know"`（“我不知道”）来拒绝回答，由一个全局的奖励模型阈值决定，这被称为*选择性预测（selective prediction）*。

RL 的实证结果与 WebGPT 类似：RL 只带来有限的提升，与拒绝采样结合时则没有提升。

# 附录：评估基准

以下是本文提到的数据集列表。

**TruthfulQA**（Lin 等人，2021）用于衡量 LLM 生成真实回答的能力。该基准包含 817 个问题，涵盖健康、法律、金融和政治等 38 个主题。

**FactualityPrompt**（Lee 等人，2022）是一个由事实性提示和非事实性提示组成的基准。它依赖维基百科文档或句子作为事实依据的知识库。

**SelfAware**（Yin 等人，2023）包含五个类别下的 1,032 个无法回答的问题和 2,337 个可以回答的问题。无法回答的问题来自在线论坛并经过人工标注，而可以回答的问题则根据与无法回答问题的文本相似度，取自 SQuAD、HotpotQA 和 TriviaQA。

**LongFact**（Wei 等人，2024）用于检查长文本生成的事实性。它包含 2280 个寻求事实的提示，要求在 38 个人工挑选的主题上给出长篇回答。

**HaDes**（Liu 等人，2021）是一个将幻觉检测作为二分类任务的基准。该数据集通过扰动维基百科文本并进行人工标注创建。

**FEVER**（Fact Extraction and VERification，事实提取与验证）数据集包含 185,445 条断言，它们由修改从维基百科中提取的句子生成，随后在不知道其来源句子的情况下进行验证。每条断言被分类为 `Supported`（支持）、`Refuted`（反驳）或 `NotEnoughInfo`（信息不足）。

**FAVABench**（Mishra 等人，2024）是一个用于评估细粒度幻觉的基准。它有 200 个信息寻求类源提示，每个提示有 3 个模型回答，共 600 个回答。每个模型回答都人工标注了细粒度的幻觉错误类型。
