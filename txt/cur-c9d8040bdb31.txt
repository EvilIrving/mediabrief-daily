从零理解并实现大模型中的 KV 缓存（Understanding and Coding the KV Cache in LLMs from Scratch） ｜ Sebastian Raschka ｜ 文章 ｜ https://magazine.sebastianraschka.com/p/coding-the-kv-cache-in-llms

Sebastian Raschka 在养伤期间写了这篇教程，补上他《从零构建大语言模型》一书没收录的 KV 缓存：把推理时算出的键和值存起来复用，显著加快文本生成，代价是代码更复杂、更占内存，且不能用于训练，但在生产环境里通常很划算。

他用"Time → flies → fast"的例子说明问题：LLM 每生成一个 token 都要重新处理整个序列，而旧 token 的 k、v 由同样的投影矩阵得出，每步都一样，重算纯属浪费。有了缓存，提示里的 token 只算一次，之后每步只算新 token，文本越长复用越多。

代码以可读性为先，用两个自包含脚本对照改动：在注意力模块里注册缓存缓冲区，前向时用 torch.cat 拼接新的 k、v；两次生成之间必须清空缓存，否则会关注到上一段的过时键；模型还要记录已缓存的位置，让新 token 的位置编码接着往下走。实测在 M4 Mac Mini 的 CPU 上，用 1.24 亿参数的未训练模型生成 200 个 token 提速约 5 倍，两版输出完全一致，说明实现正确，毕竟索引写错很容易让结果不同。原理上每步计算从对整个序列做注意力降为线性，代价是内存随 token 数线性增长，长序列大模型会吃掉大量显存。

部署时还可以按最大长度预分配张量、用滑动窗口限制缓存长度；但在 CUDA 上，小模型的收益会被开销抵消。他给自己实现的 Qwen3 和 Llama 3 也加了缓存：在 CPU 上提速最明显，在 GPU 上最快的反而是不带缓存的编译模型。
