## 1. 多模态 LLM 的用例

什么是多模态 LLM？正如引言中所暗示的，多模态 LLM 是能够处理多种类型输入的大语言模型，其中每一种“模态”指的是一种特定类型的数据——比如文本（就像传统 LLM 那样）、声音、图像、视频等等。为了简单起见，我们将主要关注图像模态与文本输入。

多模态 LLM 一个经典而直观的应用是图像描述：你提供一张输入图片，模型生成对这张图片的描述，如下图所示。

（图：多模态 LLM 解释[一张梗图](https://x.com/PainSci/status/1309570607458086914)的使用示例。）

当然，还有很多其他用例。例如，我最喜欢的用例之一，是从 PDF 表格中提取信息，并把它转换成 LaTeX 或 Markdown。

## 2. 构建多模态 LLM 的常见方法

构建多模态 LLM 主要有两种方法：

* 方法 A：统一嵌入解码器架构方法；
* 方法 B：跨模态注意力架构方法。

（顺便说一下，我认为这些技术目前还没有官方名称，但如果你见过，请告诉我。例如，更简短的描述可能是“仅解码器”方法和“基于交叉注意力”的方法。）

（图：开发多模态 LLM 架构的两种主要方法。）

如上图所示，***统一嵌入解码器架构***使用单个解码器模型，很像 GPT-2 或 Llama 3.2 这样未经修改的 LLM 架构。在这种方法中，图像被转换成与原始文本 token 嵌入维度相同的 token，使 LLM 能在拼接之后同时处理文本和图像输入 token。

***跨模态注意力架构***则采用交叉注意力机制，直接在注意力层内整合图像和文本嵌入。

在接下来的几节中，我们将从概念层面探讨这些方法如何工作。然后，我们会看看最近关于多模态 LLM 的研究论文，了解它们在实践中如何应用。

### 2.1 方法 A：统一嵌入解码器架构

我们从统一嵌入解码器架构开始，下图再次展示了它。

（图：统一嵌入解码器架构示意图。它是一个未经修改的解码器式 LLM（如 GPT-2、Phi-3、Gemma 或 Llama 3.2），接收由图像 token 和文本 token 嵌入组成的输入。）

在统一嵌入解码器架构中，图像被转换为嵌入向量，类似于在标准的纯文本 LLM 中，输入文本被转换为嵌入的方式。

对于一个处理文本的典型纯文本 LLM，文本输入通常先被分词（例如使用字节对编码），然后通过一个嵌入层，如下图所示。

（图：对文本进行分词并将其转换为 token 嵌入向量的标准流程示意图，这些向量随后在训练和推理时被传给 LLM。）

#### 2.1.1 理解图像编码器

与文本的分词和嵌入类似，图像嵌入是用一个图像编码器模块（而不是分词器）生成的，如下图所示。

（图：把图像编码为图像块嵌入的过程示意图。）

上面所示的图像编码器内部发生了什么？要处理一张图像，我们首先把它切分成更小的块（patch），就像分词时把单词切分成子词一样。然后这些图像块由一个预训练的视觉 Transformer（ViT）进行编码，如下图所示。

（图：经典视觉 Transformer（ViT）的结构示意。）

注意，ViT 常被用于分类任务，所以我在上图中保留了分类头。不过，在这里我们只需要图像编码器部分。

#### 2.1.2 线性投影模块的作用

上一张图中所示的“线性投影”由单个线性层（即全连接层）组成。这一层的目的，是把被展平成向量的图像块投影到与 Transformer 编码器兼容的嵌入维度。下图展示了这个线性投影。一个被展平为 256 维向量的图像块，被向上投影为一个 768 维的向量。

（图：线性投影层示意图，它把展平后的图像块从 256 维投影到 768 维的嵌入空间。）

对于喜欢看代码示例的读者，在 PyTorch 代码中，我们可以这样实现图像块的线性投影：

```python
import torch

class PatchProjectionLayer(torch.nn.Module):

    def __init__(self, patch_size, num_channels, embedding_dim):
        super().__init__()
        self.patch_size = patch_size
        self.num_channels = num_channels
        self.embedding_dim = embedding_dim
        self.projection = torch.nn.Linear(
            patch_size * patch_size * num_channels, embedding_dim
        )

    def forward(self, x):

        batch_size, num_patches, channels, height, width = x.size()
        x = x.view(batch_size, num_patches, -1)  # 展平每个图像块
        x = self.projection(x)  # 投影每个展平后的图像块
        return x

# 用法示例：
batch_size = 1
num_patches = 9  # 每张图像的图像块总数
patch_size = 16  # 每个图像块 16x16 像素
num_channels = 3  # RGB 图像
embedding_dim = 768  # 嵌入向量的大小

projection_layer = PatchProjectionLayer(patch_size, num_channels, embedding_dim)

patches = torch.rand(
    batch_size, num_patches, num_channels, patch_size, patch_size
)

projected_embeddings = projection_layer(patches)
print(projected_embeddings.shape)

# 输出为
# torch.Size([1, 9, 768])
```

如果你碰巧读过我的书《Machine Learning Q and AI》，你可能知道，有一些方法可以用卷积操作替代线性层，而且可以实现得在数学上等价。在这里，这一点尤其方便，因为我们可以把图像块的创建和投影合并成两行代码：

```python
layer = torch.nn.Conv2d(3, 768, kernel_size=(16, 16), stride=(16, 16))

image = torch.rand(batch_size, 3, 48, 48)
projected_patches = layer(image)

print(projected_patches.flatten(-2).transpose(-1, -2).shape)
# 输出为
# torch.Size([1, 9, 768])
```

#### 2.1.3 图像与文本的分词

既然我们已经简要讨论了图像编码器（以及作为编码器一部分的线性投影）的作用，让我们回到前面文本分词的类比，把文本和图像的分词与嵌入并排来看，如下图所示。

（图：并排展示图像分词与嵌入（左）和文本分词与嵌入（右）。）

如上图所示，我在图像编码器之后加了一个额外的***投影器***（projector）模块。这个*投影器*通常就是另一个与前面解释过的类似的***线性投影***层。它的目的是把图像编码器的输出投影到与嵌入后的文本 token 维度相匹配的维度，如下图所示。（我们稍后会看到，投影器有时也被称为适配器（adapter/adaptor）或连接器（connector）。）

（图：图像分词与文本分词的另一张并排对比图，其中投影器的作用是匹配文本 token 的嵌入维度。）

既然图像块嵌入与文本 token 嵌入的维度相同了，我们就可以简单地把它们拼接起来作为 LLM 的输入，如本节开头的图所示。为了方便参考，下面再放一次同一张图。

（图：把图像块 token 投影到与文本 token 嵌入相同的维度之后，我们就可以简单地把它们拼接起来，作为标准 LLM 的输入。）

顺便说一下，我们在本节讨论的图像编码器通常是一个预训练的视觉 Transformer。常见的选择是 [CLIP](https://github.com/openai/CLIP) 或 [OpenCLIP](https://github.com/mlfoundations/open_clip)。

不过，也有直接在图像块上操作的方法 A 版本，比如 [Fuyu](https://www.adept.ai/blog/fuyu-8b)，如下图所示。

（图：Fuyu 多模态 LLM 的标注图，它不使用图像编码器，直接在图像块上操作。标注图来自 https://www.adept.ai/blog/fuyu-8b。）

如上图所示，Fuyu 把输入的图像块直接送入一个线性投影（或嵌入层），学习它自己的图像块嵌入，而不是像其他模型和方法那样依赖一个额外的预训练图像编码器。这大大简化了架构和训练设置。

### 2.2 方法 B：跨模态注意力架构

既然我们已经讨论了构建多模态 LLM 的统一嵌入解码器架构方法，也理解了图像编码背后的基本概念，现在来谈谈通过交叉注意力实现多模态 LLM 的另一种方式，如下图所总结的。

（图：构建多模态 LLM 的跨模态注意力架构方法示意图。）

在上图所示的跨模态注意力架构方法中，我们仍然使用前面讨论过的同样的图像编码器设置。不过，我们不再把图像块编码作为 LLM 的输入，而是在多头注意力层中通过交叉注意力机制接入输入的图像块。

这个思路与 2017 年《Attention Is All You Need》论文中的原始 Transformer 架构相关，可以追溯到它，如下图中高亮所示。

（图：原始 Transformer 架构中使用的交叉注意力机制的高层示意图。标注图来自《Attention Is All You Need》论文：https://arxiv.org/abs/1706.03762。）

注意，上图中所示的原始《Attention Is All You Need》Transformer 最初是为语言翻译开发的。所以它由一个文本**编**码器（图的左半部分）和一个文本**解**码器（图的右半部分）组成：编码器接收要翻译的句子，再由解码器生成译文。在多模态 LLM 的语境中，编码器是图像编码器而不是文本编码器，但同样的思路依然适用。

交叉注意力是如何工作的？我们先看一张常规自注意力机制内部发生了什么的概念图。

（图：常规自注意力机制的概要。这一流程描绘的是常规多头注意力模块中的一个头。）

在上图中，x 是输入，*Wq* 是用于生成查询（*Q*）的权重矩阵。类似地，*K* 代表键，*V* 代表值。A 表示注意力分数矩阵，*Z* 是被转换为输出上下文向量的输入（x）。（如果这看起来令人困惑，我的[《从零构建大语言模型》](https://www.amazon.com/Build-Large-Language-Model-Scratch/dp/1633437167/)一书第 3 章有全面的介绍，可能会有帮助；或者，我的文章[《理解并编写 LLM 中的自注意力、多头注意力、交叉注意力和因果注意力》](https://magazine.sebastianraschka.com/p/understanding-and-coding-self-attention)也可能有帮助。）

与自注意力不同，在交叉注意力中我们有两个不同的输入源，如下图所示。

（图：交叉注意力示意图，其中可以有两个不同的输入 x1 和 x2。）

如前两张图所示，在自注意力中，我们处理的是同一个输入序列。在交叉注意力中，我们混合或结合两个不同的输入序列。

在《Attention Is All You Need》论文的原始 Transformer 架构中，两个输入 *x1* 和 *x2* 分别对应右侧解码器部分正在处理的输入序列（*x1*）和左侧编码器模块返回的序列（*x2*）。在多模态 LLM 的语境中，*x2* 是图像编码器的输出。（注意，查询通常来自解码器，而键和值通常来自编码器。）

注意，在交叉注意力中，两个输入序列 *x1* 和 *x2* 的元素数量可以不同。但它们的嵌入维度必须匹配。如果我们令 *x1 = x2*，这就等价于自注意力。

## 3. 统一解码器与交叉注意力模型的训练

既然我们已经稍微谈过两种主要的多模态设计选择，现在简要谈谈在模型训练中如何处理三个主要组件，如下图所总结的。

（图：多模态 LLM 中不同组件的概览。编号 1-3 的组件在多模态训练过程中可以被冻结或解冻。）

与传统纯文本 LLM 的开发类似，多模态 LLM 的训练也包括两个阶段：预训练和指令微调。不过，与从零开始不同，多模态 LLM 的训练通常以一个经过预训练和指令微调的纯文本 LLM 作为基础模型。

对于图像编码器，通常使用 CLIP，并且它在整个训练过程中往往保持不变，不过也有例外，我们稍后会探讨。在预训练阶段保持 LLM 部分冻结也很常见，只训练投影器——一个线性层或一个小型多层感知机。鉴于投影器的学习能力有限（通常只有一两层），在多模态指令微调（第 2 阶段）中，LLM 往往会被解冻，以允许更全面的更新。不过要注意，在基于交叉注意力的模型（方法 B）中，交叉注意力层在整个训练过程中都是解冻的。

介绍完两种主要方法（方法 A：统一嵌入解码器架构；方法 B：跨模态注意力架构）之后，你可能想知道哪一种更有效。答案取决于具体的取舍。

统一嵌入解码器架构（方法 A）通常更容易实现，因为它不需要对 LLM 架构本身做任何修改。

跨模态注意力架构（方法 B）通常被认为计算效率更高，因为它不会用额外的图像 token 塞满输入上下文，而是在之后的交叉注意力层中才引入它们。此外，如果在训练中保持 LLM 参数冻结，这种方法能保留原始 LLM 的纯文本性能。

我们将在后面讨论英伟达 NVLM 论文的一节中，再来讨论建模性能和回答质量。

### 4.1 Llama 3 模型群

Meta AI 的[《Llama 3 模型群》（The Llama 3 Herd of Models）](https://arxiv.org/abs/2407.21783)论文（2024 年 7 月 31 日）在今年夏初发布，按 LLM 领域的标准，这感觉像是很久以前的事了。不过，鉴于他们只是描述了多模态模型，直到很久以后才发布，我认为把 Llama 3 列入这份清单是合理的。（Llama 3.2 模型于 9 月 25 日正式发布并开放使用。）

多模态 Llama 3.2 模型有 110 亿和 900 亿参数两个版本，是图文模型，采用前面描述的基于交叉注意力的方法，如下图所示。

（图：Llama 3.2 所用多模态 LLM 方法的示意图。标注图来自 Llama 3 论文：https://arxiv.org/abs/2407.21783。视频和语音部分被遮住，以便聚焦于图像部分。）

注意，虽然图中也描绘了视频和语音作为可能的模态，但截至撰文时已发布的模型只关注图像和文本。

Llama 3.2 采用基于交叉注意力的方法。不过，它与我前面写的有点不同，即在多模态 LLM 开发中，我们通常冻结图像编码器，在预训练期间只更新 LLM 参数。

在这里，研究者几乎采取了相反的做法：他们更新图像编码器，但不更新语言模型的参数。他们写道，这是有意为之，目的是保留纯文本能力，让 11B 和 90B 的多模态模型在文本任务上可以直接替换 Llama 3.1 8B 和 70B 纯文本模型。

训练本身分多轮进行，从 Llama 3.1 文本模型开始。加入图像编码器和投影（这里称为“适配器”）层之后，他们在图文数据上预训练模型。然后，与 Llama 3 纯文本模型的训练类似（我在[之前的一篇文章](https://magazine.sebastianraschka.com/i/147749119/llama-overview)中写过），他们接着进行指令微调和偏好微调。

研究者没有采用 CLIP 这类预训练模型作为图像编码器，而是使用了一个他们从零预训练的视觉 Transformer。具体来说，他们采用了经典视觉 Transformer 架构（[Dosovitskiy 等，2020](https://arxiv.org/abs/2010.11929)）的 ViT-H/14 变体（6.3 亿参数）。然后，他们在一个包含 25 亿个图文对的数据集上把 ViT 预训练了五个轮次；这是在把图像编码器接入 LLM 之前完成的。（图像编码器接收 224×224 分辨率的图像，把它们切分成 14×14 的图像块网格，每个图像块大小为 16×16 像素。）

由于交叉注意力层会增加大量参数，它们只被加在每四个 Transformer 块中的一个里。（对于 8B 模型，这增加了 30 亿参数；对于 70B 模型，这增加了 200 亿参数。）

### 4.2 Molmo 与 PixMo

[《Molmo 与 PixMo：面向最先进多模态模型的开放权重与开放数据》](https://www.arxiv.org/abs/2409.17146)论文（2024 年 9 月 25 日）值得注意，因为它承诺不仅开源模型权重，还开源数据集和源代码，类似于纯语言的 OLMo LLM。（这对 LLM 研究非常好，因为它让我们能看到确切的训练流程和代码，还能让我们在同一个数据集上做消融研究、复现结果。）

如果你想知道为什么论文标题里有两个名字：Molmo 指的是模型（Multimodal Open Language Model，多模态开放语言模型），PixMo（Pixels for Molmo）是数据集。

（图：Molmo 仅解码器方法（方法 A）的示意图。标注图改编自 Molmo 与 PixMo 论文：https://www.arxiv.org/abs/2409.17146。）

如上图所示，图像编码器采用现成的视觉 Transformer，具体来说是 CLIP。这里的“连接器”指的是将图像特征与语言模型对齐的“投影器”。

Molmo 通过避免多个预训练阶段来简化训练流程，选择了一条简单的管线，以统一的方式更新所有参数——包括基础 LLM、连接器和图像编码器的参数。

Molmo 团队为基础 LLM 提供了几种选择：

* OLMo-7B-1024（完全开放的模型骨干），
* OLMoE-1B-7B（混合专家架构；最高效的模型），
* Qwen2 7B（开源权重模型，表现优于 OLMo-7B-1024），
* Qwen2 72B（开源权重模型，表现最好的模型）。

### 4.3 NVLM：开放的前沿级多模态 LLM

英伟达的[《NVLM：开放的前沿级多模态 LLM》](https://arxiv.org/abs/2409.11402)论文（2024 年 9 月 17 日）特别有意思，因为它没有只专注于一种方法，而是两种方法都做了探索：

* 方法 A，统一嵌入解码器架构（“仅解码器架构”，NVLM-D），以及
* 方法 B，跨模态注意力架构（“基于交叉注意力的架构”，NVLM-X）。

此外，他们还开发了一种混合方法（NVLM-H），并对三种方法进行了同等条件下的比较。

（图：三种多模态方法的概览。标注图来自 NVLM 论文：https://arxiv.org/abs/2409.11402。）

如下图所总结的，NVLM-D 对应前面讨论的方法 A，NVLM-X 对应方法 B。混合模型（NVLM-H）背后的理念是结合两种方法的优势：先提供一张图像缩略图作为输入，然后让数量动态变化的图像块通过交叉注意力传入，以捕捉更精细的高分辨率细节。

简而言之，研究团队发现：

* NVLM-X 在处理高分辨率图像时表现出更优的计算效率。
* NVLM-D 在 OCR 相关任务中达到更高的准确率。
* NVLM-H 结合了两种方法的优点。

与 Molmo 和其他方法类似，他们从一个纯文本 LLM 开始，而不是从零预训练一个多模态模型（因为这通常效果更好）。此外，他们使用的是指令微调过的 LLM，而不是基础 LLM。具体来说，骨干 LLM 是 Qwen2-72B-Instruct（据我所知，Molmo 用的是 Qwen2-72B 基础模型）。

在 NVLM-D 方法中他们训练了 LLM 的全部参数，而对于 NVLM-X，他们发现在预训练和指令微调期间都冻结原始 LLM 参数、只训练交叉注意力层，效果很好。

对于图像编码器，他们没有用典型的 CLIP 模型，而是使用了 [InternViT-6B](https://arxiv.org/abs/2312.14238)，它在所有阶段都保持冻结。

投影器是一个多层感知机，而不是单个线性层。

### 4.4 Qwen2-VL

前面两篇论文和模型 Molmo 与 NVLM，都基于 Qwen2-72B LLM。在这篇论文中，Qwen 研究团队自己发布了一个多模态 LLM：[《Qwen2-VL：增强视觉-语言模型在任意分辨率下对世界的感知》](https://arxiv.org/abs/2409.12191)（2024 年 10 月 3 日）。

这项工作的核心是他们所谓的“朴素动态分辨率”（Naive Dynamic Resolution）机制（“naive”一词是有意为之，并不是“native”（原生）的笔误，不过“native”可能也很贴切）。这一机制让模型能够处理不同分辨率的图像，而无需简单地下采样，从而可以输入原始分辨率的图像。

（图：多模态 Qwen 模型的概览，它可以原生处理各种不同分辨率的输入图像。标注图来自 Qwen2-VL 论文：https://arxiv.org/abs/2409.12191。）

原生分辨率输入是通过一个修改过的 ViT 实现的：去掉原来的绝对位置嵌入，引入 2D-RoPE。

他们使用了一个 6.75 亿参数的经典视觉编码器，以及不同规模的 LLM 骨干，如下表所示。

（表：不同 Qwen2-VL 模型的组成部分。标注图来自 Qwen2-VL 论文：https://arxiv.org/abs/2409.12191。）

训练本身包括 3 个阶段：(1) 只预训练图像编码器；(2) 解冻所有参数（包括 LLM）；(3) 冻结图像编码器，只对 LLM 进行指令微调。

### 4.5 Pixtral 12B

[Pixtral 12B](https://mistral.ai/news/pixtral-12b/)（2024 年 9 月 17 日）采用方法 A：统一嵌入解码器架构，是 Mistral AI 的第一个多模态模型。遗憾的是，没有可用的技术论文或报告，但 Mistral 团队在他们的[博客文章](https://mistral.ai/news/pixtral-12b/)中分享了一些有意思的细节。

有意思的是，他们选择不使用预训练的图像编码器，而是从零训练了一个 4 亿参数的图像编码器。对于 LLM 骨干，他们使用了 120 亿参数的 [Mistral NeMo](https://mistral.ai/news/mistral-nemo/) 模型。

与 Qwen2-VL 类似，Pixtral 也原生支持可变的图像尺寸，如下图所示。

（图：Pixtral 如何处理不同尺寸图像的示意图。标注图来自 Pixtral 博客文章：https://mistral.ai/news/pixtral-12b/。）

### 4.6 MM1.5

[《MM1.5：多模态 LLM 微调的方法、分析与洞见》](https://arxiv.org/abs/2409.20566)论文（2024 年 9 月 30 日）提供了实用的技巧，并在一个类似 Molmo 的稠密模型之外，还推出了一个混合专家多模态模型。这些模型的规模跨度很大，从 10 亿到 300 亿参数。

这篇论文中描述的模型聚焦于方法 A，即统一嵌入 Transformer 架构，它为多模态学习有效地组织输入。

此外，论文还有一系列有意思的消融研究，探讨数据混合以及使用坐标 token 的效果。

（图：MM1.5 方法示意图，其中包括用于表示边界框的额外坐标 token。标注图来自 MM1.5 论文：https://arxiv.org/abs/2409.20566。）

### 4.7 Aria

[《Aria：一个开放的原生多模态混合专家模型》](https://arxiv.org/abs/2410.05993)论文（2024 年 10 月 8 日）介绍了另一种混合专家模型方法，类似于 Molmo 和 MM1.5 系列中的某个变体。

Aria 模型有 249 亿参数，每个文本 token 分配 35 亿参数。图像编码器（[SigLIP](https://arxiv.org/abs/2303.15343)）有 4.38 亿参数。

这个模型基于交叉注意力方法，总体训练流程如下：

1. 完全从零训练 LLM 骨干。
2. 同时预训练 LLM 骨干和视觉编码器。

### 4.8 Baichuan-Omni

[《Baichuan-Omni 技术报告》](https://arxiv.org/abs/2410.08565)（2024 年 10 月 11 日）介绍了 Baichuan-Omni，一个基于方法 A：统一嵌入解码器架构的 70 亿参数多模态 LLM，如下图所示。

（图：Baichuan-Omni 模型的概览，它可以处理各种输入模态。标注图来自 Baichuan-Omni 论文：https://arxiv.org/abs/2410.08565。）

Baichuan-Omni 的训练过程采用三阶段方法：

1. **投影器训练**：一开始只训练投影器，视觉编码器和语言模型（LLM）都保持冻结。
2. **视觉编码器训练**：接下来，解冻并训练视觉编码器，LLM 仍然冻结。
3. **完整模型训练**：最后，解冻 LLM，让整个模型端到端地训练。

该模型使用 SigLIP 视觉编码器，并加入了 [AnyRes](https://arxiv.org/abs/2204.07156) 模块，通过下采样技术处理高分辨率图像。

虽然报告没有明确说明 LLM 骨干，但根据模型的参数规模和命名惯例，它很可能基于百川 7B LLM。

### 4.9 Emu3

《Emu3：下一个 token 预测就是你所需要的一切》论文（2024 年 9 月 27 日）为图像生成提出了一个引人注目的、替代扩散模型的方案，它完全基于 Transformer 解码器架构。虽然它不是经典意义上的多模态 LLM（即专注于图像理解而非生成的模型），但 Emu3 非常有意思，因为它证明了可以用 Transformer 解码器做图像生成，而这一任务通常由扩散方法主导。（不过要注意，之前也有过其他类似的方法，比如[《自回归模型击败扩散模型：用 Llama 实现可扩展的图像生成》](https://arxiv.org/abs/2406.06525)。）

（图：Emu3 主要是一个用于图像生成、作为扩散模型替代方案的 LLM。标注图来自 Emu3 论文：https://arxiv.org/abs/2409.18869。）

研究者从零训练了 Emu3，然后用[直接偏好优化](https://github.com/rasbt/LLMs-from-scratch/blob/main/ch07/04_preference-tuning-with-dpo/dpo-from-scratch.ipynb)（DPO）让模型与人类偏好对齐。

该架构包含一个受 [SBER-MoVQGAN](https://arxiv.org/abs/2209.09002) 启发的视觉分词器。核心 LLM 架构基于 Llama 2，但完全是从零训练的。

### 4.10 Janus

前面我们主要关注用于图像理解的多模态 LLM，刚才只看了 Emu3 这一个图像生成的例子。现在，[《Janus：解耦视觉编码以实现统一的多模态理解与生成》](https://arxiv.org/abs/2410.13848)论文（2024 年 10 月 17 日）提出了一个框架，在单个 LLM 骨干中统一了多模态理解和生成任务。

Janus 的一个关键特点，是把视觉编码通路解耦，以满足理解任务和生成任务的不同需求。研究者认为，图像理解任务需要高维的语义表示，而生成任务需要图像中详细的局部信息和全局一致性。通过把这些通路分开，Janus 有效地兼顾了这些不同的需求。

该模型采用与 Baichuan-Omni 中类似的 SigLIP 视觉编码器来处理视觉输入。对于图像生成，它使用一个[向量量化（VQ）](https://arxiv.org/abs/2406.06525)分词器来处理生成过程。Janus 的基础 LLM 是 13 亿参数的 [DeepSeek-LLM](https://arxiv.org/abs/2401.02954)。

（图：Janus 所用的统一仅解码器框架概览。标注图来自 Janus 论文：https://arxiv.org/abs/2410.13848。）

这个模型的训练过程遵循三个阶段，如下图所示。

（图：Janus 模型三阶段训练过程示意图。标注图来自 Janus 论文：https://arxiv.org/abs/2410.13848。）

在第一阶段，只训练投影层和图像输出层，LLM、理解编码器和生成编码器都保持冻结。在第二阶段，解冻 LLM 骨干和文本输出层，在理解和生成任务上进行统一的预训练。最后，在第三阶段，包括 SigLIP 图像编码器在内的整个模型都被解冻，进行监督微调，让模型充分整合并精炼其多模态能力。

## 5. 结论

你可能已经注意到，我几乎完全跳过了建模性能和计算性能的比较。首先，由于普遍存在的数据污染——即测试数据可能已被包含在训练数据中——在公开基准上比较 LLM 和多模态 LLM 的性能很有挑战。

此外，各模型的架构组件差异如此之大，很难做同等条件下的比较。所以，要大大称赞英伟达团队开发了不同形态的 NVLM，至少让仅解码器方法和交叉注意力方法之间可以做比较。
