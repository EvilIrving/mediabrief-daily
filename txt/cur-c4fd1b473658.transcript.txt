# 我那些怀疑 AI 的朋友全都疯了（My AI skeptic friends are all nuts）

作者：Thomas Ptacek（Fly.io 博客），2025-06-02

一篇关于 AI 辅助编程的、发自肺腑的挑衅之作。

科技公司高管们正在强制要求采用 LLM。这是糟糕的策略。但我理解他们的出发点。

我认识的一些最聪明的人打心底里相信 AI 只是一时的潮流——是 NFT 狂热的下一个版本。我一直不太愿意反驳他们，因为，嗯，他们比我聪明。但他们的论点并不严肃，值得正面回应。一些极具天赋的人，出于赌气，还在做那些 LLM 已经做得比他们更好的工作。

即便 LLM 的所有进展今天就停止，LLM 仍将是我整个职业生涯中发生的第二重要的事情。

**重要声明**：我只讨论 LLM 对软件开发的影响。至于艺术、音乐和写作？我没什么可说的。在那些领域，我倾向于相信怀疑者。我只是不相信他们对我这个领域的看法。

我的资历：我从 1990 年代中期就开始交付软件了。我起步于盒装、塑封发售的 C 代码。熬过了一段不明智的 Alexandrescu 式 C++ 阶段。写过大量 Ruby 和 Python 工具。做过一些内核工作。写过一大堆服务端的 C、Go 和 Rust。不管你怎么定义“严肃的开发者”，我都够格。哪怕只是在你划分的较低档次里。

### 统一认识

首先，我们得达成共识。如果你在 6 个月前（或者，老天保佑，2 年前用 Copilot）尝试用 LLM 写代码却失败了，那你做的并不是大多数严肃的 LLM 辅助程序员在做的事。

今天用 LLM 写代码的人用的是智能体（agent）。智能体可以自己在你的代码库里四处探查。它们直接编写文件。它们运行工具。它们编译代码、运行测试，并根据结果迭代。它们还会：

- 把代码树中、或网上其他代码树中的任意代码拉进它们的上下文窗口，
- 运行标准的 Unix 工具来浏览代码树并提取信息，
- 与 Git 交互，
- 运行现有工具，比如 linter、格式化工具和模型检查器，以及
- 通过 MCP 进行基本上任意的（由你配置的）工具调用。

智能体中真正对代码“动手做事”的那部分代码，本身并不是 AI。这应该能让你放心。它是出奇简单的系统代码，像 Makefile 一样连接着关于编程的客观事实。你可以在一个周末写出一个好用的编程智能体。它的强项更多取决于你如何思考和组织构建、lint 和测试框架，而不是 o3 或 Sonnet 变得有多先进。

如果你是在 ChatGPT 网页上提需求，然后把得到的（有问题的）代码粘贴到编辑器里，那你做的并不是 AI 鼓吹者在做的事。难怪你们鸡同鸭讲。

### 正面论证

LLM 可以写出你这辈子需要写的所有乏味代码中的很大一部分。而大多数项目里的大多数代码都是乏味的。LLM 大大减少了你需要去 Google 的东西。它们会自己去查。最重要的是，它们不会累；它们对惰性免疫。

想想任何你想做却没做的东西。你试过找准最初的几步。如果你当时正处于对一门新编程语言的热恋期，你早就开始写了。但你不是，所以你把它推迟了，推迟一天、一年，或者你的整个职业生涯。

一想到新项目里那些记账般的琐事、没完没了的 Google 和依赖地狱，我就感觉血压在升高。你可以吩咐 LLM 把那些破事全都搞定。它常常会把你恰好送到那个黄金时刻：东西几乎能跑了，开发就变成调整代码、马上看到效果变好。那种多巴胺的冲击正是我写代码的原因。

这也有坏处。有时候，有些棘手的活必须要做。但你不想做。于是你去重构单元测试，用“我在做正经工作”的谎言安慰自己。但你可以让 LLM 去重构你所有的单元测试。一个智能体可以在虚拟机里折腾你的测试好几个小时，然后带着一个 PR 回来。如果你听我的，你就会明白这一点。你会因为在做无关紧要的琐事（yak-shaving）而感觉更糟。最终你会去做……真正的工作。

### “但你根本不知道代码是什么”

你是个靠氛围编程（vibe coding）的 YouTuber 吗？你看不懂代码吗？如果是：说得很有道理。否则：你他妈的有什么毛病？

你一直都要为你合并到 `main` 的东西负责。五年前是这样。明天也是这样，不管你用不用 LLM。

如果你用 LLM 构建了一个别人会依赖的东西，那就读代码。事实上，你可能会做得更多。你会花 5 到 10 分钟把它改回你自己的风格。LLM 已经显示出适应本地惯用写法的迹象，但还没到那一步。

人们抱怨 LLM 生成的代码是“概率性的”。不，不是的。它就是代码。它不是 Yacc 的输出。它是可知的。LLM 也许是随机的。但 LLM 不重要。重要的是你能否理解结果，以及你的护栏是否守得住。

读别人的代码本来就是工作的一部分。如果你消化不了 LLM 生成的那些枯燥、重复的代码：那是你能力不行！人类开发者赶 deadline 时搞出来的一团乱麻，你又是怎么应付的？

最近一个月左右，Gemini 2.5 一直是我的首选（因为它的上下文窗口能装下 5 万到 7 万行代码）。它给我吐出来的东西几乎没有不经修改就能合并的。我相信让一个 SOTA 模型一次性写完一个功能并直接合并是有技巧的！但我不在乎。我喜欢挪动代码，一边删掉所有愚蠢的注释一边暗自发笑。反正我也得逐行读代码。

### “但会有幻觉”

如果幻觉对你来说是个问题，那是你的编程语言让你失望了。

智能体会做 lint。它们会编译、运行测试。如果它们的 LLM 发明了一个新的函数签名，智能体会看到错误。它们把错误反馈给 LLM，LLM 会说“哦，对，这完全是我编的”，然后再试一次。

只有当你盯着智能体生成的思维链日志看时，你才会注意到这种情况。别看。这就是我喜欢 Zed 智能体模式的原因：它恳求你切到别的窗口、让它干活，干完之后用桌面通知提醒你。

我相信仍然存在幻觉很要紧的环境。但每当有人建议使用 LLM 时，开发者首先提起的就是“幻觉”，尽管它（或多或少）是一个已经解决的问题。

### “但代码很烂，像初级开发者写的”

实习生一个月只要 20 美元吗？因为 Cursor.ai 就是这个价。

当一名资深开发者，部分职责就是让能力较弱的程序员变得高效，不管他们是血肉之躯还是代数构成的。用好智能体既是一种技能，也是一个独立的工程项目，涉及提示词、索引，以及（尤其是）工具链。只有当你放任它们时，LLM 才会写出烂代码。

也许目前的困惑在于谁在做什么工作。今天，LLM 做了大量的打字、Google 搜索、测试用例（还有：你从此以后应该写的所有 Bash 代码，100% 都交给它），以及“编辑-编译-测试-调试”的循环。但即便是世界上中毒最深、最离不开 Claude 的严肃开发者，也依然掌管着筛选、判断、指导和方向。

还有：别再自欺欺人地以为我们人类写的初稿有多好了。

### “但它不擅长 Rust”

给 Brainfuck 找一套好用的工具链也很难。干铝合金外墙板这行，日子可不好过。

很多对 LLM 的怀疑可能其实与 LLM 无关。那是投射。人们说“LLM 不会写代码”，其实他们真正的意思是“LLM 写不好 Rust”。这很公平！但人们选择语言，部分依据就是 LLM 对它的支持程度，所以搞 Rust 的人应该在这方面加把劲（他们肯定会的；Rust 社区很重视工具链）。

我主要用 Go 工作。我确信 Go 语言的设计者当初并没有打算做出业界最易于被 LLM 读懂的语言。但他们还是做到了。Go 有恰到好处的类型安全、丰富的标准库，以及推崇（通常是重复性的）惯用写法的文化。LLM 生成 Go 代码简直无敌。

说这么多是想说：我也写一些 Rust。我挺喜欢它的。如果 LLM 和 Rust 对你来说配合不好，我感同身受。但如果你的全部论点就是这个，那我们争论的就不是同一件事。

### “但手艺呢”

你喜欢精致的日本木工吗？全靠手工工具和指物（sashimono）榫卯？我也喜欢。在你自己的时间里做吧。

我在地下室有一个简单的木工房（和我那些做木工的朋友比起来，我只是个门外汉）。打造一张桌子能给我带来很大的满足感。而且，如果那张桌子是工作台或烧烤桌，当然，我会自己做。但如果我需要的就是，呃，一张桌子？给人坐的？放在我办公室里的？我他妈的就去买一张。

职业软件开发者的工作是用代码为人们解决实际问题。在日常工作中，我们不是工匠。Steve Jobs 错了：我们不需要雕刻雕塑上那双看不见的脚。没人在乎主板上的走线排布得是否赏心悦目。如果我们构建的东西有什么能够流传下去，那也不会是因为代码库很漂亮。

再说，实际情况也并非如此。如果你正在花时间小心翼翼地把函数精简成优雅、流畅、极简的函数式表达式，那就该敲响警钟了。你在做无关紧要的琐事。真正的工作已经耗尽了你的专注力。你不是在构建：你是在自我安慰。

而这恰恰——等着瞧——正是 LLM 擅长的事。它们吞下那些苦差事，为重要的东西扫清道路，在那里，你的判断和价值观才真正重要。

### “但它很平庸”

作为一个职业生涯处于中后期的程序员，我已经学会了欣赏平庸。如果你能让平庸几乎毫不费力地像自来水一样流出来，那你就够幸运了。

我们都会写平庸的代码。平庸的代码：通常没问题。并非所有代码都同样重要。有些代码就应该是平庸的。在一个随便什么单元测试上倾尽全力？那你肯定做错了什么。你的组长应该纠正你。

开发者都爱在代码上自我炫耀。他们担心 LLM 会降低质量的“天花板”。也许吧。但它们也抬高了“地板”。

Gemini 的地板比我自己的高。我的代码看起来不错。但它没那么周全。LLM 的代码重复啰嗦。但我的代码里有一些蠢乎乎的扭曲写法，那是我为了追求 DRY（不重复）而耍了太多小聪明。

而且 LLM 并不是在每个维度上都平庸。它们几乎肯定比你掌握更多的算法技巧：基数树（radix trie）、拓扑排序、图归约、LDPC 码。人类把 `rsync` 浪漫化了（Andrew Tridgell 还为它写了一篇论文！）。对 LLM 来说，它可能并不比一个 SQL join 有趣多少。

但我有点扯远了。这不重要。即使我们从 LLM 那里得到的永远只有真正平庸的代码，那也仍然意义重大。这意味着人类需要写的平庸代码少了那么多。

### “但它永远不会成为 AGI”

我才不在乎。

聪明的从业者会被 AI/风投的炒作周期搞得心烦意乱。我不怪他们。但这算不上一个论点。东西要么管用，要么不管用，不管 Jensen Huang（黄仁勋）对此怎么说。

### “但它们抢——走——了——饭——碗”

开源也是如此。我们过去要为数据库花大价钱。

我们这个领域的前提，就是把别人的工作自动化掉。经济学家说这叫“生产率提升”。你明白这是什么意思吧？更少的人做同样的事。你最近跟旅行代理聊过吗？或者交易所场内经纪人？或者唱片店店员？或者暗房技术员？

每当这个论点出现，倾向自由意志主义的风投们就开始齐声念叨：点灯人、创造性破坏、新型工作。也许吧。但我没被催眠。我他妈完全不知道有了 LLM 之后我们会不会过得更好。情况对我们来说可能会变得糟糕得多。

LLM 真的可能会取代许多软件开发者。这可不是我们能居高临下的事。过去 30 年里，其他所有人的工作都处在科技的火力范围之内，我们的工作也一样。我们不是东海岸的码头工人；我们自己是阻止不了进步的。

### “但这是剽窃”

人工智能对视觉艺术家构成了深刻的——而且可能是不公平的——威胁，如果你不在艺术领域工作，可能很难体会这种威胁。

我们想象艺术家们把工作时间花在突破表达的极限上。但中位数的艺术家并不是在创作画廊作品。他们按需求简报创作：为杂志封面、博物馆展陈、动态图形和游戏素材产出合格的插画和构图。

LLM 轻而易举地——令人警觉地——越过了行业的质量门槛。令人恼火的是，它们最擅长的事情之一，就是批量产出刚好够用的人类创意作品仿制品。我有家人在做视觉艺术。我没法和他们谈论 LLM。我不怪他们。他们很可能没错。

与此同时，软件开发者发现一些代码片段似乎是从 GitHub 公开仓库里搬来的，就气急败坏了。那许可证怎么办？如果你是律师，我听你的。但如果你是一个打出这张牌的软件开发者？请容许我放肆一下，让你把这份担忧塞回你的屁眼里。没有哪个职业比我们更蔑视知识产权了。

中位数的开发者认为《星球大战》和 Daft Punk 都是公共财产。开发者们伟大的文化工程，就是反对任何可能给一个能变现的媒体分享网站带来不便的保护措施。当他们在政策上失败时，他们就用强制手段绕过去。他们建立全球规模的盗版网络，对任何哪怕只是试图为一部电视剧保留首映窗口期的人冷嘲热讽。

如果你想看一场关于在 LibreWolf 上播放《苍穹浩瀚》（*The Expanse*）有多难的 TED 演讲，就去指出其中任何一点吧。是啊，我们懂。你不相信知识产权。那就别他妈再谈知识产权了。自食其果吧。

反正这全都是双重标准的狡辩。LLM 对代码的消化比你更彻底。如果你不相信一位字体设计师能对一个字母形态的笔画末端和字怀主张道德上的权利，那你更没资格对一棵红黑树表现出占有欲。

### 再谈正面论证

几天前我开始写这篇文章时，写了一节“统一认识”，介绍 LLM 辅助编程的最新状况。一块青鱼鱼排的保质期都比一个关于 LLM 的观点长。在你读完这篇文章的工夫里，一切都变了。

如今的年轻人不只是用智能体；他们用的是异步智能体。他们一觉醒来，随口想出 13 件不同的事情让 LLM 去做，冲杯咖啡，填一份 TPS 报告，开车去 Mars Cheese Castle（火星奶酪城堡），然后查看通知。他们有 13 个 PR 要审。三个被扔掉、重新写提示。五个得到的反馈和初级开发者会得到的一样。还有五个被合并。

*“我现在就像在喝火箭燃料，”*一个朋友告诉我。*“我团队里那些不拥抱 AI 的人？他们就像原地不动。”*他没跟我胡扯。他不在旧金山湾区工作。他没有理由撒谎。

有很多事情我无法信任 LLM 去做。在我们这里，没有任何 LLM 能访问生产环境。但我曾作为一次事故的第一响应人，把日志记录喂给 4o——不是 o4-mini，是 4o——看着它在几秒钟内就发现了一台我们抱怨了好几个月的主机上的 LVM 元数据损坏问题。在审查 OpenSearch 日志和 Honeycomb 链路追踪方面，我比 LLM 智能体强吗？不。不，我不强。

令我的许多朋友感到惊愕的是，我不是激进分子，也不是未来主义者。我是个守成派。我相信复杂系统、制度那种磕磕绊绊的韧性，相信均值回归。我写 Go 和 Python 代码。我不是那种盲目狂热的信徒。

但真实的事情正在发生。我最聪明的朋友们却对此不屑一顾。也许我能说服你。多半说服不了。但我们不能再给糟糕的论点留余地了。

### “但我已经听烦了”

在这一点上，我重新站到了你们这边。我读 Simon Willison 的东西，这对我来说就够了。但每一天、整天，HN 首页都有相当大一块被 LLM 占据：模型的增量更新、用 LLM 做事的创业公司、LLM 教程、反对 LLM 的长篇檄文。真烦人！

但 AI 也极其——我是斟酌之后才用这个词的——重要。它得到的关注和 2008 年智能手机得到的差不多，而不如当年互联网得到的那么多。这看起来大致合适。

我认为在接下来的一年里这会变得更加清晰。那种对“随机鹦鹉”和“氛围编程”的酷小孩式傲慢，经不起与现实的更多接触。我在挖苦这些人，但我说的是真心话：他们比我聪明。等他们放下这种做作的姿态，他们会让编程智能体变得比今天有效得多。
