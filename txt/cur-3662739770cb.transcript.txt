Scott：欢迎收听 Syntax。今天我们要聊 React Server Components（React 服务端组件，简称 RSC）。现在是 2025 年 4 月——我刚才还得看一眼时钟才确定是 2025 年 4 月。你可能不清楚这东西现在发展到什么程度了，有些人可能仍然把 React Server Components 看作 Next.js 的一个功能。那么它们现在的状态如何？你可以怎么用它们？它们在某种程度上到底是什么？总之，React Server Components 到底是怎么回事？

Wes：到底怎么回事？它们已经存在大概五年了，但我总觉得它们还没有完全流行起来。所以我们今天会试着解释一下原因、它们是什么，以及目前你可以在哪里使用它们——而且不只是 Next.js。

Wes：我们先快速梳理一下 React Server Components 到底是什么，因为我确实觉得，即便到了今天，人们谈论它时对它到底做什么仍然存在一些误解。

Scott：对，很多人会想："我的客户端组件本来就已经在服务端渲染了，这不就够了吗？"

Wes：React 的服务端组件，要么在构建阶段渲染，也就是提前渲染——所以服务端组件其实并不一定需要服务器，挺好笑的——要么在大多数情况下完全在服务器上按需渲染。这与客户端组件不同：客户端组件显然通常在客户端渲染，但它们也仍然可以在服务端渲染。两者的区别在于，服务端组件只是把它们的输出发送给浏览器，类似于服务端渲染 HTML 的方式；而客户端组件会把在客户端渲染自己所需的一切都带过去。在大多数情况下这并不是二选一，你会把两者结合起来使用。

服务端组件是异步的（async），这意味着你可以在返回数据之前直接 await，这在很多场景下是非常棒的 API。你不必搞一个奇怪的加载状态、"如果在加载就什么都不返回"那一套，你可以直接 await 一个数据库调用，一旦 await 完成，就可以直接渲染出你的标记、你的 JSX。

Scott：对。服务端组件也可以被挂起（suspend）。也就是说，在这些组件还在渲染的时候，你可以继续渲染应用的其余部分，所以即便你在 await 它们，也不会卡住整个页面。

Wes：现代 React 通常是流式的，也就是浏览器会开始渲染网站的一部分。如果你有某个东西可能要花点时间——比如我的新网站，等你听到这期节目时应该已经上线了，wesbos.com——页脚里有一个推特动态。我不想在抓取推特的时候卡住整个页面，万一那要花很久呢？所以你可以把它挂起，网站的其余部分会先发送过去，等那个组件完成后，它就不再挂起，服务器会把它的标记发送到客户端并渲染出来。

Scott：你页脚里放了个推特动态，兄弟？

Wes：对。为了让推特 API 能用，我不得不干了点有点见不得光的事，不过我已经把它完全逆向出来了，而且已经稳定运行好几个月了。

Scott：不错。那服务端组件基本上是把一个 RSC 负载发送到浏览器，对吧？它基本上就是发送文本，然后它会被"再水合"（rehydrate）——你在这里会用这个词吗？

Wes：不会，因为"再水合"意味着有东西要绑定到它上面，意味着浏览器要去把它设置起来。服务端组件只是把它们的 HTML 发送给浏览器；或者如果你在刷新其中某个组件，它就只是发送输出的 React 负载。你可以把它想成服务器在发送 HTML——技术上它不是 HTML，而是用来嵌入它的 React 代码——但说它是"再水合"并不准确，因为在服务端组件里不会发生任何客户端的事情，除非你显式使用了客户端组件。

Scott：明白了，说得通。如果我对其中一些东西理解有偏差还请见谅。Svelte 的做事方式里没有这些东西，所以我的理解完全来自一个除了最基础的用法之外没怎么用过 React Server Components 的 React 开发者。所以你可以从概念上这么想：就像你说的，从服务器发出来的不是 HTML，但你可以把它在概念上类比为我们做 htmx 那一套的时候——请求某个东西，它返回的是 HTML 而不是数据，然后把那段 HTML 换进去。概念上类似，只不过它是 React 代码，而不是直接的 HTML。

Wes：完全正确，而且它不会附带任何其他东西。比如说你有一个很重的库，用来做 Markdown 解析或者代码高亮——代码高亮是个很好的例子。要在浏览器里做代码高亮，你要么只能用一个效果没那么好的小库，要么用一个很大的库，还得把整个库下载到浏览器里，在某些情况下这也不算太糟。但我的代码块用的是服务端组件，100% 在服务器上渲染，只把 HTML 发送给浏览器。我完全不用担心我那些做 Markdown 解析或代码高亮的插件有多大，因为它们全都在服务器上完成，只有一层薄薄的标记被发送到客户端。

Scott：对，它发送的是结果。

Wes：没错，是结果，而不是那个库。

然后是服务端函数（server functions），之前叫服务端动作（server actions）。它们是在服务器上运行、与 React Server Components 配合工作的函数，可以是一次数据库调用，也可以是刚才说的 Markdown 代码高亮。服务端函数既可以从客户端调用，也可以在表单提交时调用，这意味着你基本上得到了 RPC：你可以写一个在服务器上运行的函数，然后直接从你的 UI 调用它。它不会把这个服务端函数导入你的客户端应用，而是在两者之间来回执行 RPC 指令，在两边传递数据。还有几个可以配合使用的 hook，其中最主要的是 useActionState，用来维护响应返回的结果、是否有东西还在等待中（pending）、清除缓存，诸如此类。

这就是对 React Server Components 的一个非常快速的梳理。
