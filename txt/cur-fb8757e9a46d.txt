CSS :has 无可否认的实用性（The Undeniable Utility Of CSS :has） ｜ Josh W. Comeau ｜ 文章 ｜ https://www.joshwcomeau.com/css/has/

Josh W. Comeau 介绍 CSS 的 :has 伪类。他坦言起初并不看好：自己主要用 React 写应用，很少写复杂选择器；但用现代 CSS 重建博客的几个月里，他发现自己完全错了，即使在 CSS-in-JS 的场景下它也极其好用。

基础很简单：过去的 CSS 选择器"自上而下"，根据父元素给子元素设样式；:has 则"自下而上"，可以根据子元素给父元素设样式，比如给包含链接的段落加虚线框。截至 2024 年 9 月，Safari 15.4、Chrome/Edge 105、Firefox 121 起均已支持，总支持率约 92%，也就是约每 12 人有 1 人用不了。好在他的大多数用法都是锦上添花，其他情况可以用 @supports selector(...) 做特性检测；他提醒旧 CSS 无法模仿 :has，后备方案应理解为用另一种方式达到同一目的。

接着是他博客里的真实例子。"关于我"页面的便当盒布局里，卡片中有尺寸会变化的按钮，键盘用户看到的焦点框很怪；他不想把整张卡片做成按钮，因为那会带来无障碍问题，连按钮里的文字都没法拖选，于是用 .bento-card:has(button:focus-visible) 把焦点框画到卡片上，并去掉按钮自带的焦点框。他强调去掉焦点框要格外谨慎，所以整段放进 @supports 里，旧浏览器则保留默认焦点框；检测时用最短的 :has(*) 就够了，因为 @supports 只检查语法。另一个例子是他的"X/Y 面板"控件：拖动手柄（:active）或键盘聚焦时，容器里的点阵和边框通过 CSS 变量变色。

他认为最酷的用法是把 :has 当成全局事件监听器：模态框打开时要禁止页面滚动，以前在 React 里得写一段 useEffect 去保存并恢复 overflow，现在只需 html:has([data-disable-document-scroll="true"]) { overflow: hidden }，模态框设置这个 data 属性即可，属性变回 false 或元素被移除时滚动自动恢复，原生 JS 也能这样用。Jen Simmons 还用它做出不写 JS 的深色模式开关：复选框被勾选时覆盖颜色变量。不过他提醒，完整的深色模式要记住用户偏好、跟随系统主题，核心功能也不宜依赖 92% 支持率的特性。

他把 :has 称为 CSS 里"缺失的选择器"：配合 + 组合器，可以选中 figure 前后两侧的段落，从此能朝两个方向选兄弟元素；甚至能跨越完全不相干的容器，比如改编自 Ahmad Shadeed 的例子里，悬停某个分类按钮时，页面上所有同类的书都会高亮，反之亦然，DOM 结构完全无关紧要。

最后他回到"最合适的工具"：他推崇用复杂度最低的方案，通常 CSS 比 JS 简单；但那个分类高亮的例子加上移动端和键盘支持后，选择器会变得冗长，真做这个界面他会用 JS 的状态变量，既能支持动态分类、一本书多个分类，还能兼容 IE。他日常用 :has 的方式要朴素得多，比如焦点框和移动端禁止滚动，这些场合它非常顺手，也能很好地融入 React 应用。
