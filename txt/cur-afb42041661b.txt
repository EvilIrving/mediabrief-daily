这期 JS Party 由 Amal Hussein 单独主持，嘉宾是微软 Edge 团队的产品经理 Alex Russell。他此前在 Google 做了约 14 年 Web 平台工作，起点是 Chrome 1.0 之前。他之前发表的《柠檬市场》（The Market for Lemons）一文在前端圈引起轩然大波，这期节目就是让他给这篇文章补上背景和细节。

Alex 先讲了自己的履历：2000 年代领导 Dojo Toolkit，给 IBM、Sun、AOL 做大型 Ajax 应用；在 Google 期间参与 ES6 的箭头函数、class、Promise、async/await，以及 Web Components、Service Worker、PWA、推送通知和 Fugu 项目，在 TC39 待了十年，后来负责 Chrome 的标准工作。他说自己本不想关心性能，但从 2015 年起给团队做咨询，性能问题永远排在第一位。那些用最新 JavaScript 框架做出来的产品性能糟糕透顶，而做产品的都是优秀工程师。他打比方说，房子容易着火不是因为工人不会盖，而是卖给他们的材料不合用。

他说公开开炮是走投无路后的“D 计划”。多年来他一直私下把糟糕的测量数据反馈给框架团队，Angular 团队虽然不爱听，但最终重写了渲染器，开始强调少发脚本。他也肯定 Svelte、Preact、Lit、FAST、Qwik 这些框架始终把用户放在中心。让他愤怒的是，这些好选项被明显更差的方案挤出了市场。团队分不清质量好坏，被 FOMO 和惯性推着走，有些推销框架的人明知没有大量约束系统就跑不动，却不肯把这一点说出来。他认为责任很大程度上在产品负责人：管理层想当然地以为新技术会保留旧技术的所有优点，又从不设约束，出了问题再甩锅给工程师。

谈到“怎么走到这一步”，他的解释是硬件和市场的断裂。2010 年代初流行起来的框架基于桌面优先的假设，企业干脆分成“移动做 App、桌面做 Web”。2015 年后苹果的 CPU 性能遥遥领先，手持 iPhone 的富裕开发者陷入特权泡泡；而全球智能手机的中位价十年来一直在 300 美元左右，新增的边际用户多在印度、印尼等地，每年可用的性能预算实际上没有增长。这就是新的数字鸿沟。他举例：欧洲一家比价网站的高管们在会上掏出来的全是最新 iPhone；Facebook 有“2G 星期四”，google.com 至今用 2009 年左右自研的轻量方案，亚马逊不谈框架，eBay 想把 Marko 换成 React 时会先算账。有个熟人发现，自家中端 SPA 电商每多 1KB JavaScript，每年损失约 70 万美元收入，而他们原先估计只有 10 万。很多团队花 18 个月做完 React 重写，结果数据暴跌，项目被叫停。

关于架构，Alex 提出“会话深度加权”。任何交互都是一个从静止到静止的循环，既可以走完整的 HTTP 往返，也可以在本地数据模型上完成。SPA 适合 Figma、Photoshop 这类高频、低延迟、会话很长的编辑器，因为前置成本能分摊到成百上千次交互上。博客读者只点一两下，分母是 1，承担不起任何前置成本。WordPress 就是两个应用：编辑器适合重前端，阅读端不适合。Gmail 也一样，单看一封邮件不该加载几 MB 脚本。大多数应用并非从零开始，可以按典型会话类型来选架构。

他还批评行业对“开发者体验更好了”的说法缺少证据。一个网站构建 40 分钟到 2 小时，用的还是 SSD；团队通过脚手架被动继承了大量自己并不理解的复杂性。产品经理应该做对比测试，算清楚一个产品上线前后瘫痪一个月到底算不算更快。他帮团队“出沟”的做法是渐进式的：先弄清技术栈里隐藏了哪些选择，学习浏览器的工作原理，再一步步修正，而不是推倒重写。

至于出路，他说不是换工具。复杂性管理能力有限的组织应该选最简单的方案，输出 HTML 和 CSS。已经陷进去的团队可以借 Core Web Vitals，尤其是 INP，让管理层看到改进的价值；也可以改用会提取静态 CSS 的 CSS-in-JS 工具（他提到 Nolan Lawson 在样式性能上的研究），或者把 React 组件的内部换成 Web Components。最关键的是把边际用户放在讨论中心，看 P75、P90，让 PM 随身带低价设备。Astro、Eleventy、Hugo、PHP、.NET、Rails、Django 都可以重新用起来。他还说懂语义化标记和现代 CSS 的人才大量闲置，“招不到人”多半是因为没认真找。

给个人的建议是：在低端设备上追求每 16 毫秒出一帧，与其学新框架，不如学浏览器从网络、DOM、CSS 到布局、绘制、光栅化的整条渲染流水线。他推荐的资料有《How Browsers Work》、Chris Harrelson 与 Pavel Panchekha 的《Web Browser Engineering》、Chromium University 里 Steve Kobes 的《Life of a Pixel》、WebPageTest 和浏览器开发者工具，并建议买一台便宜手机和笔记本，他自己的 Moto G4 从 2017 年用到现在。

对于 Laurie Voss 那篇回应文章以及“太苛刻”的批评，Alex 回应说，他从不认为开发者愚蠢，但用户和团队确实被误导、受到了伤害，其他办法都试过了。他整体是乐观的：工程师在组织里有真实的影响力，可以对胡扯说不；只要把证据和边际用户放在中心，这十年将来会被看作“一段困惑期”，之后是测量、对比测试和真正的工程权衡，而不是又一阵风潮。他认为这也是这个行业保住“社会运营许可”的唯一方式。Amal 补充说，这需要在社区层面通过培训、产品管理方式的改变和数据驱动的决策来推动，不能只靠个人自律。
