AsyncTalk 围绕前端 UI 组件库过去十年的演变与下一个十年的范式转移展开讨论，深入对比了以 Ant Design（AntD）为代表的传统一体化组件库与以 shadcn/ui、Radix 为代表的 Headless / 原子化设计体系的架构哲学与工程权衡。

在前端发展的第一个十年（2015 年前后至 2020 年初），以 AntD 为代表的组件库主打“开箱即用”与业务极速交付，核心指标是功能覆盖度与 API 的简明易用。然而，随着大型工程演进与 React Server Components（RSC）架构的普及，一体化组件库暴露出深层的设计缺陷：
其一，语义化与可访问性（a11y）严重受限。例如 Tooltip 组件粗暴将 children 视作 trigger，破坏了复杂嵌套场景下的触发边界与屏幕阅读器语义；
其二，DOM 结构黑盒化与样式冲突。顶层全量引入全局 CSS 导致 Tree-shaking 失效，开发者不得不借助深层选择器与 !important 暴力覆盖内部私有样式，造成难以维护的全局特异性竞争；
其三，挂载节点与层级地狱。为规避容器 overflow:hidden 裁剪，组件普遍依赖 getPopupContainer 强行挂载至 document.body，直接割裂了原生 DOM 树结构并导致页面滚动时位移脱节，同时在复杂页面上滋生混乱的 z-index 覆盖死锁；
其四，运行时开销与 RSC 冲突。重度依赖 Client Component 与繁重的客户端 JavaScript 计算，难以适应现代 SSR 与边缘渲染架构。

以 shadcn/ui 为代表的 Headless 组件范式则开创了“将组件代码作为自身资产（Own Your Code）”的新哲学。它摒弃了将 UI 库作为黑盒 npm 依赖引入的传统做法，采用代码复制（Copy & Paste）机制将源码直接注入业务工程：
首先，在结构上将逻辑原语（Primitive）与样式彻底解耦，Tooltip 等组件被拆解为 Root、Trigger、Content 等清晰层级，具备完备的 WAI-ARIA 属性与语义化标准；
其次，基于 Tailwind CSS 构建原子化设计系统，根除了全局样式污染与打包体积膨胀问题，赋予开发者对 DOM 结构与视觉展现的完全控制权；
再次，天然兼容 React Server Components，展示型组件无需注入 use client 指令，无版本升级断层风险。

面对 Headless 模式较高的初始抽象认知成本与组件拆解复杂度，未来的 UI 架构正进一步走向由编码智能体（Coding Agent）驱动的定制化阶段。在完备的设计系统约束与原子样式辅助下，由 Agent 按需生成完全适配业务语义与性能标准的专属组件，将成为兼顾交付吞吐率与长期可维护性的演进终局。
