什么是推理 What Is Reasoning ｜ Armin Ronacher ｜ 文章 ｜ https://lucumr.pocoo.org/2026/8/19/what-is-reasoning/

Armin Ronacher 的一篇短文。起因是几周前有论文展示了如何从闭源模型里提取推理过程，网上也有人在讨论怎么骗模型泄露推理内容，他觉得推特上半真半假的说法太多，于是去弄清楚推理到底是怎么回事。

他的核心观点是：推理过程被包装得很神秘，其实就是文本。模型被训练成在给出最终答案之前，先把思考写进回答里的一块"草稿区"。GPT-OSS 的 Harmony 格式能看得很清楚：用特殊 token 标出 analysis 频道和 final 频道，两者之间的推理用的是和最终答案"同样的文本"。模型一旦采样出 analysis 频道的 token，解析器就把后面的文字导到另一条流里，由 Responses API 单独暴露；闭源模型大概是再用一个简单模型去删改和摘要。开源模型的推理往往又长又乱，这也是把它和展示给用户的内容分开的好理由。

推理花多少预算，看起来像采样参数，实际上写在系统提示里：GPT-OSS 只是一行 "Reasoning: low"，其余行为都是训练出来的，这也解释了为什么改推理强度会让 KV 缓存失效。他说闭源 GPT 模型把推理强度叫 "juice"，问大多数模型它们有多少 juice 都能问出来；antirez 的本地推理引擎 DwarfStar（ds4）给 DeepSeek 开最高推理时，系统提示里写的是一大段"绝不走捷径、彻底拆解问题"的要求。所以推理 token 去哪儿，只是一种学来的惯例：骗模型以为自己在最终频道，它就可能泄露推理；有些老模型在关闭思考后，会把思考写进 bash 工具、输出到 /dev/null。反过来说，某些模型真正"特殊"的行为是不思考，通常靠机械手段实现：DwarfStar 关闭思考时预填 </think>，开启时预填 <think>；GPT-OSS 则让模型自己决定。他推测有些推理 API 在开启推理时替模型预填开头 token，关闭时则阻止它采样这个 token，这也许解释了为什么自定义的 think 工具只有在原生推理关闭时才能骗模型把推理放到不该放的地方。结尾他自嘲：想用 GPT-5.6 Terra 给这篇文章查拼写语法，结果被安全过滤拦了，只好换成 Kimi。
