这是 GPT-6 Luna 和 Claude Haiku 5.5 在玩海战棋（Battleship），Haiku 刚刚以一艘船的优势赢下了这场对局。每个模型都作为独立的 AI agent 运行在各自的进程里，它们之间通过一个叫 A2A 的协议互相通信。搭建这一切我没有写任何框架代码，用的只是几个 YAML 文件，外加 Docker 推出的一个新工具：Docker Agent。这期视频里，我会先讲讲 Docker Agent 是什么、怎么工作、为什么值得研究；然后从零启动一个 agent，再把两个 agent 连起来做一次真实的排错任务，最后完整打一局海战棋。一定会很有意思，我们开始吧。

Docker Agent 是 Docker 推出的开源工具，用来构建和运行 AI agent。Docker 的说法是，它之于 AI agent，就像 docker run 之于容器。你在一个 YAML 文件里描述 agent：用哪个模型、有哪些指令、允许使用哪些工具，然后用一条命令就能运行它。agent 循环（agent loop）由 Docker Agent 替你处理：调用模型、执行工具、把结果回传给模型，如此反复，直到任务完成。

下面是一个完整 agent 的例子。其中 model 这一行可以指向 OpenAI、Anthropic、Gemini、OpenRouter，也可以通过 Docker Model Runner 指向本地模型。你还可以给它配工具，工具来自 toolsets 部分，里面既有文件访问、shell 命令这类内置工具，也可以接入任何你想接的 MCP server。一个 agent 还可以有子 agent（sub-agent），这样一个协调者就能把工作分派给各个专才。

Docker 自己的文档里其实有一个很好的对比：左边是你通常要写的 Python 代码，让模型循环调用工具；右边是用 Docker Agent 写的同一个 agent。看看右边干净了多少。

Docker Agent 还有三点非常酷。第一，agent 变成了配置。你可以对它做版本管理，在 pull request 里评审，换模型只需要改一行。第二是分发。你可以把 agent 推送到 Docker Hub 或任何其他 OCI 镜像仓库，别人只要用 docker agent run 加上镜像名就能运行，和分享容器的方式一样。第三，agent 可以作为服务运行。一条命令就能让 agent 变成 HTTP API、MCP server，或者可以被其他 agent 调用的 A2A server。这第三点我们在视频后面会实际看到。

如果你用的是 Docker Desktop 4.63 或更新版本，Docker Agent 默认已经装好了。否则可以用 Homebrew 安装，再把它软链接到 Docker CLI 的插件目录，这样就能以 docker agent 的形式运行。

这是你能写出的最小的 agent：一个模型、一段描述、一条指令。我只需要运行 docker agent run agent.yaml，就会得到一个可以和它对话的终端界面（TUI）。

再看一个更贴近实际的例子。假设结账（checkout）服务挂了，而你正在值班。这个文件里我配了两个 agent。第一个是日志分析员，它是唯一能读日志的 agent，拥有一个只读的文件工具，并被限定在日志目录里。第二个是值班助手，它完全没有文件访问权限，只知道分析员的 URL。在真实的公司里，日志分析员会由平台团队负责，并部署在日志旁边；其他任何团队的 agent 都可以向它提问，而无需获得日志本身的访问权。

于是在第一个终端里，我运行 docker agent serve a2a，用 agent 参数选定日志分析员，端口设为 8080。在第二个终端里运行值班助手，问它为什么从下午两点左右开始，结账一直在报 500 错误。你可以看到问题送到了分析员那里，它查看应用日志和部署历史，然后把发现发回来，值班 agent 再把这些整理成一份事故摘要。

现在用同样的模式来做点更好玩的。海战棋这边我有三个 agent：蓝方和红方两个选手，各自通过 A2A 在自己的端口上提供服务；还有第三个 agent 是裁判，负责主持比赛。裁判我用了 Kimi K3，这样两个选手的模型都不是在给自己的比赛当裁判。棋盘跑在本地服务器上。选手监听 8080 和 8081 端口，然后我启动裁判。每一回合，选手会拿到自己看到的敌方海域，选一个格子，还会顺便加上一句垃圾话（trash talk），图个乐。

如你所见，Haiku 开局很强。它很早就找到了航空母舰，沿着一条线一路打下去直到击沉。但 Luna 强势反扑，到了残局，双方都只剩最后一艘船。最终 Haiku 在 H 行找到了最后一艘潜艇，以 34 发炮弹、50% 的命中率获胜。当时 Luna 已经击沉了 Haiku 除一艘之外的所有船，所以真的非常、非常接近。不过这只是个简单的游戏，我不会把它称作基准测试（benchmark）。两个模型显然都比随机乱打强，Haiku 只是碰巧最后赢了。

好了，各位，这就是 Docker Agent 的概况。你可以用 YAML 编写 agent，一条命令运行，通过镜像仓库分享，并且只要一个 URL 就能通过 A2A 把它们连起来。我经常在 Hugging Face 上看到那些代码示例，要写大量 Python 样板代码，所以我特别高兴 Docker 做出了这样一个工具，把整个过程大大简化了。以后我大概会经常用它。
