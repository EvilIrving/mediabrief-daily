键值缓存（KV Cache）是大语言模型自回归推理加速中最核心的基础工程技术。其设计初衷在于消除自回归生成过程中对历史 Token 键值张量的冗余重复计算，以空间换时间的策略大幅缩短端到端文本生成延迟。

在未经优化的标准自回归解码中，模型每预测一个新 Token，均需将包含完整前文的历史序列重新输入网络（例如从初始提示词“Time”预测“flies”，再将“Time flies”整体送入预测“fast”）。在具有因果因果掩码的注意力机制下，由于前置 Token 的上下文表示仅取决于更早出现的词元与网络中固定的投影权重矩阵，其对应的 Key 与 Value 投影向量在后续所有自回归步长中均保持严格恒定。若每一轮解码均对历史序列执行全量矩阵重算，单步注意力的计算量将随生成长度持续累加，造成巨大的算力与访存带宽浪费。KV 缓存的核心逻辑是将自回归过程解耦为提示词预填充（Prefill）与逐词元解码（Decode）两个独立阶段：在预填充阶段一次性计算并持久化所有输入 Token 的 Key 与 Value 矩阵；在后续解码阶段，仅对当前单个最新 Token 进行线性投影获得 Query、Key 与 Value，随后将新的 Key 与 Value 动态追加至缓存张量中，由当前单个 Query 向量与累积的历史全局 Key/Value 矩阵执行高效的向量-矩阵点积注意力。

在纯 PyTorch 手写实现层面，落地 KV 缓存涉及多项关键工程考量：
一、状态生命周期管理与位置游标同步：注意力模块内部需维护独立的缓存张量缓冲区。在多轮独立生成请求之间必须显式执行清空与重置（Reset），否则残余的过时键值将引发跨会话注意力污染。同时，自回归模型必须在状态中显式维护当前已缓存序列长度的游标索引，确保新生成的 Token 在计算旋转位置编码（RoPE）或绝对位置嵌入时，能够精确对齐到连续递增的时序位置坐标。
二、动态拼接与静态预分配的显存权衡：轻量化实现通常在每一步调用 torch.cat 动态拼接新张量，但频繁的动态显存申请会导致严重的内存碎片化并拖慢底层执行效率。生产级环境通常根据最大上下文长度（max_seq_len）预先分配固定维度的连续零张量池（形状为 [Batch, Heads, Max_Len, Head_Dim]），并在解码步长中通过切片索引原位写入新值，从而消除反复动态分配的系统开销。
三、显存线性膨胀与滑动窗口截断：KV 缓存的显存开销随生成序列长度、网络层数与并发批处理大小呈严格线性增长，长上下文大模型极易引发 GPU 显存耗尽（OOM）。针对长文本场景，可结合滑动窗口注意力（Sliding Window Attention）构建受限缓存，仅在张量缓冲区中维护最近窗口大小（window_size）内的激活值，将缓存显存占用严格钳制在恒定上限。
四、分组查询注意力（GQA）与缓存压缩：在适配现代主流模型（如 Llama 3 与 Qwen3）时，KV 缓存能够与 GQA 产生深度协同。由于多个 Query 头共享单组 Key/Value 头，缓存张量在头数维度直接缩小为原始多头注意力（MHA）的数分之一，成倍缓解了长序列下的显存带宽压力。
五、图编译优化与硬件性能权衡：若采用动态张量拼接，需将缓存逻辑解耦到模型核心前向图之外，以便与 PyTorch 的 torch.compile 图编译器深度融合，避免频繁发生图中断（Graph Break）。在 M4 芯片 Mac Mini（CPU）上对 1.24 亿参数模型生成 200 个 Token 的对照测试表明，引入 KV 缓存带来约 5 倍的生成吞吐提升，且输出 Token 与无缓存基线保持完全精确一致；叠加编译后性能进一步跃升。然而在 GPU 硬件上，对于未经静态预分配的小参数模型，动态缓存的额外内核启动开销与显存搬运延迟甚至可能抵消算力节约，凸显了推理优化对硬件拓扑与显存架构的高度敏感性。
