几周前，有人分享了一篇论文，展示了如何从闭源权重模型中提取推理轨迹。再加上网上关于如何诱骗模型泄露推理内容的讨论，出于好奇，我对此做了更多研究。推特上关于这件事是怎么运作的，似乎充斥着半真半假的说法和困惑，所以也许这篇文章能帮一些人理解到底发生了什么。

推理轨迹通常对我们是隐藏的。我们曾为此惋惜，但大体上只能接受。好在开源权重模型会展示它们，从它们的表现可以看出，推理轨迹可能又长又混乱。这大概也是把它们与通常展示给用户的内容分开的一个好理由。

至少，用户界面需要能识别它们。业界成功地让推理轨迹听起来既特别又神秘，但它们其实就是文本：模型被训练成在给出最终答案之前，把自己的思考作为回答的一部分写进一块草稿区。

GPT-OSS 的 Harmony 响应格式让这一点很容易看清：

<|channel|>analysis<|message|>
我需要把这个算出来……
<|end|><|start|>assistant<|channel|>final<|message|>
答案是……
<|return|>

这些标记是特殊 token，但它们之间的推理使用的是和最终答案"同样的文本"（只不过 GPT 的思维链文字读起来非常滑稽）。当模型采样出 analysis 频道的 token 时，解析器会把随后的文本路由到一条单独的流中，通过 Responses API 暴露出来。对于闭源模型，大概是由一个简单的模型对其进行删减和摘要。

有多少预算分配给推理？早期的 API 会暴露推理 token 预算，让它看起来像是采样过程的一个属性。实际上，推理强度是写进系统提示里的。GPT-OSS 在系统提示中写的是：

Reasoning: low

就这么一行。由此产生的行为，比如输出切换到 analysis 频道的那串 token，是训练出来的。这也解释了为什么改变推理强度会让 KV 缓存失效。我认为闭源的 GPT 模型把推理强度称为"juice"（果汁），因为你可以问大多数模型它们有多少 juice。

在 DwarfStar（antirez 开发的本地推理引擎 ds4）中，DeepSeek 开启最大推理时，系统提示里会加上这样一段：

推理强度：绝对最大，不允许任何捷径。
你必须在思考中做到非常彻底，全面拆解问题以解决根本原因，针对所有可能的路径、边界情况和对抗场景，严格地对你的逻辑进行压力测试。

因此，推理 token 的去向是一种学来的惯例：模型被训练成不把草稿工作放进最终频道。诱骗它以为自己处在那个频道里，它就可能泄露 token。我们甚至见过一些较老的模型在思考被关闭时，把推理写进 bash 工具，并把自己的想法 echo 到 /dev/null。

所以从某种意义上说，对某些模型而言唯一"特殊"的行为是不思考。这有时是通过"机械地"移除模型惯常的思考方式来实现的。在 DwarfStar 中，关闭思考时使用预填的 </think>，开启思考时使用 <think>，这两个 token 分别用于结束和开始思考。GPT-OSS 不做预填，而是让模型自己决定。

不过可以推测，有些推理 API 在开启推理时会预填开头的 token，这样模型就永远不会自己采样它；而在关闭推理时，可能会阻止推理 token 被采样，因为它很容易被检测到。这也许可以解释为什么一个自定义的 think 工具能诱骗模型把一些推理放到不该放的地方——但只有在原生推理被关闭时才行。
