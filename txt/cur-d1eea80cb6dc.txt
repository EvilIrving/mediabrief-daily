agent 架构中的安全边界（Security boundaries in agentic architectures） ｜ Vercel Blog ｜ 文章 ｜ https://vercel.com/blog/security-boundaries-in-agentic-architectures

Vercel 官方博客的这篇文章认为：如今多数 agent 运行自己生成的代码时拥有你全部密钥的访问权，这必须改变。所有 agent 都越来越像编程 agent，风险来自提示注入加代码执行。例如 agent 排查故障时读到一份藏着注入指令的日志，被诱导把 SSH 和云凭证发到外部服务器；之所以得逞，是因为 agent、生成的代码和基础设施共享同一级权限。

文章把系统拆成 agent、密钥、生成代码的执行、运行环境四个角色，提出两条原则：harness 不把自己的凭证暴露给 agent；工具范围越窄越好，客服 agent 应拿到只能访问该客户数据的工具，而不是能被注入篡改的客户 ID 参数。它再从低到高比较几种架构：零边界是今天的默认；网络出口处的密钥注入代理能防外泄但防不住滥用；把 harness 和代码装进同一沙箱保护不了 agent 自身。最好的做法是把两者放进独立的计算环境，生成代码在即开即毁的临时虚拟机里跑，再配合密钥注入。文章判断这会成为标准架构，并顺带介绍了 Vercel Sandbox。
