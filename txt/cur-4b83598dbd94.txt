在全球最大代码托管平台 GitHub 的前端性能优化演进中，工程团队彻底推翻了长期主导现代前端开发的 CSS-in-JS 运行时架构，全量迁移至基于构建时编译的静态 CSS Modules：该重构打破了前端领域盲目追求 JavaScript 动态封装的固有偏见，通过在网络传输层面适度发送更多原生 CSS 字节代码，彻底消除了客户端与服务端的运行时样式计算开销，使得页面首次输入延迟（INP）与总阻塞时间（TBT）录得断崖式改善。

回顾 GitHub 核心设计系统 Primer 的架构演进，平台早前深度依赖基于 styled-components 的 CSS-in-JS 方案以实现组件级的样式就近维护与作用域隔离。然而随着页面功能日趋复杂，单个复杂交互页面挂载的 UI 组件数量呈现爆发式增长，运行时动态生成样式的方案暴露出致命的性能瓶颈：在客户端渲染阶段，浏览器 JavaScript 引擎必须在主线程上动态解析样式对象、哈希计算类名并在 DOM 中就地注入 `<style>` 标签，导致严重的页面渲染卡顿与脚本主线程阻塞；在服务端渲染（SSR）阶段，庞大的样式收集机制同样严重拖慢了页面流式 HTML 的输出吞吐率。

为从架构根源拔除性能毒瘤，团队选定原生 CSS Modules 作为下一代样式基础设施。CSS Modules 在构建阶段通过静态分析提前完成类名局部作用域的混淆与映射，生成的样式完全作为原生静态 `.css` 文件独立分发，在运行时完全不依赖任何客户端 JavaScript 代码或虚拟 DOM 钩子注入。尽管相较于动态样式去重后的极致精简，向浏览器分发的原生静态 CSS 文件总字节体积出现了适度上浮，但其带来的系统性能收益呈压倒性优势。

在浏览器底层渲染管线中，静态 CSS 文件能够在接收时由浏览器内核自带的高性能 C++ 样式引擎与 HTML 文档流实施并行流式解析，主线程完全免去了高昂的 JavaScript 运行时代谢与垃圾回收暂停。性能基准实测显示，彻底告别 CSS-in-JS 后，大型代码差异对比（PR Diff）等重载页面的主线程交互冻结时间大幅削减，首屏渲染平滑度显著跃升。这一工业级工程实践明确昭示：现代 Web 架构的最优解应当顺应浏览器原生底层能力的演进方向，坚决剥离过度依赖 JavaScript 运行时代价的脆弱抽象。

在工程迁移的实施路径上，Primer 团队制定了严密的分阶段演进方案，确保在不破坏平台每日数亿次代码交互连续性的前提下完成平滑过渡。团队通过自研静态代码重构工具链，对数千个组件实施了自动化 AST 转换与视觉回归对比，并在持续集成门禁中设立了对遗留运行时 CSS 注入的增量阻断规则。这次架构大迁移的成功落地，为超大型 Web 应用在面对新兴前端范式泡沫时如何保持理性、回归底层平台原生能力提供了教科书式的范例。
