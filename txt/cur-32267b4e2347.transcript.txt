距离最初的 GPT 架构问世已经七年了。乍一看，从 GPT-2（2019）回望，再向前看 DeepSeek V3 和 Llama 4（2024–2025），你可能会惊讶于这些模型在结构上依然如此相似。

当然，位置嵌入已经从绝对位置编码演进到旋转位置编码（RoPE），多头注意力（Multi-Head Attention）大体上让位给了分组查询注意力（Grouped-Query Attention），更高效的 SwiGLU 也取代了 GELU 之类的激活函数。但在这些细小改进之下，我们真的见到了突破性的变化吗？还是只是在打磨同一套架构地基？

比较各个 LLM、找出决定其表现好坏的关键因素，向来是出了名的难：数据集、训练技巧和超参数差异极大，而且往往缺乏充分的文档。

不过我认为，审视架构本身的结构变化、看看 2025 年的 LLM 开发者都在做什么，仍然很有价值。（下面的图 1 展示了其中一部分。）

你大概已经不止一次听说过，DeepSeek R1 在 2025 年 1 月发布时引起了巨大反响。DeepSeek R1 是一个推理模型，构建在 2024 年 12 月推出的 DeepSeek V3 架构之上。

虽然我这里关注的是 2025 年发布的架构，但把 DeepSeek V3 纳入进来也是合理的，因为它正是在 2025 年 DeepSeek R1 发布之后才获得广泛关注和采用。

如果你对 DeepSeek R1 的训练过程特别感兴趣，我今年早些时候的文章可能也对你有用。

本节我将聚焦 DeepSeek V3 引入的两项关键架构技术，它们提升了计算效率，也让它有别于许多其他 LLM：

* 多头潜在注意力（Multi-Head Latent Attention，MLA）
* 混合专家（Mixture-of-Experts，MoE）

在讨论多头潜在注意力（MLA）之前，先简单交代一些背景，说明为什么要用它。为此，我们从分组查询注意力（GQA）讲起。近年来，GQA 已经成为多头注意力（MHA）的新标准替代方案，在计算量和参数量上都更高效。

先简要概括一下 GQA。在 MHA 中，每个头都有自己的一组键和值；而 GQA 为了降低内存占用，会让多个头共享同一组键和值投影。

例如，如下面图 2 进一步展示的，如果有 2 个键值组和 4 个注意力头，那么头 1 和头 2 可能共享一组键和值，头 3 和头 4 共享另一组。这减少了键和值的计算总量，从而降低内存占用、提升效率（根据消融研究，对建模性能没有明显影响）。

图 2：MHA 与 GQA 的比较。这里组大小为 2，即一对键和值由 2 个查询共享。

所以，GQA 的核心思想是通过让多个查询头共享键头和值头来减少其数量。这样（1）降低了模型的参数量，（2）减少了推理时键、值张量占用的内存带宽，因为需要从 KV 缓存中存取的键和值变少了。

（如果你好奇 GQA 的代码长什么样，可以看我的《GPT-2 到 Llama 3 转换指南》，其中是不带 KV 缓存的版本；带 KV 缓存的版本见这里。）

虽然 GQA 主要是针对 MHA 的一种计算效率上的变通方案，但消融研究（例如原始 GQA 论文和 Llama 2 论文中的研究）表明，就 LLM 的建模性能而言，它与标准 MHA 表现相当。

而多头潜在注意力（MLA）提供了另一种节省内存的策略，并且同样特别适合与 KV 缓存搭配。MLA 不像 GQA 那样共享键头和值头，而是在把键和值张量存入 KV 缓存之前，先把它们压缩到一个更低维的空间。

推理时，这些压缩后的张量在使用前会被投影回原始尺寸，如下面图 3 所示。这增加了一次矩阵乘法，但降低了内存占用。

图 3：MLA（用于 DeepSeek V3 和 R1）与常规 MHA 的比较。

（顺带一提，查询也会被压缩，但只在训练时压缩，推理时不压缩。）

另外，MLA 并不是 DeepSeek V3 才有的新东西，它的前代 DeepSeek-V2 就已经使用了（甚至正是由它提出的）MLA。V2 论文中还有几项有意思的消融研究，或许可以解释 DeepSeek 团队为什么选择 MLA 而不是 GQA（见下面图 4）。

图 4：DeepSeek-V2 论文中的表格（带标注），https://arxiv.org/abs/2405.04434

如上面图 4 所示，GQA 的表现似乎不如 MHA，而 MLA 的建模性能比 MHA 更好，这很可能就是 DeepSeek 团队选择 MLA 而非 GQA 的原因。（要是还能看到 MLA 与 GQA 在“每个 token 的 KV 缓存”节省量上的对比就更有意思了！）

在进入下一个架构组件之前总结一下：MLA 是一个巧妙的技巧，能减少 KV 缓存的内存占用，同时在建模性能上甚至略胜 MHA 一筹。

DeepSeek 另一个值得强调的主要架构组件是混合专家（MoE）层。虽然 MoE 不是 DeepSeek 发明的，但它今年迎来了复兴，后面要讲的许多架构也都采用了它。

你可能已经熟悉 MoE，但简单回顾一下也许有帮助。

MoE 的核心思想是把 Transformer 块中的每个前馈（FeedForward）模块替换成多个专家层，而每个专家层本身也是一个前馈模块。也就是说，我们把单个前馈块换成多个前馈块，如下面图 5 所示。

图 5：DeepSeek V3/R1 中的混合专家（MoE）模块（右）与使用标准前馈块的 LLM（左）的对比示意。

Transformer 块内部的前馈块（上图中深灰色的块）通常包含了模型总参数中的很大一部分。（注意，Transformer 块以及其中的前馈块会在 LLM 中重复很多次；在 DeepSeek V3 中是 61 次。）

因此，把 _单个_ 前馈块换成 _多个_ 前馈块（正如 MoE 结构中那样）会大幅增加模型的总参数量。不过关键技巧在于，我们并不会为每个 token 使用（“激活”）所有专家，而是由一个路由器（router）为每个 token 只挑选一小部分专家。（出于时间考虑，或者说篇幅考虑，路由器的细节以后再讲。）

由于每次只有少数专家处于激活状态，MoE 模块常被称为 _稀疏_ 模块，与始终使用全部参数的 _稠密_ 模块相对。不过，MoE 带来的庞大总参数量增加了 LLM 的容量，意味着它在训练中可以吸收更多知识；而稀疏性又让推理保持高效，因为我们不会同时用到所有参数。

例如，DeepSeek V3 每个 MoE 模块有 256 个专家，总参数量为 6710 亿。但推理时每次只有 9 个专家处于激活状态（1 个共享专家加上路由器选出的 8 个）。这意味着每个推理步骤只用到 370 亿参数，而不是全部 6710 亿。

DeepSeek V3 的 MoE 设计有一个值得注意的特点：使用了共享专家。这是一个对每个 token 都始终激活的专家。这个想法并不新，早在 2024 年的 DeepSeek MoE 论文和 2022 年的 DeepSpeedMoE 论文中就已提出。

图 6：《DeepSeekMoE: Towards Ultimate Expert Specialization in Mixture-of-Experts Language Models》中的图（带标注），https://arxiv.org/abs/2401.06066

共享专家的好处最早是在 DeepSpeedMoE 论文中被注意到的：与没有共享专家相比，它能提升整体建模性能。这很可能是因为常见或重复的模式不必由多个独立专家分别去学，从而给它们留出更多空间去学习更专门的模式。

总结一下，DeepSeek V3 是一个庞大的 6710 亿参数模型，发布时超越了包括 405B 的 Llama 3 在内的其他开放权重模型。尽管规模更大，但得益于混合专家（MoE）架构，它在推理时效率高得多，每个 token 只激活一小部分参数（仅 370 亿）。

另一个关键区别是 DeepSeek V3 使用多头潜在注意力（MLA）而不是分组查询注意力（GQA）。MLA 和 GQA 都是标准多头注意力（MHA）在推理效率上的替代方案，尤其是在使用 KV 缓存时。虽然 MLA 实现起来更复杂，但 DeepSeek-V2 论文中的一项研究表明，它的建模性能优于 GQA。

非营利机构艾伦人工智能研究所（Allen Institute for AI）推出的 OLMo 系列模型值得关注，原因在于其训练数据和代码的透明度，以及相对详尽的技术报告。

你大概不会在任何基准测试或排行榜的榜首看到 OLMo 模型，但它们相当干净，更重要的是，得益于其透明度，它们是开发 LLM 的绝佳蓝本。

而且，OLMo 模型虽然因透明而受欢迎，表现也并不差。事实上，在 1 月发布时（早于 Llama 4、Gemma 3 和 Qwen 3），OLMo 2 模型正处于算力与性能的帕累托前沿上，如下面图 7 所示。

图 7：不同 LLM 的建模基准性能（越高越好）与预训练成本（FLOPs，越低越好）。这是 OLMo 2 论文中的图（带标注），https://arxiv.org/abs/2501.00656

如本文前面提到的，为了控制篇幅，我只关注 LLM 的架构细节（不谈训练和数据）。那么，OLMo 2 有哪些有意思的架构设计选择？主要集中在归一化上：RMSNorm 层的位置，以及新增的 QK-norm，下面我会讨论。

另一点值得一提的是，OLMo 2 仍然使用传统的多头注意力（MHA），而不是 MLA 或 GQA。

总体而言，和其他同时代的 LLM 一样，OLMo 2 大体沿用了原始 GPT 模型的架构，但有一些值得注意的偏离。我们先从归一化层说起。

与 Llama、Gemma 以及大多数其他 LLM 一样，OLMo 2 从 LayerNorm 换成了 RMSNorm。

不过 RMSNorm 早已不是新鲜事（它基本上是 LayerNorm 的简化版，可训练参数更少），所以我略过 RMSNorm 与 LayerNorm 的讨论。（好奇的读者可以在我的《GPT-2 到 Llama 转换指南》中找到 RMSNorm 的代码实现。）

但 RMSNorm 层的位置值得讨论。原始 Transformer（出自论文《Attention is all you need》）把 Transformer 块中的两个归一化层分别放在注意力模块和前馈模块 _之后_。

这也被称为 Post-LN 或 Post-Norm。

GPT 以及之后的大多数 LLM 则把归一化层放在注意力模块和前馈模块 _之前_，这被称为 Pre-LN 或 Pre-Norm。下图展示了 Post-Norm 与 Pre-Norm 的比较。

图 8：Post-Norm、Pre-Norm 以及 OLMo 2 风格的 Post-Norm 的比较。

2020 年，Xiong 等人表明，Pre-LN 在初始化时能得到更良好的梯度。此外，研究者还提到，Pre-LN 即使不做精细的学习率预热（warm-up）也能工作良好，而学习率预热对 Post-LN 来说是至关重要的手段。

我之所以提到这一点，是因为 OLMo 2 采用了一种 Post-LN 形式（但用的是 RMSNorm 而不是 LayerNorm，所以我称之为 _Post-Norm_）。

在 OLMo 2 中，归一化层不是放在注意力层和前馈层之前，而是放在之后，如上图所示。但请注意，与原始 Transformer 架构不同，这些归一化层仍然位于残差层（跳跃连接）内部。

那么，他们为什么要移动归一化层的位置？原因是这有助于训练稳定性，如下图所示。

图 9：Pre-Norm（如 GPT-2、Llama 3 及许多其他模型）与 OLMo 2 风格的 Post-Norm 的训练稳定性对比图。这是 OLMo 2 论文中的图（带标注），https://arxiv.org/abs/2501.00656

遗憾的是，这张图展示的是重新排序与 QK-Norm 一起使用的结果，而 QK-Norm 是另一个独立的概念。所以很难判断归一化层的重新排序本身贡献了多少。

既然上一节已经提到了 QK-norm，而后面讨论的其他 LLM（例如 Gemma 2 和 Gemma 3）也使用 QK-norm，我们就简单讨论一下它是什么。

QK-Norm 本质上就是又一个 RMSNorm 层。它被放在多头注意力（MHA）模块内部，在应用 RoPE 之前作用于查询（q）和键（k）。为了说明这一点，下面是我为 Qwen3 从零实现编写的分组查询注意力（GQA）层的一段节选（GQA 中 QK-norm 的应用方式与 OLMo 的 MHA 类似）：

```
class GroupedQueryAttention(nn.Module):
    def __init__(
        self, d_in, num_heads, num_kv_groups,
        head_dim=None, qk_norm=False, dtype=None
    ):
        # ...

        if qk_norm:
            self.q_norm = RMSNorm(head_dim, eps=1e-6)
            self.k_norm = RMSNorm(head_dim, eps=1e-6)
        else:
            self.q_norm = self.k_norm = None

    def forward(self, x, mask, cos, sin):
        b, num_tokens, _ = x.shape

        # Apply projections
        queries = self.W_query(x) 
        keys = self.W_key(x)
        values = self.W_value(x) 

        # ...

        # Optional normalization
        if self.q_norm:
            queries = self.q_norm(queries)
        if self.k_norm:
            keys = self.k_norm(keys)

        # Apply RoPE
        queries = apply_rope(queries, cos, sin)
        keys = apply_rope(keys, cos, sin)

        # Expand K and V to match number of heads
        keys = keys.repeat_interleave(self.group_size, dim=1)
        values = values.repeat_interleave(self.group_size, dim=1)

        # Attention
        attn_scores = queries @ keys.transpose(2, 3)
        # ...
```

如前所述，QK-Norm 与 Post-Norm 一起稳定了训练。注意，QK-Norm 并非 OLMo 2 发明，而是可以追溯到 2023 年的论文《Scaling Vision Transformers》。

简而言之，OLMo 2 值得注意的架构设计决策主要在于 RMSNorm 的位置：把 RMSNorm 放在注意力模块和前馈模块之后而不是之前（一种 Post-Norm 变体），以及在注意力机制内部为查询和键增加 RMSNorm（QK-Norm）。两者结合起来有助于稳定训练损失。

下图进一步把 OLMo 2 和 Llama 3 并排比较。可以看到，除了 OLMo 2 仍使用传统的 MHA 而不是 GQA 之外，两者的架构相对相似。（不过，OLMo 2 团队在 3 个月后发布了一个使用 GQA 的 32B 版本。）

图 10：Llama 3 与 OLMo 2 的架构比较。

谷歌的 Gemma 模型一直都非常出色，而且我认为与 Llama 系列等其他热门模型相比，它们一直有点被低估了。

Gemma 的一个显著特点是词表相当大（以更好地支持多种语言），而且更侧重 27B 这个规模（而不是 8B 或 70B）。不过要注意，Gemma 2 也有更小的规模：1B、4B 和 12B。

27B 这个规模恰好处在一个很理想的平衡点：它比 8B 模型强大得多，但又不像 70B 模型那样耗费资源，在我的 Mac Mini 上本地运行完全没问题。

那么，Gemma 3 还有什么有意思的地方？前面讨论过，DeepSeek V3/R1 等模型在模型规模固定的情况下，使用混合专家（MoE）架构来降低推理时的内存需求。（后面要讨论的其他几个模型也用了 MoE 方法。）

Gemma 3 则用了另一个“技巧”来降低计算成本，即滑动窗口注意力（sliding window attention）。

借助滑动窗口注意力（最初由 2020 年的 LongFormer 论文提出，Gemma 2 也已经用过），Gemma 3 团队大幅降低了 KV 缓存的内存需求，如下图所示。

图 11：Gemma 3 论文（https://arxiv.org/abs/2503.19786）中的图（带标注），展示了滑动窗口注意力带来的 KV 缓存内存节省。

那么，什么是滑动窗口注意力？如果把常规自注意力看作一种 _全局_ 注意力机制（因为每个序列元素都能访问其他所有序列元素），那么滑动窗口注意力就可以看作 _局部_ 注意力，因为它把上下文范围限制在当前查询位置附近。如下图所示。

图 12：常规注意力（左）与滑动窗口注意力（右）的比较。

请注意，滑动窗口注意力既可以和多头注意力一起使用，也可以和分组查询注意力一起使用；Gemma 3 用的是分组查询注意力。

如上所述，滑动窗口注意力也被称为 _局部_ 注意力，因为局部窗口围绕当前查询位置并随之移动。相比之下，常规注意力是 _全局_ 的，因为每个 token 都能访问其他所有 token。

正如上面简要提到的，前代架构 Gemma 2 之前也使用过滑动窗口注意力。Gemma 3 的不同之处在于调整了全局（常规）注意力与局部（滑动）注意力之间的比例。

例如，Gemma 2 使用一种混合注意力机制，以 1:1 的比例组合滑动窗口（局部）注意力和全局注意力。每个 token 可以关注附近 4k token 窗口内的上下文。

Gemma 2 是每隔一层使用一次滑动窗口注意力，而 Gemma 3 现在的比例是 5:1，即每 5 个滑动窗口（局部）注意力层才有 1 个完整注意力层；此外，滑动窗口的大小也从 4096（Gemma 2）缩小到仅 1024（Gemma 3）。这让模型的重心转向更高效、更局部化的计算。

根据他们的消融研究，使用滑动窗口注意力对建模性能的影响微乎其微，如下图所示。

图 13：Gemma 3 论文（https://arxiv.org/abs/2503.19786）中的图（带标注），表明滑动窗口注意力对 LLM 生成输出的困惑度几乎没有影响。

虽然滑动窗口注意力是 Gemma 3 最值得注意的架构特点，但作为前面 OLMo 2 一节的延续，我还想简单讲讲归一化层的位置。

一个小而有趣的细节是：Gemma 3 在其分组查询注意力模块周围同时以 Pre-Norm 和 Post-Norm 的方式使用 RMSNorm。

这和 Gemma 2 类似，但仍值得强调，因为它不同于：（1）原始 Transformer（《Attention is all you need》）中使用的 Post-Norm；（2）由 GPT-2 推广、之后被许多其他架构采用的 Pre-Norm；（3）我们前面看到的 OLMo 2 风格的 Post-Norm。

图 14：OLMo 2 与 Gemma 3 的架构比较；注意 Gemma 3 中额外的归一化层。

我认为这种归一化层的布置是一种相对直观的做法，因为它兼得了 Pre-Norm 和 Post-Norm 两者之长。在我看来，多一点归一化没有坏处。最坏的情况下，如果额外的归一化是多余的，也只是因为冗余而带来一点低效。而实际上，由于 RMSNorm 在整体上相对廉价，这不应该有任何明显影响。

Gemma 3 是一个表现出色的开放权重 LLM，在我看来，它在开源圈子里有点被低估了。最有意思的部分是使用滑动窗口注意力来提升效率（将来把它和 MoE 结合起来会很有意思）。

此外，Gemma 3 的归一化层布置也很独特：在注意力模块和前馈模块之前和之后都放置了 RMSNorm 层。

Gemma 3 发布几个月后，谷歌推出了 Gemma 3n。这是一个针对小型设备效率优化过的 Gemma 3 模型，目标是在手机上运行。

Gemma 3n 为提升效率所做的改动之一是所谓的逐层嵌入（Per-Layer Embedding，PLE）参数层。其核心思想是只把模型参数的一个子集保留在 GPU 内存中。与 token 层相关的特定嵌入（例如文本、音频和视觉模态的嵌入）则按需从 CPU 或 SSD 流式加载。

下图展示了 PLE 带来的内存节省，其中标准 Gemma 3 模型列出的参数量是 54.4 亿。这很可能指的是 Gemma 3 的 40 亿参数版本。

图 15：谷歌 Gemma 3n 博客（https://developers.googleblog.com/en/introducing-gemma-3n/）中的图（带标注），展示了 PLE 的内存节省。

54.4 亿和 40 亿参数之间的差异，源于谷歌报告 LLM 参数量的一种有趣方式。他们通常会排除嵌入参数，让模型显得更小；只有在像这样的场合，把嵌入参数算进去能让模型显得更大时，才会把它们算进去。这并非谷歌独有，这种做法已经成为整个领域的普遍惯例。

另一个有趣的技巧是 MatFormer 概念（Matryoshka Transformer，即“套娃 Transformer”的缩写）。例如，Gemma 3n 使用单一的共享 LLM（Transformer）架构，可以切分成更小的、可独立使用的模型。每个切片都经过训练、能够单独工作，因此在推理时，我们可以只运行需要的那部分（而不是整个大模型）。

Mistral Small 3.1 24B 于 3 月发布，就在 Gemma 3 之后不久。它值得注意之处在于，在多项基准上（数学除外）超越了 Gemma 3 27B，而且速度更快。

Mistral Small 3.1 的推理延迟低于 Gemma 3，原因很可能在于其定制的分词器，以及缩小了 KV 缓存和层数。除此之外，它是一个标准架构，如下图所示。

图 16：Gemma 3 27B 与 Mistral 3.1 Small 24B 的架构比较。

有趣的是，早期的 Mistral 模型曾使用滑动窗口注意力，但如果看官方 Model Hub 配置文件中的默认设置（`“sliding_window”: null`），他们在 Mistral Small 3.1 中似乎已经放弃了它。而且模型卡中也完全没有提及。

所以，由于 Mistral 使用的是常规分组查询注意力，而不是像 Gemma 3 那样带滑动窗口的分组查询注意力，或许能因此使用更优化的代码（即 FlashAttention）而进一步节省推理计算。例如，我推测，滑动窗口注意力虽然降低了内存占用，却不一定能降低推理延迟，而推理延迟恰恰是 Mistral Small 3.1 所关注的。

本文前面对混合专家（MoE）所做的大篇幅介绍再次派上了用场。Llama 4 也采用了 MoE 方法，其余部分则遵循一个相对标准的架构，与 DeepSeek V3 非常相似，如下图所示。（Llama 4 具备原生多模态支持，与 Gemma、Mistral 等模型类似。不过由于本文聚焦于语言建模，我们只关注文本模型。）

图 17：DeepSeek V3（6710 亿参数）与 Llama 4 Maverick（4000 亿参数）的架构比较。

虽然 Llama 4 Maverick 的架构总体上看起来与 DeepSeek V3 非常相似，但也有一些值得强调的有趣差异。

首先，Llama 4 和它的前代一样使用分组查询注意力，而 DeepSeek V3 使用我们在本文开头讨论过的多头潜在注意力。DeepSeek V3 和 Llama 4 Maverick 都是非常大的架构，其中 DeepSeek V3 的总参数量大约多出 68%。然而，DeepSeek V3 有 370 亿激活参数，是 Llama 4 Maverick（170 亿）的两倍多。

与 DeepSeek V3（9 个激活专家，每个隐藏层大小为 2,048）相比，Llama 4 Maverick 使用了一种更经典的 MoE 设置，专家更少但更大（2 个激活专家，每个隐藏层大小为 8,192）。此外，DeepSeek 在每个 Transformer 块中都使用 MoE 层（前 3 个除外），而 Llama 4 则每隔一个 Transformer 块交替使用 MoE 模块和稠密模块。

鉴于各架构之间存在许多细小差异，很难确定它们对最终模型性能的确切影响。不过主要的结论是，MoE 架构在 2025 年人气大涨。

Qwen 团队一直在持续推出高质量的开放权重 LLM。我记得在协助指导 NeurIPS 2023 的 LLM 效率挑战赛时，排名靠前的获胜方案全都基于 Qwen2。

如今，Qwen3 又是一个在各自规模级别排行榜上名列前茅的爆款模型系列。它有 7 个稠密模型：0.6B、1.7B、4B、8B、14B 和 32B。还有 2 个 MoE 模型：30B-A3B 和 235B-A22B。

（顺便说一句，“Qwen3”中没有空格并不是笔误；我只是尽量保留 Qwen 开发者选择的原始拼写。）

我们先讨论稠密模型的架构。截至撰写本文时，0.6B 模型很可能是目前最小的当代开放权重模型。根据我的个人经验，就其小巧的体量而言，它的表现非常好。如果你打算本地运行，它的 token/秒吞吐量很高，内存占用也很低。更重要的是，由于体量小，它也很容易在本地训练（用于教学目的）。

所以，对我来说，Qwen3 0.6B 在大多数用途上已经取代了 Llama 3 1B。下面是这两种架构的比较。

如前所述，Qwen3 还有两个 MoE 版本：30B-A3B 和 235B-A22B。为什么有些架构（如 Qwen3）会同时提供常规（稠密）和 MoE（稀疏）两种版本？

正如本文开头提到的，MoE 版本有助于降低大型基础模型的推理成本。同时提供稠密和 MoE 版本，能让用户根据自己的目标和约束灵活选择。

稠密模型通常在微调、部署以及在各种硬件上优化方面更直截了当。

另一方面，MoE 模型针对推理的扩展进行了优化。例如，在固定的推理预算下，它们可以实现更高的整体模型容量（即因体量更大而在训练中吸收更多知识），而推理成本不会成比例地增加。

通过同时发布两种类型，Qwen3 系列可以支持更广泛的用例：稠密模型用于稳健性、简洁性和微调，MoE 模型用于大规模高效部署。

作为本节的收尾，我们把 Qwen3 235B-A22B（注意 A22B 代表“220 亿激活参数”）与 DeepSeek V3 比较一下，后者的激活参数（370 亿）几乎是前者的两倍。

图 19：DeepSeek V3 与 Qwen3 235B-A22B 的架构比较。

如上图所示，DeepSeek V3 和 Qwen3 235B-A22B 的架构惊人地相似。不过值得注意的是，Qwen3 模型不再使用共享专家（早期的 Qwen 模型，例如 Qwen2.5-MoE，确实使用了共享专家）。

遗憾的是，Qwen3 团队没有透露放弃共享专家的原因。如果非要我猜，也许是当他们把专家数从 2 个（Qwen2.5-MoE）增加到 8 个（Qwen3）时，共享专家对于他们这套设置的训练稳定性已经不再必要。于是他们只用 8 个专家而不是 8+1 个，从而省下额外的计算和内存成本。（不过这无法解释为什么 DeepSeek V3 仍然保留了共享专家。）

**更新：**Qwen3 的开发者之一林俊旸（Junyang Lin）回应如下：

> 当时我们没有发现共享专家带来足够显著的提升，而且我们担心共享专家会给推理优化带来问题。老实说，这个问题没有直接的答案。

如下面的架构比较图所示，SmolLM3 的架构看起来相当标准。不过它最有意思的地方或许是使用了 NoPE（No Positional Embeddings，无位置嵌入）。

图 21：Qwen3 4B 与 SmolLM3 3B 的并排架构比较。

在 LLM 领域，NoPE 是一个较早的想法，可以追溯到 2023 年的一篇论文（《The Impact of Positional Encoding on Length Generalization in Transformers》），其做法是去掉显式的位置信息注入（例如早期 GPT 架构中经典的绝对位置嵌入层，或如今的 RoPE）。

在基于 Transformer 的 LLM 中，位置编码通常是必要的，因为自注意力对 token 的处理与顺序无关。绝对位置嵌入通过增加一个额外的嵌入层、把信息加到 token 嵌入上来解决这个问题。

图 22：改编自我的《Build A Large Language Model (From Scratch)》一书（https://www.amazon.com/Build-Large-Language-Model-Scratch/dp/1633437167）的图，展示了绝对位置嵌入。

而 RoPE 则通过根据 token 的位置旋转查询向量和键向量来解决这个问题。

但在 NoPE 层中，根本不添加任何这样的位置信号：既没有固定的，也没有学习得到的，也没有相对的。什么都没有。

即使没有位置嵌入，得益于因果注意力掩码，模型仍然知道哪些 token 在前面。这个掩码阻止每个 token 关注未来的 token。因此，位置 _t_ 上的 token 只能看到位置 _≤ t_ 的 token，从而保留了自回归的顺序。

所以，虽然没有显式添加位置信息，模型结构中仍然隐含着一种方向感；在常规的基于梯度下降的训练中，如果 LLM 发现利用它对优化目标有益，就可以学会利用它。（更多信息请参阅 NoPE 论文中的定理。）

总的来说，NoPE 论文不仅发现无需注入位置信息，还发现 NoPE 具有更好的长度泛化能力，也就是说，随着序列长度增加，LLM 的回答性能下降得更少，如下图所示。

图 23：NoPE 论文（https://arxiv.org/abs/2305.19466）中的图（带标注），显示 NoPE 有更好的长度泛化能力。

注意，上面展示的实验是在一个约 1 亿参数、相对较小的 GPT 风格模型上、以相对较小的上下文长度进行的。这些发现能在多大程度上推广到更大的当代 LLM 上，目前尚不清楚。

因此，SmolLM3 团队很可能只在每第 4 层“应用”了 NoPE（或者说省略了 RoPE）。

Kimi K2 最近在 AI 社区掀起了巨浪，因为它是一个性能好得惊人的开放权重模型。根据基准测试，它与谷歌的 Gemini、Anthropic 的 Claude 和 OpenAI 的 ChatGPT 等最好的专有模型不相上下。

一个值得注意的方面是，它使用了相对较新的 Muon 优化器的一个变体，而不是 AdamW。据我所知，这是 Muon 首次在如此规模的生产级模型上替代 AdamW（此前它只被证明能扩展到 16B）。这带来了非常漂亮的训练损失曲线，很可能帮助这个模型一举登上了上述基准测试的榜首。

虽然有人评论说损失曲线异常平滑（因为没有尖峰），但我认为它并不算异常平滑（例如，看看下图中 OLMo 2 的损失曲线；另外，梯度的 L2 范数可能是追踪训练稳定性更好的指标）。不过，损失曲线下降得如此之好，确实令人瞩目。

然而，正如本文引言所说，训练方法是以后再谈的话题。

而且这也算是绕了一圈回到原点：Kimi K2 使用的正是我们在本文开头介绍的 DeepSeek V3 架构，只不过把它做得更大了，如下图所示。

另一方面，gpt-oss 是一个宽得多的架构：

* 嵌入维度为 2880，而不是 2048
* 专家（前馈）中间投影维度同样为 2880，而不是 768

还值得注意的是，gpt-oss 使用的注意力头数是两倍，但这并不会直接增加模型的宽度。宽度由嵌入维度决定。

在参数量固定的情况下，哪种做法更有优势？经验法则是，更深的模型灵活性更高，但由于梯度爆炸和梯度消失导致的不稳定问题（RMSNorm 和捷径连接正是为缓解这些问题），可能更难训练。

更宽的架构则有推理更快的优势（token/秒吞吐量更高），因为并行化更好，代价是更高的内存开销。

至于建模性能，遗憾的是，据我所知，并没有很好的同条件对比（即保持参数规模和数据集不变），唯一的例外是 Gemma 2 论文（表 9）中的一项消融研究。该研究发现，对于一个 90 亿参数的架构，较宽的设置略好于较深的设置。在 4 项基准上，较宽的模型平均得分为 52.0，较深的模型平均得分为 50.8。

如上面图 27 所示，同样值得注意的是，gpt-oss 的专家数量少得出奇（32 个而不是 128 个），并且每个 token 只使用 4 个激活专家而不是 8 个。不过，每个专家都比 Qwen3 中的专家大得多。

这很有意思，因为近期的趋势和进展都表明，更多、更小的专家（原文为 models）更有益。在总参数量不变的情况下的这种变化，在 DeepSeekMoE 论文的下面图 28 中有很好的展示。

你可能注意到的另一个细节是图 30 代码截图中 `sinks` 的定义。在一般的模型中，注意力汇聚点（attention sinks）是放在序列开头、“始终被关注”的特殊 token，用于稳定注意力，这在长上下文场景中尤其有用。也就是说，如果上下文变得很长，开头这个被特殊关注的 token 仍然会被关注，并且它可以学会存储一些关于整个序列的普遍有用信息。（我认为它最初是在论文《Efficient Streaming Language Models with Attention Sinks》中提出的。）

在 gpt-oss 的实现中，_注意力汇聚点_ 并不是输入序列中的真实 token。它们是按头学习的偏置 logits，被附加到注意力分数上（图 31）。目标与上面提到的注意力汇聚点相同，但不需要修改分词后的输入。

我觉得值得把它纳入进来，因为 Grok 2.5 是 xAI 去年的旗舰生产模型。到目前为止，我们讨论的所有模型从一开始就是作为开放权重模型发布的。例如，gpt-oss 很可能不是 GPT-4 的开放权重克隆，而是专门为开源社区训练的定制模型。

借助 Grok 2.5，我们难得地看到了一个真实的生产系统，哪怕是去年的。

从架构上看，Grok 2.5 总体相当标准（图 32），但有几个值得注意的细节。

图 32：Grok 2.5 与规模相当的 Qwen3 模型并列

例如，Grok 2.5 使用少量大型专家（8 个），这反映了较早的趋势。如前所述，较新的设计（例如 DeepSeekMoE 论文中的设计）倾向于使用数量更多、规模更小的专家（Qwen3 中也是如此）。

另一个有趣的选择是使用了相当于共享专家的结构。图 32 左侧所示的额外 SwiGLU 模块起到了一个始终开启的共享专家的作用。它与经典的共享专家设计并不完全相同，因为它的中间维度翻了一倍，但思路是一样的。（我仍然觉得 Qwen3 省略共享专家这件事很有意思，看看 Qwen4 及之后的模型是否会改变这一点也会很有意思。）

GLM-4.5 是今年的另一个重要发布。

它是一个与 Qwen3 类似的指令/推理混合模型，但针对函数调用和智能体式场景做了更好的优化。

图 33：官方 GitHub 仓库 https://github.com/zai-org/GLM-4.5 中的 GLM-4.5 基准测试

如图 34 所示，GLM-4.5 有两个版本。旗舰版 3550 亿参数模型在 12 项基准上的平均表现超过 Claude 4 Opus，仅略逊于 OpenAI 的 o3 和 xAI 的 Grok 4。还有 GLM-4.5-Air，一个更紧凑的 1060 亿参数版本，性能只比 3550 亿参数模型略低一点。

图 35 把 3550 亿参数的架构与 Qwen3 进行了比较。

图 34：GLM-4.5 与规模相近的 Qwen3 模型并列。

两者的设计大体相似，但 GLM-4.5 采用了 DeepSeek V3 首先引入的一种结构选择：在混合专家（MoE）块之前放置 3 个稠密层。为什么？在大型 MoE 系统中，先用几个稠密层开头可以提升收敛稳定性和整体性能。如果一开始就引入 MoE 路由，稀疏专家选择的不稳定性可能会干扰早期的句法和语义特征提取。所以可以说，让最初几层保持稠密，能确保模型在路由决策开始塑造更高层处理之前，先形成稳定的底层表示。

此外，GLM-4.5 像 DeepSeek V3 一样使用了共享专家（这一点与 Qwen3 不同）。

（有趣的是，GLM-4.5 还保留了 GPT-2 和 gpt-oss 中使用的注意力偏置机制。）

2025 年 9 月 11 日，Qwen3 团队发布了 Qwen3 Next 80B-A3B（图 35），提供 Instruct 和 Thinking 两个版本。虽然它的设计建立在前面讨论过的 Qwen3 架构之上，但我把它作为单独一节列在这里，以保持图片编号一致，并让大家注意它的一些设计改动。

新的 Qwen3 Next 架构之所以引人注目，是因为尽管它比之前的 235B-A22B 模型小 3 倍（图 35），却引入了四倍的专家数量，甚至还加入了一个共享专家。这两项设计选择（大量专家和加入共享专家）都是我在这次发布之前就强调过的未来方向，尤其是在我放在文章开头的那个视频版本中。

图 35：5 月发布的原版 Qwen3 模型（左）与 9 月发布的 Qwen3 Next 模型（右）并列。

另一个亮点是，他们用 Gated DeltaNet（门控 DeltaNet）+ Gated Attention（门控注意力）的混合结构取代了常规注意力机制，这在内存占用方面帮助实现了原生 262k token 的上下文长度（之前的 235B-A22B 模型原生支持 32k，借助 YaRN 扩展可支持 131k）。

那么这种新的混合注意力是怎么工作的？分组查询注意力（GQA）仍然是标准的缩放点积注意力（如前所述，它在查询头组之间共享 K/V，以减小 KV 缓存的大小和内存带宽，但其解码成本和缓存仍会随序列长度增长）。与之相比，他们的混合机制以 3:1 的比例混合 _Gated DeltaNet_ 块和 _Gated Attention_ 块，如图 36 所示。

我们可以把门控注意力块看作可用于 GQA 的标准缩放点积注意力，只是在其上做了一些调整。_门控注意力_ 与普通 GQA 块的主要区别在于：

1. 一个输出门（由 sigmoid 控制，通常按通道），在注意力结果加回残差之前对其进行缩放；
2. QKNorm 使用零中心化的 RMSNorm，而不是标准 RMSNorm；
3. 部分 RoPE（只作用于一部分维度）。

注意，这些本质上只是对 GQA 的稳定性改动。

Gated DeltaNet 则是一个更重大的改动。在 DeltaNet 块中，q、k、v 和两个门（α、β）由带归一化的线性层和轻量卷积层产生，并且该层用一种快速权重（fast-weight）的 _delta 规则_ 更新取代了注意力。

不过，代价是 DeltaNet 提供的基于内容的检索不如完整注意力精确，这就是为什么还保留了一个门控注意力层。

鉴于注意力的开销呈二次增长，加入 DeltaNet 组件是为了提升内存效率。在“线性时间、无缓存”这一类方法中，DeltaNet 块本质上是 Mamba 的一种替代方案。Mamba 用一个学习得到的状态空间滤波器（本质上是一种随时间的动态卷积）来维护状态。DeltaNet 则维护一个很小的快速权重记忆，用 α 和 β 更新它，并用 q 读取它，小卷积只用于帮助生成 q、k、v、α、β。

上面两个小节描述了两项面向效率的设计决策。既然好事成三，Qwen3 还在此基础上加了另一种效率技术：多 token 预测（Multi-Token Prediction，MTP）。

（注意，DeepSeek V3 和 V3.2，以及后来的 GLM-4.5 和 MiniMax-M2，都在训练中使用了 MTP；但由于它是一种训练技术，我没有在架构比较中明确讨论它。）

多 token 预测训练 LLM 在每一步预测多个未来 token，而不是只预测一个。具体来说，在每个位置 _t_，几个小的额外头（线性层）输出 _t+1...t+k_ 的 logits，并把这些偏移位置的交叉熵损失相加（在 MTP 论文中，研究者推荐 _k=4_）。这个额外信号能加快训练，而推理时仍可以一次生成一个 token。不过，这些额外的头也可以用于推测式多 token 解码，Qwen3-Next 似乎正是这么做的，只是细节仍然不多：

> Qwen3-Next 引入了原生的多 token 预测（MTP）机制，这不仅产生了一个在推测解码中接受率很高的 MTP 模块，还提升了整体性能。此外，Qwen3-Next 专门优化了 MTP 的多步推理性能，通过保持训练与推理一致的多步训练，进一步提高了推测解码在真实场景中的接受率。来源：Qwen3-Next 博客文章

2026 年 2 月初，Qwen3 团队发布了 80B 的 Qwen3-Coder-Next 模型（激活参数 3B）。它在编程任务上超越了 DeepSeek V3.2（激活 37B）以及 Kimi K2.5 和 GLM-7.5（均为激活 32B）等大得多的模型，因而成为头条新闻。

此外，Qwen3-Coder-Next 在 SWE-Bench Pro 上的表现与 Claude-Sonnet-4.5 大致相当（仅略低于 Claude-Opus-4.5），对一个开放权重模型来说这令人印象深刻！

注意，Qwen3-Coder-Next 背后的架构与我们上面讨论的 Qwen3-Next 80B 完全相同（事实上，他们正是以 Qwen3-Next 作为基础模型来训练 Qwen3-Coder-Next 的）。由于这是一篇关于 LLM 架构的文章，训练细节不在讨论范围内。不过，感兴趣的读者可以在他们发布在 GitHub 上的详细技术报告中找到更多信息。

最近，开放权重 LLM 的开发者们推出了一些针对效率优化的核心架构变体。一个例子是 Qwen3-Next（见上一节），它用快速的门控 DeltaNet 模块替换了部分完整注意力块。另一个例子是 DeepSeek V3.2，它使用稀疏注意力，这是一种以部分建模性能换取更好计算性能的线性注意力变体（我计划在后续文章中更详细地介绍这一机制）。

MiniMax-M1 与上述模型属于类似的类别，它使用一种线性注意力变体（闪电注意力，lightning attention），比常规（完整）注意力效率更高。我最初没有介绍 MiniMax M1，因为它不像这里讨论的其他一些模型那么受欢迎。然而，他们新发布的 MiniMax-M2 目前被认为是最好的开放权重模型（根据基准性能），这让它分量太重，无法忽视。

图 37：MiniMax-M2 与其他热门开放权重和专有 LLM 的基准性能比较。图片来自官方 Model Hub 发布的 readme 文件。

如下面的概览图所示，我把 MiniMax-M2 与其他解码器式 Transformer LLM 归为一组，因为它没有使用 MiniMax-M1 中提出的高效闪电注意力变体。相反，开发者回归使用完整注意力，很可能是为了提升建模（以及基准测试）性能。

图 38：本文涵盖的主要 LLM 的时间线，旁边是一些混合注意力模型，它们构成了更高效的替代方案，以部分建模性能换取更高效率。

总体而言，MiniMax-M2 与 Qwen3 惊人地相似。除了改变层数、尺寸等之外，它总体上使用了相同的组件。

这里或许唯一值得注意的亮点是，MiniMax-M2 使用了一种所谓的 “per_layer”（逐层）QK-Norm，而不是常规的 QK-Norm。仔细看代码会发现，它在注意力机制内部是这样实现的：

```
self.q_norm = MiniMaxText01RMSNormTP(self.head_dim * self.total_num_heads, eps=...)

self.k_norm = MiniMaxText01RMSNormTP(self.head_dim * self.total_num_kv_heads, eps=...)
```

这里，`hidden_size` 等于拼接后的所有头（`num_heads * head_dim`），所以这个 RMSNorm 的缩放向量对每个头（以及每个头的每一维）都有各自不同的参数。

所以，“`per_layer`”的意思是，RMSNorm（如前所述用于 QK-Norm）在每个 Transformer 块中定义（与常规 QK-Norm 一样），但除此之外，它不是在各注意力头之间复用，而是每个注意力头都有独特的 QK-Norm。

模型配置文件中也包含一个滑动窗口注意力设置（与第 3 节的 Gemma 3 类似），但和 Mistral 3.1（第 4 节讨论过）一样，默认是禁用的。

除此之外，除了逐层 QK-Norm，这个架构与 Qwen3 非常相似，如下图所示。

图 39：Qwen3 与 MiniMax-M2 的比较。

其他有趣的细节（如下图所示）包括：它们没有使用共享专家（与 Qwen3 类似，但与 Qwen3-Next 不同）。如前所述，在我看来，共享专家是有用的，因为它们减少了其他专家之间的冗余。

此外，从上图可以明显看出，MiniMax-M2 的“稀疏”程度是 Qwen3 的两倍。也就是说，在与 Qwen3 235B-A22B 大致相同的规模下，MiniMax-M2 每个 token 只有 100 亿而不是 220 亿激活参数（即 MiniMax-M2 每个推理步骤使用 4.37% 的参数，而 Qwen3 使用 9.36%）。

最后，与 MiniMax-M1 类似，MiniMax-M2 在注意力模块内部使用“部分”RoPE 而不是常规 RoPE 来编码位置信息。与常规 RoPE 一样，旋转是在应用 QK-Norm 之后作用于查询和键的。

这里的部分 RoPE 是指每个头只有前 `rotary_dim` 个通道获得旋转位置编码，其余 `head_dim - rotary_dim` 个通道保持不变。

在官方 M1 的 README 文件中，开发者提到：

> 旋转位置嵌入（RoPE）应用于注意力头维度的一半，基础频率为 10,000,000

我们可以这样想象：

```
Full RoPE:     [r r r r r r r r]
Partial RoPE:  [r r r r — — — —]
```

在上面这个概念示意图中，“r”表示被旋转（经过位置编码）的维度，短横线表示未被改动的维度。

这样做的意义何在？在 M1 论文中，开发者表示：

> ……在 softmax 注意力维度的一半上实施 RoPE，可以在不降低性能的情况下实现长度外推。

我的推测是，这可以防止长序列，尤其是比训练数据集中最长文档还长的序列，发生“过多”的旋转。也就是说，这里的理由可能是：不旋转要好过一个模型在训练中从未见过的“糟糕”或“过于极端”的旋转。

最近，为了提升 LLM 的效率，线性注意力机制出现了复兴。

论文《Attention Is All You Need》（2017）中提出的注意力机制，也就是缩放点积注意力，至今仍是当今 LLM 中最流行的注意力变体。除了传统的多头注意力，它还被用于更高效的变体中，例如分组查询注意力、滑动窗口注意力和多头潜在注意力。

原始注意力机制的开销随序列长度呈二次方增长：

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V $$

这是因为查询（Q）、键（K）和值（V）都是 _n_×_d_ 的矩阵，其中 _d_ 是嵌入维度（一个超参数），_n_ 是序列长度（即 token 的数量）。

关于注意力的更多细节，可以参阅我的另一篇文章。

图 40：注意力中由序列长度 _n_ 导致的二次方开销示意图。

线性注意力变体已经存在很久了，我记得在 2020 年代看过大量相关论文。例如，我记得最早的之一是 2020 年的论文《Transformers are RNNs: Fast Autoregressive Transformers with Linear Attention》，研究者在其中对注意力机制做了如下近似：

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V \approx \phi(Q)\big(\phi(K)^\top V\big)$$

这里，φ(·) 是一个核特征函数，设为 φ(x) = elu(x) + 1。

这种近似之所以高效，是因为它避免了显式计算 n \times n 的注意力矩阵 QK^T，从而不必执行所有成对的 token 交互（那需要 O(n^2d) 的时间和内存）。

我不想在这些较早的尝试上停留太久。但其要点是，它们把时间和内存复杂度都从 O(n^2) 降到了 O(n)，使注意力在长序列上高效得多。

然而，它们从未真正流行起来，因为会降低模型精度，而且我从未见过哪个开放权重的最先进 LLM 真正采用过这些变体。

今年下半年，线性注意力变体出现了一点复兴。第一个值得注意的模型是 6 月发布的 MiniMax-M1，它使用闪电注意力，是一个 4560 亿参数、460 亿激活参数的混合专家（MoE）模型。

接着，8 月，Qwen3 团队推出了 Qwen3-Next，我在上面已经较详细地讨论过。然后在 9 月，DeepSeek 团队发布了 DeepSeek V3.2。这三个模型（MiniMax-M1、Qwen3-Next、DeepSeek V3.2）都在大部分或全部层中，用高效的线性变体取代了传统的二次方注意力变体。

有趣的是，最近出现了一个剧情反转：MiniMax 团队发布了新的 2300 亿参数 M2 模型（在第 13 节讨论过），没有使用线性注意力，而是回归常规注意力。该团队表示，线性注意力在生产级 LLM 中很棘手。它在普通提示上似乎表现不错，但在推理和多轮任务上精度很差，而这些任务不仅对普通聊天会话很重要，对智能体应用也很重要。

这本可能成为一个转折点：线性注意力也许终究不值得追求。然而事情变得更有意思了。10 月，Kimi 团队发布了采用线性注意力的新模型 Kimi Linear。

图 41：线性注意力混合架构概览。

附注：我本可以在概览图中把 Qwen3-Next 和 Kimi Linear 与其他 Transformer–状态空间模型（SSM）混合架构归为一组。我个人把那些 Transformer-SSM 混合架构看作带有 Transformer 组件的 SSM，而把这里讨论的模型（Qwen3-Next 和 Kimi Linear）看作带有 SSM 组件的 Transformer。不过，既然我已经把 IBM Granite 4.0 和 NVIDIA Nemotron Nano 2 列在 Transformer-SSM 那一栏，也有理由把它们归入同一类。

Kimi Linear 与 Qwen3-Next 在结构上有若干相似之处。两个模型都依赖混合注意力策略。具体来说，它们把轻量的线性注意力与较重的完整注意力层结合起来。两者都采用 3:1 的比例，即每三个采用线性 Gated DeltaNet 变体的 Transformer 块，就有一个使用完整注意力的块，如下图所示。

图 42：Qwen3-Next 与 Kimi Linear 并列。

Gated DeltaNet 是一种受循环神经网络启发的线性注意力变体，其中包括来自论文《Gated Delta Networks: Improving Mamba2 with Delta Rule》的门控机制。从某种意义上说，Gated DeltaNet 就是带有 Mamba 风格门控的 DeltaNet，而 DeltaNet 是一种线性注意力机制。由于本文是概览性质，DeltaNet 将来很适合单独写一篇文章。

注意，上图 Kimi Linear 部分中省略 RoPE 方框是有意为之。Kimi 在多头潜在注意力（MLA）层（全局注意力）中使用 NoPE（无位置嵌入）。正如作者所说，这让 MLA 在推理时可以作为纯粹的多查询注意力运行，并避免为长上下文扩展重新调整 RoPE（位置偏置据称由 Kimi Delta Attention 块来处理）。关于 MLA 以及多查询注意力（分组查询注意力的一个特例）的更多信息，请参阅我的《The Big LLM Architecture Comparison》一文。

**此外，我在这里更详细地写了 Gated DeltaNet。**

Kimi Linear 用 Kimi Delta Attention（KDA）机制修改了 Qwen3-Next 的线性注意力机制，KDA 本质上是 Gated DeltaNet 的一种改进。Qwen3-Next 使用标量门（每个注意力头一个值）来控制记忆衰减速率，而 Kimi Linear 将其替换为针对每个特征维度的逐通道门控。据作者介绍，这对记忆的控制更精细，进而提升了长上下文推理能力。

此外，对于完整注意力层，Kimi Linear 把 Qwen3-Next 的门控注意力层（本质上是带输出门控的标准多头注意力层）换成了多头潜在注意力（MLA）。这与我们前面在 DeepSeek V3/R1 一节讨论的 MLA 机制相同，只是多了一个门。（回顾一下，MLA 压缩键/值空间以减小 KV 缓存的大小。）

没有与 Qwen3-Next 的直接比较，但与 Gated DeltaNet 论文中的 Gated DeltaNet-H1 模型（本质上是带滑动窗口注意力的 Gated DeltaNet）相比，Kimi Linear 在保持相同 token 生成速度的同时取得了更高的建模精度。

图 43：Kimi Linear 论文中的图（带标注），显示 Kimi Linear 与 GatedDeltaNet 一样快，比采用多头潜在注意力的架构（如 DeepSeek V3/R1）快得多，同时基准性能更高。

此外，根据 DeepSeek-V2 论文中的消融研究，在超参数精心选择的情况下，MLA 与常规完整注意力不相上下。

而 Kimi Linear 在长上下文和推理基准上优于 MLA，这一事实让线性注意力变体对于更大的最先进模型再次显得有前途。话虽如此，Kimi Linear 有 480 亿参数，比 Kimi K2 小 20 倍。看看 Kimi 团队是否会在即将推出的 K3 模型中采用这种方法，会很有意思。

Allen AI 于 11 月 20 日发布了新的 Olmo 3 7B 和 32B 模型。（官方拼写已从 OLMo 改为 Olmo，所以本节我也采用这一写法。）

如前所述，Olmo 模型总是很有意思，因为它们完全开源。这意味着团队还公开了详细的训练报告、多个检查点、训练数据信息等等。换句话说，Olmo 模型是完全透明的。

这一次，Olmo 套件除了基础模型和指令模型之外，还增加了推理模型版本，而且 Olmo 3 的技术报告中有大量有关训练的有趣细节。不过，由于这是一篇关于架构比较的文章，本节只关注 Olmo 3 的架构。

最适合与 Olmo 3 比较的模型是 Qwen3，因为 Qwen3 系列有两个规模相近的模型，性能也相近。

首先来看两者中较小的 Olmo 3 7B。

可以看到，Olmo 3 的架构与 Qwen3 相对相似。但值得注意的是，这本质上很可能是受其前代 Olmo 2 启发，而不是受 Qwen3 启发。

图 45：Olmo 3 32B 与 Qwen3 32B 并列。

总体上，这是同一个架构，只是放大了规模。而且各种比例（例如前馈层中从输入维度到中间维度的扩展等）也与 Qwen3 大致吻合。

我猜，由于词表较小，这个架构最初比 Qwen3 稍小，于是他们把中间维度的扩展倍数从 Qwen 3 的 5 倍提高到 Olmo 3 的 5.4 倍，以得到一个可以直接比较的 32B 模型。

在 Qwen3 中，YaRN 是可选的，用于把原生上下文从 32k token 扩展到 131k token。

本文并不是对所有 LLM 的详尽罗列。为了控制篇幅，我只关注主要亮点。这里的“亮点”是指它们要么非常受欢迎，要么表现非常好，要么有一个有趣的架构组件。

话虽如此，终于是时候把 NVIDIA 的一个模型加入这个列表了。NVIDIA 于 2025 年 12 月 15 日刚刚发布了 Nemotron 系列的最新成员 Nemotron 3。Nemotron 的好处在于，它不仅提供开放权重和技术报告，NVIDIA 还像 Olmo 3 一样公开了数据集和训练代码。

根据发布公告，Nemotron 3 有三种规模：

1. Nano（30B-A3B），
2. Super（100B），（后来更新为 120B，见第 18.1 节）
3. 以及 Ultra（500B）。

从架构上看，这些模型是一种混合专家（MoE）Mamba-Transformer 混合架构。截至撰写本文时（12 月 17 日），只有 Nano 模型作为开放权重模型发布，所以下面的讨论将聚焦于它，如下图所示。

图 51.1：Nemotron 3 Nano 模型的概要图，这是一种 Transformer-Mamba 混合架构。

如上图所示，Nemotron 3 Nano（30B-A3B）是一个 52 层的 Mamba-Transformer 混合模型，它把 Mamba-2 序列建模块与稀疏混合专家（MoE）前馈层交错排列，只在一小部分层中使用自注意力。

上图信息量很大，但简而言之，这个架构由 13 个宏块组成，每个宏块中重复着 Mamba-2 → MoE 子块，外加几个分组查询注意力层。把宏块和子块相乘，这个架构总共有 52 层。

至于 MoE 模块，每个 MoE 层包含 128 个专家，但每个 token 只激活 1 个共享专家和 6 个路由专家。

Mamba-2 层本身就需要一整篇文章来解释（也许以后再写）。但目前从概念上讲，你可以把它们看作类似于上面介绍过的 Qwen3-Next 和 Kimi-Linear 所用的 Gated DeltaNet 方法。你也可以在我的另一篇文章《Beyond Standard LLMs》中读到更多相关内容。

Gated DeltaNet 和 Mamba-2 层的相似之处在于，两者都用门控状态空间更新取代了标准注意力。这种状态空间式模块背后的思想是：维护一个持续更新的隐藏状态，并通过学习得到的门来混入新的输入。与注意力不同，它的开销随输入序列长度线性增长，而不是二次方增长。

这个架构真正令人兴奋的地方在于，与规模相近的纯 Transformer 架构相比，它的性能非常好，同时 token/秒吞吐量高得多。

总的来说，这是一个有趣的方向，在只使用少量注意力层这一点上，它比 Qwen3-Next 和 Kimi-Linear 还要极端。不过，Transformer 架构的强项之一在于它在（非常）大规模下的表现。我很想知道 Nemotron 3 Super，尤其是 Ultra，与 DeepSeek V3.2 之类的模型相比会怎样。

2026 年 3 月 11 日，NVIDIA 在 Hugging Face Hub 上以开放权重模型的形式发布了 120B 的 Super 版本，同时发布了一份不错的、专门针对 “Super” 的新技术报告。

与 Nano 模型相比，除了扩大架构规模之外，架构上主要有两处改动。

第一，Nemotron 3 Super 使用了多 token 预测（MTP），这是一种训练 LLM 在每一步预测多个未来 token 而不是单个 token 的技术。

MTP 不只用标准的下一个 token 目标训练模型，还训练它从同一位置预测多个未来 token 偏移。这提供了更丰富的训练信号，并且据 Super 报告所述，同时提升了建模质量和推理效率。

图 51.2：多 token 预测与常规下一个 token 预测的对比。（左侧子图受 MTP 论文启发。）MTP 最初只在训练时使用，推理时不用；因此，推理时间步（下方）显示的是单个下一个 token 预测。

与 MTP 的标准用法（我在上面图 51.2 中画出的那种）的一个关键区别是，Nemotron 3 Super 并不只在训练时使用它。

Nemotron 3 Super 明确地在推理时也使用 MTP，其中共享权重的 MTP 头充当原生推测解码的内部草稿模型。在生成过程中，模型可以先提出候选续写，再用主模型对其进行验证。这样无需单独的外部草稿模型就能降低推理延迟。

由于这并不完全是标准的 MTP，更准确的说法也许是：Nemotron 3 Super 使用共享权重的 MTP 来做推测解码，而不是像其他架构（例如我在这里介绍过的 Step 3.5 Flash）那样称之为 “MTP-3” 之类的名字。

与 Nano 相比的第二个主要区别是，Super 架构使用了潜在专家（latent experts），即专家在潜在空间中运作（MoE 层的输入先从 4096 维下投影到 1024 维，应用专家，然后输出再从 1024 维上投影回 4096 维）。

图 51.3：带有潜在 MoE 层、多 token 预测和 Mamba-2 混合注意力方法的 Nemotron 3 Super 120B-A12B。

在基准测试上，Nemotron 3 Super 与 Qwen3.5 122B-A10B 和 GPT-OSS 120B 不相上下，但得益于前面提到的“技巧”（MTP、潜在 MoE 和混合注意力），它的吞吐量非常出色：比 Qwen3.5 122B-A10B 快 2 倍，（就 NVFP4 版本而言）比 GPT-OSS 120B 快 2.2 倍。

图 51.4：来自 Hugging Face Hub 页面的 Nemotron 3 Super 基准比较。

有趣的是，它以 5:1 的比例将滑动窗口注意力（SWA）与全局（常规）注意力结合使用，与 Gemma 3（见第 3 节）类似。不过，它使用的滑动窗口大小要激进得多（128），比 Gemma 3（1024）小 8 倍。

距离上一次新增 LLM 架构已经有一段时间了。1 月 27 日，Arcee AI（一家此前不在我关注范围内的公司）开始在 Model Hub 上发布其开放权重的 400B Trinity Large LLM 的各个版本，以及两个较小的变体。

他们的旗舰大模型是一个 4000 亿参数的 MoE（激活参数 130 亿）。两个较小的变体是 Trinity Mini（26B，激活参数 3B）和 Trinity Nano（6B，激活参数 1B）。

图 53：Trinity Large 架构概览（基于 Model Hub 上的配置文件）。

除了模型权重，Arcee AI 还发布了一份包含大量细节的不错的技术报告。

那么，我们来仔细看看 400B 的旗舰模型。下图把它与前面讨论过的 GLM 4.5（第 11 节）进行比较，GLM 4.5 也许是与它最相似的模型，而且也相对较小。此外，Trinity 技术报告显示，Trinity Large 和 GLM-4.5 基础模型的建模性能几乎完全相同（我猜他们没有与更新的基础模型比较，是因为如今许多公司只公开微调后的模型）。

图 54：Arcee AI Trinity Large 与规模相对相近（400B 对 355B）的 GLM 4.5 并列。

但正如我们所见，Trinity 模型加入了几个有趣的架构组件。

首先，它像前面的 Gemma 3、Olmo 3、Xiaomi MiMo 等一样，交替使用局部:全局（滑动窗口）注意力层。但它没有采用 Gemma 3 和小米所用的常见 5:1 比例，而是选择了与 Olmo 3 类似的 3:1 比例，以及相对较大的 4096 滑动窗口大小（同样与 Olmo 3 类似）。

除了 QK-Norm（在第 2 节 Olmo 2 中介绍过），他们还在全局层中使用 NoPE（我们在第 7 节 SmolLM3 中讨论过 NoPE）。

他们还采用了一种门控注意力。他们没有使用完整的 GatedDeltaNet（在第 12 节讨论过），而是使用了与 Qwen3-Next 注意力机制中类似的门控。

不过，他们修改了标准注意力：在输出线性投影之前，对缩放点积的结果加入逐元素门控（如下图所示），这减少了注意力汇聚现象，并提升了长序列泛化能力。此外，这也有助于训练稳定性。

图 55：Trinity Large 在注意力机制中所用门控机制的示意图。

你可能已经注意到，在前面的 Trinity Large 架构图中使用了四个（而不是两个）RMSNorm 层。这就是他们所谓的深度缩放三明治归一化（depth-scaled sandwich norm），它基于以前的研究工作，但我此前从未在主要架构中见过。总体上，它看起来像 Gemma 3 那样的 RMSNorm 布置，但不同之处在于，（每个块中）第二个 RMSNorm 的增益是按深度缩放的，即初始化为约 1 / sqrt(L)（L 为总层数）。因此在训练初期，残差更新从很小开始，随着模型学到合适的尺度而逐渐增大。

其 MoE 是类似 DeepSeek 的、带有大量小专家的 MoE，但把粒度做得更粗了一些，因为这有助于推理吞吐量（我们在 Mistral 3 Large 采用 DeepSeek V3 架构时也看到过这种做法）。

最后，还有一些关于训练改进的有趣细节（一种新的 MoE 负载均衡策略，以及另一项使用 MuOpt 优化器的改进），但由于这是一篇架构文章，这些不在讨论范围之内。

农历新年已经出人意料地成为强势开放权重模型发布的可靠窗口期。例如，GLM-4 和 Qwen 1.5 分别在 2024 年 1 月和 2 月发布，DeepSeek R1 和 Qwen 2.5 则在 2025 年发布。

今年，z.AI（智谱 AI）于 2026 年 2 月 11 日（同样相对较早地）以 GLM-5 拉开序幕，大约在 2 月 17 日农历新年前一周。

与我在本文前面介绍的 GLM-4.5 模型（见第 11 节，2025 年夏季发布）相比，其继任者 GLM-5 的规模翻了一倍：从 3550 亿参数增加到 7440 亿，进入了 DeepSeek-V3.2 和 Kimi K2 之间的区间。

与 GLM-4.5 一样，GLM-5 也是一个混合专家（第 1.2 节）模型，每个 token 的激活参数只略有增加：GLM-5 为 400 亿，GLM-4.5 为 320 亿。

图 56：GLM-5 与 GLM-4.5 的架构并列。

有趣的是，如上面图 56 所示，GLM-5 采用了 DeepSeek 的多头潜在注意力（MLA，见第 1.1 节）以及 DeepSeek 稀疏注意力（我在《DeepSeek V3.2》一文中有更详细的介绍）。这些改动的动机是降低处理长上下文时的推理成本。

除此之外，架构相对相似。规模增大主要是因为专家更多（256 个而不是 160 个），以及层的尺寸略有增大。例如，嵌入维度和专家尺寸现在是 6,144（此前为 5,120），中间投影尺寸也从 1,536 略增到 2,048。有趣的是，层数（Transformer 块）从 92 个减少到 78 个。我猜这是为了降低推理成本、让模型更快（因为层的深度无法并行化）。

由于本文聚焦于架构，我通常不在这里放基准测试。如果把训练细节和评估都纳入进来，这篇文章的范围和篇幅会大大失控。话虽如此，我发现自己在 2025 年 7 月放过 GLM-4.5 的基准测试，所以这里再破例一次，因为这些基准测试结果看起来确实令人印象深刻，与所有主要的旗舰 LLM（GPT-5.2 extra-high、Gemini Pro 3 和 Claude 4.6 Opus）不相上下。但还是要再次强调，基准性能并不一定等于真实世界中的性能。

图 57：GLM 各架构与基准测试并列。GLM-4.7 的架构与 GLM-4.5 相似。基准测试数据取自 GLM-5 发布博客文章：https://z.ai/blog/glm-5

3 月 Nemotron 3 Super 发布之后，这个月余下的时间里旗舰级开放权重模型的发布相对平静。我还在等 DeepSeek-V4，不过 4 月至少给我们带来了谷歌的 Gemma 4。

从架构上看，Gemma 4（31B）与 Gemma 3（27B）相比几乎没有变化，如下图所示。

图 58：Gemma 3（27B）与 Gemma 4（31B）并列。

（注意，Gemma 4 现在也支持多模态，但图像编码器部分我会留到以后另写文章；这里只关注文本部分。）

从上图可以看到，Gemma 4 保留了相对独特的 Pre-norm 加 Post-norm 设置，并且仍相对经典，采用 5:1 的混合注意力机制，组合滑动窗口（局部）层和完整注意力（全局）层。注意力机制本身也是经典的分组查询注意力（GQA）。

不过，相对 Gemma 3 有一个容易被忽视的小改动：在全局（完整）注意力层中，它们在注意力机制里复用了键。也就是说，它们设置 values = keys，这应该能进一步缩小 KV 缓存。

此外，Gemma 4 还使用了 p-RoPE，即只有 25% 的频率对获得位置信息。这有助于减少长上下文情况下的位置噪声。

但别被缺少大（较大）的架构变化所迷惑。看看基准测试，Gemma 4 相比 Gemma 3 是一次巨大的飞跃！例如，在 AI Arena 排行榜上，Gemma 4（31B）的排名与大得多的 Qwen3.5-397B-A17B 模型相近。不过正如我在模型评估文章（链接见下）中讨论的，竞技场分数有点问题，因为它们可能被刷分，而且偏向人类（风格）偏好。

然而，如果看看我在下面绘制的其他一些常见基准，就会发现它确实相比 Gemma 3 有非常明显的飞跃，并与 Qwen3.5 27B 不相上下。

图 59：Gemma 3、Gemma 4 与 Qwen3.5 的对比（数据取自 Gemma 4 和 Qwen3.5 的 Model Hub 页面）。

注意，Gemma 4 还有一个混合专家（MoE）版本，下图把它与规模相近的 Qwen3 模型放在一起展示。

图 60：Qwen3 Coder Flash 与 Gemma 4 MoE 的比较。
