揭秘 GitHub Agentic Workflows 的安全架构（Under the hood: Security architecture of GitHub Agentic Workflows） ｜ GitHub Blog ｜ 文章 ｜ https://github.blog/ai-and-ml/generative-ai/under-the-hood-security-architecture-of-github-agentic-workflows/

GitHub 官方博客介绍 Agentic Workflows（跑在 GitHub Actions 上的 AI agent 自动化）怎样按安全优先来设计。agent 是非确定性的，要读取不可信的输入，而 Actions 默认所有东西都在同一个信任域里，一个被提示注入的 agent 就可能拿到密钥或刷屏仓库。所以他们把 agent 默认视为不可信，把工作流编译成权限、输出和网络访问都受约束的 Action，并遵循四条原则。一是纵深防御，分为隔离的运行底座、声明式配置和分阶段规划三层。二是不把密钥交给 agent：它被关进专用容器，联网要过防火墙，工具和模型调用分别经由持有凭据的网关和代理，宿主文件系统只读挂载进 chroot 环境。三是所有写操作先暂存再审查，限定类型和数量、过滤内容后才生效。四是在每个信任边界记录一切，以便取证和检测异常，并为将来的信息流控制打下基础。
