编程 agent 的组成部分（Components of A Coding Agent） ｜ Sebastian Raschka ｜ 文章 ｜ https://magazine.sebastianraschka.com/p/components-of-a-coding-agent

Sebastian Raschka 写的一篇参考性文章，回答读者常问的"编程 agent 到底是什么、怎么运作"。他的出发点是：最近大模型应用的很多进步并不来自更好的模型，而来自怎么使用模型，工具、上下文管理和记忆这些外围系统和模型本身同样重要，这也是为什么同一个模型在 Claude Code 或 Codex 里比在普通聊天界面里强得多。

他先厘清概念：大模型是预测下一个 token 的核心；推理模型仍是大模型，只是被训练或提示在中间推理、验证上花更多算力；agent 是套在模型外面的控制循环，根据目标决定接下来看什么、调用什么工具、怎么更新状态、何时停止。打个比方，大模型是引擎，推理模型是加强版引擎，agent harness 则是让引擎变成能开的车的整套系统。人们谈论模型的编程能力时，常把这三者混为一谈。

接着他配合一个极简的 Python 实现，讲编程 harness 的六个组成部分。一是实时的仓库上下文：启动时收集工作区结构、git 状态、项目说明等信息，让模型知道自己身处何处。二是提示的结构和缓存复用：把稳定不变的部分放在前面，变化的部分放在后面，以充分利用提示缓存、降低成本。三是工具的访问和使用：模型发出工具调用后，harness 先检查是否是已知工具、参数是否合法、是否需要用户批准、路径是否在工作区内，全部通过才真正执行。四是控制上下文膨胀：截断过长的工具输出，压缩历史记录，只保留有用的部分。五是结构化的会话记忆：把任务、已做的事和关键发现记录下来，支撑长会话的连续性。六是有边界的子 agent 委派：把子任务交给独立上下文的子 agent，并限制其权限和步数，只把结果交回。最后他把这套框架和 OpenClaw 这类通用个人 agent 对比：后者同样能派生子会话、调用工具、维护记忆，但面向的是更广泛的日常任务，编程 harness 则围绕代码仓库做了专门优化。
