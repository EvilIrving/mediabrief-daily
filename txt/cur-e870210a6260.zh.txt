uv 是 Python 生态十年来最好的事情

编程 | 2025 年 10 月 23 日 | 阅读时间：6 分钟

现在是 2025 年。安装 Python、管理虚拟环境、在同事之间同步依赖，真的非得这么难吗？嗯……不必！最近出了一个叫 uv 的绝妙新工具，它彻底改变了安装和使用 Python 的难易程度。

uv 是一个免费开源工具，由 Astral 开发。这家小型初创公司过去几年推出了一系列 Python 工具（比如出色的代码检查工具 Ruff）。uv 可以：

- 为你安装任意版本的 Python
- 安装包
- 管理虚拟环境
- 极快地解决依赖冲突（这对大型项目非常重要）

最棒的是，在我看来，以上每一项它都比其他任何工具做得更好。它快得惊人，用 Rust 编写，几乎可以在任何操作系统或平台上运行。

安装 uv

uv 安装起来很简单。有几种方式，但（在我看来）最简单的是这条一行命令。在 Linux 和 Mac 上是：

curl -LsSf https://astral.sh/uv/install.sh | sh

在 Windows 的 PowerShell 中是：

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

之后你就可以通过 uv 命令使用它了。安装 uv 不会搞乱你现有的任何 Python 安装：它是一个独立的工具，所以只是装来试试也很安全。

为项目管理 Python

对任何 Python 项目来说，使用虚拟环境都是个好主意。它能把不同的代码和依赖彼此隔离开；根据我的经验，尽早养成使用虚拟环境的习惯，能省去大量麻烦。uv 天然使用虚拟环境，所以一旦用上 uv，开始使用虚拟环境就非常容易。

uv 会根据你所在目录（或上级目录）中 pyproject.toml 文件的内容为你构建 Python 环境。pyproject.toml 是为 Python 项目声明依赖的一种标准的现代格式。一个最基本的文件大概是这样：

```
[project]
name = "my_project"
version = "1.0.0"
requires-python = ">=3.9,<3.13"
dependencies = [
  "astropy>=5.0.0",
  "pandas>=1.0.0,<2.0",
]
```

本质上，它只需要指定使用哪个 Python 版本和一些依赖。再加上名称和版本号也不错。

（附注：对于你要以包的形式发布的项目，比如发布到 pip 和 uv 所使用的 Python 包索引 PyPI，pyproject.toml 是声明发布所需全部信息的现代方式。）

用 uv 新建项目

要用 uv 开始一个新的 Python 项目，可以运行：

uv init

它会为你创建一个新项目，包含 pyproject.toml、README.md 以及其他重要的样板文件。

这条命令有很多不同的用法，比如 uv init --bare（只创建 pyproject.toml）、uv init --package（建立一个新的 Python 包）等等。我建议运行 uv init --help 来了解它们。

当你已经有了 pyproject.toml 文件

初始化项目之后，或者如果你的项目里本来就有 pyproject.toml 文件，开始使用 uv 就非常容易了。你只需在 pyproject.toml 所在的目录里运行：

uv sync

这条命令（实际上，如果你还没运行过它，大多数 uv 命令都会）会：

1. 自动安装一个合适版本的 Python
2. 把所有依赖安装到 .venv 目录下的一个新虚拟环境中
3. 在目录中创建一个 uv.lock 文件，记录所安装的每一个包的确切、与平台无关的版本，这意味着其他同事可以完全复现你的 Python 环境。

原则上，你可以像在其他工具里见过的普通虚拟环境那样"激活"这个新环境，但最"uv 风格"的用法是直接在任何命令前加上 uv run。这条命令会自动为你找到正确的虚拟环境，并用它来运行你的命令。比如要运行一个脚本，不必这样：

```
source .venv/bin/activate
python myscript.py
```

只需：

uv run myscript.py

效果完全一样。同样，要使用 Jupyter Lab 这样的"工具"，只需在项目目录里运行：

uv run jupyter lab

而不必先"激活"环境再单独运行 jupyter lab。

添加依赖

你随时可以手动编辑 pyproject.toml 文件：uv 会检测到改动并重建项目的虚拟环境。但 uv 也有更简单的添加依赖的方式，你只需：

uv add numpy>=2.0

就能添加一个包，还可以像上面那样指定版本约束。这条命令会自动替你编辑 pyproject.toml。uv add 在添加来自 git 或你电脑上其他位置的远程依赖时也极其强大（不过这里就不展开了）。

固定 Python 版本

最后，我认为 uv 能做的最有用的事情之一，是为项目固定一个特定的 Python 版本。运行：

uv python pin 3.12.9

就会把当前项目固定为恰好 Python 3.12.9，对你和其他使用 uv 的人都一样，这意味着你真的可以在多台机器上复现完全相同的 Python 安装。

uvx：忽略以上所有内容，现在就运行一个工具！

不过有时候，你可能只想快速运行一个工具，比如在某处用 Ruff 检查代码，或者不建环境就启动一个 Jupyter 笔记本服务器，甚至只是快速开一个装好 pandas 的 IPython 会话来打开某个文件。uv tool run 命令（简写别名为 uvx）让这一切变得极其简单。运行像这样的命令：

uvx ruff

就会自动下载你想用的工具，并在一个一次性的虚拟环境中运行它。工具下载过一次之后，由于 uv 使用缓存的方式，速度快如闪电。

我在很多场合都想这么做。一个常见的场景是快速启动一个装好 pandas 的 IPython 会话（用 --with 添加依赖），好快速打开、查看一个 parquet 文件。比如：

uvx --with pandas,pyarrow ipython

或者只是启动一个 Jupyter Lab 服务器，好快速打开学生发给我的 Jupyter 笔记本：

uvx --from jupyter-core jupyter lab

说实话，还有太多别的奇怪的一次性用途，有 uvx 在手真的很方便。我并不觉得总是使用虚拟环境让我错过了什么，因为只要你需要，uvx 总能给你一张"免罪金牌"。

如果这还没打动你：一点个人体会

我第一次发现 uv 是在去年，当时我正和其他可爱的开发者一起构建 Astrosky 生态系统（The Astrosky Ecosystem），这是一个为网上的天文学家打造开源社交媒体集成的很棒的项目。但由于多名开发者在多种操作系统上异步工作，管理 Python 安装很快就成了一项艰巨的任务。

对我们来说，uv 是一次极其有力的简化，我们在整个技术栈中都使用它。作为开发者，我们都可以使用完全相同的 Python 安装，这一点尤其重要，因为我们用到的一些半实验性的依赖每个版本都有破坏性变更。在 GitHub Actions 上，我们计划用 uv 快速构建 Python 环境并运行单元测试。在生产环境中，uv 已经在管理我们所有服务器上的 Python。

能始终确信 Python 和包的安装在我们所有机器上总是被一致且正确地处理，这种感觉实在太好了。这就是为什么 uv 是 Python 生态十年来最好的事情。
