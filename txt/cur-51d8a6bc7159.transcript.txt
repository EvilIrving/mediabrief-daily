Redis 冒险的终点

十多年前我启动 Redis 项目时，正处在职业生涯最激动人心的时刻之一。我和合伙人成功推出了意大利互联网上两个主要的 Web 2.0 服务。为了让它们能够扩展，我们不得不发明许多新概念。这些概念大多在业内早已为人所知，但我们并不知道，也懒得去查。有问题？那就想个办法解决。我们想解决问题，但更想玩得开心。Redis 就诞生在这样一种好玩的氛围里。

可如今，不可思议的是，Redis 已经成了许许多多系统的主要组成部分。一年又一年，我的工作从"打造这个东西"，变成了确保它尽可能有用、尽可能可靠。而最近几年，我每天做的事变化太大了，大部分注意力都花在查看其他开发者对 Redis 代码提出的意见上：怎么改进它，要怎么改才能更正确、更快或更安全。然而，我从来就不想当一名软件维护者。

我写代码是为了表达自己。我把自己写的代码看作一件作品，而不只是用来把事情办成的有用之物。可以说，我写的东西有用只是一个副作用，我的首要目标是做出某种意义上美的东西。说到底，我宁愿被人记成一个糟糕的艺术家，也不愿被记成一个优秀的程序员。现在，一个变得如此重要的项目所造成的处境，越来越多地要求我少表达自己、多维护项目。而这确实正是 Redis 眼下需要的。但这不是我想做的事，过去几年我已经把自己撑到了极限。

所以，亲爱的 Redis 社区，从今天起我不再担任 Redis 的维护者。我的新角色一方面是在 Redis Labs 做一个"出点子的人"，为 Redis 的新可能性提供思路：我会继续留在 Redis Labs 的顾问委员会。另一方面，我的双手会是自由的，我会去做点别的事，也许写代码，也许不写，谁知道呢，我暂时不想做计划。不过，我非常怀疑自己将来真的会不再写代码。那实在太好玩了 :D

我把 Redis 交到 Redis 社区手中。我请同事 Yossi Gottlieb 和 Oran Agra 从今天起继续维护这个项目：最近几年帮我最多的就是他们俩，即使跟上我那些非常主观的观点并不总是"顺理成章"，他们也努力去理解我对 Redis 的设想。因为我不想参与塑造新的 Redis 开发体制（那正是最"元"的维护工作，恰恰是我想避开的），我就把"如何与其他 Redis 开发者对接、找到一种可持续的开发模式"这件事留给 Yossi 和 Oran。你可以在这篇博文里直接听听他们怎么说：https://redislabs.com/blog/new-governance-for-redis/

我相信，我不只是把 Redis 交给了一群专业的程序员，也交给了一群在乎 Redis 社区精神这份遗产的人。十一年来，我希望自己提供了一种观点，一种另类的写软件方式，而且有些人理解了它。我希望在 Redis 的演进中，这种观点仍会被考虑进去。

Redis 是我职业生涯中压力最大的事，可能也是最重要的事。我不太喜欢近些年地下编程圈变成的样子，但即便这段旅程并不容易，我也有幸与许多了不起的人共事、交流。感谢你们的人情味和帮助，感谢你们教给我的东西。你们知道我说的是谁！我还要感谢那些公司，以及这些公司里的人，让我能在这么多年里每天写开源代码，并且有自由去做我认为对用户群正确的事。Redis Labs、VMware 和 Pivotal，谢谢你们的大力帮助和慷慨。

正如我所说，除了参与 Redis 顾问委员会，我真的不知道未来等着我的是什么。我想有一段时间，四处看看、别做太多事，是个好主意。我想多探索一下自己的几个爱好。写博客也是我一直想做、却因为时间关系做得越来越少的一件大事。最近我发布了一些意大利语视频，向大众讲解技术概念，做得很开心，反馈也不错，也许我会多做一些。总之，我想你们有些人知道我在 Twitter 上很活跃，账号是 @antirez。如果你好奇一个又老又怪的程序员接下来会做什么，那就在那儿见。
