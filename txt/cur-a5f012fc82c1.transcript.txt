2025 年大模型年度回顾

2025 年是大语言模型（LLM）取得强劲进展、大事频出的一年。下面列出的是我个人认为值得注意、又略感意外的一些“范式转变”，它们改变了格局，在概念上让我印象深刻。

1. 基于可验证奖励的强化学习（RLVR）

2025 年初，所有实验室的 LLM 生产流程大致是这样的：

1. 预训练（约 2020 年的 GPT-2/3）
2. 监督微调（约 2022 年的 InstructGPT），以及
3. 基于人类反馈的强化学习（约 2022 年的 RLHF）

在相当一段时间里，这是训练生产级 LLM 的稳定且经过验证的配方。2025 年，基于可验证奖励的强化学习（RLVR）成了加入这一组合的事实上的新主要阶段。通过在多种环境中（比如数学、代码谜题）用可自动验证的奖励来训练 LLM，模型会自发地发展出在人类看来像“推理”的策略：它们学会把解题过程分解为中间计算，也学会了许多来回试探、把事情弄清楚的解题策略（例子可见 DeepSeek R1 论文）。在以前的范式里，这些策略很难实现，因为对 LLM 来说，最优的推理轨迹和纠错过程是什么样子并不清楚，它必须通过针对奖励的优化，自己找到对它有效的方法。

SFT 和 RLHF 阶段都相对较薄、较短（在计算上只是小规模微调），而 RLVR 是针对客观的（无法钻空子的）奖励函数进行训练，这允许长得多的优化过程。事实证明，运行 RLVR 的“能力/美元”比很高，它吞掉了原本打算用于预训练的算力。因此，2025 年的大部分能力进步，都是由各 LLM 实验室消化这个新阶段积压的潜力所决定的，总体上我们看到的是规模大致相同的 LLM，但 RL 运行的时间长得多。同样是这个新阶段独有的，我们得到了一个全新的旋钮（以及与之相关的规模定律），可以通过生成更长的推理轨迹、增加“思考时间”，把能力作为测试时计算量的函数来控制。OpenAI o1（2024 年底）是 RLVR 模型的第一个演示，但 o3 的发布（2025 年初）才是明显的拐点，你能直观地感受到其中的差别。

2. 幽灵与动物 / 参差不齐的智能

2025 年，我（我想业界其他人也是）第一次开始以更直观的方式内化 LLM 智能的“形状”。我们不是在“进化/养育动物”，而是在“召唤幽灵”。LLM 技术栈的一切都不同（神经网络架构、训练数据、训练算法，尤其是优化压力），所以我们在智能空间中得到非常不同的实体也就不足为奇了，用动物的视角去理解它们是不合适的。从监督信息的角度看，人类的神经网络是为了一个部落在丛林中生存而优化的，而 LLM 的神经网络是为了模仿人类的文本、在数学谜题中收集奖励、在 LM Arena 上赢得人类的点赞而优化的。由于可验证的领域允许进行 RLVR，LLM 在这些领域附近的能力会“冲高”，整体上呈现出参差不齐得有些好笑的表现特征：它们同时是一位天才博学家，也是一个困惑的、认知有障碍的小学生，可能几秒钟之后就被越狱手段骗去泄露你的数据。

（蓝色是人类智能，红色是 AI 智能。我喜欢这个版本的梗图（抱歉，我找不到它在 X 上原帖的出处了），因为它指出人类智能也以自己不同的方式参差不齐。）

与这一切相关的，是我在 2025 年对基准测试普遍变得冷淡、失去了信任。核心问题在于，基准测试几乎从构造上就是可验证的环境，因此立刻就容易受到 RLVR 以及通过合成数据生成实现的较弱形式的影响。在典型的“刷榜”过程中，LLM 实验室的团队不可避免地会在基准测试所占据的嵌入空间小角落附近构造环境，长出“尖刺”去覆盖它们。在测试集上训练成了一门新的艺术形式。

把所有基准测试都刷爆，却仍然没有得到 AGI，会是什么样子？

3. Cursor / LLM 应用的新一层

我觉得 Cursor 最值得注意的地方（除了它今年的爆发式崛起）在于，它令人信服地揭示了“LLM 应用”的一个新层次，人们开始谈论“某某领域的 Cursor”。正如我今年在 Y Combinator 的演讲（文字稿和视频）中强调的，像 Cursor 这样的 LLM 应用为特定垂直领域打包和编排 LLM 调用：

1. 它们负责“上下文工程”。
2. 它们在底层编排多次 LLM 调用，串成越来越复杂的有向无环图（DAG），小心地平衡性能和成本之间的取舍。
3. 它们为参与其中的人提供特定于应用的图形界面。
4. 它们提供一个“自主程度滑块”。

2025 年，大家花了很多口舌讨论这个新的应用层有多“厚”。LLM 实验室会吃掉所有应用，还是 LLM 应用还有一片绿色牧场？我个人猜测，LLM 实验室会倾向于培养出能力全面的大学毕业生，而 LLM 应用会通过提供私有数据、传感器、执行器和反馈回路，把一群这样的毕业生组织起来、加以微调，真正把他们变成特定垂直领域里部署上岗的专业人士。

4. Claude Code / 住在你电脑上的 AI

Claude Code（CC）是第一个令人信服地展示 LLM agent 样子的产品：它以循环的方式把工具使用和推理串起来，进行长时间的问题求解。此外，CC 让我觉得值得注意的是，它运行在你的电脑上，使用你的私有环境、数据和上下文。我认为 OpenAI 在这一点上做错了，因为他们早期的 Codex/agent 工作重心放在由 ChatGPT 编排的云端容器部署上，而不是简单的 localhost。虽然在云端运行的 agent 集群感觉像是“AGI 的终局”，但我们生活在一个能力参差不齐、起飞足够缓慢的过渡世界里，把 agent 直接运行在开发者的电脑上更为合理。请注意，真正重要的区别不在于“AI 运算”碰巧在哪里运行（云端、本地或其他地方），而在于其他一切：那台已经存在并且开着机的电脑、它的安装环境、上下文、数据、密钥、配置，以及低延迟的交互。Anthropic 把这个优先顺序搞对了，并把 CC 打包成一种讨人喜欢的、极简的命令行形态，改变了 AI 的样子：它不再只是一个你像访问 Google 那样去访问的网站，而是一个“住”在你电脑上的小精灵/幽灵。这是一种新的、独特的与 AI 交互的范式。

5. 氛围编程（vibe coding）

2025 年，AI 越过了一个能力门槛，只需用英语就能构建各种令人印象深刻的程序，甚至忘了代码的存在。好笑的是，我在这条“洗澡时的随想”推文里造出了“vibe coding”这个词，完全没意识到它会走得这么远 :)。有了氛围编程，编程不再严格属于训练有素的专业人士，而是任何人都能做的事。从这个意义上说，它又一次印证了我在《权力归于人民：LLM 如何颠覆技术扩散的剧本》中写到的：与迄今为止所有其他技术形成鲜明对比，普通人从 LLM 中获得的好处，远远多于专业人士、公司和政府。而氛围编程不仅让普通人能够接触编程，也让训练有素的专业人士能写出多得多的（氛围编程出来的）软件，这些软件否则永远不会被写出来。在 nanochat 中，我用氛围编程写了一个我自己定制的、非常高效的 Rust 版 BPE 分词器，而不必采用现有的库，或者把 Rust 学到那个程度。今年我用氛围编程做了很多项目，作为我希望存在的某个东西的快速应用演示（例如 menugen、llm-council、reader3、HN time capsule）。我还用氛围编程写过整个临时应用，只为了找一个 bug，因为何乐而不为呢：代码突然变得免费、短暂、可塑，用一次就可以扔掉。氛围编程将重塑软件，并改变职位描述。

6. Nano Banana / LLM 的图形界面

Google Gemini 的 Nano Banana 是 2025 年最不可思议、最具范式转变意义的模型之一。在我的世界观里，LLM 是下一个重大的计算范式，类似于 1970 年代、80 年代的计算机。因此，出于本质上相似的原因，我们会看到类似的创新。我们会看到个人计算、微控制器（认知内核）、（agent 的）互联网等等的对应物。特别是在用户界面和用户体验方面，和 LLM“聊天”有点像在 1980 年代向计算机控制台输入命令。文本是计算机（和 LLM）原始的、偏爱的数据表示形式，但它不是人偏爱的格式，尤其是在输入端。人其实不喜欢阅读文字，它又慢又费劲。相反，人喜欢以视觉化、空间化的方式获取信息，这就是传统计算中发明图形界面（GUI）的原因。同样地，LLM 也应该用我们偏爱的格式和我们交流：图片、信息图、幻灯片、白板、动画/视频、网页应用等等。这方面早期和现在的版本，当然就是表情符号和 Markdown 之类的东西，它们是用标题、粗体、斜体、列表、表格等，把文字在视觉上“打扮”和排版一下、方便阅读的方式。但到底谁会真正构建出 LLM 的图形界面呢？在这种世界观下，Nano Banana 是关于它可能是什么样子的第一个早期迹象。重要的是，它值得注意的一点在于，这不仅仅关乎图像生成本身，而是关乎文本生成、图像生成和世界知识共同带来的联合能力，它们全都纠缠在模型权重之中。

太长不看版：2025 年是 LLM 令人兴奋、又略感意外的一年。LLM 正在成为一种新型的智能，同时比我预期的聪明得多，也比我预期的笨得多。无论如何，它们极其有用，而且我认为即使以目前的能力，业界实现的潜力也远不到 10%。与此同时，有太多想法可以尝试，这个领域在概念上感觉完全是敞开的。正如我今年早些时候在 Dwarkesh 的播客上提到的，我同时（而且表面上看起来自相矛盾地）相信：我们既会看到快速而持续的进步，同时也还有大量的工作要做。系好安全带吧。
