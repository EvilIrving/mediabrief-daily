Nielsen Norman Group 阐述了智能体运行框架（Agent Harness，亦称 Agentic Harness）的核心定义、架构职责及其对用户体验（UX）的决定性影响。两个采用相同基础大语言模型（LLM）的排会助手，一个仅能润色会议文本，另一个却能查日程、辨别空闲并主动发送邀请，其根本差异不在于模型本身，而在于包围并驱动模型的底层底盘系统——Harness。

## 一、什么是 Agent Harness：从文本预测到执行循环

大语言模型的核心机制是通过概率预测序列中的下一个词元。模型本身无法直接调用外部系统，只能生成结构化的工具调用指令（如发起日历查询）。Agent Harness 是围绕在模型外部的控制软件，负责执行模型的工具调用请求、获取真实返回结果，并严格控制注入模型的上下文信息与操作权限。

这一持续轮转的“请求—行动—结果”（Request-Action-Result）链路被称为执行循环（Execution Loop）。Harness 接管并运转该循环，正是让被动应答的聊天机器人（Chatbot）跨越为具备长程自主推进能力的智能体（AI Agent）的核心工程所在。在实际生产系统中，界面交互（UI）、Harness 与模型紧密协同，例如由 Harness 判定何时弹出确认窗口，确保敏感邀请在发出前由人工完成最终复核。

## 二、Harness 承担的三大核心支撑职责

### 1. 装配与供给上下文（Supplying Context）
Harness 为每个任务动态聚合模型决策所需的全部上下文，包括用户诉求、系统指令、对话历史、持久化偏好以及外部文件或日程。已保存的信息若未被 Harness 正确注入模型的工作上下文，便毫无价值（例如用户已设定“周五不排会”，若 Harness 遗漏传递，模型便会犯错，导致用户反复重新输入）。

此外，Harness 决定了信息的输入形态。例如处理一份客户旅程地图 PDF 时，若 Harness 仅提取纯文本注入模型，模型将完全丢失版面排版所传递的空间关联；若同时将页面转为图像输入，模型对整体流程的理解力将显著提升。

### 2. 桥接工具与权限硬拦截（Connecting Tools & Enforcing Permissions）
Harness 赋予模型调用外部 API 的能力，同时建立权限防火墙。即使面对同一个日历连接器，读取同事空闲与向全员发送会议邀请属于完全不同的权限级别。
- **细粒度权限区分**：严格隔离只读与写入能力；
- **双层防护网**：Harness 在前端拦截未授权操作或设置人工批准断点，而底层连接应用与 API 也保有自身的鉴权规则；Harness 的授权绝不能突破底层系统的硬性限制。

### 3. 注入执行指引与施加刚性边界（Instructions & Hard Limits）
Harness 为长流程任务设置预算阈值，包括单次会话步数上限、超时时间与 Token 成本配额，防范失控死循环：
- **边界与冲突决断**：当排会系统在指定时间段内找不到所有人共有的空闲时间时，搜索已陷入死胡同，此时由 Harness 驱动下一步分支策略——是向组织者提问将部分参会人改为可选、扩大搜索时间窗口，还是立即停止并客观交代冲突；
- **硬限制优于纯 Prompt 引导**：行为层面的软提示词无法保证模型百分百遵守，Harness 的硬性熔断与返回校验才能提供不可逾越的执行兜底。

## 三、对 UX 设计与系统评估的实践准则

### 1. 产品选型：脱离模型名盲信，下钻检验 Harness 配置
单纯获知产品采用了哪款前沿大模型，无法代表其能胜任特定业务。必须审查其外部连接器生态、权限控制机制与单任务步数限制。若缺少必要权限与连接，用户仍将被迫手工拷贝数据，智能体沦为空壳。

### 2. 交互设计：界面控件与 Harness 行为契约同步推演
设计 AI 交互时不能仅停留在静态页面，必须联合工程师明确后端运行细节：
- 当用户保存某项配置时，Harness 如何持久化并在后续轮次精准注入；
- 用户中途触发“取消”（Cancel）操作时，Harness 应如何中断执行循环，对已经产生的外部副作用（如已提交的审批单）采取何种回滚或补偿策略；
- 明确哪些写操作需要人工介入（Human-in-the-Loop），并在确认弹窗后端落实强鉴权校验。

### 3. 评测验证：基于真实场景进行全链路端到端闭环测试
评估 AI 系统不能仅考核模型生成文本的质量，必须在挂载真实连接器、真实权限边界与复杂偏好下运行端到端任务。测试集应主动纳入边界异常：如日历断开连接、用户偏好突变、全员无空闲时间等。一旦发生任务失败，需精准下钻定界：问题究竟源自前端交互缺陷、Harness 调度失误，还是模型底层推理能力不足。
