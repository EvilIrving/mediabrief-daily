How Anthropic’s product team moves faster than anyone else | Cat Wu (Head of Product, Claude Code) ｜ Lenny's Podcast ｜ 86分钟 ｜ https://www.lennysnewsletter.com/p/how-anthropics-product-team-moves

这期 Lenny's Podcast 由 Lenny Rachitsky 对谈 Anthropic 的 Claude Code 与 Cowork 产品负责人 Cat Wu，核心话题是 Anthropic 的产品团队为何能以近乎每天一个重大发布的速度推进，以及 AI 时代 PM 的角色在如何变化。Cat 先介绍了她和 Claude Code 创造者 Boris 的分工：Boris 是技术负责人和产品愿景者，负责定义三到六个月后"最具 AGI 感"的产品形态；她则负责规划从现状走到那个愿景的路径，并打通市场、销售、财务和算力等跨职能环节，两人约八成想法一致，其余各自主导自己更在意的部分。

她认为许多 PM 候选人的思路已经过时。过去技术变化慢、写代码贵，PM 的重心是对齐跨季度路线图；如今功能周期已从六个月缩到一个月、一周甚至一天，PM 的价值在于缩短从想法到用户手中的时间。具体做法有三：设定清晰而能排除选项的目标，例如"让企业专业开发者安全地做到零权限弹窗"；几乎所有功能以"研究预览"名义发布，降低承诺成本，一两周就能上线；建立工程、市场、文档之间的紧密流程，工程师把内部试用过的功能贴到常设发布频道，第二天就能出公告。团队每周全员过指标，并有一份写明核心用户及理由的团队原则，使人人能自行决策；只有模糊或基础设施很重的项目才写 PRD。她强调提速主要来自低流程和团队预期，而非内部使用 Mythos 等前沿模型。

谈及争议话题，她称 Claude Code 源码泄露源于发布软件包流程中的人为失误，虽经两层人工审核仍出错，团队已加固流程，当事人仍在职；限制用订阅跑 OpenClaw 等第三方产品，是因为订阅并非为其使用模式设计，算力需求紧张，公司须优先保障第一方产品和 API，并为用户补发了额度。Anthropic 目前约有三四十名 PM，分为研究、开发者平台、Claude Code、企业和增长等团队。

关于角色融合，她认为 PM、工程师、设计师的边界正在消失，团队偏好招募有产品品味的工程师，几乎所有 PM 都写过代码，设计师也做过前端。代码越便宜，"决定写什么"越有价值，产品品味因此是最稀缺的技能；工程背景的优势在于能判断实现难度，从而辅助排优先级。她也坦言代价：功能重叠、产品一致性下降、用户难以跟上，这促使团队违背"不做新手引导"的初衷推出 /powerup。她认为人类仍提供模型欠缺的常识与情商，例如理解相关方关系，而在持续混乱中保持乐观、睡好觉、无情地排优先级，是避免倦怠的关键。

她将 Anthropic 后来居上归因于两点：统一使命和专注。团队愿意牺牲自己的 KR 服务公司目标，她甚至说 Claude Code 失败而 Anthropic 成功她也会很高兴。产品使用上，她用终端 CLI 处理一次性编码任务，用桌面端做前端预览和总览会话，用网页和移动端在外出时启动任务，凡产出非代码的工作则交给 Cowork。她举例说，连接 Slack、Gmail、日历和 Drive 后，Cowork 用一夜时间综合各渠道资料，做出符合公司设计系统的 20 页大会演讲幻灯片，她只需决定大纲；销售同事则自建工具，从 Salesforce 和 Gong 拉取客户信息，几秒生成定制幻灯片。应用 AI 团队是工程之外 token 用量最大的部门，常用 Cowork 为次日客户会议准备简报。

谈到 PM 的新技能，她认为最难的是把握"恰到好处的 AGI 信念"：为超强模型设计产品很容易，难的是为当下模型找到黄金路径、扬长避短。培养方法包括让模型反思自己出错的原因以修正 harness、找到约五位反馈可靠的人、构建约十个高质量评测。她特别提到负责塑造 Claude 性格的 Amanda，认为 Claude 不端架子、积极、敢于给出诚实反馈是其受欢迎的关键。新模型到来时，团队常删除作为"拐杖"的功能和提示词，例如早期为防止重构半途而废而加入的待办清单，在 Opus 4 后已不再必要；同时新模型也会解锁过去做不好的功能，如在 Opus 4.5、4.6 之后才可靠的多 agent 代码审查，所以值得提前做"还不太能用"的产品。长期愿景是从单任务成功走向同时管理几十上百个远程运行、能自我验证并从反馈中自我改进的 agent。

给听众的建议是：把重复的手工任务交给 AI，而且要把自动化做到 100% 可靠，因为 95% 的自动化价值不大；做每天真正会用的应用而非一次性原型；也别沉迷于过度定制配置。她认为 2024 年的产品以聊天为主，而 Claude Code 一代以行动为主，"它能替你把事做完"正是人们的顿悟时刻。快问快答中，她推荐《亚洲大趋势》《技术陷阱》《折纸动物园》，喜欢《疾速争胜》和《徒手攀岩》，最爱的产品是 Waymo，人生信条是"直接去做"，并感谢早年在 Scale 的经历。最后她请听众多反馈可复现的失败案例。

几个细节值得一提。Cat 认为 token 成本会随每次模型跃升而上升，目前仍远低于工程师薪水，但占比在提高；Anthropic 内部 token 并非无限，公司信任员工自行判断，浪费被视为不妥。她描述的评测实践是：在功能需要更清晰的产品定义时亲自写五个左右评测，交付运行方法、成败结果和提高成功率的提示词，记忆类功能尤其受益；另有小组与研究团队合作，具体量化 Claude Code 的行为短板。新模型测试时，团队会在午餐时逐人询问观感，收集"解释不充分""爱写低质量记忆""自测不足"等印象，再据此提出假设、到数据中验证。她还承认自己也在教 Cowork 清空 Gmail 收件箱，过程很耗时且尚未完全成功，Lenny 则分享了自己的垃圾邮件分类工作流同样卡在 95%。她表示团队正在简化定义 skill、反馈、更新 skill 的流程，因为目前用户需要掌握的概念太多。谈到职业发展，她认为在早期创业公司没有角色边界的经历最能培养能动性，学校教育所训练的"照指令做事拿好成绩"需要被主动忘掉；谈到 AGI 之后，她认为技术扩散到整个社会需要很长时间，眼下更重要的是帮助世界跟上，之后她想去枫丹白露攀岩，并把读书速度提高到每周一两本。
