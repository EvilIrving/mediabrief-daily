第 1020 期：你读 agent 写的代码吗？（1020: Do You Read The Code?） ｜ Syntax ｜ 播客 ｜ https://syntax.fm/1020

《Syntax》2026 年 7 月的一期周一新闻杂谈，主持人 Scott Tolinski 和 CJ Reynolds 先围绕最近开发者圈争论不休的话题"要不要读 AI 写的代码"展开，再聊一串前端和 AI 工具新闻，最后照例分享个人推荐。

开场他们梳理了网上的各种观点。有人拿两个个人 agent 项目对比：OpenClaw 每次更新都会坏，Hermes 的维护者则会读代码、更加审慎。也有人说这就像当年无休止的框架之争，开发者什么都能吵。Scott 的立场是答案在中间：原型和个人项目可以只测效果不读代码，但生产代码他会读。他们特别提到自家公司 Sentry 的联合创始人、前 CEO David Cramer：他把公司做到十亿美元规模，早已不是工程师，却仍在写代码、用 agent、打磨工作流，"他知道什么才重要"。他们还认同 David Fowler 的一句话：网红们都在谈读代码和软件工厂，却很少有人讨论未来的工程团队会是什么样，软件是多人游戏，不是一群 agent 就够了。Scott 提到在 JS Nation 大会的讨论里，很多人关心"结对提示"、多人一起驾驭 agent，他认为 AI 时代的团队协作是最大的问题。

新闻部分，CJ 介绍了 HTTP QUERY 方法的 RFC：GET 请求按规范不能带请求体，复杂的只读查询只好用 POST，GraphQL 就是这样；QUERY 相当于可以带请求体、仍然幂等安全的 GET，请求体可以是表单编码或 JSON，目前只有 Node.js 的 http 模块支持，需要各家实现者逐步跟进。他们还看了一个新前端框架：主打编译期把代码接好线，用 JSX 和 Signals、没有虚拟 DOM，hello world 只有两百多字节，待办应用的体积和 Solid 相当、远小于 Svelte，组件和 store 都是类，UI 组件基于用有限状态机驱动的 Zag.js。Scott 喜欢它的代码组织，但不爱 JSX，也不觉得它足以改变什么，不过乐见有人尝试。

AI 工具方面，Scott 分享用 agent 给自己的动画库做出关键帧编辑系统；CJ 为一个个人音乐流媒体项目，把同一段规划提示分别交给 GPT-5.5、Opus 4.8、Kimi K2.7 和 Fable：前三者查几下文档就给出计划，Fable 则一头扎进调研，甚至开始逆向亚马逊音乐的 API，工具调用一个接一个，更"agent 化"，但也迅速耗光了他 GitHub Copilot 的额度；他发现每月 100 美元的 Codex 套餐反而更划算。他们也谈到团队内部的 bot：能接入邮件排期、YouTube 分析、Notion 等分散的工具并整合信息，CJ 出于安全意识想找办法攻破它，指出如果它对 YouTube 有写权限，评论里的提示注入就可能造成危害，所以坚持最小权限，这也是他迟迟不做个人 agent 的原因；Scott 则坦白自己说过"永远不会在 Slack 里写代码"，结果这周就这么干了，而且感觉不错。他们还吐槽 Claude Code 曾悄悄加入"用户 60 秒不回答就自动选推荐选项继续写"的功能，被用户在 GitHub 上当成 bug 抗议，他们认为这本该默认关闭，并调侃这样还能多烧 token；另有人逆向发现 Claude Code 会在检测到中国时区时改变提示里日期和撇号的格式，被视为一种隐写式的标记。

推荐环节，CJ 推荐了完全离线、基于开放地图数据的导航应用 Organic Maps，适合徒步露营；以及一个收录各种电脑在电影中出镜截图的网站 Starring the Computer。
