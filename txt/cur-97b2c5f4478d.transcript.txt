以大语言模型（LLM）作为核心控制器来构建智能体，是一个很酷的想法。AutoGPT、GPT-Engineer 和 BabyAGI 等几个概念验证演示都是令人振奋的例子。LLM 的潜力不止于写出漂亮的文案、故事、文章和程序；它可以被看作一个强大的通用问题求解器。

# 智能体系统概览

在 LLM 驱动的自主智能体系统中，LLM 充当智能体的大脑，并由几个关键组件加以补充：

- **规划**
  - 子目标与分解：智能体把大任务拆解成更小、可管理的子目标，从而高效处理复杂任务。
  - 反思与改进：智能体可以对过去的行动进行自我批评和自我反思，从错误中学习，并在之后的步骤中加以改进，从而提高最终结果的质量。
- **记忆**
  - 短期记忆：我认为所有上下文学习（参见《提示工程》一文）都是在利用模型的短期记忆来学习。
  - 长期记忆：让智能体能够在较长时间内保留和回忆（近乎无限的）信息，通常借助外部向量数据库和快速检索来实现。
- **工具使用**
  - 智能体学会调用外部 API，获取模型权重中缺失的额外信息（权重在预训练之后通常很难修改），包括实时信息、代码执行能力、访问专有信息源等。

# 组件一：规划

一个复杂任务通常包含很多步骤。智能体需要知道这些步骤是什么，并提前做好规划。

## 任务分解

**思维链**（Chain of Thought，CoT；Wei 等，2022）已经成为提升模型在复杂任务上表现的标准提示技术。模型被要求"一步一步地思考"，以利用更多的推理时计算，把困难任务分解为更小、更简单的步骤。CoT 把大任务变成多个可管理的小任务，也让人得以窥见模型的思考过程。

**思维树**（Tree of Thoughts；Yao 等，2023）在 CoT 的基础上，在每一步探索多种推理可能。它先把问题分解为多个思考步骤，每一步生成多个想法，形成树状结构。搜索过程可以是 BFS（广度优先搜索）或 DFS（深度优先搜索），每个状态由分类器（通过提示）或多数投票来评估。

任务分解可以通过以下方式完成：（1）由 LLM 通过简单提示完成，例如 `"Steps for XYZ.\n1."`、`"What are the subgoals for achieving XYZ?"`；（2）使用特定任务的指令，例如写小说时用 `"Write a story outline."`；（3）借助人工输入。

另一种截然不同的方法 **LLM+P**（Liu 等，2023）依靠外部的经典规划器来做长程规划。这种方法使用规划领域定义语言（PDDL）作为描述规划问题的中间接口。过程中，LLM（1）把问题翻译成"问题 PDDL"，然后（2）请经典规划器基于现有的"领域 PDDL"生成 PDDL 计划，最后（3）把 PDDL 计划翻译回自然语言。本质上，规划步骤被外包给了外部工具，前提是存在特定领域的 PDDL 和合适的规划器——这在某些机器人场景中很常见，但在许多其他领域并非如此。

## 自我反思

自我反思是一个至关重要的方面，它让自主智能体能够通过改进过去的行动决策、纠正先前的错误来迭代提升。在不可避免需要试错的现实任务中，它起着关键作用。

**ReAct**（Yao 等，2023）通过把动作空间扩展为"特定任务的离散动作 + 语言空间"的组合，将推理与行动整合进 LLM。前者让 LLM 能与环境交互（例如使用维基百科搜索 API），后者则促使 LLM 以自然语言生成推理轨迹。

ReAct 的提示模板包含让 LLM 显式思考的步骤，大致格式如下：

```
Thought: ...
Action: ...
Observation: ...
... (Repeated many times)
```
在知识密集型任务和决策任务的实验中，`ReAct` 的表现都优于去掉了 `Thought: …` 步骤的纯 `Act` 基线。

**Reflexion**（Shinn & Labash，2023）是一个为智能体配备动态记忆和自我反思能力、以提升推理能力的框架。Reflexion 采用标准的强化学习设置：奖励模型提供简单的二元奖励，动作空间沿用 ReAct 的设置，即在特定任务的动作空间中加入语言，以支持复杂的推理步骤。每执行一个动作 $a_t$ 之后，智能体会计算一个启发值 $h_t$，并可根据自我反思的结果*决定是否重置*环境、开始新的一轮尝试。

启发函数用来判断轨迹何时低效或包含幻觉、应当停止。低效规划指耗时过长却仍未成功的轨迹。幻觉的定义是：连续出现一串相同的动作，并在环境中得到相同的观察结果。

自我反思是通过向 LLM 展示两个示例（two-shot）来生成的，每个示例是一对（失败的轨迹，用于指导后续计划调整的理想反思）。然后这些反思会被加入智能体的工作记忆（最多三条），作为查询 LLM 时的上下文。

**后见之链**（Chain of Hindsight，CoH；Liu 等，2023）通过向模型显式呈现一系列带有反馈标注的过往输出，鼓励模型改进自己的输出。人类反馈数据是一个集合 $D_h = \{(x, y_i, r_i, z_i)\}_{i=1}^n$，其中 $x$ 是提示，每个 $y_i$ 是一个模型补全，$r_i$ 是人类对 $y_i$ 的评分，$z_i$ 是相应的人类事后反馈。假设反馈元组按奖励排序，$r_n \geq r_{n-1} \geq \dots \geq r_1$。训练过程是监督微调，数据是形如 $\tau_h = (x, z_i, y_i, z_j, y_j, \dots, z_n, y_n)$ 的序列，其中 $1 \leq i \leq j \leq n$。模型在给定序列前缀的条件下只被训练去预测 $y_n$，从而能根据反馈序列进行自我反思、产出更好的输出。在测试时，模型还可以选择与人类标注者进行多轮指令交互。

为避免过拟合，CoH 加入了一个正则项，以最大化预训练数据集的对数似然。为避免走捷径和照抄（因为反馈序列中有很多常见词），训练时会随机遮蔽 0%–5% 的过往 token。

他们实验中的训练数据集由 WebGPT 对比数据、基于人类反馈的摘要数据以及人类偏好数据集组合而成。

CoH 的思路是在上下文中呈现一段逐步改进的输出历史，并训练模型顺应这一趋势产出更好的输出。**算法蒸馏**（Algorithm Distillation，AD；Laskin 等，2023）把同样的思路应用到强化学习任务的跨回合轨迹上，把一个*算法*封装进一个以长历史为条件的策略中。考虑到智能体与环境交互多次、每个回合都会进步一点，AD 把这段学习历史拼接起来输入模型。因此，我们应当期望模型预测的下一个动作比之前的尝试表现更好。其目标是学习强化学习的过程本身，而不是训练一个特定任务的策略。

论文假设：任何能生成一组学习历史的算法，都可以通过对动作做行为克隆，被蒸馏进一个神经网络。历史数据由一组源策略生成，每个源策略针对一个特定任务训练。在训练阶段，每次强化学习运行时都会随机采样一个任务，并用多回合历史的一个子序列来训练，使学到的策略与任务无关。

实际上，模型的上下文窗口长度有限，因此回合必须足够短，才能构建多回合历史。要学到接近最优的上下文内强化学习算法，需要 2–4 个回合的多回合上下文。上下文内强化学习的涌现需要足够长的上下文。

与三个基线相比——包括 ED（专家蒸馏，用专家轨迹而非学习历史做行为克隆）、源策略（用 UCB 生成供蒸馏的轨迹）、RL^2（Duan 等，2017；因为需要在线强化学习，被用作上界）——AD 展现出了上下文内强化学习能力，尽管只使用离线强化学习，其表现仍接近 RL^2，并且学习速度远快于其他基线。在以源策略的部分训练历史为条件时，AD 的提升速度也远快于 ED 基线。

# 组件二：记忆

（非常感谢 ChatGPT 帮我起草这一节。在和 ChatGPT 的对话中，我学到了很多关于人脑以及用于快速 MIPS 的数据结构的知识。）

## 记忆的类型

记忆可以定义为用于获取、存储、保持并在之后提取信息的过程。人脑中有几种类型的记忆。

1. **感觉记忆**：这是记忆的最早阶段，能在原始刺激结束后保留对感官信息（视觉、听觉等）的印象。感觉记忆通常最多只持续几秒钟。子类别包括图像记忆（视觉）、回声记忆（听觉）和触觉记忆（触摸）。
2. **短期记忆**（STM）或**工作记忆**：存储我们当前意识到的、执行学习和推理等复杂认知任务所需的信息。短期记忆的容量据信约为 7 个项目（Miller，1956），持续 20–30 秒。
3. **长期记忆**（LTM）：长期记忆可以把信息保存相当长的时间，从几天到几十年不等，存储容量基本上是无限的。LTM 有两个子类型：
  - 外显记忆 / 陈述性记忆：关于事实和事件的记忆，指那些可以有意识地回想起来的记忆，包括情景记忆（事件和经历）和语义记忆（事实和概念）。
  - 内隐记忆 / 程序性记忆：这类记忆是无意识的，涉及自动执行的技能和习惯，比如骑自行车或在键盘上打字。

我们可以大致做如下对应：

- 感觉记忆对应于为原始输入（包括文本、图像或其他模态）学习嵌入表示；
- 短期记忆对应于上下文学习。它短暂而有限，受限于 Transformer 有限的上下文窗口长度。
- 长期记忆对应于外部向量数据库，智能体可以在查询时关注它，并通过快速检索访问。

## 最大内积搜索（MIPS）

外部记忆可以缓解有限注意力跨度的限制。标准做法是把信息的嵌入表示存入支持快速最大内积搜索（MIPS）的向量数据库。为了优化检索速度，常见的选择是*近似最近邻（ANN）*算法，返回近似的 top k 个最近邻，以损失一点精度换取巨大的速度提升。

用于快速 MIPS 的几种常见 ANN 算法：

- **LSH**（局部敏感哈希）：引入一个*哈希*函数，使相似的输入项以高概率映射到同一个桶中，而桶的数量远小于输入的数量。
- **ANNOY**（Approximate Nearest Neighbors Oh Yeah）：核心数据结构是*随机投影树*，即一组二叉树，其中每个非叶节点代表一个把输入空间一分为二的超平面，每个叶节点存储一个数据点。这些树是独立、随机构建的，因此在某种程度上它模拟了哈希函数。ANNOY 在所有树中搜索，迭代地沿着离查询最近的那一半向下搜索，然后汇总结果。这个思路与 KD 树很相近，但可扩展性强得多。
- **HNSW**（分层可导航小世界）：灵感来自小世界网络的思想，即大多数节点都可以在少量步数内由任何其他节点到达，例如社交网络的"六度分隔"特性。HNSW 构建多层这样的小世界图，最底层包含实际的数据点，中间各层创建捷径以加速搜索。搜索时，HNSW 从顶层的一个随机节点出发，向目标导航；当无法再靠近时，就下降到下一层，直到到达最底层。上层的每一步都可能在数据空间中跨越很大的距离，而下层的每一步则细化搜索质量。
- **FAISS**（Facebook AI 相似性搜索）：它基于这样的假设：在高维空间中，节点之间的距离服从高斯分布，因此数据点应当存在*聚类*。FAISS 使用向量量化，先把向量空间划分为若干簇，再在簇内细化量化。搜索时先用粗量化寻找候选簇，再在每个簇内用更细的量化进一步查找。
- **ScaNN**（可扩展最近邻）：ScaNN 的主要创新是*各向异性向量量化*。它把数据点 $x_i$ 量化为 $\tilde{x}_i$，使得内积 $\langle q, \tilde{x}_i \rangle$ 尽可能接近原始内积 $\langle q, x_i \rangle$，而不是简单选取最近的量化质心点。

更多 MIPS 算法及性能对比可参见 ann-benchmarks.com。

# 组件三：工具使用

使用工具是人类一个了不起的、与众不同的特征。我们创造、改造并利用外部物体，去做超出自身身体和认知极限的事情。为 LLM 配备外部工具，可以显著扩展模型的能力。

**MRKL**（Karpas 等，2022），全称"模块化推理、知识与语言"（Modular Reasoning, Knowledge and Language），是一种用于自主智能体的神经-符号架构。MRKL 系统包含一组"专家"模块，通用 LLM 充当路由器，把查询分派给最合适的专家模块。这些模块可以是神经的（如深度学习模型），也可以是符号的（如数学计算器、货币换算器、天气 API）。

他们以算术为测试用例，做了一个微调 LLM 调用计算器的实验。实验表明，解决文字表述的数学题比解决显式给出的数学题更难，因为 LLM（7B 的 Jurassic1-large 模型）无法可靠地提取基本算术运算所需的正确参数。结果说明，即使外部符号工具能可靠工作，*知道何时以及如何使用工具也至关重要*，而这取决于 LLM 的能力。

**TALM**（工具增强语言模型；Parisi 等，2022）和 **Toolformer**（Schick 等，2023）都通过微调语言模型来让它学会使用外部工具 API。数据集的扩充依据是：新加入的 API 调用标注能否提升模型输出的质量。更多细节参见《提示工程》一文中的"外部 API"一节。

ChatGPT 插件和 OpenAI API 的函数调用，是 LLM 借助工具使用能力在实践中发挥作用的好例子。工具 API 集合可以由其他开发者提供（如插件），也可以自定义（如函数调用）。

**HuggingGPT**（Shen 等，2023）是一个用 ChatGPT 作为任务规划器的框架：根据模型描述选择 HuggingFace 平台上可用的模型，并根据执行结果汇总回复。

该系统由 4 个阶段组成：

**（1）任务规划**：LLM 充当大脑，把用户请求解析为多个任务。每个任务有四个属性：任务类型、ID、依赖关系和参数。他们用少样本示例引导 LLM 进行任务解析和规划。

指令：

**（2）模型选择**：LLM 把任务分派给专家模型，请求被表述为一道多项选择题。LLM 会拿到一份可供选择的模型列表。由于上下文长度有限，需要按任务类型进行过滤。

指令：

**（3）任务执行**：专家模型执行具体任务并记录结果。

指令：

**（4）响应生成**：LLM 接收执行结果，并向用户提供汇总后的结果。

要把 HuggingGPT 投入实际使用，需要解决几个挑战：（1）需要提升效率，因为 LLM 的多轮推理以及与其他模型的交互都会拖慢流程；（2）它依赖很长的上下文窗口来沟通复杂的任务内容；（3）需要提升 LLM 输出和外部模型服务的稳定性。

**API-Bank**（Li 等，2023）是一个评估工具增强型 LLM 性能的基准。它包含 53 个常用 API 工具、一套完整的工具增强 LLM 工作流，以及 264 段带标注的对话，涉及 568 次 API 调用。API 的选择相当多样，包括搜索引擎、计算器、日历查询、智能家居控制、日程管理、健康数据管理、账户认证流程等。由于 API 数量很多，LLM 首先可以使用一个 API 搜索引擎来找到要调用的 API，然后根据相应的文档进行调用。

在 API-Bank 的工作流中，LLM 需要做几个决策，每一步我们都可以评估该决策的准确程度。这些决策包括：

1. 是否需要调用 API。
2. 找出要调用的正确 API：如果不够好，LLM 需要迭代修改 API 输入（例如为搜索引擎 API 决定搜索关键词）。
3. 根据 API 结果作出回应：如果结果不满意，模型可以选择改进后再次调用。

该基准从三个层级评估智能体的工具使用能力：

- 第 1 级评估*调用 API* 的能力。给定 API 的描述，模型需要判断是否调用该 API、正确地调用它，并对 API 的返回作出恰当回应。
- 第 2 级考察*检索 API* 的能力。模型需要搜索可能满足用户需求的 API，并通过阅读文档学会使用它们。
- 第 3 级评估*在检索和调用之外规划 API* 的能力。面对不明确的用户请求（例如安排小组会议、为一次旅行预订机票/酒店/餐厅），模型可能需要进行多次 API 调用才能解决。

# 案例研究

## 科学发现智能体

**ChemCrow**（Bran 等，2023）是一个特定领域的例子：LLM 配备了 13 个由专家设计的工具，用于完成有机合成、药物发现和材料设计等任务。该工作流用 LangChain 实现，体现了前文 ReAct 和 MRKL 中描述的做法，把 CoT 推理与任务相关的工具结合起来：

- 向 LLM 提供工具名称列表、工具用途描述以及预期输入/输出的细节。
- 然后要求它在必要时使用所提供的工具来回答用户给出的提示。指令建议模型遵循 ReAct 格式——`Thought, Action, Action Input, Observation`。

一个有趣的发现是：基于 LLM 的评估认为 GPT-4 和 ChemCrow 表现几乎相当，但由专家进行、着眼于解决方案完成度和化学正确性的人工评估显示，ChemCrow 大幅优于 GPT-4。这表明，在需要深厚专业知识的领域用 LLM 评估自身表现存在潜在问题：缺乏专业知识可能导致 LLM 意识不到自己的缺陷，因而无法很好地判断任务结果是否正确。

Boiko 等（2023）也研究了用于科学发现的 LLM 智能体，让它自主设计、规划和执行复杂的科学实验。这个智能体可以使用工具浏览互联网、阅读文档、执行代码、调用机器人实验 API，以及借助其他 LLM。

例如，当被要求 `"develop a novel anticancer drug"`（开发一种新型抗癌药物）时，模型给出了如下推理步骤：

1. 查询抗癌药物发现的当前趋势；
2. 选定一个靶点；
3. 请求一个针对这些化合物的骨架；
4. 确定化合物之后，模型尝试合成它。

他们还讨论了风险，尤其是涉及非法药物和生物武器的风险。他们构建了一个包含已知化学战剂清单的测试集，要求智能体合成这些物质。11 个请求中有 4 个（36%）被接受，智能体试图获得合成方案，并查阅文档以执行流程。11 个中有 7 个被拒绝，在这 7 个被拒绝的案例中，5 个发生在网络搜索之后，2 个仅凭提示就被拒绝。

## 生成式智能体模拟

**生成式智能体**（Generative Agents；Park 等，2023）是一个非常有趣的实验：受《模拟人生》启发，25 个虚拟角色各由一个 LLM 驱动的智能体控制，在一个沙盒环境中生活和互动。生成式智能体为交互式应用创造了可信的人类行为模拟。

生成式智能体的设计把 LLM 与记忆、规划和反思机制结合起来，使智能体能够基于过去的经验行事，并与其他智能体互动。

- **记忆流**：一个长期记忆模块（外部数据库），用自然语言记录智能体经历的完整列表。
  - 每个元素是一条*观察*，即由智能体直接提供的一个事件。
- 智能体之间的交流可以触发新的自然语言陈述。
- **检索模型**：根据相关性、时近性和重要性，提取用于指导智能体行为的上下文。
  - 时近性：越近的事件得分越高
  - 重要性：区分平凡记忆和核心记忆。直接询问语言模型。
  - 相关性：基于它与当前情境 / 查询的相关程度。
- **反思机制**：随着时间推移把记忆综合成更高层次的推断，并指导智能体未来的行为。它们是*对过去事件的更高层次总结*（<- 注意这与上文的自我反思略有不同）
  - 用最近的 100 条观察提示语言模型，让它根据一组观察/陈述生成 3 个最突出的高层问题，再让语言模型回答这些问题。
- **规划与反应**：把反思结果和环境信息转化为行动
  - 规划本质上是为了在当下与时间维度上优化可信度。
  - 提示模板：`{Intro of an agent X}. Here is X's plan today in broad strokes: 1)`
  - 智能体之间的关系以及一个智能体对另一个智能体的观察，都会在规划和反应时被考虑进去。
  - 环境信息以树状结构呈现。

这个有趣的模拟产生了涌现的社会行为，例如信息扩散、关系记忆（例如两个智能体延续之前的对话话题）以及社交活动的协调（例如举办派对并邀请许多其他人）。

# 挑战

在梳理了构建以 LLM 为中心的智能体的关键思想和演示之后，我开始看到几个共同的局限：

- **有限的上下文长度**：受限的上下文容量限制了历史信息、详细指令、API 调用上下文和响应的容纳量。系统设计必须在这有限的通信带宽内运作，而像从过去错误中学习的自我反思这类机制，会从很长甚至无限的上下文窗口中大大受益。尽管向量数据库和检索能提供更大的知识库访问，但其表示能力不如完整注意力强大。
- **长期规划与任务分解的挑战**：在冗长的历史上做规划、有效探索解空间仍然很有挑战性。LLM 在遇到意外错误时难以调整计划，因此不如从试错中学习的人类那样稳健。
- **自然语言接口的可靠性**：当前的智能体系统依赖自然语言作为 LLM 与记忆、工具等外部组件之间的接口。然而模型输出的可靠性存疑，因为 LLM 可能出现格式错误，偶尔还会表现出"叛逆"行为（例如拒绝遵循指令）。因此，很多智能体演示代码都集中在解析模型输出上。
