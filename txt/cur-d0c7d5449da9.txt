编程 Agent（Coding Agent）及其底层脚手架（Agent Harness）的系统架构表明，大语言模型在实际软件工程中的性能差距不仅取决于模型本身，更取决于外围系统工程。在概念分工上，基础大模型负责下一个 Token 预测；推理模型在推理阶段分配额外计算资源进行中间推演与自验证；Agent 是围绕模型建立的闭环控制系统，决策执行路径并调用工具；Agent Harness 则是维系全局生命周期的脚手架，负责上下文编排、工具路由、状态持久化与流程控制；Coding Harness 属于针对代码工程特化的子类。在各家前沿基座性能差距逐步收窄的背景下，脚手架的系统工程能力成为拉开最终编程表现的关键。

基于纯 Python 实现的 Mini Coding Agent，现代编程 Agent 包含六大核心架构组件：

一、实时仓库上下文（Live Repo Context）：Agent 在执行前预先收集 Git 分支状态、未提交修改、AGENTS.md、README 与目录树等稳定事实，组装成紧凑的工作区摘要（WorkspaceContext），避免每轮交互从零猜测项目结构，确保模型在动手前已掌握全局代码布局。

二、提示词结构与前缀缓存复用（Prompt Shape and Cache Reuse）：运行时将全局规则、工具描述与工作区摘要组织为静态的提示词前缀（Stable Prompt Prefix），尽可能触发大模型服务商的提示词缓存（Prompt Caching）降低延迟与成本；动态变化的短期工作记忆、近期交互历史与最新用户输入置于前缀之后按轮更新，避免全量重构造成的显存与计算浪费。

三、结构化工具校验与权限沙箱（Structured Tools, Validation, and Permissions）：模型不能输出自由文本命令，必须生成预定义的结构化参数。脚手架在执行前执行前置拦截校验：检查工具合法性、校验参数类型、验证目标文件路径是否严格限定在仓库根目录内，并对高危 Shell 命令触发显式用户审批，兼顾灵活性与系统安全性。

四、上下文动态压缩与输出管理（Context Reduction and Output Management）：长会话容易遭遇上下文膨胀与噪音干扰。脚手架采用双重截断与压缩策略：对过长命令输出与文件片段强制截断（Clipping）；在历史序列构建中实施非对称压缩，较早期的历史记录仅保留高层摘要，近期事件保留完整技术细节，并自动对重复读取的文件内容去重，保证输入上下文的信息纯度。

五、多层持久化会话记忆（Transcripts, Memory, and Resumption）：状态管理显式拆分为两层存储介质。底层以磁盘 JSON/JSONL 完整记录全量会话轨迹（Full Transcript），涵盖所有原始输入、工具调用与响应，用于中断后的无损恢复；上层维护极小体量的动态工作记忆（Working Memory），随轮次持续重写，记录当前任务、关键文件与临时笔记，分别解耦提示词重构与跨轮任务连续性。

六、受限边界的子 Agent 委派（Delegation and Bounded Subagents）：针对代码符号检索、配置排查或局部测试分析等辅助分支，主 Agent 可派生轻量级子 Agent。子 Agent 继承必要的基础上下文，但在执行边界上受到严格约束（如强制只读权限、隔离沙箱与递归派生深度限制），防止子进程失控或修改冲突。

相较于 OpenClaw 这类面向长生命周期、多工作区与全通道的通用本地平台，专用编程 Agent 专为单用户在本地代码仓库内的精准读写与高频修改进行垂直优化，体现了针对特定垂直工程场景裁剪控制流的系统架构优势。
