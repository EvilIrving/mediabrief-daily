使用 Shadow DOM 与样式封装的利弊（Pros and cons of using Shadow DOM and style encapsulation） ｜ Manuel Matuzovic ｜ 文章 ｜ https://www.matuzo.at/blog/2023/pros-and-cons-of-shadow-dom

奥地利前端开发者 Manuel Matuzovic 用了将近一年 Web Components 后的反思。他当初选了 Lit，文档说不推荐渲染到子元素而不是 Shadow DOM，MDN 也把封装称为 Web Components 的重要方面，于是他以为 Shadow DOM 就是核心卖点，几乎每个组件都用了它。一年里踩了无数坑之后，他在 Mastodon 上说开始怀疑样式封装和 Shadow DOM 的用处，没有它，样式和一些无障碍问题容易得多。出乎意料，很多人回复表示赞同，默认用 light DOM（普通 DOM），只在合适时才启用 Shadow DOM。这促使他重构了一些组件，并整理出这份利弊清单。他特别说明，自己首先关心的是无障碍和结构良好的语义化 HTML，JavaScript 对他只是可选的附加层，这也许解释了为什么弊端清单比好处长。

好处有三条。一是样式封装：当你给别人做组件、又无法控制使用环境里的全局样式时，它非常有用，你交付几个包含全部结构和样式的 JS 文件，升级时对方只需替换文件，不用操心内部结构和类名。Egor 在回复里说，他做的组件库要同时用于 React、Angular 和 Blazor，又碰不到文档样式，没有 Shadow DOM 几乎没法工作。对不知道谁会在什么环境、搭配什么样式表使用组件的设计系统来说，封装很合理。二是 DOM 封装：演示里页面上有四个按钮，但脚本只数出三个，绑在 document 上的点击处理也只作用于 light DOM 里的按钮；不过他也指出，即便不用 Shadow DOM，this.querySelectorAll 也只会查组件内部。三是插槽：不用 Shadow DOM 也能接收 light DOM 传入的内容，但有了 Shadow DOM，可以用具名插槽控制内容的渲染位置，light DOM 里顺序写乱了也没关系，这是他最喜欢的特性之一。

弊端则多得多。所谓样式"封装"并非百分之百：可继承属性和自定义属性会渗进来。他强调继承是好事，组件要是不能读外部的自定义属性，他几个月前就把它扔了，但为了防止渗入，得主动重置可继承属性，自定义属性最好加前缀防冲突。给插槽内容写样式时，外部上下文的普通规则优先于组件内部规则，想覆盖只能用 !important，很烦。::slotted() 只能选第一层元素，嵌套的 li 选不到，组合选择器也不起作用。light DOM 和 shadow DOM 之间无法互相引用，label 的 for、aria-labelledby、锚点链接都会失效，未来的跨根 ARIA 也许能解决一部分。Firefox 还不支持声明式 Shadow DOM，不用它又不用 light DOM，就意味着屏幕上任何东西都要靠 JavaScript 渲染，这对他不可接受；随之而来的是未定义自定义元素的样式闪烁和布局偏移，很多人建议在元素定义前用 :not(:defined) 把它隐藏，他认为那只是权宜之计。表单也会出问题：他读了 Simon MacDonald 的《Shadow DOM：不该默认使用》才知道，shadow DOM 里的输入框不会关联到外层表单；虽然可以按 Craig Buckler 文章里的方法用 ElementInternals API 解决，他引用 MacDonald 的话说，用更多 JavaScript 去修 JavaScript 制造的问题，就像递给溺水的人一杯水。全局样式也缺失了，比如他总是全局定义焦点样式，现在每个有交互元素的组件都得重复一遍，最多借自定义属性共享数值。调试也更难：WAVE 这样的无障碍检测工具未必支持 Shadow DOM，演示里至少三个错误它一个也没报；Chrome 开发者工具里用实时表达式记录 document.activeElement，聚焦 shadow DOM 里的按钮时只会返回外层组件，得再加一个记录 shadowRoot.activeElement 的表达式，而且聚焦没有 shadow root 的元素时还会报错。

他承认这些弊端大多不是致命问题，也都有绕过的办法，问题在于要考虑的东西太多，而只要不用 Shadow DOM 就能避开。他的结论是：Shadow DOM 有其道理，但不必总是首选；不过说起来容易做起来难，时间会给出答案。文末感谢 Egor、Dave 和 Simon 的反馈，并列出延伸阅读：Heydon Pickering、Simon MacDonald、Bramus Van Damme、Alice Boxhall、Egor Kloos、Craig Buckler、Nolan Lawson 的相关文章。
