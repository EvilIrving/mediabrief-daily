这是“月球大叔”直播间的一场一小时技术直播，DeepSeek V4 技术报告发布的第二天录制。主持人蓝青和月球大叔请来 SGLang 社区的三位开发者：晨阳、做推理框架的万晨、做强化学习训练的悦明，后两人都在 RadixArk。主题是 SGLang 和它的 RL 训练框架 Miles 怎样在模型发布当天就做到“Day-0”支持：推理能跑，RL 训练也能跑。前半场是两段技术分享，后半场是直播间问答，最后聊到新人怎么入门。整场的基调是：V4 的架构改动非常大，适配工作量很重，但做系统的人对此是兴奋的，因为新架构意味着新问题。

**推理：五类状态和几个关键算子**

万晨先讲推理侧最大的难点：V4 全新的混合注意力。每个新词元都要同时处理两类注意力。一类是只看最近若干词元的滑动窗口注意力（SWA）；另一类在不同层二选一，要么是把每 4 个词元压成 1 个、再从中挑出最相关部分计算的稀疏注意力（C4），要么是每 128 个压成 1 个、全部参与计算的 C128。为了维护还没攒够、尚未压缩的中间状态，框架总共要同时管理五类状态。SGLang 的解法叫 ShadowRadix：所有层共用一套虚拟地址，查找和搬运 KV Cache 时只看虚拟地址，再按层号和缓存类型映射到各自的物理存储；滑出窗口的部分在物理上直接释放，压缩中的状态用环形缓冲区，保证内存占用有上限。

算子层面他举了两个例子。KV 压缩原本要经过五次显存读写，把中间三步计算融合成一个算子后只剩两次。百万上下文下，挑选相关词元的 TopK 一次要约 100 微秒，模型 60 层累计就是 6 毫秒，严重拖慢推理；他们写的 Lightning TopK 通过改写计算流程、提高并行度，把它降到约 15 微秒。并行方面，SGLang 支持上下文并行、张量并行、专家并行和 PD 分离（prefill 与 decode 分到不同集群），也支持这些方案的各种组合。张量并行有个坑：底层内核要求注意力头数是 64 的倍数，切分后常常不满足，只能补齐，但在小批量、低延迟场景下它仍然是好选择。几类缓存所占的比例随上下文长度变化，所以内存池先静态预分配，运行时再动态调整。V4 的 KV Cache 压得很小，百万词元不到 10 GB，于是他们用 HiSparse 把不活跃的 KV 卸载到 CPU 内存，容量和吞吐最高提升三倍。他认为随着 agent 和编程类应用对上下文的需求越来越大，这会是长期方向。

**训练：最费时间的是“对精度”**

悦明解释了训练做 Day-0 为什么比推理难：除了前向还要写反向；推理掉点了一测 benchmark 就知道，训练却没有标准基线，往往要训好几天才能判断实现对不对，debug 成本极高。Miles 的目标就是让用户第一天就能用上一套验证过的 RL 系统。工作分三块。第一块是在 Megatron 里重新实现 compressor、indexer、mHC 等原生不支持的结构，打通 DP、TP、SP、EP、PP、CP 六种并行。其中 PP 要处理 mHC 带来的四维隐藏状态；CP 最麻烦，因为 C4 相邻压缩块用到的原始词元有重叠，只能先 all-gather 再切回本地。kernel 部分借用并扩展了 slime 为 GLM-5 写的 DSA indexer 和 TileLang kernel。第二块是推理与训练的联动：FP8 rollout，FP8/BF16 训练，基于 FP8 的注意力 QAT，路由重放 R3，以及实验性的 indexer replay，也就是把推理时稀疏注意力的选择结果记录下来，训练时重放，以减少不确定性。

第三块花的时间最多，就是保证训练正确且能涨点。他们把端到端每个激活和梯度张量都存下来，每次改动都逐张量比对。一个典型案例是 CP=1 和 CP=2 时，KV 梯度的余弦相似度总差 0.2，其他张量的差异只在十万分之一量级。查下来是稀疏注意力的累加路径复杂，BF16 精度不够，单把这个张量换成 FP32 就好了。他们还提前做了确定性方面的工作，比如 cuDNN 确定性模式、禁用 NCCL 的非确定性做法，之后 KL loss 的尖刺就消失了。在 32 张 GB300 上用 DAPO 训 Flash 模型，reward 和评测分数都稳定上涨，首步训推差异约 0.02。他说他们从 V3.2 起就发现这类稀疏注意力模型很难训稳，正是这些长期积累才撑起了这次的 Day-0。

**问答里的判断**

问答中有几条值得记住的观点。对精度最耗时，agent 和 skill 能帮上不少，但时间紧时仍得手工推进。训 Flash 大约需要 64 张 H200 或 32 张 GB300，Pro 预计要 256 张 H200 或 128 张 GB300。万晨认为混合注意力是大势所趋，因为模型既要看得远，显存又吃不消；MoE 也会长期存在，显存越来越大，但全用稠密计算太贵，速度与智能的权衡离不开稀疏。算子融合并非总是划算，两个算子必须沿同一维度切分，对其中一个可能不是最优。悦明认为 V4 这种近乎纯稀疏、支撑百万上下文的注意力已接近极限；RL 的 off-policy 问题尚无共识，关键是限制数据陈旧度，再靠实验找稳定性和效率的平衡点。推理中的长尾请求可以暂停、腾出空间后再处理。V4 在 GB200 上单请求约每秒 200 个 token。至于 Miles 与 slime，前者从后者分叉而来，更侧重 Blackwell 等新硬件和 agent 训练。

**给新人的建议与收尾**

万晨讲了自己的路径：第一个 PR 修的是 MoE 算子的非法内存访问，之后逐步扩展到专家并行、DP attention、投机解码和 CUDA Graph。他建议新人从标注为 good first issue 的问题入手。晨阳推荐先读代码更干净的 mini-SGLang，理解 continuous batching 等核心机制。主持人建议在大厂的工程师先设法接触算力，哪怕只有一张 A100，再补底层算子课程，从小项目做到大项目。月球大叔则谈了什么才算 systems research：每天补一个个性能“窟窿”只是出活，当你开始归纳几十个窟窿的共性，用一套抽象、优雅的设计一次性解决，并换来显著的性能提升时，才是在做研究，这需要抽象能力和美感。主持人补充说，存储、通信、计算的平衡会被每一代新硬件打破，而 PagedAttention 这类方案往往借鉴了几十年前操作系统的思想；随着 agent 兴起，很多问题正在从压榨算力转向数据管理、存储和记忆，做数据库和后端的人反而有新机会。直播在“一起乘风破浪”的祝福中结束。
