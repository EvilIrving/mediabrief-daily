GitHub Agentic Workflows 构建于 GitHub Actions 基础设施之上，将软件开发生命周期的自动化从确定性流水线延伸至自主智能体编排。由于智能体具备非确定性决策特征，且必须频繁读取工单、拉取请求、第三方日志以及外部网页等不可信输入，若将其置于传统流水线的扁平信任域中，提示注入攻击将直接威胁代码库权限与敏感凭据。GitHub 团队确立了将智能体默认视为不可信执行实体的原则，将开放式提示词编译为带有明确资源约束、网络受限和强审计能力的专用流水线作业单元。

系统安全架构由四个纵深防御支柱构成：
第一，计算环境的分层隔离机制。流水线通过声明式配置定义智能体的输入输出契约，将不可信执行环境封闭于独立容器中。宿主机文件系统通过只读命名空间和 chroot 机制实施沙箱隔离，阻止不可信进程窥探或篡改流水线底层工作目录与同级作业环境，保证宿主主机的绝对隔离与确定性状态。

第二，凭据隔离与受控网关转发体系。系统彻底剥离了智能体直接访问安全凭据及第三方 API 密钥的途径。智能体容器处于受限网络命名空间，外部互联网访问必须经由受控防火墙策略。智能体若需调用语言模型或外部工具服务，必须将结构化请求转发至特权代理网关；代理网关在边界外侧完成身份认证与密钥注入，返回清洗后的结果，从而彻底切断凭据渗漏路径。模型本身与工具执行服务均运行于独立沙箱中，杜绝侧信道泄漏。

第三，写操作暂存与合规过滤流水线。智能体在执行过程中不具备直接向版本仓库提交代码或发布版本的直接权限。所有文件修改、分支推送以及工单交互均写入受保护的暂存缓冲区。暂存内容随后接受数量上限、文件类型白名单以及安全审查规则的自动化校验，并在必要时触发人工审批流程，只有完全合规的变更才能合入主干代码库，防止恶意补丁注入。

第四，全链路密码学可验证审计记录。系统在所有信任边界记录详尽的可观测性追踪日志，全面覆盖每一次上下文注入、工具调用入参以及网络出站通信。完备的事件链不仅为安全事后审计提供数字证据，也为未来细粒度动态信息流控制确立了数据基础，实现从请求发起、策略仲裁到执行生效全周期的确定性追溯，确立了安全工程防护的高等级基准。
