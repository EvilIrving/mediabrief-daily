读代码之前我先跑的几条 Git 命令（The Git Commands I Run Before Reading Any Code） ｜ Hacker News ｜ 文章 ｜ https://piechowski.io/post/git-commands-before-reading-code/

代码审计顾问 Ally Piechowski 介绍她接手新代码库时先跑的五条 git log 命令，用提交历史判断问题在哪、团队状态如何。一是过去一年改动最多的文件，改得多又没人负责是最明确的危险信号，再和 bug 热点交叉比对；二是按提交数排贡献者，看"巴士因子"和建系统的人是否还在；三是提交信息带 fix、bug 的文件，与热点重合的就是反复坏、反复补的最高风险代码；四是按月统计提交数，骤降或持续下滑往往意味着人员流失、团队失去动力；五是 revert、hotfix 的频率，过于频繁说明团队不信任自己的部署流程。几分钟跑完，就知道先读哪些代码、注意什么。
