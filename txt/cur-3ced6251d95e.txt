起因是 McMaster-Carr 网站在推特上走红：一家百年老公司，网站却快得惊人。Wes Bos 研究后发现，最见效的一招是鼠标悬停在链接上就预加载目标页的 HTML。他借这个话题向 Scott Tolinski 介绍浏览器新推出的 Speculation Rules API；CSS Wizardry 的 Harry Roberts 已经在自己的网站上用上了。

他们先回顾老办法。link rel="preload" 提前下载字体、首屏图片这类资源；preconnect 只提前做好 DNS 和 SSL 握手，免得 HTML、CSS、字体一层层排队请求。Scott 的比方是：preload 是"穿鞋上车出发"，preconnect 是"先把导航打开"。新 API 是在页面里放一个 type="speculationrules" 的脚本，用正则或 CSS 选择器写规则，指定哪些链接要 prefetch（只下载 HTML），哪些要 prerender（像后台标签页那样连资源一起完整渲染，点击后瞬间切换）。积极程度用 eagerness 设定，分 immediate、eager、moderate、conservative 四档；浏览器还会参考网速、设备性能和电量自行决定，比如电量只剩 4% 就不预取。

两人重点讨论了代价。一个 HTML 页面大约 30–100K，静态页走 CDN 几乎不花钱；但如果按带宽计费，或者每个页面都要服务器渲染，预取 10 个页面就等于 10 倍的带宽、服务器和数据库开销。缓解办法有：用缓存头和 stale-while-revalidate 让 CDN 缓存；把状态放进 URL 参数，首次渲染后缓存起来，不必把上万种组合全部预生成；个人数据页不能放进全局缓存。Scott 补充说，SvelteKit 写 prerender = true 就能在构建时静态化路由；用户那边的流量套餐也要考虑。McMaster-Carr 本身靠激进缓存，只是预取 HTML，局部替换页面，并没有用 prerender。有人用 Next.js 仿写了一个 Next Master，公开的 Vercel 账单是：4.5 万独立访客、约 100 万次浏览，共 513 美元，其中 Edge 请求 220 美元，图片优化 160 美元是一次性的。Wes 认为自己托管能便宜很多。这个 API 目前只有 Chrome 支持，但已经有 polyfill；Next.js 则能细到组件层面去预取。

最后他们批评了对 PageSpeed/Lighthouse 分数的迷信。McMaster-Carr 分数很低，普通用户却都说它是最喜欢的网站；wesbos.com 移动端七十多分，vercel.com 只有 44 分，用起来却飞快；同一个网站多跑几次，分数能从 80 掉到 50。Scott 的结论是，用户实际感受到的速度比分数重要，预加载、缓存和本地优先应用（首次加载重，之后每个操作都是瞬间）才是让网站"感觉快"的正道。
