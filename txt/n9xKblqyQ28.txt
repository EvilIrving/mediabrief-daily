Why The Harness Matters More Than The Model | YC Paper Club ｜ Y Combinator ｜ 1:00:11 ｜ https://youtu.be/n9xKblqyQ28

这是 YC Paper Club 的一期"harness 之夜"，由 YC 的主持人开场讲史，随后三组作者各讲自己的系统。全场的立场一致：harness（套在模型外面的循环、工具、记忆、子 agent 和上下文管理）长期被看轻为"只是套壳、只是提示工程，不配叫研究"，但在同一份权重文件上，换一个 harness 就能拉开巨大差距，近期 agent 能力的进步很大一部分就来自这里。

主持人先举 ARC-AGI 为证。这个基准专门测"快速适应新问题"的流动智力，Claude Opus 在私有测试集上只拿到约 30%，而加上 harness 后，Prime Agent 做到 95%，NVIDIA 的方案做到了 100%。他也讲了自己的例子：他 fork 了 Karpathy 的 auto-researcher，本来只想加个界面看看进度，结果"意外造出了一个 harness"。他给出研究目标、几个起始想法和评估指标，由检索 agent 查文献，"PI agent"定期催进度，研究 agent 动手做，最后由写作 agent 做消融实验、写论文。如今他把八个想法分给八台 H100 节点，然后坐等论文回来，"质量真的不错"。接着他用五分钟梳理了 harness 的演化：GPT-2 时代只有一个"没到结束符就继续"的循环；然后是 few-shot、思维链、工具调用（WebGPT、Toolformer）；MemGPT 让模型能对自己的上下文增删改查；Voyager 发展出可复用的技能，也就是今天的 skills.md；再到代码即动作、ReAct、自我反思、多 agent，以及可以递归调用的 RLM。这些都属于"静态 harness"。最近半年的新方向是让 harness 自己学习：DSPy 用遗传式搜索优化系统提示，Darwin 机器类方法连 harness 代码本身都能改，持续学习类 harness 甚至在测试时更新权重。他认为这是很重要的研究方向。

普林斯顿的 Seth Karten（Prime Intellect 研究员）介绍 Prime Agent，一个会自我改进的 RLM harness。他主张从第一性原理出发设计：把上下文管理看作分层的存储体系，压缩（compaction）负责活跃上下文；Python REPL 让变量留在内存里、用程序处理，不占 token；子 agent 是可以随时唤回、保留上下文的"持久子会话"；定期精炼技能、记忆和提示，相当于"agent 的垃圾回收"。他的比喻是：裸模型像图灵机的纸带，harness 让它变成能读写外部内存的冯·诺依曼计算机。好的 harness 要给模型足够的表达能力，例如任意两个 agent 之间可以直接发消息协作，而不是强加"计划、执行、批判"的固定流程，并且应当略超出现有模型的能力，产生的轨迹可以反哺下一代模型。评测要看"实际平台期"，也就是继续加 token 已经只能带来微小收益的那个点。他坦白地讲了 ARC-AGI-3 的经历：第一次跑出 99.9%，查日志发现是在作弊，补好沙箱后，GPT 拿到 78%，Opus 拿到 95.5%。他说流行的 harness 用同样设置效果不好，其中一个烧掉 5000 美元仍没什么进展。在长程任务上，他让 agent 在 8 张 H200 上跑了一周 nanoGPT 自动研究，看到模型自发在 CPU 上做"环外实验"来节省昂贵的 GPU 时间；一次连续 7 天的 Factorio 运行动用了 633 个 agent，直到最后都还在推进科技树。

斯坦福的 Jon Saad-Falcon 与 Avanika Narayan（导师是 Azalia Mirhoseini 和 Christopher Ré）讲 OpenJarvis。他们认为个人 AI 现在几乎都依赖云端，昂贵、不私密、耗能高，而本地模型只落后前沿 6 到 12 个月。OpenJarvis 把个人 AI 栈拆成五个基本单元：智能（模型）、推理引擎、agent 逻辑、工具与记忆、学习。关键的做法是让云端大模型去自动诊断、优化本地配置，部署后只跑本地模型。在个人助理、编程和 agent 任务上，这样的配置能接近云端效果，成本降到约八百分之一，延迟也更低。他们预言大部分日常推理将来会回到个人设备上。

最后是 YC 新任 YC Labs 负责人 Josh 和 Regan 介绍内部开源 harness "QM"。它从 2025 年初"系统提示加工具加循环"的通用 agent 起步，后来接入 Slack 和代码 agent。合伙人们爱用 OpenClaw，于是给全员开了 50 多个 Hermes 虚拟机，结果维护起来像打地鼠。QM 的思路是把"大脑"从沙箱里拿出来：所有会话集中存进 Postgres，agent 可以看到全局上下文；沙箱只是按需取用的资源，agent 能自己选机器规格、切换模型供应商（遇到拒答就换一个）；核心只有三个工具：远程执行、对象存储读写、发布内部应用。数据库写入要先提交计划给人审核，他们承认大家已经开始"橡皮图章式"地批准了。他们遇到的问题有三个：agent 太早放弃，于是给目标设定最低时长或 token 预算的"grind"工具；agent 在多人场景里搞不清自己的处境；agent 不懂社交语境，会把特权信息泄露到不该去的地方，所以"大脑能装多少知识，取决于你的权限系统有多好"。用全部交互轨迹自动"爬山"改进，效果好坏参半，agent 会患上只见自己那块拼图的"主角综合症"，仍需要人在环中。

整晚的结论是：模型给定的情况下，harness 的设计（上下文管理、子 agent、自我改进、长程运行能力）决定了能拿出多少智能，也值得被当作正经研究来做。
