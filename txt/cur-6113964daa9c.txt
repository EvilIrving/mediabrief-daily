在面向大语言模型的智能体（Agent）系统架构中，调度系统存在“大脑”（宿主 Harness）与“手”（目标执行环境 Execution Environment）的明确物理与信任边界。Codemode 机制通过在受信任的宿主侧嵌入轻量沙箱运行时，让模型直接编写代码编排工具调用，从根本上解决由工具调用导致上下文窗口膨胀、并发调度受限与跨环境状态丢失引发的工程瓶颈。

在常规设计中，Agent 通常依赖 Bash 与命令行工具组合外部能力。命令行工具天然适合在文件系统内管道式传递数据，且模型在预训练与强化学习中已经对文件路径与终端命令语义建立了深厚直觉。然而，Bash 的执行边界仅限于可独立运行的系统程序，无法承载需要宿主原生介入的底层能力。例如，多模态模型的图像读取（view_image）不能简单通过 cat 获取，必须由宿主将二进制载荷注入模型协议；子 Agent 的递归派发与生命周期管理，若强行通过 Unix Socket 或环境变量在外部脚本与宿主间通讯，会导致通信链路脆弱且权限边界模糊。更深层的矛盾在于信任分级：目标执行环境往往运行在受限制的容器或 Gondolin 沙箱中，处理不可信代码；而负责调度与协议组装的宿主是受信任的控制平面。

Codemode 在宿主内部开辟了一个无网络、无文件系统、无计时器且严格限制内存的 WASM QuickJS 沙箱，专门执行模型生成的 JavaScript 调度代码。这一设计重构了工具交互流程：
1. 规避上下文污染：传统工具调用若产生大体积输出，宿主通常只能截取末尾数千行塞入上下文，迫使模型在下一轮对话中反复读取溢出文件；在 Codemode 下，工具调用的中间数据（如数百个 API 对象的结构化响应）直接停留在 JS 沙箱内存中，模型通过代码完成过滤、投影与聚合后，仅将精简后的最终结果送回上下文。
2. 表达并发与高级工作流：模型可原生使用 Promise.allSettled 或 Promise.all 并行触发批量工具请求。实际生产中最有效的工作范式是“小样本探测后批处理”：模型先调用工具拉取 5 到 10 条真实数据探测响应模式，验证字段逻辑后再编写 Codemode 循环处理全部数据集。
3. 跨轮次状态驻留：Codemode 允许脚本将中间计算状态持久化到会话上下文（Transcript）中，后续轮次的 Codemode 调用可以直接载入先前留存的变量，避免在外部文件系统中进行易碎的状态序列化。

针对当前 Model Context Protocol（MCP）生态，Codemode 暴露了协议层面的摩擦。部分服务端（如 Cloudflare MCP）由于缺乏宿主侧原生代码支持，选择在 MCP 服务内部嵌套代码执行引擎，导致宿主内外的“双重 Codemode”困境：代码需要嵌套在 JSON 字符串中二次转义，小参数模型极易生成格式语法错误，且内层代码完全无法访问外层宿主工具。要使 MCP 与代码化调度无缝契合，服务端与协议规范需满足四项关键约束：
- 结构化内容规范：工具必须返回符合 outputSchema 定义的稳定 JSON 结构，而非拼装的纯文本。
- 响应模式一致性：禁止为了节省 Token 而在小样本探测与大规模批量返回之间动态裁切数据结构，模式漂移会导致模型编写的映射函数在全量运行时崩溃。
- 原生二进制支持：协议必须规范化解决图像与大文件载荷，消除使用预签名 URL 等绕行手段带来的时序与安全缺陷。
- 可组合的工具检索：随着挂载工具膨胀，宿主需要高效、可组合的工具发现接口，而非简单将数十个工具元数据平铺进系统提示词。

Codemode 确立了以受限代码运行时替代纯文本提示词调度的确定性方向。后续架构演进的核心在于引入类似持久化工作流（Durable Workflow）的调用快照机制以保证故障恢复，以及评估是否采用 Starlark 等确定性脚本语言替代动态 JavaScript，以进一步收敛执行副作用并提升小模型的执行稳定性。
