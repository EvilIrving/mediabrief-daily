韩国外卖巨头 Woowa Brothers（优雅的兄弟们 / 配送的民族）技术团队分享了其将企业级 AI 治理（AI Governance）深度集成至内部技术底座的工程实践，通过统一网关、权限隔离、成本透明化与安全护栏，化解多模型与智能体生态下的合规与算力成本失控风险。

## 一、背景与挑战：多供应商混乱与凭证滥用

此前，企业内部各业务部门分散调用外部大模型与 MCP 服务，面临典型的治理失控：
- **申请入口碎片化**：开发者分别从 AWS Bedrock、第三方供应商（GCP/Azure）及内部平台独立申请凭证；
- **成本归属模糊**：多个研发课题共用相同密钥，总账单虽可见，但无法精细拆解各项目的实际消耗；随着 Agent 自主多轮调用的普及，成本黑盒问题被成倍放大；
- **安全与合规死角**：缺乏对个人隐私数据（PII）外发与高危工具调用的硬性拦截手段。

## 二、架构核心：AI Gateway 与 AI Studio 的双轮驱动

### 1. 基于 LiteLLM 的统一 AI Gateway
企业将所有 LLM 与 MCP 工具调用全量收拢至自建的 AI Gateway：
- **Virtual Key 体系**：以具体研发项目（Project）为基本管理单元，向调用方发放虚拟密钥（Virtual Key）。网关在转发请求前，严格校验该 Key 绑定的允许模型列表、预算限额、RPM（每分钟请求数）与 TPM（每分钟 Token 数）；
- **链路打通**：在 AI Gateway、Virtual Key 与 Langfuse 分布式追踪系统中使用完全一致的项目标识符，确保调用轨迹、审计日志与成本消耗端到端无缝对齐。

### 2. AI Studio 统一控制中枢
将原本分散的申请入口整合为单一的 AI Studio 门户：
- **分级自动化审批**：注册课题时依据标准化政策自动化评估，默认安全配额直接发 Key；仅当涉及高成本旗舰模型、申请超额预算或涉及数据安全例外场景时，才联动企业内部 OA 审批流进行成本与安全专项审核；
- **元数据同源联动**：服务负责人与业务用途对接内部服务目录（Service Catalog），审批状态直连审批流系统，预算与模型策略直连网关，Virtual Key 自动继承项目全部合规属性。

## 三、FinOps 成本精细化度量与缓存实战

- **实时对账 vs 账单滞后**：AI Gateway 在请求发生时即时计算扣减成本，而 AWS Bedrock 官方账单通常存在约两天的结算延迟；配合按角色的可视化大盘与 Slack 预警机器人，在预算接近耗尽或发生调用突增时自动熔断阻断；
- **Prompt Cache 性能与成本实证**：在真实生产案例中，团队通过将动态变量剥离至 User 消息、并在 System 提示词中注入 `cache_control`，使 Prompt 缓存命中率从 5% 飙升至 97%，单次请求 Token 成本断崖式下跌 84%；但平均响应延迟从 0.79 秒微增至 1.33 秒（因 LiteLLM 需额外执行一次 Gemini 缓存查询）；
- **跨区域推理政策优化**：针对符合地域合规要求的课题，开放 Global 跨区域推理路由，输入输出单价相较于固定 Geographic 区域低约 10%。

## 四、SecOps 数据安全护栏与隔离底盘

- **分级路由机制**：涉及用户个人隐私或高密业务数据的请求，硬性路由至企业内部自建推理的私有化 AI Platform；常规公开信息才允许分发至公有云供应商（Bedrock、Azure、GCP）；
- **多阶段生命周期拦截**：安全护栏挂载于调用前（pre_call）、调用中（during_call）与调用后（post_call），支持对敏感字段执行掩码脱敏（MASK）及对违规内容执行直接阻断（BLOCK）；
- **基础设施物理隔离**：AI 底座整体迁移至独立 AWS 账户与专用 VPC，仅暴露 AI Gateway 入口。通过 IRSA（IAM Roles for Service Accounts）实现无凭据认证，公网访问严格限制固定 IP 白名单，管理端强制启用企业 SSO 单点登录；
- **高可用发布保障**：采用零中断发布策略，先起新 Pod，摘除旧 Pod 流量后强制等待 30 秒以排空在途请求；多可用区分散部署，供应商接口异常时自动执行指数退避重试或故障降级切流。

## 五、Agent 专属治理与演进规划

针对长程智能体，平台通过公共 Helm Chart 固化模型与安全 MCP 访问链路：
- **高危工具硬隔离**：严格封禁未经安全审计的终端控制（Bash）、本地文件系统、动态代码执行及无头浏览器等高危扩展；
- **权限向下透传**：Agent 发起的所有下游业务查询，强制以终端用户的真实身份权限执行，防范提权越权；
- **演进路线**：下一步将构建中心化 Agent 注册表（Agent Registry）、按会话级（Session-level）限制调用总成本与步数上限、深化 Agent 细粒度认证授权，并依托 Slack 终端用户反馈闭环驱动 Langfuse 质量评估评分。
