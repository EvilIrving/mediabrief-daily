Anthropic 的 Claude Platform 工程负责人 Katelyn Lesse 与主持人 Gergely Orosz 对谈，讲述一个小团队用约五到六个月，把承载 Claude 每一个词元的 API 层从 Python 单体整体重写为 Rust，以及智能体接手大部分实现工作之后，工程师的时间怎样转向协调、设计和打造工具。

Lesse 大学原读化学工程，上过计算机导论后转专业；在智能投顾公司 Betterment 实习并全职近七年，较早转做管理，带领 401(k) 新业务团队；之后在 Stripe 做贷款业务 Stripe Capital。她负责的平台处在推理层之上、应用之下：请求先经过认证授权，随后进入多区域、多云的 CPU 集群，完成分词、计费和安全检查，才送往 GPU。公司自己的应用与外部客户用同一套 Messages API，一个请求可以保持打开约一小时。

重写的起因是 CPU。原系统约三年前由一个与研究交叉的小团队用 Python 写成，曾只部署在单个 GCP 区域。请求量持续攀升，超级碗广告带来的应用下载同样经过 API，CPU 集群吃紧，向云厂商要更多 CPU 也比以往艰难。团队先做了多区域部署和基础设施层面的优化，之后一位工程师提议改用 Rust。此前新服务选 Go，是因为当时模型还没好到语言无所谓；如今模型能处理借用检查器之类的实现细节，Rust 大量的编译期检查又让智能体的产出更可验证。她估计约 75% 的情况下不必懂确切语法，约 25% 出于工程师天性会向模型提问学习。

原计划逐块拆分，进展太慢。一位新来的资深工程师提议“大跃进式”一次性重写：保留一层很薄的 Python 前门，请求照常经过 Python，同时把影子流量送进 Rust，逐日压低两边输出不一致的比例。难点在于公司不看用户的提示词和补全，只能比对进入推理之前的各层，并在返回时核对词元数。上线初期 Python 前门仍作为出错时的回退。团队估计约 80% 由智能体开出的拉取请求没有逐行细读，约 20% 需要深挖。曾有一个 beta 功能在 Python 侧意外转为正式发布，影子流量随即出现大量差异，此后团队加入 lint 和静态分析，要求周边团队同时写 Python 与 Rust 实现。新人入职也不靠白板讲解了，而是直接请 Claude 解释系统，它借助各系统的 MCP 服务器读代码库，可生成交互式应用、文字、视频或播客风格的材料。她还对比 Stripe：当年 V2 抽象改用 Java，写到一半因预计要花好几年而退回 Ruby。

Claude Managed Agents 是从零构建的项目。最初方案是每个请求启动一个沙箱，在里面启动 Claude Code，结果有四个问题：沙箱挂掉智能体随之失效，启动延迟高，凭证与智能体同处沙箱，每个会话都占用 CPU。早期 beta 之后团队从第一性原理推倒重来：运行框架放在持久服务器上，只在需要执行时创建沙箱，会话存储独立；凭证存放在保险库，由旁路代理在请求出口处即时附加；CPU 用量约为原系统的三分之一。从想法到上线约五到六个月。她加入时 API 团队约 30 名工程师，这类构想过去只能搁置。

团队仍是五到十人的“两个披萨”规模，以便理解系统、维持值班轮岗，但人员更偏资深，人人都在做设计和跨团队协调，普通工程师花在协调上的时间多于实现。日常工作大多在 Slack 里与“一个 Claude”合作，相关产品 Claude Tag 依此理念设计。一个 Claude 分类器检查每个改动，决定是否需要人看、需要几个人和哪些团队；升级 SDK 版本号这类机械改动可以无人评审直接合并，CI 变红由智能体修复，这类比例在逐步提高。API 值班已有 Claude 影子值班，先判断告警是否为噪音，确属问题时升级给人，人到电脑前时它往往已给出诊断和修复建议。一位产品经理与自己的 Claude 在 Slack 里做出开发者控制台的提示缓存诊断功能并推到生产环境；出了问题，被呼叫的仍是负责该系统的开发者体验团队。中央基础设施部门的开发者加速团队打造了源代码管理系统 Scion，平台内部的 Platform Acceleration 团队做了 QA 智能体等工具。她认为投入工具这类“元工作”的人力比重反而上升，一位工程师自发搭建了在 Slack 频道里编排多智能体团队的实验。

招聘方面，编程面试被逐步淘汰，因为其他面试表现出色的候选人如今很少手写代码，常在这一轮失手；团队正试验评审智能体写的代码或系统设计、借助编程智能体构建系统等面试，技术设计和项目深挖面试不变。职级、晋升和绩效评估仍在，但项目耗时已无法代表复杂度，评价回到影响力，例如节省的 CPU、降低的延迟、避免的事故以及跨团队协调的质量。反馈大部分公开透明。

对陷入身份认同困境的工程师，她语气乐观：要让成千上万个智能体协作解决药物上市申报这类难题，人得先解决安全、身份认证、基础设施等底层工程问题；她团队有人参与创造并维护 MCP，与他们合作的另一批人在研究让智能体操作实验设备的模型硬件标准 MHS。她的建议是提高野心水平，在变得更重要的领域钻得更深。Orosz 在结尾认为多数公司终将放弃编程面试，招聘会更主观，并对产品经理普遍发布生产代码持保留态度。
