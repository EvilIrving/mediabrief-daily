2025 年即将结束，我想回顾这一年大语言模型领域最重要的一些进展，反思仍然存在的局限和悬而未决的问题，并谈谈对接下来可能发生什么的一些想法。

就像我每年都会说的那样，2025 年对 LLM 和 AI 来说是非常多事的一年，而且今年丝毫没有进展趋于饱和或放缓的迹象。

# 1. 推理、RLVR 与 GRPO 之年

我想谈的有趣话题很多，不过先按时间顺序，从 2025 年 1 月说起。

规模扩展依然有效，但它并没有真正改变 LLM 在实际使用中的行为和感受（唯一的例外是 OpenAI 刚刚发布的 o1，它加入了推理轨迹）。所以，当 DeepSeek 在 2025 年 1 月发布 R1 论文，表明可以用强化学习培养出类似推理的行为时，这是一件非常重大的事。（在 LLM 的语境中，推理指模型会解释它的答案，而这种解释本身往往能提高答案的准确率。）

## **1.1 DeepSeek 时刻**

DeepSeek R1 受到大量关注，原因有好几个：

第一，DeepSeek R1 以开放权重模型的形式发布，表现非常好，可以与当时最好的专有模型（ChatGPT、Gemini 等）相媲美。

第二，DeepSeek R1 论文促使许多人，尤其是投资者和记者，回头重读 2024 年 12 月更早发布的 DeepSeek V3 论文。这随后导致人们修正了结论：训练最先进的模型虽然依然昂贵，但可能比之前以为的便宜一个数量级，估算更接近 500 万美元，而不是 5000 万或 5 亿美元。

DeepSeek R1 的补充材料估计，在 DeepSeek V3 的基础上训练 DeepSeek R1 模型又花了 29.4 万美元，同样远低于所有人的预想。

当然，500 万美元这个估算有很多需要注意的地方。例如，它只涵盖了最终模型训练那一次运行的算力费用，没有计入研究人员的薪水，以及与超参数调优和实验相关的其他开发成本。

第三，也是最有意思的一点，论文提出用 GRPO 算法实现*基于可验证奖励的强化学习*（Reinforcement Learning with Verifiable Rewards，RLVR），作为开发所谓推理模型、在后训练阶段改进 LLM 的一种新的（或者至少是改进的）算法方法。

在此之前，监督式指令微调（SFT）和基于人类反馈的强化学习（RLHF）等后训练方法——它们至今仍是训练流程的重要组成部分——都受制于需要昂贵的人工撰写回答或偏好标注这一瓶颈。（当然，也可以用其他 LLM 合成生成这些数据，但这有点像先有鸡还是先有蛋的问题。）

DeepSeek R1 和 RLVR 之所以如此重要，在于它们让我们能在大量数据上对 LLM 进行后训练，这使它们成为在后训练阶段通过扩展算力（在可用算力预算内）来提升和解锁能力的绝佳选择。

RLVR 中的 V 代表"可验证"（verifiable），意思是我们可以用确定性的方法分配正确性标签，而这些标签就足以让 LLM 学会解决复杂问题。（典型的类别是数学和代码，但也可以把这个思路扩展到其他领域。）

我不想在这里过多陷入技术细节，因为在这篇年度回顾文章里我还想谈其他方面。关于推理 LLM 和 RLVR，完全可以写出整篇文章甚至整本书。例如，如果你有兴趣了解更多，可以看看我之前的文章：

话虽如此，结论是：今年的 LLM 发展基本上由使用 RLVR 和 GRPO 的推理模型主导。

在 DeepSeek R1 之后，基本上每一家主要的开放权重或专有 LLM 开发者都发布了自家模型的推理（常被称为"思考"）版本。

## **1.2 LLM 的发展重点**

如果要为每一年简要概括 LLM 发展的重点（除了单纯扩展架构和预训练算力之外），我的清单会是这样：

- **2022 RLHF + PPO**
- **2023 LoRA SFT**
- **2024 中期训练（Mid-Training）**
- **2025 RLVR + GRPO**

预训练依然是一切的必要基础。除此之外，RLHF（通过 PPO 算法）当然就是 2022 年最初带给我们 ChatGPT 的东西。

2023 年，大量关注集中在 LoRA 以及类似 LoRA 的参数高效微调技术上，用来训练小型定制 LLM。

然后在 2024 年，所有主要实验室都开始让自己的（预）训练流程更加精细，重点放在合成数据、优化数据配比、使用领域特定数据，以及增加专门的长上下文训练阶段上。我当时在 2024 年的文章中总结了这些不同的方法（我把这些技术归在预训练之下，因为那时"中期训练"这个词还没有被提出来）：

当时我把它们视为预训练技术，因为它们使用的是相同的预训练算法和目标。如今，这些在通用数据上的常规预训练之后进行的、稍微更专门化的预训练阶段，常被称为"中期训练"（作为常规预训练与后训练之间的桥梁，后训练包括 SFT、RLHF，以及现在的 RLVR）。

那么，你可能会问：接下来是什么？

我认为明年我们会看到对 RLVR（更多的）关注。目前，RLVR 主要应用于数学和代码领域。

合乎逻辑的下一步，是在 RLVR 训练中不仅用最终答案的正确性作为奖励信号，还要评判 LLM 的解释过程。这在过去许多年里已经有人做过，研究上称为"过程奖励模型"（process reward models，PRM）。然而，它到目前为止还不算非常成功。例如，引用 DeepSeek R1 论文中的话：

**4.2. 不成功的尝试**

［……］总之，虽然 PRM 在对模型生成的前 N 个回答进行重排序或辅助引导式搜索（Snell 等，2024）方面表现出不错的能力，但在我们的实验中，与它在大规模强化学习过程中引入的额外计算开销相比，它的优势有限。

不过，看了上个月发布的 DeepSeekMath-V2 论文（我在上一篇文章《From DeepSeek V3 to V3.2: Architecture, Sparse Attention, and RL Updates》中讨论过），我认为将来我们会看到更多把"解释评分"用作训练信号的做法。

目前对解释进行评分的方式需要用到第二个 LLM。这引出了我看到的 RLVR 的另一个方向：扩展到数学和代码之外的其他领域。

所以，如果你今天问我 2026 年和 2027 年的前景如何，我会这样说：

- **2026 RLVR 的扩展，以及更多推理时扩展**
- **2027 持续学习**

除了前面提到的 RLVR 扩展之外，我认为 2026 年会更关注推理时扩展（inference-time scaling）。推理时扩展是指在训练完成之后、让 LLM 生成答案时投入更多时间和金钱，但它的效果很显著。

推理扩展并不是一个新范式，LLM 平台已经在底层使用某些相关技术。它是延迟、成本和回答准确率之间的权衡。然而，在某些准确率比延迟和成本更重要的应用中，极端的推理扩展完全值得。例如，正如最近的 DeepSeekMath-V2 论文所示，它把模型推到了一项高难度数学竞赛基准的金牌水平。

今年同事之间也经常谈到持续学习。简单来说，持续学习是指在不从头重新训练的情况下，用新数据或新知识训练模型。

这不是一个新想法，我也纳闷为什么它今年被提得这么多，因为到目前为止持续学习并没有任何新的或实质性的突破。持续学习面临的挑战是灾难性遗忘（正如持续预训练的实验所显示的，学习新知识意味着 LLM 会在一定程度上遗忘旧知识）。

不过，既然这似乎是一个如此热门的话题，我确实预计未来几年在尽量减少灾难性遗忘方面会有更多进展，持续学习方法的研发也会成为一个重要的发展方向。

# 2. GRPO：年度研究宠儿

在 LLM 训练成本高昂的时代，学术研究近几年颇具挑战。当然，尽管预算较小（或者正因为预算较小），学术界依然可以做出重要发现，并成为主流以及 LLM 进步与突破的关键支柱。

近年来的热门例子包括 LoRA（《LoRA: Low-Rank Adaptation of Large Language Models》，2021）及相关的参数高效微调方法。

另一个例子是 DPO（《Direct Preference Optimization: Your Language Model is Secretly a Reward Model》）及相关的无需奖励模型的对齐方法，它们是基于人类反馈的强化学习的一种替代方案。

在我所处的圈子里，今年的研究亮点是 GRPO。虽然它是在 DeepSeek R1 论文中提出的，并非源自学术界，但它依然让研究者度过了激动人心的一年：RLVR 和 GRPO 在概念上都很有意思，而且视规模而定，做实验的成本并不会高到令人望而却步。

因此，今年我在 LLM 研究文献中看到了许多对 GRPO 的数学改进（来自公司和学术研究者），这些改进后来被最先进 LLM 的训练流程所采用。例如，其中一些改进包括：

- 零梯度信号过滤（DAPO，Yu 等，2025）
- 主动采样（DAPO，Yu 等，2025）
- token 级损失（DAPO，Yu 等，2025）
- 去掉 KL 损失（DAPO，Yu 等，2025；Dr. GRPO，Liu 等，2025）
- 提高裁剪上限（Clip higher，DAPO，Yu 等，2025）
- 截断重要性采样（Yao 等，2025）
- 去掉标准差归一化（Dr. GRPO，Liu 等，2025）

- 按领域设置不同 KL 强度的 KL 调节（数学领域为零）
- 重新加权的 KL
- 离策略序列掩码
- 为 top-p / top-k 保留采样掩码
- 保留原始 GRPO 的优势归一化

我可以确认，这些 GRPO 技巧或修改在实践中影响巨大。例如，加入其中一些或多项修改之后，糟糕的更新不再毁掉我的训练运行，我也不再需要定期重新加载检查点。

# 3. LLM 架构：走到岔路口？

说到 LLM 架构，最先进的模型仍在使用老牌的解码器式 Transformer。不过今年，开放权重 LLM 或多或少都趋同于使用混合专家（MoE）层，以及至少一种"效率优化版"的注意力机制：分组查询注意力、滑动窗口注意力或多头潜在注意力。

在这些相当标准的 LLM 架构之外，我们也看到了一些更激进的效率优化，针对注意力机制，让它随序列长度线性扩展。例子包括 Qwen3-Next 和 Kimi Linear 中的 Gated DeltaNet，以及英伟达 Nemotron 3 中的 Mamba-2 层。

总之，我不想在这里讲太多细节，因为如果你想了解更多，我有一整篇 1.3 万词、最近刚更新过的专门文章讲这些架构：《The Big LLM Architecture Comparison》。

我的预测是，至少在未来几年里，我们还会继续沿用 Transformer 架构进行构建，至少在追求最先进建模性能方面如此。

与此同时，我确实认为我们会看到越来越多像 Gated DeltaNet 和 Mamba 层这样的效率和工程优化，因为以 LLM 训练、部署和使用的规模来看，这些公司仍在 LLM 服务上大量烧钱，从财务角度看这样做完全合理。

这并不意味着没有其他替代方案。比如，正如我在《Beyond Standard LLMs》中写过的，文本扩散模型就是一种有意思的方法。目前它们属于实验性研究模型的范畴，但谷歌已经表示将发布 Gemini Diffusion 模型。它在建模质量上不会与谷歌最先进的产品匹敌，但会非常快，对低延迟要求的任务（例如代码补全）很有吸引力。

另外，两周前开放权重的 LLaDA 2.0 模型发布了。其中最大的一个有 1000 亿参数，是迄今为止最大的文本扩散模型，水平与 Qwen3 30B 相当。（是的，它整体上并没有推进最先进水平，但在扩散模型领域仍是一次值得关注的发布。）

# 4. 这也是推理扩展和工具使用之年

通过扩展训练数据和架构来改进 LLM，是一个成熟且（仍然）持续见效的公式。然而，尤其是今年，它已经不再是"唯一"足够的配方。

我们在 GPT 4.5（2025 年 2 月）身上看到了这一点。据传它比 GPT 4（以及后来发布的 GPT 5）大得多，而单纯的规模扩展通常并不是最明智的前进方式。GPT 4.5 的能力或许比 GPT 4 强，但增加的训练预算被认为"性价比很差"。

相反，更好的训练流程（更加注重中期训练和后训练）以及推理扩展推动了今年的大部分进展。

例如，正如前面谈到达到数学金牌水平的 DeepSeekMath-V2 时所讨论的，推理扩展是我们可以拉动的杠杆之一，让 LLM 按需解决极其复杂的任务（GPT 的 Heavy Thinking 或 Pro 是其他例子；由于延迟和成本很高，把它们用于所有事情并不合理，但在某些情况下，比如高难度的数学或编程问题，高强度的推理扩展是合理的）。

另一项重大改进来自在训练 LLM 时就考虑到工具使用。你可能知道，幻觉是 LLM 最大的问题之一。可以说幻觉率在不断改善，而我认为这在很大程度上要归功于工具使用。例如，当被问到 1998 年 FIFA 世界杯冠军是谁时，LLM 不必靠记忆，而是可以通过工具调用传统搜索引擎，从关于这个话题的可信网站（比如在这个例子里就是 FIFA 官网本身）选取并抓取这条信息。数学问题也是一样，可以使用计算器 API，等等。

例如，OpenAI 的 gpt-oss 模型就是今年较早发布的、专门为工具使用而开发的开放权重模型之一。

遗憾的是，开源生态还没有完全跟上，许多（如果不是大多数）工具默认仍以非工具使用模式运行这些 LLM。原因之一是这是一个较新、仍在演变的范式，相关工具需要做出调整。另一个原因是，由于安全问题，这本身就是一个更难解决的问题（给 LLM 不受限制的工具访问权限，可能带来安全风险，或在你的系统上造成其他破坏。我认为应该始终问一个合理的问题：你会信任一个新来的实习生，让他拥有对你系统这么大的访问权限来做这件事吗？）

我确实认为，在未来几年里，在本地使用 LLM 时启用并允许工具使用会越来越普遍。

# 5. 年度词汇：Benchmaxxing（刷榜）

如果要选一个词或一种趋势来描述今年的 LLM 发展，那就是"benchmaxxing"。

这里的 benchmaxxing 指的是高度专注于推高排行榜上的数字，有时甚至到了基准表现本身成为目标、而不再是通用能力的代理指标的地步。

一个突出的例子是 Llama 4，它在许多公认的基准上得分极高。然而，一旦用户和开发者上手使用，他们就发现这些分数并不能反映它在现实中的能力和实用性。

正如一句流行的话所说：如果测试集是公开的，它就不是真正的测试集。而如今的问题是，测试集数据不仅（有意或无意地）成为训练语料的一部分，而且在 LLM 开发过程中还常常被直接针对性地优化。

过去，即使公开测试集上的基准分数被夸大了，至少模型的排名还是保持不变的。例如，可以看看下面这张来自 2019 年论文《Do ImageNet Classifiers Generalize to ImageNet?》并加了标注的图。

在 LLM 开发中，情况已经到了基准数字不再是 LLM 性能可信指标的地步。

不过，我确实认为基准仍然是 LLM 必须跨过的必要门槛。也就是说，如果我看到一个 LLM 在基准 Y 上的得分低于 X，我就已经知道它不是一个好的 LLM。然而，如果它在基准 Y 上的得分高于 X，这并不意味着它比另一个在同一基准上同样高于 X 的 LLM 好很多。

另一个需要考虑的方面是，图像分类器只有一项工作，即对图像进行分类。而 LLM 被用于许多不同的任务：翻译文本、总结文本、写代码、头脑风暴、解数学题，以及更多。评估图像分类器有分类准确率这样清晰的指标，比在确定性任务和自由形式任务上评估 LLM 要简单得多。

除了在实践中试用 LLM、不断创建新的基准之外，遗憾的是这个问题没有解决办法。

# 6. 用于编程、写作和研究的 AI

由于这个话题经常被提起，我想就 LLM 在某些类型的任务（甚至工作）上取代人类这件事说说我的看法。

从宏观上看，我把 LLM 视为给某些职业的人带来"超能力"的工具。我的意思是，用得好的话，LLM 能让个人的生产力大幅提高，消除日常工作中的大量摩擦。这既包括相对琐碎的任务，比如确保各节标题的首字母大写保持一致，也包括在较大的代码库中找出复杂的 bug。

## **6.1 编程**

如今，我在意的大部分代码仍然是我自己写的。所谓"在意"，指的是那些我必须理解代码、代码必须正确的场合。例如，如果我搭建一个 LLM 训练脚本，我会亲自实现并仔细检查训练逻辑。这样做一是为了确保它确实在做我认为它该做的事，二是为了保住我在这项任务上的知识和专长。不过，我现在会用 LLM 来添加周边那些更琐碎的代码，比如添加命令行 argparse 样板代码，让我能更方便地从命令行使用自己的代码。

但我也越来越依赖 LLM 来发现问题、提出改进建议或对想法做合理性检查。与此同时，我想理解自己在构建什么，作为个人目标，我希望加深自己的知识和技能，持续增长专长。

同时，对于我核心专长之外的任务，LLM 极有价值。它们让我能把一些原本没时间或没精力去处理的事情自动化。一个例子是我最近写的一个工具，用来把我的 Substack 文章提取并备份为 Markdown。（我所有文章都用 Markdown 起草，但经常直接在 Substack 编辑器里修改和扩充，所以我本地的草稿并不总是最新的。）LLM 还帮我清理了网站的 CSS，那里积累了多年的重复和不一致。今年我在许多类似的场合都用了 LLM。

或者简而言之，我认为这里的诀窍在于认清什么时候该用 LLM、什么时候不该用，以及如何以一种既能帮助你增长专长、又让人感到满足的方式使用 LLM。

## **6.2 代码库与代码库项目**

LLM 写代码的能力变强了，但不管我听到其他一些人怎么说，我都不认为代码现在是、或将来会变成转瞬即逝或过时的东西。LLM 给人们超能力，让他们能生成某些原本要花很大力气才能做出来的编程项目。

然而，纯粹由 LLM 生成的代码库无法取代专家打造的代码库。这些专家代码库甚至可能是人类程序员借助 LLM 写出来的。但关键在于，有这方面专长的人投入了大量时间和精力去创建、测试和打磨它。别人要复制它需要大量工作，既然它已经存在，为什么不直接采用呢？

简而言之，我认为一位学习过良好设计模式和权衡取舍、在职业生涯中研究过、见过并构建过许多平台的资深全栈 Web 开发者，能够构建出比随便一个人提示 LLM 构建出来的更好的平台。

了不起的是，现在随便一个人也能构建一个平台，即使不是最好的。然而，使用和提示 LLM 只能让这个人走到某个程度，平台的质量可能会停滞不前。所以，如果这个人真的在意改进平台，那么深入下去、学习别人如何构建平台，再带着更多知识回来，更有效地用 LLM 指导和改进平台设计，会是个好主意。

## **6.3 技术写作与研究**

和编程类似，我不认为 LLM 会让技术写作过时。写一本好的技术书需要几千个小时，以及对主题的深入了解。这个过程可能会用到 LLM 来提高清晰度、检查技术正确性、探索替代方案或运行小实验，但核心工作仍然依赖人的判断和专长。

是的，LLM 可以让技术书变得更好。它们能帮作者发现错误、扩充参考文献，总体上减少花在琐碎任务上的时间。这样就能腾出更多时间，用于真正需要创造力和经验的深度工作。

从读者的角度看，我也不认为 LLM 会取代技术写作。用 LLM 学习某个主题，对于快速提问和入门级解释效果很好。然而，当你想建立更深入的理解时，这种方式很快就会变得混乱。

到了那一步，与其自己可能浪费几个小时，去筛选关于一个你正在学习、但（还）不是专家的主题的 LLM 回答，不如遵循由专家设计的结构化学习路径，这往往更合理。（这位专家可能用过、也可能没用过 LLM。）

当然，在上课或读书学习时，用 LLM 来澄清问题或探索旁支，仍然是完全合理的。让它设计测验或练习来巩固知识也很棒。

总体而言，我认为 LLM 对作者和读者都是净收益。

但我也认为，这里的诀窍在于学会认清什么时候该用 LLM、什么时候不该用。例如，主要的弊端在于，当主题变难时，人很容易忍不住立刻去用 LLM，而先自己苦苦钻研一个问题，往往能带来扎实得多的学习效果。

我对研究的看法也大致相同。LLM 在查找相关文献、发现数学符号中的问题以及建议后续实验方面非常有用。但让人类研究者坐在驾驶座上仍然是合理的。

也许这里的经验法则大致如下：

- 如果这篇（研究）文章或这本书完全由人生成，那它本有可能被进一步改进。
- 而如果这篇（研究）文章或这本书仅靠提示 LLM 就能生成，那它可能不够新颖和/或不够深入。

## **6.4 LLM 与职业倦怠**

LLM 仍然相当新、还在演进，我认为过度使用 LLM 还有一个较少被讨论的弊端。例如，我认为如果模型包揽了所有动手的工作，人主要负责监督，工作就会开始让人感到空洞。

当然，有些人真心喜欢专注于管理系统和编排工作流，这是完全正当的偏好。但对于喜欢亲手做事本身的人来说，我认为这种工作模式可能会加速倦怠。（对于那些因为现在有了 LLM 就期望更快拿出更多成果的公司来说，这一点可能尤其如此。）

与一个难题苦苦缠斗、最终看到它跑通，会带来一种特别的满足感。当 LLM 一次就给出解决方案时，我不会有同样的感觉。我想这有点像做饭（这只是我突然想到的，而且我厨艺并不好）。如果你喜欢做披萨，用现成的面团、只往上加配料，很可能会失去大部分乐趣，做饭就变成了达到目的的手段。这未必是坏事，但我认为，如果你在较长一段时间里（几个月或几年）每天花许多小时做这种工作，我能理解它会让人感到空虚，最终导致倦怠。

所以，从自私的角度看，写代码也比读代码更有乐趣。你可能也同意，创建拉取请求通常比审阅拉取请求更有意思（当然，并非对每个人都是如此）。

关于我们应该如何可持续地使用 AI，一个不错的、理想化（但并不完美）的类比也许是国际象棋。

国际象棋引擎几十年前就超越了人类棋手，但由人类进行的职业国际象棋依然活跃而繁荣。我不是国际象棋专家，但我会说，这项运动可能甚至变得更丰富、更有趣了。

根据我听到的（例如卡斯帕罗夫的著作《Deep Thinking》以及马格努斯·卡尔森参与的播客），现代棋手一直在用 AI 探索不同的思路、挑战自己的直觉，并以过去根本不可能达到的深度分析错误。

我认为，这对于思考 AI 在其他形式的智力工作中的作用是一个有用的模型。用得好的话，AI 可以加速学习，扩大一个人能够合理承担的工作范围。我认为我们应该更多地把它当作伙伴，而不是替代品。

但我也认为，如果用 AI 把思考和编程完全外包出去，就有可能削弱动力，损害长期的技能发展。

# 7. 优势所在：私有数据

LLM 在通用编程、知识问答和写作方面的能力不断提升。这在很大程度上是因为，得益于训练流程和范式（例如 RLVR）的改进，以及推理扩展和工具使用的进步，规模扩展仍然能带来正的投资回报。

然而，到了某个时候这会开始趋于停滞（类似于我们在 GPT 4 到 GPT 4.5 的发展中看到的那样），除非我们不断发明新的训练方法和/或架构（目前还没人知道它们会是什么样子）。

LLM 目前能够解决大量通用任务和（较）容易摘到的果子。但要让它们在某些行业扎下根来，就需要更多的领域专门化。我认为 LLM 提供商很想拿到高质量的领域特定数据。目前看来，这将是一项挑战。

例如，似乎大多数被接洽的公司都拒绝了这类交易，恰恰是因为这些数据是专有的，是它们业务差异化的核心。（我从多个渠道听说过这一点，The Information 也有一篇关于这个话题的文章。）

在我看来，这完全合理。我认为，把有价值的专有数据——那些有朝一日可能给公司带来优势的数据——卖给 OpenAI 或 Anthropic，可能有点目光短浅。

目前，LLM 开发在规模化时成本高得令人望而却步、难度极大，这就是为什么只有少数几家大公司开发最先进的 LLM。然而，我认为 LLM 开发正日益商品化，因为 LLM 开发者经常在雇主之间流动，最终会被更大的金融机构、生物科技公司以及其他有预算的机构聘用，去开发能从其私有数据中获益、具有竞争力的内部 LLM。

这些 LLM 甚至不必完全从头训练；许多最先进的 LLM，比如 DeepSeek V3.2、Kimi K2 和 GLM 4.7，已经发布出来，可以拿来改造并进一步做后训练。

# 8. 从零构建 LLM 和推理模型

你可能想知道我今年都在忙些什么。我的精力几乎全部放在与 LLM 相关的工作上。去年，我决定成为独立人士、创办自己的公司，主要是为了有更多时间投入到自己的研究、写书、Substack 写作以及与业界的合作中。

作为一名独立研究者，咨询项目是让这种模式得以持续的一部分。这包括日常的常规开销（从买菜到医疗保险），也包括不那么显眼的成本，比如前面提到的那些实验所需的云计算费用。

随着时间推移，我的目标是进一步减少咨询工作，把更多时间花在长篇研究和写作上，尤其是我在这里分享的那些技术深度文章。

我很幸运，有许多公司联系过我，邀请我担任全职职位，如果独立这条路走不通，这会是一个可行的选择，但目前我打算继续保持独立。

如果你觉得我的工作有用，并且条件允许，订阅这个 Substack 或买一本我的书，确实能帮助这类工作持续下去，我非常感谢大家的支持。

今年我个人的亮点之一，是我的书《Build A Large Language Model (From Scratch)》（从零构建大语言模型）收到的积极反馈。我收到了来自世界各地公司和大学的读者许多用心的来信。

这些反馈涵盖了各种各样的用途：有大学教授把这本书作为讲授 LLM 原理的主教材，有往届学生用它准备求职面试并找到新工作，也有工程师把它当作在生产环境中实现定制 LLM 的垫脚石。

我也很高兴得知，这本书目前已被翻译成至少九种语言。

许多读者还问会不会出第二版，涵盖更新、更高级的主题。虽然我考虑过这件事，但我很谨慎，不想让这本书变得不那么易懂。例如，把标准的多头注意力换成更复杂的变体，比如一些较新的 DeepSeek 模型中使用的多头潜在注意力，会让入门门槛提高不少。

所以目前，我更愿意让这本书保持原样，因为它对于想入门 LLM 的人来说效果非常好。而对于对更高级内容感兴趣的读者，作为后续，我在这一年里往这本书的 GitHub 仓库添加了大量附加材料。我计划随着时间推移继续扩充这些材料。

此外，你可能知道，我目前正在写续作《Build A Reasoning Model (From Scratch)》（从零构建推理模型）。

第一本书《Build A Large Language Model (From Scratch)》侧重于大语言模型的核心架构和预训练的基础知识。

推理模型这本书则从第一本书结束的地方接着讲。它从一个预训练好的基础模型出发，探讨专门用于提升推理能力的推理时扩展方法和强化学习技术。

除了这个 Substack，我正在努力写这本推理模型的书，从很多方面来说，我认为这是我迄今为止构思最周全、打磨最精细的一本书。

目前，我估计每一章大约要花 75 到 120 个小时。如果你好奇的话，我估计时间通常是这样分配的：

- 3–5 小时：头脑风暴并修改选题
- 5–10 小时：组织内容结构
- 20 小时：编写初始代码
- 10–20 小时：运行额外实验并阅读最新文献以获得更多洞见
- 10–20 小时：制作插图
- 10 小时：撰写初稿文字
- 10–20 小时：改写和打磨这一章
- 5–10 小时：编写练习并运行相应实验
- 2–5 小时：吸收编辑和读者的建议

目前，我正写到第 6 章的一半，这一章实现用于训练推理模型的基于可验证奖励的强化学习（GRPO）代码。

《Build A Reasoning Model (From Scratch)》是非常辛苦的工作，但我做得乐在其中！希望你和其他读者会像觉得*《Build A Large Language Model (From Scratch)》*有用一样，觉得它有用。

# 9. 2025 年的意外与 2026 年的预测

我想用一些主要收获来结束这篇文章，重点放在我觉得有点出乎意料的事情，以及我对 2026 年的预测上。

## **9.1 2025 年值得关注和出乎意料的事**

我们先从 2025 年的意外说起。如果一年前、也就是 2024 年你问我，这些进展我很可能不会预料到：

1. 已经有好几个推理模型在主要数学竞赛中达到了金牌水平（OpenAI 一个未具名的模型、Gemini Deep Think，以及开放权重的 DeepSeekMath-V2）。这件事会发生我并不意外，但我意外的是它在 2025 年就已经发生了，而不是 2026 年。
2. Llama 4（或者说整个 Llama 系列）在开放权重社区中几乎完全失宠，Qwen 在受欢迎程度上超过了 Llama（以 Nathan Lambert 的 ATOM 项目报告的下载量和衍生模型数量衡量）。
3. Mistral AI 在 2025 年 12 月发布的最新旗舰模型 Mistral 3 中采用了 DeepSeek V3 的架构。
4. 除了 Qwen3 和 DeepSeek R1/V3.2 之外，在开放权重最先进模型的竞赛中还涌现出许多新的竞争者，包括 Kimi、GLM、MiniMax 和 Yi。
5. 更便宜、更高效的混合架构已经成为领先实验室更优先的方向（Qwen3-Next、Kimi Linear、Nemotron 3），而不再只是由一些独立的实验室开发。
6. OpenAI 发布了一个开放权重模型（gpt-oss，我今年早些时候专门写过一篇文章介绍它）。
7. MCP（已加入 Linux 基金会）已经成为智能体式 LLM 系统中工具和数据访问的标准（至少目前如此）；我原本预计这个生态在 2025 年会保持更加分散，至少要到 2026 年才会统一。

## **9.2 2026 年的预测**

1. 我们很可能会看到一个面向消费者、达到工业规模的扩散模型，用于便宜、可靠、低延迟的推理，Gemini Diffusion 很可能会率先推出。
2. 开放权重社区会缓慢但稳定地采用具备本地工具使用能力、智能体能力日益增强的 LLM。
3. RLVR 将更广泛地扩展到数学和编程之外的其他领域（例如化学、生物等）。
4. 经典 RAG 作为文档查询默认方案的地位会慢慢淡化。开发者不再对每个与文档相关的查询都使用检索，而是更多依赖更好的长上下文处理能力，尤其是随着更好的"小型"开放权重模型的出现。
5. LLM 在基准和性能上的大量进步，将来自更好的工具和推理时扩展，而不是来自训练或核心模型本身。看起来 LLM 好像变强了很多，但这主要是因为周边的应用在改进。与此同时，开发者会更专注于降低延迟，让推理模型在不必要的地方少消耗推理 token。别误会，2026 年会进一步推进最先进水平，但这一年进步中来自推理端的比例会比单纯来自训练端的更高。

总结一下，我认为如果说 2025 年有一条元教训，那就是 LLM 的进步不太依赖某一项单一突破，而是通过多个独立的杠杆在多条战线上同时取得改进。这包括架构调整、数据质量改进、推理训练、推理扩展、工具调用等等。

与此同时，评估依然困难，基准并不完美，而判断何时以及如何使用这些系统的良好判断力仍然必不可少。

我对 2026 年的希望是，我们继续看到有意思的改进，同时也能理解这些改进从何而来。这既需要更好、更一致的基准测试，当然也需要透明度。

感谢阅读，也感谢大家这一年来在评论区以及从 Substack Notes 到 GitHub 等各个平台上提供的所有用心的反馈和讨论。

这些积极的反馈和深入的交流，确实一直激励着我投入撰写长文所需的时间和精力，并继续深入钻研 LLM 研究和实现细节。我从这些交流中学到了很多，希望你也是。

随着这个领域在 2026 年继续发展，我非常期待继续这些对话！
