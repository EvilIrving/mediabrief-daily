推特上有个流行的说法："编程现在已经被解决了。"我不确定它在多大程度上是真的，但有一点很清楚：熟悉一门语言这件事已经不再重要，而一些对人类来说很要紧的摩擦，对 agent 来说并不存在。

因此，大模型让语言选择远没有以前那么举足轻重。如果你不喜欢某个选择，似乎可以直接用另一门语言重写；你甚至可以让它选一门你作为程序员完全不熟悉的语言。

这反过来意味着，人们可以、而且确实更多地根据语言的营销形象来做选择。作为一名多年的 Rust 程序员，我觉得很有意思的是，看到一些过去可能不会选择 Rust 的人现在也在交付 Rust 代码。我认为这至少部分要归因于最近的两次风向转变：人们越来越多地谈论想要快速的软件，也越来越多地谈论大模型非常擅长在不引起行为回退的前提下优化代码。

Mitchell Hashimoto、Charlie Marsh、Jarred Sumner、Daniel Lemire 等不少人一直对快速、高性能的软件有某种程度的执念，他们也恰好都乐于接受 agent 写代码。也许正因为如此，又或者与此无关，其他人现在也加入了进来。这是因为有了自动化研究（autoresearch）之类的东西，你甚至不一定需要懂得所有技巧：只需要派一个 agent 去做就行——当然，懂行会大有帮助！

环顾四周，有很多项目都想做得又快又小，它们越来越多地选择"难的语言"。受益的也不只是 Rust。即便是 Zig——尽管它的创建者和部分核心社区对 AI 整体相当负面——也在受益。例如，Cloudflare 新的 Artifacts 服务使用一个纯 Zig 编写的 Git 协议引擎，编译成大约 100 KB 的 WebAssembly 模块；Vercel 发布了 fx，一个用 Zig 编写、主打小而快的编程 agent。据我所知，这些项目在很大程度上都是大模型辅助完成的。

但不只是人们在选择更冷门的语言，他们也越来越多地在使用"难得多"的技术。突然之间，我看到有人用 DWARF 文件、eBPF、自定义网络驱动、自定义密码学和非常古老的计算机硬件做出了相当惊艳的东西。其中很多东西过去对许多开发者来说是禁区。在某些情况下（比如密码学），你甚至会被推开，因为这些东西被懂行的人有意设置了门槛。

所以，也许世界上会有更多劣质代码，但也可能会有更多想把东西做得又快又小的开发者。
