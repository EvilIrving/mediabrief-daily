【LLM 生态概览】

大家好。这期视频我想继续面向大众的大语言模型系列，讲的是 ChatGPT 这类模型。上一期视频《深入解析 LLM》（Deep Dive into LLMs）可以在我的 YouTube 频道找到，我们在那期里讲了很多底层的基础知识：这些模型是怎么训练出来的，以及应该怎么理解它们的认知或者说“心理”。这期我想讲这些工具更实际的用法。我会展示大量例子，带你过一遍各种可用的设置，给你看我自己是怎么用这些工具的，以及你在自己的生活和工作中也可以怎么用。我们开始吧。

首先，我这里打开的网页是 chatgpt.com。你可能知道，ChatGPT 是 OpenAI 开发的，2022 年上线。这是人们第一次能够通过文字界面直接和大语言模型对话，它在网上迅速爆红、铺天盖地，影响巨大。不过从那以后，这个生态已经发展壮大了很多。我会专门展示很多 ChatGPT 的例子，但到了 2025 年，已经有许多类似 ChatGPT 的应用，生态也变得更大、更丰富了。尤其是 OpenAI 的 ChatGPT，我觉得它是元老级（original gangster）的在位者，最受欢迎，功能也最丰富，部分原因是它存在得最久。不过也有许多其他的、我想说不算太冤枉地称之为“克隆品”的产品，但在某些情况下，它们会有 ChatGPT 里找不到的独特体验，我们后面会看到例子。

比如说，大科技公司纷纷跟进，推出了很多类似 ChatGPT 的体验，比如 Gemini、Meta AI 和 Copilot，分别来自 Google、Meta 和微软。也有不少创业公司，比如 Anthropic 有 Claude，大致相当于 ChatGPT；xAI，也就是埃隆的公司，有 Grok；还有很多别的。以上这些基本都是美国公司。DeepSeek 是一家中国公司，Le Chat 则来自法国公司 Mistral。

那到哪里能找到这些产品、怎么跟踪它们的动态呢？第一，网上到处都是。不过也有一些排行榜，上一期视频里我给大家看过，Chatbot Arena 就是其中之一。在这里你可以看到不同模型的排名，以及它们的实力，也就是 Elo 分数。所以这是一个可以跟踪它们的地方。另一个地方，我想说可能是 Scale 公司的 SEAL 排行榜。这里同样能看到不同类型的评测（eval）、不同的模型以及它们的排名，你也可以来这里看看哪些模型目前在各种任务上表现最好。总之要明白，这个生态相当丰富。不过现在我先从 OpenAI 讲起，因为它是在位者，功能也最丰富，但之后我也会陆续展示其他产品。

【ChatGPT 交互的底层原理】

那我们就从 ChatGPT 开始。这个文本框是什么，我们在里面输入什么？和语言模型交互最基本的形式是：我们给它一段文字，然后它回给我们一段文字。举个例子，我们可以让它写一首俳句，写写当一个大语言模型是什么感觉。这是一个很适合语言模型的示例任务，因为这些模型非常擅长写作，写俳句、写诗、写求职信、写简历、写邮件回复，它们都很在行。

当我们提出这样的请求时，发生的事情是这样的：模型回复了“字句如溪流淌，无尽回声，无心之念，未见之思的幽灵”（Words flow like a stream / Endless echo, never mine / Ghost of thought unseen）。好吧，相当戏剧化。我们在 ChatGPT 里看到的，看起来有点像你和朋友之间的对话，这些就像聊天气泡。但上一期视频里我们看到，底层实际发生的是：这段我们称为“用户查询”的文字，以及模型的回复这段文字，都会被切成一个个小的文本块，我们称之为 token（词元）。所以这段文字在底层其实是一个 token 序列，一维的 token 序列。

要看这些 token，我们可以用一个应用，比如 Tiktokenizer。确认选中了 GPT-4o，我把我的文字粘贴进去，这其实就是模型在底层看到的东西：我的这段文字在模型眼里是一个正好 15 个 token 的序列，这些就是模型看到的小文本块。这里的词表大约有 20 万个可能的 token，这些是与我的查询中各个小文本块对应的 token ID。你可以玩一玩、改一改，比如它是区分大小写的，大小写不同就会得到不同的 token，你可以编辑文字，实时看到 token 序列怎么变化。所以我们的查询是 15 个 token，然后模型的回复在这里，它回给我们的是一个正好 19 个 token 的序列，所以那首俳句就是这 19 个 token 组成的序列。

我们发了 15 个 token，它回了 19 个 token。不过因为这是一场对话，而我们其实想保留构成一个“对话对象”的许多元数据，所以底层发生的不止这些。上一期视频里我们稍微讲过对话格式。情况会更复杂一点：我们得把用户查询套进这种聊天格式。我把系统消息删掉，我觉得对理解发生了什么不太重要。我把我的消息作为用户（user）粘贴进去，再把模型的回复作为助手（assistant）粘贴进去，然后在这里正确地裁剪一下，这个工具这里做得不太对。好，这就是底层实际发生的样子：有一些特殊 token，基本上表示“用户的消息开始”，然后是用户说的内容，也就是我们说的话，然后是“用户消息结束”；接着“助手开始”，然后说了那些话，等等。对话格式的具体细节并不重要，我想传达的是：在你我看来是来回往复的小聊天气泡，在底层，我们是在和模型协作，双方一起往一条 token 流里写东西。这两个来回的气泡在底层是一个正好 42 个 token 的序列。我贡献了前面一些 token，然后模型用它的回复接续了这个 token 序列。我们可以轮流下去，继续往里添加 token，一起构建一个 token 窗口，一个一维的 token 序列。

好，回到 ChatGPT。我们在这里看到的，是我们和模型之间来回往复的小气泡；在底层，我们在构建一个一维的 token 序列。当我点击这里的“新聊天”（New chat）时，就会清空 token 窗口，把 token 基本重置为零，从头开始一场对话。

我在和模型说话时，脑子里的卡通示意图大概是这样的：点击“新聊天”，我们就开始一个 token 序列，这是一个一维的 token 序列。作为用户，我们可以往这条流里写 token，按下回车后，我们就把控制权交给语言模型，语言模型用它自己的 token 流来回应。语言模型有一个特殊 token，意思大致是“我说完了”。当它发出这个 token 时，ChatGPT 应用就把控制权交还给我们，我们可以轮流来。我们一起构建这条 token 流，我们也称之为上下文窗口（context window）。上下文窗口有点像 token 的工作记忆，凡是在这个上下文窗口里的东西，都相当于在这场对话的工作记忆中，模型可以非常直接地访问。

那我们在对话的这个实体是什么，应该怎么理解它呢？上一期视频里我们看到，这个语言模型的训练有两个主要阶段：预训练阶段和后训练阶段。预训练阶段有点像把整个互联网切成 token，然后压缩成一个类似 zip 文件的东西。但这个 zip 文件不是精确的，它是一个有损的、概率性的 zip 文件，因为我们不可能用一个比如一 TB 的 zip 文件来表示整个互联网，信息实在太多了。所以我们只是把大意（gestalt）或者说“感觉”（vibes）装进了这个 zip 文件。zip 文件里实际装的是一个神经网络的参数，比如说，一个 1 TB 的 zip 文件大致对应这个神经网络里约一万亿个参数。这个神经网络要做的，基本上就是接收 token，然后预测序列中的下一个 token，只不过它是在互联网文档上做这件事，所以它有点像一个互联网文档生成器。在预测互联网上序列的下一个 token 的过程中，神经网络获得了大量关于世界的知识，这些知识全部被表示、塞进并压缩在这个语言模型大约一万亿个参数里。

我们也看到，这个预训练阶段相当昂贵，可能要花几千万美元，比如说训练三个月之类的。这是一个昂贵而漫长的阶段，因此不会经常做。比如 GPT-4o 这个模型，很可能是好几个月前预训练的，到现在也许都有一年了。所以这些模型会有点过时，它们有所谓的知识截止日期（knowledge cutoff），因为这个截止日期对应模型预训练的时间，它的知识只到那个时间点为止。有些知识可以通过后训练阶段进入模型，我们马上会讲到，但大体上你应该把这些模型看作有点过时，因为预训练太贵了，很少进行。所以任何较新的信息，比如你想和模型聊上周发生的事，我们就需要别的方式把这些信息提供给模型，因为它们没有存储在模型的知识里。所以我们会用各种工具来把这些信息提供给模型。

预训练之后是第二个阶段，后训练。后训练阶段其实就是给这个 zip 文件贴上一张笑脸，因为我们不想让它生成互联网文档，我们想让它扮演一个回应用户查询的助手角色。这是在后训练过程中完成的：我们把数据集换成由人类构建的对话数据集。基本上就是在这里，模型获得了这个人设，让我们可以向它提问、它给出回答。所以它获得了助手的风格，这是后训练的作用；但它拥有整个互联网的知识，这来自预训练。这两者结合在这个产物里。

我觉得这一部分要理解的重点是：你对话的对象默认是一个完全自成一体的实体。可以把这个语言模型看作磁盘上一个 1 TB 的文件，它暗中代表着一万亿个参数及其在神经网络里的精确取值，这个神经网络在尽力给你序列中的下一个 token。但它是一个完全自成一体的实体：没有计算器，没有电脑和 Python 解释器，不能浏览万维网，什么都没有。在我们目前讲的内容里还没有任何工具。你是在和一个 zip 文件说话，你把 token 流给它，它就回给你 token。这个 zip 文件拥有来自预训练的知识，以及来自后训练的风格和形式。这大致就是你可以怎么理解这个实体。

如果要总结我们目前讲的内容，我大概会用一段 ChatGPT 的自我介绍来概括，这是我认为你应该如何理解它的方式。这段自我介绍会是：“嗨，我是 ChatGPT。我是一个 1 TB 的 zip 文件。我的知识来自互联网，我大约六个月前把它从头到尾读了一遍，而且只记得个大概。我迷人的个性是由 OpenAI 的人类标注员通过示例编程出来的。”所以个性是在后训练中编程的，知识来自预训练期间对互联网的压缩，这些知识有点过时，而且是概率性的、有些模糊。互联网上被提及非常频繁的东西，我会记得比那些很少被讨论的东西清楚得多，这和你对人类的预期非常相似。

【基本交互示例】

那我们来谈谈这个实体带来的一些影响：我们怎么和它对话，可以期待它做什么。我想用真实例子来讲。比如今天早上我问了 ChatGPT 这个问题：一份浓缩（one shot）美式咖啡里有多少咖啡因？我好奇是因为我在拿它和抹茶比较。ChatGPT 会告诉我大约是 63 毫克左右。我之所以觉得问 ChatGPT 这个问题没问题，第一，我问的不是什么很新的知识，所以我确实预期模型读到过一份浓缩咖啡里有多少咖啡因，我不认为这个信息变化很大。第二，我认为这个信息在互联网上极其常见，这类问题和这类信息在网上到处都有，因为被提及的次数太多了，我预期模型的知识里对它有很好的记忆。所以这里没有用任何工具，模型，也就是那个 zip 文件，回答说大约 63 毫克。当然，我不能保证这是正确答案，这只是它对互联网的模糊回忆。但我可以去查一手资料，比如搜索“咖啡因 美式咖啡”，核实一下，嗯，看起来大约 63 毫克基本是对的。你可以查一手资料来判断真假。所以严格来说，我不能保证这是对的，但我觉得这大概属于 ChatGPT 会知道的那类东西。

再举个例子，这是我两天前的一段对话，这又是一个基于知识的对话，属于我愿意问 ChatGPT 的那类问题，但附带一些保留。我有点感冒，流鼻涕，想找能缓解的药。它告诉了我一堆东西。我希望鼻子不再流涕，于是根据它说的内容补充说明了一下，然后它给了我一些可能有帮助的东西。接着我看了看家里有的药，问它：DayQuil 或 NyQuil 管用吗？它就去逐一分析 DayQuil 和 NyQuil 的成分，以及它们能不能缓解流鼻涕。说到这些成分，再次记住，我们是在和一个对互联网有记忆的文件对话，我不能保证这些成分是对的。事实上，我真的把药盒拿出来看了成分表，确认 NyQuil 的成分正是这些。我这样做是因为我并不总是完全信任它输出的东西，对吧？这只是对互联网的概率性、统计性的回忆。话虽如此，DayQuil 和 NyQuil 是非常常见的药，网上大概有海量相关信息，这正是模型记得相当清楚的那类东西，所以这些其实全都是对的。然后我说：好，我有 NyQuil，它大概多快起效？它告诉了我。然后我问它：这基本上就是泰诺（Tylenol）吗？它说是的。

所以这是一个 ChatGPT 对我有用的好例子：这是一个基于知识的查询，不是什么新知识，全都来自模型自身的知识。我觉得这是常见信息，也不是高风险的情境。我稍微核实了一下 ChatGPT 的说法，但这本来也不是高风险情境，所以没什么大不了的。于是我吃了一片 NyQuil，确实有用。这大致就是我对这里发生的事情的理解。

【留意所用模型与定价档位】

好，说到这里我想提两点。第一点：在你和这些模型交互时，自然会发现对话越来越长，对吧？每当你切换话题时，我建议你都开一个新聊天。正如我们讲过的，开新聊天就是清空上下文窗口里的 token，把它重置为零。如果那些 token 对你的下一个查询不再有用，我建议你这样做，因为窗口里的这些 token 是昂贵的，而且在两方面都昂贵。第一，如果这里有很多 token，模型可能会觉得有点分心。这有点像模型的工作记忆，当模型在很久之后尝试采样 token 时，可能会被过去那些 token 分散注意力，这可能降低模型的准确性和表现。第二，窗口里的 token 越多，采样序列中下一个 token 的成本就越高一点，不是高很多，但会高一点。所以模型其实会稍微变慢，这里的 token 越多，计算下一个 token 就越贵。所以要把上下文窗口里的 token 当作宝贵资源，把它看作模型的工作记忆，不要用无关信息让它超载，尽量保持简短，这样它就会更快、表现也稍好一些。当然，如果这些信息确实和你的任务相关，你也许想保留它们。但我建议你尽可能地在切换话题时开新聊天。

第二点：我始终建议你留意自己实际在用哪个模型。在左上角这里，我们可以打开下拉菜单，看到我们目前在用 GPT-4o。现在有很多不同的模型，各种各样的版本，其实太多了，我们会陆续讲到其中一些。所以我们现在用的是 GPT-4o，我目前给你看的所有内容都是 GPT-4o。当我打开一个新的无痕窗口，进入 chatgpt.com 而不登录，这时我对话的模型，比如我只说一句“你好”，可能就不是 GPT-4o，可能是一个更小的版本。遗憾的是，我没登录时，OpenAI 不告诉我在用哪个模型，这有点遗憾，但你有可能在用一个更小、更笨的模型。

如果我们去 ChatGPT 的定价页面，会看到面向个人有三个基本档位：免费版、Plus 和 Pro。免费档你能用的是所谓的 GPT-4o mini，这是 GPT-4o 的小号版本，参数更少的较小模型。它的创造力没那么强，比如写作可能没那么好，知识也没那么好，大概还会更多地出现幻觉，等等。但它算是免费档的产品。他们确实说你可以有限地使用 4o 和 o3-mini，但我其实不能百分之百确定，因为它没告诉我们在用哪个模型，所以我们根本无从知道。当你每月付 20 美元时，虽然页面上没写，我觉得他们在描述上基本搞砸了，但如果你去看适用的细则，就能看到 Plus 用户每三小时可以给 GPT-4o 发 80 条消息。这就是截至今天可用的旗舰、最大的模型，也就是我们想用的。所以每月付 20 美元，你就能在一定限额内用它。如果每月付 200 美元，你就是 Pro，有一堆额外的好东西，还有无限量的 GPT-4o。我们会讲到其中一些，因为我确实订了 Pro。

我希望你从中得到的整体结论是：留意你在用的模型。通常在这些公司，更大的模型计算成本更高，所以公司对更大的模型收费更高。所以要根据你对 LLM 的使用情况自己权衡：看看你能不能用便宜的方案凑合，如果智能水平不够，而你又是专业使用，那你可能真的要考虑付费用这些公司提供的顶级模型。就我而言，在专业工作中我写很多代码之类的东西，这对我来说仍然非常便宜，所以我很乐意付费，因为我能用上一些非常强大的模型，我待会儿给你看。所以，记得留意你在用哪个模型，自己做决定。

我还想给你看看，其他所有 LLM 提供商也都有不同的定价档位，不同档位对应不同的模型可以付费使用。比如去看 Anthropic 的 Claude，你会看到我付的是专业版（Pro）计划，这让我能用 Claude 3.5 Sonnet；如果你不付费买 Pro 计划，那你大概只能用 Haiku 之类的。所以用对你来说管用的最强模型。这里有个我前阵子用 Claude 的例子，我只是在问旅行建议，问有什么很酷的城市可去，Claude 告诉我瑞士的采尔马特（Zermatt）很酷，于是我听了 Claude 的建议，新年假期就去了那里。这只是另一个例子，说明我觉得这些模型在旅行建议、构思点子、获取可以进一步研究的线索上相当有用。

这里还有一个 gemini.google.com 的例子，这是 Google 的产品。我问了 Gemini 的看法，问它有什么很酷的城市可去，它也推荐了采尔马特，挺好的。所以我喜欢在不同模型之间切换，问它们类似的问题，看看它们怎么想。Gemini 左上角同样有一个模型选择器，你可以付费购买更高级的档位来用那些模型。Grok 也一样，刚刚发布了，我们不想去问 Grok 2，因为我们知道 Grok 3 是最先进的模型，所以我要确保付足够的钱，能用上 Grok 3。所以对于这些不同的提供商，找一个最适合你的，针对你在处理的问题，试试不同的提供商、试试不同的定价档位。我自己最后往往是给很多家都付了费，然后把同一个问题问遍所有模型。我把这些模型统称为我的“LLM 议会”（LLM Council），有点像语言模型组成的议会。比如我在想去哪里度假，就会把它们全问一遍。如果这适合你，你也可以这么做。

【思考模型及其适用场景】

好，接下来我想讲的话题是所谓的“思考模型”。上一期视频里我们看到，训练有多个阶段：预训练，然后是监督微调，然后是强化学习。强化学习阶段，模型会在一大批类似课本练习题的问题上练习，它会在大量数学和代码问题上练习。在强化学习的过程中，模型会发现能带来好结果的思考策略。你去看这些思考策略，会发现它们非常像你解决问题时的内心独白：模型会尝试不同的想法，会回溯，会重新审视假设，诸如此类。很多这样的策略，人类标注员很难硬编码出来，因为并不清楚思考过程应该是什么样的。只有在强化学习中，模型才能尝试大量做法，找到适合它自身知识和能力的思考过程。

这是训练这些模型的第三个阶段。这个阶段相对较新，只是一两年前的事。过去一年里，各家 LLM 实验室都在试验这类模型，最近它被视为一项重大突破。我们上次看过 DeepSeek 的那篇论文，它是第一个基本公开讨论这件事的，他们有一篇不错的论文，讲的是通过强化学习激励 LLM 的推理能力（Incentivizing Reasoning Capability in LLMs via Reinforcement Learning），上一期视频里我们看过这篇。所以现在我们得稍微调整一下卡通图，因为现在我们的表情小人多了一个可选的“思考气泡”。当你使用会做额外思考的思考模型时，你用的是额外经过强化学习调优的模型。

从定性上看是什么样子呢？定性地说，模型会做多得多的思考。你可以期待更高的准确率，尤其是在数学、代码这类需要大量思考的问题上。非常简单的问题可能其实得不到什么好处，但真正深入、困难的问题可能会获益很多。基本上你付出的代价是模型要思考，有时会花好几分钟，因为模型会在好几分钟里输出大量大量的 token，你得等着，因为模型在思考，就像人类会思考一样。但在你遇到很难的问题时，这可能会转化为更高的准确率。

我们来看一些例子。这是一个具体例子，我最近卡在一个编程问题上：所谓的梯度检验（gradient check）失败了，我不知道为什么，于是我把代码复制粘贴给模型。代码细节不重要，基本上是一个多层感知机的优化。细节不重要，就是我写的一堆代码，里面有个 bug，因为我的梯度检验没通过，我只是在征求建议。GPT-4o 是 OpenAI 旗舰、最强的模型，但它不带思考，它就列了一堆它认为有问题或者我应该复查的地方，但其实并没有真正解决问题。它给我的这些东西都不是问题的核心，所以模型并没有真正解决问题，它在告诉我怎么调试，等等。

然后我做的是，在这个下拉菜单里换成了一个思考模型。在 OpenAI，所有以 o 开头的模型都是思考模型：o1、o3-mini、o3-mini-high 和 o1 pro mode 全都是思考模型。他们给模型起名不太在行，但就是这样。这里他们会写一些诸如“使用高级推理”“擅长代码和逻辑”之类的描述，但这些基本上都是用强化学习调优过的。因为我每月付 200 美元，所以我能用 o1 pro mode，它最擅长推理。但根据你的定价档位，你也许可以试试其他几个。当我把同样的提示词给 o1 pro，也就是那个最擅长推理、要每月付 200 美元才能用的模型时，完全相同的提示词，它去思考了一分钟，经历了一连串思考。OpenAI 不完整展示具体的思考内容，只给你一些思考的小摘要。但它对代码思考了一阵子，然后真的给出了正确的解决方案：它注意到参数不匹配，以及我打包和解包参数的方式有问题，等等。所以这真的解决了我的问题。

我还试着把完全相同的提示词给了一堆别的 LLM。比如 Claude，我把同样的问题给了 Claude，它也找出了正确的问题并解决了。而且它用的还是 Sonnet，并不是思考模型。据我所知，Claude 3.5 Sonnet 不是思考模型，而且据我所知，Anthropic 截至今天还没有部署思考模型，不过等你看到这个视频时可能已经变了。但即便没有思考，这个模型也解决了问题。我去问 Gemini，它也解决了问题，虽然我也可以试它的思考模型，但没必要。这次我也把问题给了 Grok 3，Grok 3 折腾了一番之后也解决了问题。

最后我去了 perplexity.ai。我喜欢 Perplexity 的原因是，在它的模型下拉菜单里，它托管的模型之一就是 DeepSeek R1，所以可以用 DeepSeek R1 模型做推理，也就是我们在这篇论文里看到的那个模型。Perplexity 直接托管了它，用起来非常方便。所以我把代码复制粘贴过去运行了一下。我觉得他们的渲染做得真的很糟糕，但在下面这里你能看到模型的原始思考过程，虽然你得把它展开。你会看到：“好，用户的梯度检验遇到了问题……”然后它尝试了一堆东西，接着它说：“但是等等，他们在累加梯度的时候做错了。我们来检查一下顺序，参数是这样打包的……”然后它注意到了问题，说“这是个关键错误”。它就这样一步步想下去，你得等几分钟，然后它也给出了正确答案。

长话短说，我想给你看的是：存在一类我们称为思考模型的模型，各家提供商可能有、也可能没有思考模型。这些模型对数学、代码之类的难题最有效，在这类情况下，它们能提高准确率。在很多情况下，比如你在问旅行建议之类的，思考模型不会带来什么好处，没必要等它花一分钟去思考你可能想去的目的地。所以我自己通常先试非思考模型，因为它们响应真的很快；但当我怀疑回答没有达到应有的水平，想给模型机会多思考一会儿时，我就会换成思考模型，看你手头有哪个。

比如去 Grok，我在 Grok 开一个新对话，在这里输入问题，比如“你好”，你应该输入点重要的东西，你会看到这里有个“Think”，意思是让模型慢慢来。打开 Think 再点发送，点了 Think 之后，Grok 在底层就切换到了思考模型。各家提供商都会有某种选择器，让你选择是想让模型思考，还是直接用上一代那种模型就行。

【工具使用：联网搜索】

好，下一部分我想讲工具使用。到目前为止，我们只是通过文字和语言模型对话。再说一遍，这个语言模型就是文件夹里的一个 zip 文件，它是惰性的、封闭的，没有任何工具，只是一个能输出 token 的神经网络。现在我们想要超越这一点，赋予模型使用一系列工具的能力。最有用的工具之一就是联网搜索，我们来看看怎么让模型使用联网搜索。

还是用我自己生活中的具体例子。几天前我在看《白莲花度假村》（The White Lotus）第三季，看了第一集。顺便说一句，我很喜欢这部剧。我想知道第二集什么时候出。在过去，你会去 Google 之类的地方，输入“白莲花度假村第三季新剧集”，然后开始点这些链接，也许打开几个，然后开始翻找，试图弄明白。有时你运气好，找到了播出时间表，但很多时候你可能会看到特别夸张的广告，乱七八糟的东西一大堆，整体就是一种不愉快的体验，对吧？所以，要是模型能替你做这种搜索，访问所有网页，把这些网页的内容全部塞进上下文窗口，然后直接给你答案，那该多好。这正是我们现在要做的。

基本上，我们引入了一种机制，让模型可以输出一个特殊 token，某种“搜索互联网”的 token。当模型输出这个“搜索互联网” token 时，ChatGPT 应用，或者你用的任何 LLM 应用，就会停止从模型采样，拿着模型给出的查询去做搜索，访问网页，取出所有文字，然后把所有东西都放进上下文窗口。所以现在有了这个联网搜索工具，它本身也能往我们的上下文窗口里贡献 token。在这个例子里，就是大量网页，也许有 10 个，它可能把它们全拼在一起，这可能是来自这些网页的成千上万个 token，就像我们自己在看这些网页一样。在把所有网页插入上下文窗口之后，它会回到你的问题，“嘿，这一季什么时候播出”，它能引用那些文字，给你正确答案。

注意，这是一个说明我们为什么需要联网搜索的很好例子。没有联网搜索，这个模型根本不可能给出正确答案。因为正如我提到的，这个模型是几个月前训练的，那时候播出时间表大概还没公布，所以《白莲花度假村》第三季什么时候播出并不在模型的真实知识里，很可能不在 zip 文件里，因为这大概是最近几周才定下来的。所以模型基本上得去联网搜索才能获得这个知识，它从网页中学到这些，就像你我没有它也会做的那样。一旦这些信息进入上下文窗口，它就能回答问题了。再说一遍，上下文窗口就是工作记忆，一旦我们加载了这些文章，可以把它们的文字看作被复制粘贴进了上下文窗口，现在它们就在工作记忆里，模型就能回答这些问题，因为内容就在上下文窗口里。

长话短说，别手动做这些，用 Perplexity 之类的工具。perplexity.ai 有一个很不错的、能联网搜索的 LLM，我觉得它是第一个真正令人信服地做到这件事的应用。最近 ChatGPT 也推出了一个“搜索网页”（Search the web）的搜索按钮，我们待会儿看。现在先来问：“《白莲花度假村》第三季的新剧集什么时候播出？”你直接问就行，不用自己手动干活，按回车，模型就会访问这些网页，生成所有查询，然后给你答案。它就这么替你干了一大堆活。通常还会有引用来源，你可以自己访问这些网页，确认这些不是模型的幻觉，确实可以复查一下它是不是对的，因为原则上这并不能保证，这只是可能管用也可能不管用的东西。

我们也可以把这个问题拿到比如 ChatGPT，问同样的问题。但如果不选“搜索”就直接把问题放进去，我其实不能百分之百确定模型会怎么做。有时候模型真的会知道这是新知识、它大概不知道，于是自己发起搜索；有时候我们得明确声明要搜索。我自己用的时候，我会知道模型不知道，所以就直接选搜索。但我们先看看会发生什么。好，“正在搜索网页”，然后打出一些东西，然后给出引用。所以模型自己检测到它需要搜索网页，因为它明白这是某种最新信息之类的，所以这是对的。另一种做法是，我新建一个对话，也可以直接选上搜索，因为我知道需要搜索，回车，然后它做同样的事：搜索网页，给出结果。

所以基本上，在用这些 LLM 时要留意这一点。比如 Grok，我们试试不选搜索的 Grok。好，模型自己知道需要搜索，做了一些搜索，给出了答案。我们看看 Claude 怎么样。你看，Claude 其实没有搜索工具，所以它会说“截至我最后一次更新，也就是 2024 年 4 月……”。这个最后更新就是模型做预训练的时间。所以 Claude 只是在说，截至它 2024 年 4 月的知识截止日期，这部剧已经宣布了，但它不知道具体时间。Claude 没有把联网搜索作为一个选项集成进来，所以不会给你答案。我估计 Anthropic 可能正在做这个功能。

我们试试 Gemini，看看它怎么说：“很遗憾，《白莲花度假村》第三季尚未公布官方播出日期。”所以 Gemini 2.0 Pro Experimental 无法联网搜索，也不知道答案。我们可以试试其他几个，比如 2.0 Flash，我试一下。好，这个模型似乎知道，但没给引用。哦，等等，好了，有了，“来源和相关内容”。你看，2.0 Flash 实际上有联网搜索工具，但我猜 2.0 Pro 这个他们最强的模型反而没有联网权限。它这里其实也告诉我们了：“2.0 Pro Experimental 无法获取实时信息和部分 Gemini 功能。”所以这个模型没有完全接入联网搜索。

长话短说，我们可以让模型替我们做 Google 搜索，访问网页，把信息拉进上下文窗口，然后回答问题。这是一个非常非常酷的功能，但不同的模型、可能还有不同的应用，对这一能力的集成程度不同，你得留意这一点。有时模型会自动检测到需要搜索，有时你最好直接告诉模型你想让它搜索。所以当我用 GPT-4o、并且知道这需要搜索时，你大概应该勾上那个选项。

这就是搜索工具。我还想再给你看几个我在自己工作中使用搜索工具的例子，也就是我会用哪类查询。这对我来说很容易找，因为这类情况我出于习惯通常会去 Perplexity，尽管如今 ChatGPT 也能做这类事，大概很多其他服务也能，但我恰好习惯用 Perplexity 做这类搜索查询。每当我预期答案可以通过类似 Google 搜索、访问排名靠前的几个链接得到，而答案就在这些链接里的某处时，我就会用搜索工具，就会来 Perplexity。

这里有一些例子。“今天股市开盘吗？”那天是总统日（Presidents' Day），我不能百分之百确定，Perplexity 知道今天是哪天，它会搜索，然后弄清楚总统日那天休市。“《白莲花度假村》第三季在哪里拍的？”同样，我不确定模型的知识里有没有这个，这是比较小众的东西，网上的提及可能没那么多，而且也比较新，所以我不指望模型默认就知道，这很适合用搜索工具。“Vercel 提供 PostgreSQL 数据库吗？”这是个很好的例子，因为这类东西会随时间变化，Vercel 这家公司的产品可能会变，我想要最新信息。凡是涉及最新信息或者会变化的东西，我都倾向于用搜索工具，所以我来 Perplexity。“明天苹果发布会发布什么？有哪些传闻？”同样是新近的事。“《单身即地狱》（Singles Inferno）第四季的演员阵容，必知信息”，这又是个好例子，因为是非常新鲜的信息。“Palantir 的股价为什么在涨？是什么在推动这股热情？”“《文明 7》（Civilization VII）具体什么时候出？”还有这个例子：“Brian Johnson 有没有讲过他用的牙膏？”我就是好奇 Brian 用什么。这个问题同样有两个特点：第一，它有点冷门，我不能百分之百确定这在互联网上有足够的量，会成为模型知识的一部分；第二，这可能随时间变化，我想知道他最近用什么牙膏，所以这又很适合用搜索工具。“去越南旅行安全吗？”这个可能会随时间变化。然后我在推特上看到很多关于 USAID 的东西，想知道到底是怎么回事，于是搜了一下，然后你可以从很多方面深入下去。这个用例大致是：我看到某个东西在热议，好奇发生了什么，它的要点是什么。我经常快速发起一个搜索，问问“发生了什么”，让模型给我讲讲大概经过，因为很多单条推文或帖子本身可能没有完整的上下文。这些就是我使用搜索工具的例子。

【工具使用：深度研究】

好，接下来我想介绍一个叫“深度研究”（Deep Research）的功能。它相当新，大概一两个月前才出来，但我觉得它酷得不可思议，非常有意思，却没有引起很多人的注意，我觉得不该这样。我们去 ChatGPT 的定价页面，会注意到深度研究列在 Pro 档下面，所以目前需要每月 200 美元，这是最高档。但我觉得它非常酷，我通过例子来给你看看在什么样的场景下你可能会想用它。

粗略地说，深度研究是联网搜索加思考的组合，而且会长时间运行。模型会花几十分钟去做研究。第一家宣布这个功能的公司是 ChatGPT，作为 Pro 产品的一部分，就在最近，大约一个月前。

这里有个例子。最近我在网上买保健品，我知道这有点疯狂，但 Brian Johnson 有一个入门套装，我有点好奇，里面有个东西叫“长寿混合饮”（Longevity Mix），含有一堆健康活性成分。我想知道这些东西是什么，对吧？比如这个 Ca-AKG，这到底是什么鬼？“促进能量生成，维持持久活力”，这又是什么意思？你当然可以打开 Google 搜索，看看维基百科页面之类的，做所有你习惯做的事，但深度研究让你可以走另一条路，它会替你处理大量这类信息，并且解释得好得多。

举个例子，我们可以这样做，这是我的示例提示词：“Ca-AKG 是 Brian Johnson 的 Blueprint 中的健康活性成分之一，每份含 2.5 克。你能研究一下 Ca-AKG 吗？告诉我它为什么可能出现在长寿混合饮里，它在人体或动物模型中可能的功效，潜在的作用机制，任何潜在的隐患或毒性，诸如此类。”这里我有这个按钮可用，你除非现在每月付 200 美元，否则是没有的。但我可以打开深度研究，把提示词复制粘贴进去，点发送。

现在模型会说：“好，我来研究一下。”有时它喜欢在出发前先问一些澄清问题：“重点关注人类临床研究、动物模型，还是两者都要？”我们说两者都要。“具体来源？”所有来源都行，我也不知道。“要和其他长寿化合物做比较吗？”不需要比较，只要 AKG，可以写得简短一些。模型明白了，我们出发。“好，我来研究 AKG。”开始研究。现在我们大概得等 10 分钟左右。如果你想点开它，可以看到模型在高层次上在做什么的一些预览。它会去做我说的思考加联网搜索的组合，会发起大量联网搜索，会翻阅大量论文，查看论文，思考，然后在 10 分钟后回来。所以这会运行一阵子。

在它运行期间，我想给你看看业界的同类功能。受此启发，很多人都想复制它。比如 Perplexity，在它的模型下拉菜单里有个叫“深度研究”（Deep Research）的东西，你可以在这里发出同样的查询，我们把它交给 Perplexity。然后 Grok 也有个东西，叫“深度搜索”（DeepSearch）而不是深度研究，但我觉得 Grok 的深度搜索大概类似深度研究，不过我不能百分之百确定。所以我们也可以发起 Grok 深度搜索，Grok 3 深度搜索，发送，这个模型也会出发去干活。

我看看我的 ChatGPT 在哪儿。ChatGPT 大概完成了四分之一，Perplexity 马上就要好了，好，还在思考，Grok 也还在跑。我最喜欢 Grok 的界面，看起来，好，基本上它在看各种论文、WebMD、浏览结果，把这些都收集过来。当然，在这一切进行的同时，它在积累一个巨大的上下文窗口，处理所有这些信息，试图为我们写出一份报告。“要点：Ca-AKG 是什么，为什么出现在长寿混合饮里，它和长寿有什么关联”等等。它会给出引用，把方方面面都告诉你。所以这不是一个简单简短的回答，而几乎像是一篇针对你想要的任何话题量身定制的研究论文。这真的很酷，它给出很多参考文献，你可以去自己读一读，之后也许再问一些澄清问题。它能给你这么多不同的引用，还替你把信息稍微处理一下，这真的很不可思议。

我们看看，Perplexity 完成了吗？好，Perplexity 还在研究，ChatGPT 也还在研究。那我先暂停一下视频，等完成了再回来。

好，Perplexity 完成了，我们能看到它写的一部分报告，这里有一些参考文献和一些基本的描述。然后 ChatGPT 也完成了，它思考了五分钟，看了 27 个来源，写出了一份报告。报告里谈到了在线虫、果蝇（Drosophila）和小鼠中的研究，以及正在进行的人体试验，然后是推测的作用机制，还有一些安全性和潜在隐患，以及可以深入阅读的参考文献。目前在我自己的工作中，我大概只用它做过 10 到 20 次查询，差不多这个量。通常我觉得 ChatGPT 的产品目前是最好的，它最全面，读起来最好，篇幅最长，我读的时候觉得最有道理。我觉得 Perplexity 和 Grok 的要短一些、简略一些，没有像 ChatGPT 的深度研究那样深入细节。

我要说的是，这里给你的所有东西，再次记住，尽管它在做研究、在拉取资料，但不能保证没有幻觉。其中任何内容在任何时候都可能是幻觉，可能完全是编造的、捏造的，或者被模型误解了。这就是为什么这些引用非常重要。把它当作你的初稿，当作要去看的论文清单，但不要当成一定正确。所以我现在会做的是，真的去读这些论文，试着弄清楚 ChatGPT 理解得对不对，也许我还会有一些后续问题，等等。这些你都可以做，但偶尔看看这些报告，获得一批之后可能想深入研读的来源，仍然非常有用。

好，和之前一样，我想简单给你看几个我用深度研究的例子。比如我当时想换浏览器，因为 Chrome 惹恼了我，它把我所有标签页都删了。所以我在考虑 Brave 或 Arc，我最关心哪个更注重隐私。ChatGPT 基本上为我整理了这份报告，这其实很有帮助。我去看了一些来源，大致明白了为什么 Brave 基本上，简而言之（TL;DR），明显更好。这就是为什么，比如这里我用的就是 Brave，因为我现在已经换过来了。所以这是一个研究不同产品并比较它们的例子，我觉得这很适合深度研究。这里我想了解小鼠的寿命延长，它给了我一份很长的读物，基本上小鼠是研究长寿的动物模型，不同实验室尝试用各种技术延长它们的寿命。

【文件上传：把文档加入上下文】

这里真正有意思的地方在于，我们在给 LLM 提供额外的、具体的文档，让它在上下文窗口里引用。所以模型不只是依赖知识，依赖它通过参数对世界形成的模糊认识、依赖它“脑子”里知道的东西，我们其实是在给它具体的文档。这就好像你我在回答某个问题时，会参考互联网上之类的具体文档一样。我们可以通过联网搜索或者像这样的工具来做到这一点，但我们也可以自己通过文件上传给这些 LLM 提供具体文档。我发现这个功能在很多方面都相当有用。

举个例子，我们来看 Claude，因为就在我录这期视频的时候，他们刚刚发布了 Claude 3.7，这是一个新的 Claude 模型，现在是最先进的。注意这里，3.7 现在有了思考模式。“普通”（Normal）就是我们目前看到的，但他们刚刚发布了“扩展”（Extended）模式，“最适合数学和编程挑战”。他们没说、但在底层很可能确实如此的是，这是用强化学习训练出来的，方式和其他所有思考模型类似。

所以我们现在能做的是，上传我们想让它在上下文窗口里引用的文档。举个例子，最近出了一篇我挺感兴趣的论文，来自 Arc Institute，基本上是一个在 DNA 上训练的语言模型。我有点好奇，我不是学生物的，但我有点好奇这是什么。这正是 LLM 极其擅长的完美例子，因为你可以把这些文档上传给 LLM，把这个 PDF 加载进上下文窗口，然后就它提问，基本上就是和 LLM 一起读这篇文档、向它提问。做法基本上就是拖拽，我们把这个 PDF 拖进来放在这里，大约 30 MB。
当 Claude 拿到这个文档时，很可能其实丢掉了大量图片之类的信息。我其实不清楚他们底层具体怎么做，他们也没怎么讲过，但很可能图片被扔掉了，或者即便保留了，模型对它们的理解可能也不如你我。底层很可能发生的是，这个 PDF 基本上被转换成一个文本文件，然后这个文本文件被加载进 token 窗口。一旦进了 token 窗口，它就在工作记忆里了，我们就可以就它提问。

通常当我开始和这些 LLM 一起读论文时，我会先说：“你能给我总结一下这篇论文吗？”我们看看 Claude 3.7 怎么说。好，“超出了本次对话的长度限制”。天哪，真的吗？该死。好吧，那我们试试 ChatGPT：“你能总结一下这篇论文吗？”我们用的是 GPT-4o，没开思考，这没问题，可以先不开思考。“正在阅读文档……论文《跨越所有生命域的基因组建模与设计》（Genome modeling and design across all domains of life）摘要：这篇论文介绍了 Evo 2，一个大规模生物学基础模型。”然后是关键特点，等等。我个人觉得这相当有帮助。然后我们可以来回交流，我一边读摘要、引言等等，一边向 LLM 提问，这让我更容易理解这篇论文。

我大量使用这个功能的另一个场景是读书。如今我已经几乎不会自己一个人读书了，我总会让一个 LLM 帮我读。最近的一个好例子是《国富论》（The Wealth of Nations），我最近在读。这本书出版于 1776 年，作者是亚当·斯密，算是古典经济学的奠基之作。这本书真的很好，让我觉得非常有意思的是，它写于那么久以前，却有很多见解我觉得即便在今天也非常应景。

举个例子，我现在读书的方式是：基本上先把书调出来，你得拿到这些内容的原始文本。《国富论》的话这很容易，因为它是 1776 年的书，比如在古腾堡计划（Project Gutenberg）上就能找到。然后基本上找到你正在读的那一章。比如我们读第一卷的这一章，这一章我最近在读，讲的是分工以及分工如何受市场范围的限制。粗略地说，如果你的市场很小，人们就无法专业化。而专业化基本上是一件大事，专业化对创造财富极其重要，因为你可以有专精于各自简单工作的专家，但这只有在有规模时才能做到，因为没有规模，你就没有足够大的市场来出售你的专长。

所以我们要做的是复制粘贴这本书，至少复制这一章，这是我喜欢的做法。我们去比如 Claude，说类似“我们在读《国富论》”这样的话。记住，Claude 知道《国富论》，但大概记不清这一章的具体内容，所以直接问 Claude 关于这一章的问题没有意义，因为它大概不记得这一章讲了什么。但我们可以通过把这一章加载进上下文窗口来提醒 Claude。所以：“我们在读《国富论》，请先总结一下这一章。”然后我在这里复制粘贴。在 Claude 里，当你复制粘贴的内容超过一定长度时，它不会在文本框里显示全部文字，而是生成一个小的文本附件。然后我们可以按回车，开始。通常我喜欢先从这一章讲了什么的总结开始，这样我有个大致的概念，然后我开始读这一章。任何时候我们有问题，就过来直接问。

我发现，基本上和 LLM 携手阅读，能显著提高我对这些章节的记忆和理解。我发现尤其是在你读其他领域的文档时，比如生物学，或者年代久远的文档，比如 1776 年的，你甚至需要一点帮助才能理解语言的基本意思。比如说，有了 LLM，我会更有勇气去啃一部非常古老、又在我专业领域之外的文本，也许是在读莎士比亚之类的东西。我觉得 LLM 让很多阅读比以前大大地更容易进入了，因为你不会一上来就陷入困惑，你可以慢慢读，和手边的 LLM 一起弄明白。所以我大量这样用，我觉得这极其有帮助。

遗憾的是，我不知道今天有什么工具能让这件事变得很容易。我现在是笨拙地来回折腾：字面意义上，我会在某个地方找到书，把内容复制粘贴来粘贴去，来回切换，极其别扭和笨拙。遗憾的是，我不知道有什么工具能让这件事变得很容易，但显然你想要的是，读书时直接选中一段文字，然后就它提问。据我所知，这目前还不存在，但这极其有帮助。我鼓励你试一试，不要独自读书。

【工具使用：Python 解释器与生态的混乱】

好，接下来我想讲的下一个非常强大的工具，是使用 Python 解释器，基本上就是赋予 LLM 使用和编写计算机程序的能力。这样 LLM 不再直接给你答案，而是现在有能力编写一个计算机程序，并输出 ChatGPT 应用能识别的特殊 token，意思是：“嘿，这不是给人看的，这基本上是在说，我在这里输出的东西其实是一个计算机程序，请去运行它，把运行结果给我。”所以这是语言模型和编程语言（这里是 Python）的整合。这极其强大。

我们来看看最简单的使用场景，以及它是什么样子。如果我去 ChatGPT，给它一道乘法题，比如 30 乘以 9 之类的，这是一道相当简单的乘法，你我大概都能心算，对吧？30 乘以 9，你直接就能得出 270。我们看看会怎样。好，LLM 做的正是我刚才做的，它算出乘法结果是 270。但它其实并不是真的在做数学，更像是近乎靠记忆，不过这足够简单，可以心算。所以这里没有用任何工具，发生的只是 zip 文件在做下一个 token 预测，在“脑子里”给出了正确结果。

现在的问题是，如果我们想要更复杂的东西呢？比如这个数乘以这个数是多少？当然，如果我让你算这个，你会立刻放弃，因为你知道自己不可能心算出来，你会去找计算器。这正是 LLM 现在也会做的。OpenAI 已经训练 ChatGPT 识别出它无法心算的问题，转而依靠工具。所以对于这类查询，我预期 ChatGPT 会转向使用工具。我们看看是什么样子。好，来了。这里打开的就是所谓的 Python 解释器。Python 基本上是一种小型编程语言。LLM 不是直接告诉你结果，而是写一个程序，然后有一些这里没显示的特殊 token，告诉 ChatGPT 应用请运行这个程序，然后 LLM 暂停执行。Python 程序运行，得出结果，再把结果作为文字传回给语言模型，语言模型接手，告诉你结果是多少。所以使用工具非常强大。OpenAI 已经训练 ChatGPT 知道在什么情况下依靠工具，他们是通过示例来教它的：人类标注员参与整理数据集，通过示例告诉模型在哪些情况下应该依靠工具、以及怎么用。总之，我们有了一个 Python 解释器。这只是一个乘法的例子，但它的能力要强大得多，我们待会儿看看在编程语言里实际能做些什么。

在继续之前，我只是想说明一点：遗憾的是，你得留意你在对话的 LLM 有哪些工具可用，因为不同的 LLM 可能没有完全相同的工具。尤其是，无法使用 Python 解释器或编程语言、或者不愿意使用它的 LLM，在一些较难的问题上可能给不出正确结果。举个例子，这里我们看到 ChatGPT 正确地使用了编程语言，没有心算。而 Grok 3，我相信它没有 Python 解释器这样的编程语言可用，它在这里其实是心算的，结果非常接近，但如果你仔细看，它算错了：这里应该是 120，而不是 060。所以 Grok 3 会靠幻觉硬算完这道乘法，心算，然后算错，虽然确实非常接近。然后我试了 Claude，这次 Claude 写的其实不是 Python 代码，而是 JavaScript 代码，但 JavaScript 也是一种编程语言，它得出了正确结果。然后我来到 Gemini，问的是 2.0 Pro，Gemini 看起来没有用任何工具，没有任何这方面的迹象，但它给出了我认为是正确的结果，这其实让我有点意外。所以我觉得 Gemini 是真的在“脑子里”正确算出来的，这有点不可思议。我们判断它没用工具的办法是，直接试一个更难的，我们得给它加大难度。好，它给了我们一个结果，然后我用这里的计算器算一下，它是错的，对吧？我用的是 MacBook Pro 的计算器，结果不对，非常接近，但不对，它就是会靠幻觉编出答案。

我想我的意思是，遗憾的是，LLM 目前的状况就是这样：不同的 LLM 有不同的可用工具，你得留意这一点。如果它们没有可用的工具，就会尽力而为，这意味着它们可能会给你编造一个结果。所以这是需要注意的地方。

【ChatGPT 高级数据分析：图表与绘图】

好，这个功能能发挥相当大威力的一个实际场景，是所谓的 ChatGPT 高级数据分析（Advanced Data Analysis）。据我所知，这是 ChatGPT 相当独有的功能，它基本上能让 ChatGPT 变成一个你可以与之协作的初级数据分析师。我给你看一个具体例子，不展开全部细节。

首先我们需要一些可以分析、绘图、做图表的数据。在这个例子里，我说：“我们来研究一下 OpenAI 的估值。”我明确要求 ChatGPT 使用搜索工具，因为我知道底层有这样一个工具，我不想让它给我编造数据，我想让它真的去查、有据可依，然后创建一个表格，每年对应一个估值。这些就是 OpenAI 历年的估值。注意 2015 年是“不适用”（N/A），所以估值是未知的。然后我说：“现在把它画出来，Y 轴用对数刻度。”这就是它变得强大的地方：ChatGPT 去写了一个程序，把数据画在这里。它为我们做出了一张小图，运行之后展示给我们。所以这可能相当不错、很有价值，因为这是收集数据、把数据上传到电子表格并可视化等等的一种非常简单的方式。

我要指出这里的一些问题。比如，注意 2015 年我们填的是 N/A，但 ChatGPT 在写代码时，再说一遍，我始终建议你仔细审查代码，它给 2015 年填了 0.1。所以它基本上隐含地假设了，在代码里做了一个假设：2015 年的估值是 1 亿美元，因为它填了 0.1。而且它这么做却没有告诉我们，所以有点偷偷摸摸。这就是为什么你得稍微留意一下代码。我熟悉代码，总会读一读，但我想，如果人们不能自己读懂并稍加核实，我会对推荐使用这些工具有所犹豫。

然后：“拟合一条趋势线，外推到 2030 年，标出 2030 年的预期估值。”它就去做了，基本上做了一个线性拟合，用的是 SciPy 的 curve_fit，做完之后给出了一张图，并告诉我按趋势，2030 年的估值约为 1.7 万亿美元。这听起来很惊人，但这里我起了疑心，因为我看到 ChatGPT 告诉我是 1.7 万亿，可当我看这里 2030 年时，它打印的是 20271.7B（B 即十亿美元，相当于约 20 万亿）。所以它打印变量时的外推结果和 1.7 万亿对不上，看起来估值应该是大约 20 万亿。于是我说：“把这个变量单独直接打印出来，它是多少？”然后它重写了代码，给出了变量本身，正如我们在这里的标签看到的，它确实是 20271.几，所以 2030 年真正的指数趋势外推估值是 20 万亿。我就想当面质问 ChatGPT：“你骗了我，对吧？”它说：“是的，抱歉，我搞错了。”

我喜欢这个例子，第一，它展示了这个工具的威力，它能为你做出这些图，非常好；但第二，我觉得它也展示了其中的棘手之处：比如这里它做了一个隐含假设，而这里它其实告诉了我一个错误的东西，它编造了 1.7 万亿。所以再说一遍，它有点像一个非常非常初级的数据分析师，能画图很了不起，但你仍然得大致知道这段代码在做什么，得小心、仔细审查，确保你真的在密切关注，因为你的初级分析师有点心不在焉，并不总是对的。所以它真的很强大，但也要小心使用。高级数据分析我就不展开全部细节了，关于这个话题已经有很多视频，如果你想在工作中用到其中一些，我建议你去看看那些视频。我不展开全部细节了。总之前景很好，但要小心。

【Cursor：Composer 与写代码】

好，我已经给你展示了 LLM 相当擅长写代码。它们不仅能输出代码，而且很多应用，比如 ChatGPT、Claude 等等，已经开始在浏览器里部分地运行这些代码：ChatGPT 会生成图表并显示出来，Claude Artifacts 则会真正集成你的 React 组件，让你直接在浏览器里内嵌使用。

其实，我个人在生活和工作中的大部分时间都花在写代码上，但我并不会去 ChatGPT 要代码片段，因为那太慢了，ChatGPT 根本没有在专业上和我一起写代码所需的上下文，其他所有 LLM 也一样。所以我不是在网页浏览器里使用这些 LLM 的功能，而是用一个专门的应用，我觉得业内很多人也是这样。现在这类应用已经有好几个了：VS Code、Windsurf、Cursor 等等。我目前喜欢用 Cursor，这是一个单独的应用，你可以装在比如你的 MacBook 上，它直接处理你文件系统里的文件。所以这不是一个你访问的网页，而是一个你下载的程序，它引用你电脑上的文件，和你一起处理和编辑这些文件。

它看起来是这样的。这里有一个简单的例子，是我用 Cursor 几分钟搭出来的一个 React 应用。在底层，Cursor 用的是 Claude 3.7 Sonnet，所以它在底层调用 Anthropic 的 API，让 Claude 做所有这些事。但我不必手动去 Claude 那里把代码块复制粘贴来粘贴去，这个程序替我做了，它拥有目录里所有文件的上下文，诸如此类。我在这里开发的应用是一个非常简单的井字棋（tic-tac-toe），作为例子，Claude 大概一分钟左右就写好了。我们可以玩一下，X 可以赢，也可以打平。哦，等等，抱歉，不小心赢了。也可以打平。

我只是想简单给你看看，如何高效使用 Cursor 足够单独做一期视频。我只是想让你有个感觉：我从一个全新的项目开始，让这里的 Composer 应用，也就是所谓的 Composer 功能，基本上搭建一个新的 React 仓库，删掉大量样板代码，请做一个简单的井字棋应用。所有这些都是 Cursor 完成的，我其实什么都没做，只写了大约五句话，然后它改动了一切，写了所有的 CSS、JavaScript 等等。然后我在这里运行它，在本地托管，在浏览器里和它交互。

【语音输入与输出】

好，现在我想再换个方向。到目前为止我们讲的一切都是通过文字与模型交互：我们输入文字，它回给我们文字。现在我想谈谈不同的模态，也就是说，我们想用更符合人类天性的方式和这些模型交互：我想对它说话，想让它用语音回答我；我想给它图片或视频，反过来也想让它生成图片和视频。所以它需要处理语音和音频的模态，以及图像和视频的模态。

我想先讲的是，怎样非常轻松地直接和这些模型说话。我自己用的时候，粗略地说，50% 的时候我在键盘上打字，另外 50% 的时候我其实懒得打，宁愿直接对模型说话。在手机上这一点更明显，我大概 80% 的查询都是语音，因为我懒得在手机上打字。手机上的事情稍微简单一些。现在 ChatGPT 应用长这样，我想先讲的是，其实有两种语音模式。你看这里有个小麦克风，这里还有个小音频图标，这是两种不同的模式，我两个都讲。先说音频图标，抱歉，是这里的麦克风图标，它能让应用听你的声音，然后转录成文字，这样你就不用打字了，它会把你的语音转换成文字。在应用上这非常简单，我一直这么做：打开应用，新建一个对话，按下按钮，“天空为什么是蓝色的？是因为它在反射海洋吗？对，为什么？”然后我点“好”。我不知道这会不会出来，但它基本上把我的语音转成了文字，我直接点发送，就能得到回复。所以这相当简单。

到了桌面端，事情会复杂一点，原因如下：在桌面应用里，你看我们有音频图标，写着“使用语音模式”，这个我们马上讲，但没有麦克风图标，所以我没法在这个应用里直接说话、让它转成文字。所以我在 MacBook 上一直用的是，基本上退而求其次，用一些提供这种功能的应用。它不是 ChatGPT 专属的，而是一个系统级的功能，把你的语音转录成文字。人们似乎在用的一些应用有 SuperWhisper、Wispr Flow、MacWhisper 等等。我目前在用的叫 SuperWhisper，我觉得相当不错。

用法是这样的：你下载这个应用，装在你的 MacBook 上，然后它就随时准备听你说话。你可以绑定一个你想用的按键，比如我用 F5。每当我按下 F5，它就会听我说话，我可以说话，然后再按一次 F5，它就会转录成文字。我演示一下，我按 F5：“我有个问题，天空为什么是蓝色的？是因为它在反射海洋吗？”好，就在这里，回车，我什么都不用打。所以我想说，我的很多查询，大概一半，都是这样的，因为我不想真的打字。当然很多查询会需要我说出产品名称、具体的库名之类的东西，这些往往转录得不太好，这种情况下我会打字，确保正确。但在非常简单的日常使用中，我经常可以直接对模型说话，它会正确转录。

这基本上是输入端。在输出端，通常应用会有让它朗读给你听的选项。它的作用是把这段文字交给一个做反向转换、也就是文字转语音的模型。在 ChatGPT 里，这里有个图标，写着“朗读”（Read aloud），我们可以点一下：“不，天空并不是因为反射海洋才是蓝色的，这是一个常见的误解。天空呈蓝色的真正原因是瑞利散射……”好，我停下来。不同的应用，比如 ChatGPT、Claude、Gemini 或者你在用的任何应用，可能有、也可能没有这个功能，但这绝对是你可以留意的东西。输入端如果是系统级的，你当然可以在任何应用里把语音转成文字；但朗读给你听这一点，不同的应用可能有也可能没有这个选项，或者你可以考虑下载一个系统级的语音转文字，抱歉，文字转语音应用，就像这些一样，让它大声朗读。这些就是你可用的选项，也是我想提一下的。基本上这里最大的结论是：别打字，用语音。它效果相当好，我无处不用。我想说我大约一半的查询，可能还多一点，都只是语音，因为我懒，而且这样快得多。

【高级语音模式：模型内部的真音频】

好，但我们目前讲的，我会称之为“假音频”。说它是假音频，是因为我们仍然是通过文字与模型交互，只是让它更快了，因为我们基本上是用语音转文字或文字转语音模型做预处理，从音频到文字、从文字到音频，所以这并不是在语言模型内部直接完成的。不过，我们现在确实有技术能真正做到这一点，把真音频放在语言模型内部处理。如果你还记得的话，这里实际被处理的是文字 token。所以你可以做的是，用类似把文字切成 token 的方式，把音频这样的其他模态切块。通常的做法是，基本上把音频分解成频谱图（spectrogram），看到音频里存在的所有不同频率，然后按一个个小窗口，基本上把它们量化成 token。所以你可以有一个包含 10 万个可能的小音频块的词表，然后真的用这些音频块来训练模型，让它真正能理解这些小段音频。这赋予了模型很多你用我们目前讲的假音频永远得不到的能力。这正是这里另一个按钮的用途，这就是我所说的真音频，不过有时人们会叫不同的名字。比如你去看 ChatGPT 的定价，得找那个叫“高级语音模式”（Advanced Voice Mode）的东西。高级语音模式指的就是真音频，意思是语音在语言模型内部原生处理，模型能理解音频块、预测音频块，所以它能直接用音频听和说，完全不涉及文字。这相当神奇，真的很棒，我来试一下。

【NotebookLM：生成播客】

好，我还想给你看另一种通过音频与语言模型交互的范式，就是 Google 的 NotebookLM。你去 notebooklm.google.com，它的用法是：左边是来源（sources），你可以在这里上传任意数据，可以是纯文本、网页、PDF 文件等等。我上传了这篇 PDF，讲的是 Arc Institute 做的一个用于基因组序列分析的基础模型。你把它放进来之后，它就进入了模型的上下文窗口。然后第一，我们可以就这些信息聊天，可以提问、得到回答。但第二，有意思的是，右边有这个“深度对谈”（Deep Dive）播客，有一个生成按钮，你按下去，等几分钟，它就会根据你放进来的任何信息来源生成一期定制播客。比如这里，我们为这篇论文生成了一期大约 30 分钟的播客。能按需获得播客真的很有意思，我觉得如果你出去散步之类的，这有点有趣，也有点疗愈。我有时会上传一些我被动地有点兴趣、想听一期播客的东西，听着挺好玩的。我们简单看看它是什么样的：

“好，听好了，我们要深入探讨能理解 DNA 的 AI。”
“真是很迷人的东西。”
“不只是读懂它，而是预测变化会如何影响一切。”
“对，从单个蛋白质一直到整个生物体。”
“真的很了不起。有一个叫 Evo 2 的新生物学基础模型，真正站在这一切的最前沿。”
“Evo 2，好。”
“它是在一个叫 OpenGenome2 的海量数据集上训练的，涵盖了超过 9……”

好，我想你大致明白了。这里有几点：你可以用特别指示来定制播客的内容，然后重新生成；你还可以进入一个叫“互动模式”的东西，在播客进行中真的插话提问，我觉得这挺酷的。所以我偶尔会用它，当有一些我通常不是专家、只是被动地有点兴趣的文档、话题或论文，而我要出去散步或者长途开车，想听一期关于这个话题的定制播客时。我发现它在这种小众场景下很好用，因为这类话题不会有真人制作的播客覆盖。它有点像一个关于你想要的任何小众话题的 AI 播客。这就是 NotebookLM。

我还想简单提一下我生成的这个播客，它像是一档叫《神秘历史》（Histories of Mysteries）的播客的一季，我把它上传到了 Spotify。这里我只是挑了一些我感兴趣的话题，为每个话题都生成了一期深度对谈播客。如果你想对这个工具能做什么有个感觉，这是一种获得定性认识的方式：去 Spotify 找到它，听其中几期，感受一下它能做什么，然后自己拿一些文档和来源玩一玩。这就是用 NotebookLM 生成播客的交互方式。

【图像输入与 OCR】

好，接下来我想讲图像。和音频一样，事实证明你也可以用 token 来表示图像。我们可以把图像表示为 token 流，让语言模型像之前对文字和音频建模那样对它们建模。举个例子，最简单的做法是：拿一张图像，基本上画一个矩形网格，把它切成一个个小块（patch），然后图像就只是一串小块。对每一个小块进行量化，基本上就是构建一个包含比如 10 万个可能小块的词表，然后用词表里最接近的那个小块来表示每一块。这样你就能把图像表示成 token 流，然后把它们放进上下文窗口，用它们训练模型。

这其中不可思议的地方在于，语言模型，也就是 Transformer 神经网络本身，甚至不知道有些 token 碰巧是文字，有些 token 碰巧是音频，有些碰巧是图像，它只是对 token 流的统计规律建模。只有在编码器和解码器那里，我们才暗中知道：好，图像是这样编码的，然后 token 流再以这种方式解码回图像或音频。所以就像我们处理音频一样，我们可以把图像切成 token，应用所有相同的建模技术，什么都没真正改变，变的只是 token 流和 token 词表。

现在我给你看一些具体例子，说明我在自己生活中是怎么用这个功能的。好，先从图像输入开始，我想给你看一些我用 LLM 时上传图片的例子。如果你去你最喜欢的 ChatGPT 或其他 LLM 应用，通常都可以上传图片并就它提问。

这里有一个例子，我在看 Brian Johnson 长寿混合饮的营养成分表。基本上我不太清楚所有这些成分是什么，对吧？我想多了解一些，想知道它们为什么在长寿混合饮里。这是一个很好的例子：首先我想把它转录成文字。我喜欢先把相关信息转录成文字的原因是，我想确保模型正确地看到了这些数值，因为我不能百分之百确定它能看清东西。所以当它把内容整理成表格时，我可以确认它看对了，然后再就这段文字提问。所以只要有可能，我喜欢分两步来做。然后比如这里，我让它把成分分组，基本上按它们可能的安全程度排序，因为我想有个概念：好，这些成分里哪些是你在复合维生素里就能找到的超级基础的成分，哪些有点可疑、奇怪、或者研究不够充分之类的。模型非常好地帮我理清了长寿混合饮里有什么、可能缺什么、为什么会有这些成分等等。这同样是我之后自己做研究的一个很好的初稿。

第二个我想给你看的例子是我的验血报告。最近我做了一套血液检查，他们发回给我的是一份大约 20 页的 PDF，超级没用，我拿它能干什么？显然我想了解多得多的信息。所以我在这里做的是上传我所有的结果。比如我先做了血脂检查，上传了我血脂检查结果的小截图，然后我确认 ChatGPT 看到的所有结果都是对的，然后它真的给我做了解读，然后我就这样迭代下去。你能看到这里的滚动条很靠下，因为我一部分一部分地上传了我所有的验血结果。顺便说一句，结果都很好，我对这次验血非常满意。

我想说的是，第一，注意转录，确保它是对的。第二，这样做非常容易，比如在 MacBook 上，你可以按 Control+Shift+Command+4，框选一个窗口，它会把这个窗口复制到剪贴板，然后你就可以去 ChatGPT，按 Control+V 或 Command+V 粘贴进去，然后就它提问。所以用这个技巧，截取屏幕上的一块区域、就它提问，非常容易。另外我想说的是，当然这是医疗信息，你不希望它出错。我想说，在验血结果这件事上，我觉得可以更有信心地信任 ChatGPT 一些，因为这不是什么冷门的东西，我确实预期会有海量关于验血结果的文档，我也确实预期模型的知识足够好，大致理解这些数字、这些参考范围，而且我可以告诉它更多关于我自己的情况之类的。所以我确实觉得它相当不错，但当然你大概也想和真正的医生谈谈。不过我觉得这是一个非常好的初稿，也许能给你一些可以和医生讨论的东西，等等。

另一个例子是，我做很多数学和代码方面的事情，最近我在一篇论文里发现了这道很刁钻的题目。我复制粘贴了这个表达式，要求它转成文字，因为这样我就可以复制这段文字，问一个模型，它认为 x 取 π 时这个表达式的值是多少之类的。这是一道陷阱题，你可以自己试试。

下一个例子，这里我有一支高露洁（Colgate）牙膏，我对我这支高露洁牙膏里的所有成分有点怀疑，想知道这些到底都是什么鬼东西。所以：“这是高露洁，这些到底是什么东西？”它转录了成分，然后给我讲了讲这些成分，我觉得这极其有帮助。然后我问它：“好，这些里面哪些算最安全的，哪些可能最不安全？”然后我问它：“好，如果我只关心牙膏的实际功能，不太在乎颜色之类其他没用的东西，这些里面哪些可以扔掉？”它说：好，这些是必要的功能性成分，而这一堆是你大概不想要出现在牙膏里的杂七杂八的东西。基本上，剧透一下，这里大部分东西都不该在里面。所以公司往你的食物、化妆品之类的东西里加这么多其实根本不需要的东西，这真的让我很不爽。

我想给你看的最后一个例子是，这是我发给一个朋友的梗图，我朋友很困惑，说：“这是什么梗？我没看懂。”于是我给他们演示 ChatGPT 能帮你理解梗图。我复制粘贴了这张梗图，让它解释。它基本上解释了这个梗：一群乌鸦在英文里叫作“a murder”（字面意为“谋杀”），所以当这只乌鸦靠近那只乌鸦时，就像是“attempted murder”（谋杀未遂，这里双关为“凑成一群未遂”）。所以，是的，ChatGPT 解释这个笑话解释得相当好。

【图像输出：DALL·E、Ideogram 等】

好，反过来，你也可以让这些模型生成图像。OpenAI 的这项产品叫 DALL·E，现在是第三版，它基本上能根据任意提示词生成非常漂亮的图像。这是京都的那座寺庙吗？我想我去过。这真的很漂亮。它能生成风格非常鲜明的图像，你可以要求任意主题的任意风格，等等。我个人其实不太常用这个功能，所以我随便弄了个例子给你看。比如：“今天的重大新闻头条是什么？”有一堆关于政治、健康、国际、娱乐等等的头条，我在这里用了搜索工具。然后我说：“生成一张概括今天的图像。”有了上下文里的所有这些内容，我们就能生成这样一张概括今天的图像，只是举个例子。

我使用这个功能通常是为了做各种内容创作。比如你去我的 YouTube 频道，这期视频《我们来复现 GPT-2》（Let's reproduce GPT-2），这里的这张图其实是用 DALL·E 的一个竞争对手生成的，叫 Ideogram（ideogram.ai）。这张图也一样，也是 AI 生成的。这张图我想也是 Ideogram 生成的，也可能是 ChatGPT，我不确定，这几个工具我会换着用。所以我用它来生成图标之类的东西，你基本上可以要任何你想要的。

我要指出的是，就图像输出而言，它的实际运作方式目前并不是完全在模型内部完成的。用 DALL·E 3 的话，这是一个单独的模型，接收文字、生成图像。在当前版本的 ChatGPT 中，底层实际发生的是：当我说“生成一张概括今天的图像”时，它其实会在底层为这张图写一段描述（caption），然后这段描述被发送给一个单独的模型，也就是图像生成模型。所以它是以这种方式拼接起来的。不过我觉得在现阶段完全理解这一点并不是特别重要。这就是图像输出。

【视频输入：在手机应用上指着说】

接下来我想给你看一个扩展功能：模型其实能“看”视频。这包含在我之前给你看过的高级语音模式里。网页版没有，但手机应用里有。我们进入高级语音模式，连接上。

“你好，我正在演示视频功能。”我对着镜头展示，那边有个小视频图标，你按下它，就能看到，基本上可以给模型看各种东西。
“我能看到摄像头画面了。看起来你墙上有一些黑色的吸音泡沫板。你是在测试它们降低房间回声的效果吗？”
“对，我是在测试吸音泡沫，没错，但它其实没那么有用。”
“有时摆放位置会有很大影响。你试过多覆盖一些墙角，或者尝试不同的布局吗？”
“好吧，我们看看这个。这是什么书？”
“是的，这是杰克·威泽弗德（Jack Weatherford）的《成吉思汗与今日世界之形成》（Genghis Khan and the Making of the Modern World），一本讲述成吉思汗对世界历史影响的精彩著作。”
“对，很好。你看到这另一本书了吗？是什么？”
“那是理查德·费曼（Richard Feynman）的《别闹了，费曼先生》（Surely You're Joking, Mr. Feynman!），是这位物理学家生平趣事的合集，非常有趣。”

“那是一台 Aranet4，便携式二氧化碳监测仪。它可以测量二氧化碳浓度、温度、湿度和气压，对监测室内空气质量很有用。”

“对，干得好。谢谢你的演示。”
“不客气，很高兴能帮上忙。如果还需要什么，随时告诉我。”

这就是一个简短的演示。你基本上打开摄像头，可以指着东西，直接和模型说话。这相当神奇，用起来超级简单。我个人在日常生活中不用它，因为我算是所有 ChatGPT 应用的重度用户（power user），我不会到处指着东西问模型，我通常有关于代码、编程之类的非常有针对性的查询。但我觉得如果我要给我的父母或祖父母演示一些这样的东西，让他们以非常自然的方式交互，这大概就是我会给他们看的东西，因为他们只需把摄像头对着东西提问就行。至于底层，我其实不能百分之百确定他们目前是在处理视频，我觉得他们实际上可能还是只截取图像，比如每秒截一张图之类的。但从你作为工具使用者的角度来看，感觉确实就是你可以把视频流传给它，它能看懂。所以我觉得作为一个功能，这相当酷。

【视频输出：Sora、Veo 2 等】

最后，我想简单给你看看，现在有很多工具可以生成视频，它们令人惊叹，而且发展得非常快。我不打算讲得太详细，因为我觉得这相对来说不言自明，我个人在工作中也不怎么用，但那只是因为我不在创意类的行业之类的。这是一条比较多个 AI 视频生成模型的推文，举个例子。这条推文大约是一个月前的，所以之后可能已经有变化，但我只是想给你看看，你知道，所有这些模型都被要求生成，我猜是丛林里的一只老虎，它们都相当不错。我觉得目前 Veo 2 真的接近最先进水平，非常好。是的，这相当不可思议，对吧？这是 OpenAI 的 Sora，等等。所以它们都会有略微不同的风格、不同的质量等等，你可以对比一下，使用其中一些专门解决这个问题的工具。

【ChatGPT 记忆与自定义指令】

好，我想讲的最后一个话题是一些我觉得很值得一提的提升使用体验（quality of life）的功能。第一个我想讲的是 ChatGPT 的记忆功能。比如说你在和 ChatGPT 聊天，你说了类似这样的话：“你认为好莱坞的巅峰大概是什么时候？”我其实挺意外 ChatGPT 在这里给了我一个答案，因为我觉得这些模型往往非常抗拒发表任何观点，会说一些诸如“哦，我只是一个 AI，我在这里是为了帮助你，我没有任何观点”之类的话。所以这里它其实似乎有个观点，它评估说，在系列电影接管之前，最后一个真正的巅峰是 1990 年代到 2000 年代初。我恰好真的很同意 ChatGPT 的看法，“我非常同意”，完全同意。

现在我好奇这里会发生什么。好，什么都没发生。所以基本上，就像我们讲过的，每一次对话都从一个空的 token 窗口开始，一直持续到结束，一旦我开新对话或新聊天，一切都会被清空。但 ChatGPT 确实有能力在不同聊天之间保存信息，只是需要触发。有时 ChatGPT 会自动触发，但有时你得主动要求，基本上说类似“你能记住这个吗”或者“记住我的偏好”之类的话。我想要的是，我觉得它应该会生效。来了，你看，“记忆已更新：认为 1990 年代末和 2000 年代初是好莱坞最伟大的巅峰”等等。是的，然后它还稍微聊了聊 1970 年代，然后它让你可以管理记忆，我们马上会看。

这里发生的是，ChatGPT 写了一段小摘要，记录它了解到的关于我这个人的信息，并把这段文字记录在它的记忆库里。记忆库基本上是 ChatGPT 中单独的一部分，有点像一个关于你的知识数据库，这个知识数据库总是被添加在所有对话的开头，让模型能够访问它。我其实非常喜欢这个功能，因为每当你和 ChatGPT 对话，记忆时不时就会更新。如果你就让它这样运行，自然地使用 ChatGPT，那么随着时间推移，它在某种程度上真的会了解你，会开始引用记忆中的内容。所以这个功能刚宣布时，我不能百分之百确定它是否会有帮助，但我想我确实渐渐认可它了，我已经在很多方面用过它，我确实感觉 ChatGPT 随着时间推移更了解我一点，和我更相关一点，而这一切都只是通过自然的交互、随着时间通过这个记忆功能发生的。所以有时它会明确触发，有时你得主动要求。

好，我本来想给你看看我的一些记忆以及怎么管理它们，但我刚看了一下，说实话有点太私人了。总之它就是一个数据库，一个文本字符串列表，这些文本字符串会被放到开头。你可以编辑记忆，这一点我很喜欢，你可以添加记忆、删除记忆、管理你的记忆数据库，这很了不起。我还要提一下，我认为记忆功能是 ChatGPT 独有的，我觉得其他 LLM 目前没有这个功能。我还要说，比如 ChatGPT 在推荐电影方面非常出色，所以我其实认为，把这些放在它的记忆里，会帮助它为我做出更好的电影推荐。所以这相当酷。

接下来我想简单展示的是自定义指令（custom instructions）。你可以在很大程度上修改你的 ChatGPT，以及你喜欢它和你说话的方式，我也相当欣赏这一点。你可以进入设置，“自定义 ChatGPT”，你看这里写着“ChatGPT 应该具备哪些特质？”我就告诉它：别像个 HR 业务伙伴（HR business partner）那样，正常和我说话就行；还有，我就是喜欢解释、教育性内容、洞见等等，所以只要有可能就尽量有教育性。你大概可以在这里输入任何东西，可以稍微试验一下。然后我在这里也试着告诉了它我的身份，我只是在试验这些，等等。我还在学韩语，所以这里我告诉它，在给我韩语时应该使用这种正式程度的语气。这是一个不错的默认设置，因为否则它有时可能给我非正式的语气，有时又可能给我过于正式的语气，而我默认就想要这种语气。所以这是我添加的一个例子。凡是你想在所有对话之间全局修改 ChatGPT 的地方，都可以放在这里的自定义指令里。所以我相当欢迎这个功能，我觉得在很多其他 LLM 上你也可以这样做，去设置里找找。

【自定义 GPT】

好，我想介绍的最后一个功能是自定义 GPT（custom GPTs），我偶尔会用，我最喜欢专门用它来学语言。我给你举个例子说明我是怎么用的。它们好像显示在左边这里。我给你看这个，比如“韩语详细翻译器”。不，抱歉，我想先从这个开始：“韩语词汇提取器”。基本上这里的想法是：这是一个自定义 GPT，我给它一个句子，它就以词典形式提取词汇。比如这里，给定这个句子，这是提取出的词汇。注意它的格式是“韩语;英语”，这可以复制粘贴到 Anki 抽认卡应用里，基本上这意味着把一个句子变成抽认卡非常容易。

它的工作方式基本上是，我们去看看底层，进入“编辑 GPT”，你会看到这全都只是通过提示词完成的，这里没有什么特别的事情发生。这里最重要的是指令（instructions）。我把它打开，我只是解释了一点背景信息：我在学韩语，我是初学者。指令：我会给你一段文字，我想让你提取词汇。然后我给了它一些示例输出。基本上我写得很详细。我给 LLM 写指令时，总是喜欢第一，给出描述，但同时也给出示例，我喜欢给具体的例子，所以这里有四个具体的例子。我在这里做的，其实是构造一个所谓的少样本提示（few-shot prompt）。我不只是描述一个任务，那有点像以零样本（zero-shot）的方式要求它表现，就是没有示例直接做；我给了它几个示例，这就是一个少样本提示。我发现这总能提高 LLM 的准确率，所以我觉得这是一个普遍适用的好策略。然后当你更新并保存这个 GPT 之后，只需给它一个句子，它就会执行那个任务。

所以注意，这里没有发生任何新的、特别的事情，我所做的只是省了自己一点工夫，因为我不必基本上从头开始、再把整个设置详细描述一遍，不必每次都把这些告诉 ChatGPT。所以这个功能的本质就是帮你省下写提示词的时间。如果有某个提示词你反复使用，与其一遍遍地复用、复制粘贴这个提示词，不如创建一个自定义 GPT，只保存一次这个提示词，然后每次使用时变化的只是不同的句子。所以我给它一个句子，它总会执行这个任务。如果有某些你总要用的提示词或任务，这就很有帮助。

下一个例子，我觉得适用于所有其他语言，就是基础翻译。比如我有一个韩语句子，我想知道它是什么意思。很多人会直接去 Google 翻译之类的地方，而众所周知，Google 翻译对韩语不太好，所以很多人用 Naver 或者 Papago 等等。如果你把句子放到这里，它会给你一个翻译。这些翻译作为翻译往往还行，但我其实并不真正理解这个句子是怎么变成这个译文的，各个部分在哪里。我需要、我想知道更多，我想能提出澄清问题等等。这里它稍微拆分了一下，但效果没那么好，因为有一堆东西被省略了，通常是助词之类的。所以我基本上在 ChatGPT 里搭了一个好得多的翻译器，我觉得它的效果明显更好。我有一个“韩语详细翻译器”，当我把同一个句子放进来时，我得到了我认为好得多得多的翻译：“现在是下午三点，我想去我最喜欢的咖啡馆。”然后这是它的拆分方式，我能清楚地看到它的各个部分是如何一点一点翻译成英语的，比如“지금”是“现在”，“오후”是“下午”，等等。所有这些都有。真正美妙的是，我不仅能看到所有细节，还能就在这里提出澄清问题，我们可以接着追问、继续对话。所以我认为在翻译上，这比你能找到的任何其他东西都要明显好得多。如果你在学一门外语，除了 ChatGPT，我不会用别的翻译器。它理解大量细微差别，理解俚语，极其出色。我不知道到了这个时候翻译器为什么还存在，我觉得 GPT 好太多了。

它的工作方式是，我们去这里编辑这个 GPT，简单看一下，这些是我给它的指令：“你会收到一个韩语句子，你的任务是先把整个句子翻译成英语，然后把整个译文详细拆解。”所以这里我同样在构造一个少样本提示。这里是我给它示例的方式，因为这些示例稍长一些，所以我用了一种类似 XML 的语言，只是为了让模型明白示例一从这里开始、到这里结束，我用的是类似 XML 的标签。这是我给它的输入，这是期望的输出，我就给它几个示例，并详细地写清楚。然后这里我还有几条指令。我觉得这其实和教人很像，就像你教一个人做一项任务：你可以用语言解释他们应该做什么，但如果你通过示例演示如何完成这项任务，效果会好得多。我觉得人类也能以少样本的方式学习，效率高得多。所以你可以用任何你喜欢的方式来编写它，然后你就得到了一个专门为你设计的定制翻译器，比你在网上能找到的好得多。从经验上看，我发现 GPT 在翻译方面相当好，尤其是对于像我现在这样的初学者。

好，也许最后给你看一个，因为我觉得它把很多功能串在了一起。是这样的：有时我在看一些韩国内容，比如这里我们能看到有字幕，但字幕是烧录在视频画面里、在像素里的，所以我无法直接获取字幕。我在这里能做的就是截个图，这是《单身即地狱》里 Jin-young 和 Seul-ki 之间的一个场景。我截下来，粘贴到这里，然后这个我称为“Korean Cap”的自定义 GPT 会先做 OCR（文字识别），然后翻译，然后拆解。基本上它就做这些，然后我可以继续看，每当我需要帮助时，就把截图复制粘贴到这里，它基本上就会完成翻译。如果我们看看底层，编辑 GPT，你会看到在指令里，它只是简单地把指令拆分开：“你会收到一张来自电视节目《单身即地狱》的截图（当然你可以改），它展示了一小段对话。”所以我在给模型一个提醒，告诉它正在发生什么的上下文。然后这些是指令：先 OCR，然后翻译，然后拆解。然后你可以用任何你喜欢的格式，可以玩一玩、改进它，但这只是一个简单的例子，效果相当不错。

所以，是的，这些就是我为自己搭建的那类自定义 GPT，其中很多和学语言有关。创建的方法是，来到这里，点击“我的 GPT”（My GPTs），基本上就是创建一个 GPT，你可以在这里随意配置。据我所知，GPT 是 ChatGPT 相当独有的功能，但我觉得有些 LLM 应用大概也有类似的功能，所以你可能想在项目设置里找找。

【总结】

好，我可以没完没了地讲 ChatGPT 等产品中的所有不同功能，但我觉得这是一个不错的入门，也是一个不错的鸟瞰，能让你看到现在有什么、人们在推出什么、应该留意什么。

总结一下：LLM 应用（比如 ChatGPT）的生态正在快速增长、变化、转移，而且蓬勃发展。ChatGPT 是第一个，也是在位者，大概是其中功能最丰富的，但其他所有应用都在非常快速地成长，要么达到功能对等，要么在某些特定方面甚至超越 ChatGPT。比如，ChatGPT 现在有了联网搜索，但我还是会去 Perplexity，因为 Perplexity 做搜索已经有一段时间了，我觉得他们的模型相当好。另外，如果我想快速做一些简单网页应用的原型，想画图表之类的，我真的很喜欢 Claude Artifacts，这不是 ChatGPT 的功能。如果我只是想和模型聊天，我觉得 ChatGPT 的高级语音模式如今相当不错；如果它对你太拘谨，你可以换到 Grok，诸如此类。所以基本上，各个应用都有各自的优缺点，但我认为 ChatGPT 迄今为止是一个非常好的默认选择，是在位者，功能也最丰富。

那么，在考虑这些应用及其功能时，我们要留意哪些东西呢？首先要意识到的、我们也看过的一点是：你基本上是在和一个 zip 文件对话。要清楚你处在哪个定价档位，以及根据定价档位你在用哪个模型。如果你用的是一个非常大的模型，那个模型基本上会有大量的世界知识，能回答复杂的问题，写作会非常好，写作上也会更有创造力，等等；如果模型很小，那它大概就没那么有创造力，世界知识也少得多，而且会犯错，比如可能产生幻觉。

在此之上，很多人对那些会思考、经过强化学习训练的模型非常感兴趣，这是当今研究的最新前沿。我们特别看到，这在数学、代码和推理之类的问题上非常有用，能带来额外的准确率。所以先试试不带推理的；如果你的模型解决不了那类问题，就试着换成推理模型，在用户界面里找找它。

在此之上，我们看到我们正在快速地给模型提供更多的工具。比如我们可以给它们联网搜索，所以如果你在聊一些新鲜的信息或知识，大概不在 zip 文件里，那你实际上需要使用联网搜索工具，而并不是所有这些应用都有。此外，你可能想让它能使用 Python 解释器，这样它就能写程序。比如你想生成图表或绘图并展示出来，你可能想用高级数据分析之类的东西；如果你在做某种网页应用的原型，或者在生成图表，你可能想用 Artifacts，因为它就内嵌在应用里；或者如果你在专业地写代码，你可能想转向另一个应用，比如 Cursor 和 Composer。

在这一切之上，还有一层多模态，它也在迅速成熟，你可能也想留意。我们讲到了所有不同模态的输入和输出，不只是文字，还有音频、图像和视频。我们还讲到，其中一些模态可以在语言模型内部原生处理，有时这些模型被称为全模态（omni）模型或多模态模型，它们可以由语言模型原生处理，这会强大得多；或者它们可以作为一个单独的模型外挂上去，通过文字之类的方式与主模型通信。所以这也是有时需要留意的一个区别。

在这一切之上，我们还讲到了提升使用体验的功能，比如文件上传、记忆功能、自定义指令、GPT 等等。也许我们看到的最后一点是，这些应用通常都有一个网页界面，你可以在笔记本电脑上访问，也有手机上可用的移动应用。我们看到，很多功能可能在浏览器版里有而手机上没有，反之亦然，所以这也是需要留意的。所以这一切有点像个动物园，有点疯狂，但这些就是现有的那类功能，当你在所有这些不同的应用之间工作时，可能会想去找找。在个性、能力之类的方面，你大概会有自己最喜欢的那一个，但这些是你在一段时间里需要思考、寻找和试验的一些东西。

我觉得作为入门，目前这就相当不错了。感谢观看，希望我的例子对你来说有趣或有帮助，我们下次见。
