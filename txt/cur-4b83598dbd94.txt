多发一点 CSS 来提升网站性能（Improving site performance by shipping more CSS） ｜ GitHub Blog ｜ 文章 ｜ https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/

GitHub 工程师 Josh Black 复盘 github.com 如何彻底告别 CSS-in-JS、改用 CSS Modules。起因是组件暴增后，基于 styled-components 的 Primer 拖慢了首屏和服务端渲染。CSS Modules 保留了就近放置和局部类名，又没有运行时开销。

迁移的原则是不弄坏网站：逐个组件新增 CSS Modules 版本，用功能开关切换，用视觉回归测试确认截图一致，再从团队、员工到全体用户逐步放量。2024 年 12 月 Primer 迁完，SSR 时间减少 55%，组件初始化时间减少 25%。期间 styled-components 宣布进入维护模式，印证了方向。更难的是遍布全站的 sx 属性：他们做了过渡包，靠 codemod 和 8 名工程师半年迁了约 6400 处，部分页面 SSR 提速最多 22%；2026 年再用 Copilot 编程 agent，两人三周清掉剩下的 895 处。主题系统也照此迁完，到 2026 年 6 月全站 100% 运行在 CSS Modules 上。作者认为这实际上是一次渐进式重建，功能开关和回归测试让它安全完成。
