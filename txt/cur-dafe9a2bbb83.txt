在由自主智能体主导生成的代码库中，重构的核心经济学价值在于通过前置消耗 Token 优化模块边界与文件粒度，使后续特征迭代中的上下文读取开销呈现断崖式下降。

Thoughtworks 的 Giles Edwards-Alexander 在 Martin Fowler 网站发布了一项针对自主编码智能体（主要使用 Claude Code 与部分 Cursor）的实证实验。作者在完全不人工审查与编写微观代码的前提下，完全委托智能体构建了一个规模约 15 万行（其中 Rust 约 12 万行，辅以 TypeScript 前端与 Terraform 基础设施）、具备自动化部署的复杂生产级 Web 系统。由于长期放任智能体自主迭代且缺乏重构干预，数据访问层不可避免地陷入极度冗余的状态，最终膨胀为一个包含 17,155 行样板代码的单一 Rust 巨石文件，充斥着重复的 HTTP 请求配置与反序列化逻辑。

这项实验旨在检验一个核心经济学假设：“在当前消耗算力与 Token 进行严格重构，能否永久性降低未来工程变更的 Token 开销？”由于大语言模型在各独立会话之间具有完全无记忆、不产生人类学习效应的纯粹机器特性，为该实验提供了完美的控制变量条件：
实验设计定义了一个包含严格工程纪律的分步重构蓝图，并设计了一个高度标准化的代表性功能变更 Prompt。基线阶段首先启动一个完全干净的子智能体在 17,155 行的原始单文件上执行该变更，测量并丢弃修改；随后在主线每完成一个局部的重构步骤，均唤醒一个全新的子智能体在重构后的代码库上执行完全相同的代表性变更任务，记录输入输出 Token、耗时与文件代码行数。

实测数据展现出惊人的非线性断崖特征：
第一阶段（步骤 1 至步骤 6）：执行局部去重与模式抽象，包括提取 FirestoreClient、抽象通用文档 ID 提取函数、抽取测试断言谓词以及构建 FieldsBuilder 等。在此阶段，数据访问层的总代码行数从 17,155 行仅微幅下降至 16,469 行，代表性变更消耗的输入 Token 在 15.5 万至 17.1 万的高位区间内平缓震荡，未见实质改善。
第二阶段（步骤 7 至步骤 15）：以抽象出的核心模式为依托，展开跨文件的物理拆解，将巨石模块依次拆分出 queries.rs、traits.rs、codec.rs、fake_store.rs，并最终将 store 目录细化拆解为 19 个独立的高内聚 Rust 源文件。随着单文件最大行数从 17,155 行逐步降至 3,695 行，输入 Token 发生雪崩式骤降——从基线的 159,564 锐减至最终的 27,360，单次任务节省 132,204 个 Token，降幅高达 83%；而在全过程中，编写代码所生成的输出 Token 始终稳定在 1,700 至 2,400 之间，耗时稳定在 7 到 8 分钟。

该实验揭示了智能体工程环境下的深层系统机理：
其一，代码总行数的守恒与上下文定位。数据访问层的总代码量在重构前后几乎保持恒定（重构后为 16,608 行），Token 的巨额节省并不是因为“可读的代码总量减少了”，而是因为良好的架构边界使得智能体能够精准识别并仅读取发生变更所必需的最小上下文子集；单纯机械地将大文件盲目截断毫无价值，前期的局部去重与公共 Trait 抽象正是为后期的精准定位提供了语义锚点。
其二，Token 节省的非一次性复利价值。虽然单次变更节省的 Token 折合当前 API 价格仅约数十美分，但这一开销降幅是永久性的，后续所有涉及该层级的功能扩展、Bug 排查与测试回归均将持续享受这 83% 的成本红利。
其三，智能体自主重构能力的严重缺失。当前的顶尖前沿模型（如 Claude）在没有人类架构师制定严密重构计划的情况下，完全不具备自发识别系统坏味道并执行模块拆分的能力；其在自主执行重构时频繁在缩进、代码宏与依赖引用上陷入混乱，甚至遗漏最关键的物理拆分步骤。重构不仅没有随智能体普及而过时，反而演进为必须由人类经验主导编排、以驾驭智能体上下文经济学的关键工程支柱。
