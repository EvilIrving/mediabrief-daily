npm under siege (what to do about it) (Friends) ｜ The Changelog ｜ 95分钟 ｜ https://changelog.com/friends/111

这期 Changelog & Friends 里，Jerod Santo 和 Adam Stacoviak 请来 Socket Security 创始人 Feross Aboukhadijeh，梳理 2025 年 8–9 月间 npm 遭遇的一连串供应链攻击，并讨论开发者能做什么、平台该做什么。

Feross 认为这是 npm 史上最严重的一波攻击：钓鱼、维护者账号被接管，恶意代码被塞进每周下载量数十亿次的包里，受害者包括 Prettier 相关包、Nx 构建系统、Sindre Sorhus 一位共同维护者手里的一批包，以及 CrowdStrike 的十几个开源包。这种手法早有先例（2017 年 event-stream 被接管、定向偷取某钱包应用用户的加密货币），这次之所以集中爆发，是因为“发邮件骗维护者重置 2FA，否则冻结账号”的钓鱼招数奏效后，在攻击者圈子里成了一种“梗”，引来大批模仿者各显神通。攻击者都图财，但收益其实很寒酸：在 Sindre 系列包被投毒的那次，恶意代码拦截前端的 fetch/XHR，用 Levenshtein 距离挑一个最像收款地址的攻击者地址做替换，可链上数据显示只偷到约 500 美元。Feross 半开玩笑地说他们“本可以做得更好”：藏进深层依赖、混淆拆分、窃取 SSH 和浏览器 Cookie 以获得持久访问，而不是动静大到几小时就被发现。主持人还猜测，这些高调攻击也可能是掩护真正目标的障眼法。

最让 Feross 意外的是 8 月底的 Nx 事件，有两个“首次”。其一，恶意代码不自己写文件搜索逻辑，而是调用本机的 Claude、Gemini 等 AI 命令行工具，用一段自称“获得授权的渗透测试代理”的英文提示词让 AI 列出敏感文件清单，再由脚本把 GitHub/npm 令牌、SSH 密钥、.env 和钱包文件做三重 base64 编码后外传。这样做是想绕过基于代码模式的扫描，但让 LLM 去读这种提示词，一眼就能看出可疑。其二是入侵路径：Nx 的 GitHub 工作流把 PR 标题直接拼进 echo 命令，形成 shell 注入；而且用的是 pull_request_target 触发器，运行环境里带着有写权限的 GitHub 令牌。Nx 其实早已修复，攻击者却针对两年前的旧分支提 PR，触发了旧的漏洞 workflow，拿到令牌后再改 publish.yml，偷出只给发布流程用的 npm 令牌。整件事从发布恶意版本到 npm 下架、令牌吊销约六小时。Feross 说 Socket 和大家一样只能走 npm 页面上的“Report malware”通道，热门包处理得快，冷门包有的恶意版本挂了一年多都没下架。他还对比了漏洞的负责任披露和恶意软件的公开警示：后者大声说出来只会伤到攻击者。他也透露 Socket 将在 10 月下旬支持 GitHub Actions，把可复用 action 当成一种有依赖树的供应链来扫描。至于已经泄露的密钥，务必先吊销；就算强制推送删掉了提交，知道哈希的人仍能在 GitHub 上找到它，只能联系客服清除。

防护建议部分：锁文件一定要用，别动不动删掉重装；pnpm 新增的 minimumReleaseAge 可以拒绝安装发布未满若干天的版本，再用 exclude 列表给紧急修复开口子。Feross 认为七天甚至 24 小时就能借助安全厂商的“群体免疫”避开大多数大型攻击，但学术研究显示冷门恶意包平均存活 200 多天，所以这招并非万能。Jerod 指出按时间延迟比停留在旧版本好得多。Feross 现场查了后台：Socket 几年来人工确认的 typosquatting（仿冒包名）包约 1700 个。

谈到根本取舍，Feross 说社区当初选择了“任何人无需审查即可 npm publish”，用安全换协作与繁荣，这也是 npm 成为最大生态的原因，若重来他仍会这么选。但平台本可做得更多：早点对有一定下载量的账号强制 2FA，对加入热门包的新维护者做身份认证。他直言 GitHub 收购 npm 后从未真正上心（当年还力推 GitHub Packages），公司层面投入严重不足。对 GitHub 近期的“强化发布”路线图（本地发布强制 2FA、限时细粒度令牌、可信发布），他认为是进步但治标：可信发布只能证明代码在受信任的 CI 上构建，并不说明代码做了什么，攻击者拿到仓库权限照样能签名发布恶意代码，“运行陌生人的代码”这一根本风险仍在。三人设想由 registry 设一个暂存期：新版本先公开放 30 分钟（或按风险分级，从几分钟起步，可疑改动再延长），供安全厂商审查后再成为 latest。Feross 强调这类措施必须落在 registry 层面，否则攻击者直接拿 npm 令牌就能绕过。Adam 追问“npm 到底谁负责”，被 Jerod 调侃为“我要找你们经理”，节目顺势向 GitHub 发出邀请。

Jerod 抛出一个激进设想：既然 LLM 能生成代码，何不干脆不装依赖？Feross 说如果攻击成为常态，企业确实会认真考虑，而且已有大公司开始把多年不更新的小依赖（比如他自己的 run-parallel、run-series）直接内置进主仓库。但他认为全面退回“自己生成一切”会是糟糕的世界，等于倒退回专有软件。Jerod 则认为 JavaScript 的微型包文化恰好让边缘小工具成为可以先砍掉的部分，React 这类骨干库仍值得共建。私有镜像方面可以用 Verdaccio。

最后 Feross 发布了新工具 Socket Firewall（sfw）：npm install -g sfw 后，在 npm、yarn、pnpm、pip、cargo 等命令前加上 sfw，它会临时起一个本地代理充当 registry，拦截恶意包、后门和仿冒包。免费版不限量、无需 API 密钥，覆盖 JS/TS、Python 和 Rust；Java、Ruby、Go 以及自定义策略、安装遥测属于企业版。Adam 希望免费生态能自选（他想要 Go），并称赞 sfw 这个名字，大家顺带开玩笑说该注册一个只让你装恶意软件的 nsfw。
