也许我们不该审查所有这些代码 Maybe We Shouldn't Be Reviewing All This Code ｜ Martin Fowler ｜ 文章 ｜ https://martinfowler.com/rachels-ramblings/code-review.html

Thoughtworks CTO Rachel Laycock 回应 DX 的 Brian Houck。两人在 Code Remix 大会圆桌上意见相左：AI 产出的代码已多到人审不过来，Meta 每个人工合入 diff 的代码行数一年涨了 106%，Brian 担心自动化审查会丢掉知识分享、带新人、集体所有权和架构理解等功能。她认同这些价值，却反问为何要等到代码审查才做。她主张"把判断左移"：方案在实现前比较，知识靠结对传递，架构一起设计并写成适应度函数，格式和已知安全问题全部自动化，只对重大架构变更、敏感安全边界或团队没把握的改动做"例外审查"。逐行排队等资深者审只会制造积压和瓶颈，让 AI 假扮审查者也只是自动化仪式。她承认认知债是真问题，但强制 PR 不是有力防线；工程师需要理解系统，而不是 diff。
