1020: Do You Read The Code? ｜ Syntax ｜ 88分钟 ｜ https://syntax.fm/1020

《Syntax》第 1020 期（2026 年 7 月 13 日）是一期周一直播新闻杂谈。Wes Bos 休假，由 Scott Tolinski 和 CJ Reynolds 主持。开场闲聊世界杯，两人吐槽足球假摔，CJ 还主张取消越位。之后的主线是开发者圈正在吵的"你还读不读代码"，后面跟着一串 Web 和 AI 新闻。

讨论起于一条推文："模型还要进步多少，你才会停止读代码？"两人梳理了各方回应。David Khourshid 说读代码本来就没意义，关键是验证；Cheng Lou 说自己连目录结构都不看了；Turso 的 Glauber Costa 则说数据库和操作系统代码永远要读，"很多人至今还在读汇编"；ThePrimeagen 认为这不过是新一轮的无谓之争。两人更认同几种务实的声音。Theo 认为一次性脚本可以不读，生产代码不能不管成本和效率。Dax 反问那些宣称"代码不重要"的人：既然这么领先，你们靠它赚到钱了吗？两人也觉得 Twitter 上很多人只是在空烧 token、拿不出成果。Zack Korman 批评有人以为当了经理、或者有了一队 agent 就可以撒手，其实掌控局面的责任比以往更大。David Fowler 指出，大家只谈"软件工厂"，却没人讨论未来的工程团队怎么协作；CJ 补充说，JS Nation 上不少人在讨论"结对提示"，团队之间如何共享 skill 和工作流还是空白。Scott 还拿 Notch 那条"PR 要好到什么程度才不读"的推文打趣 CJ 不认识 Minecraft 的作者。

两人的结论都是"看情况"。CJ 提醒，审查缺位早于 AI：大 PR 本来就常常只换来一句 LGTM，10 倍速产出只会放大这个问题。他赞同 Pi 作者 Mario Zechner"慢下来"的主张，理由是手写代码的过程就是建立代码库心智模型的过程，全交给 AI，这个模型就建立不起来。所以在重要功能上应关掉自动接受、逐一审查。Scott 坦言，自己不懂的东西（比如让 agent 移植着色器）能跑就行，在乎的项目则一定要读，因为"能用"从来不是标准。开发者更该讨论的是用户需要什么。

后半段是新闻。首先是 HTTP QUERY 方法（RFC 10008），它是 HTTP 十多年来的第一个新方法，本质上是一个可以带请求体、同样幂等的 GET。它要解决的是复杂查询只能塞进 URL 或者改用 POST 的老问题（例如 GraphQL），目前已在 Node.js 的 HTTP 模块中实现。有人说 GET 也能带请求体，CJ 回应说这在服务器和客户端之间并不可靠，算是 hack，有个明确的方法更合理；Scott 觉得它只是新增、不会破坏任何东西。
接着 Scott 聊起 GitHub"把仓库刻成 CD"的活动。这是 GitHub 借 PlayStation 宣布取消光驱的热点搞的促销，因为 GitHub 最近可用性不佳而招来骂声。Scott 怒怼"挪用基础设施资源"的说法，认为几个市场部员工的小活动和宕机毫无关系；CJ 承认时机和观感不佳，但认为大公司的部门之间本来就不会这样协调。
CJ 介绍的 Gea 是一个"编译器优先"的 UI 框架：没有虚拟 DOM、hooks 和 signals，在构建时把普通的类和函数编译成精准的 DOM 更新。Hello World 只有两百来字节，体积与 Solid 接近，远小于 Svelte。有状态的组件用类来写，函数组件只负责纯展示；UI 组件库基于状态机驱动的 Zag.js。CJ 喜欢这种"组件只运行一次"的心智模型，但担心 AI 只会生成老式的 React 代码，新框架难以获得临界规模。Scott 认可它的组织方式，但不喜欢 JSX，自己也离不开 Svelte。
随后两人聊模型。美国商务部解除出口管制后，Anthropic 的 Fable 5 短暂恢复，Scott 把额度烧光了，认为它是"感觉上最好"的模型：手把手指导更少，一次就完成了着色器移植和整套关键帧系统，但他还没在真正在乎代码的项目上用过。CJ 用同一份音乐服务器规划提示词对比了 GPT-5.5、Opus 4.8、Kimi K2.7 和 Fable。Fable 会主动调研，甚至逆向分析了亚马逊音乐的 API，代理性最强，但消耗的用量也远超其他模型。他打算用 Fable 做规划、其他模型来实现，并觉得每月 100 美元的 Codex 比 GitHub Copilot 耐用得多。他期待 OpenAI 的 Sol 以 Ultra 形态进入 Codex。他偏爱 Claude 的审美，但嫌 GPT-5.5 死板、层层嵌套函数，只是因为价格以及能接进 OpenCode 才倾向用 GPT。Scott 则发现机器人编程方面 GPT-5.5 明显更好。
Scott 还展示了自己的机器人：他在 Reachy Mini（Pollen Robotics 与 Hugging Face 出品）上接入 Hermes，做了名叫 Marshmallow 的语音助手，最难的是唤醒时机和延迟。
另一个话题是 Sentry 的 David Cramer 做的 Slack agent Junior。Scott 从"永远不想在 Slack 里写代码"变成了真香：它能汇总 YouTube 数据、定时提醒节假日，还能一次提出带预览链接的 PR；以后制作人 Randy 遇到构建失败，可以直接让它看 Vercel 日志并修复，"这才是 AI 当初许诺的工作流"。CJ 从安全角度提醒，权限越多越容易遭到提示注入，好在它对 YouTube 只有读权限，最小权限原则很关键，这也是他迟迟不敢做个人 agent 的原因。
供应链安全方面，npm、pnpm、Bun 等包管理工具都支持了"最短发布时长"，但属性名各不相同，Scott 对此颇为不满。npm 规定高影响力账户使用恢复码或更改邮箱后，72 小时内不能发布新版本。
Chrome 新推出的 user media 元素让开发者用一个 HTML 元素就能申请摄像头和麦克风权限，比 getUserMedia 更集中、更不容易出错。
Claude Code 则有两起争议：一是有人报告的 bug：用户提问后 60 秒不回应，它就自动选推荐答案继续执行。两人认为这不该默认开启，并调侃这样还能多耗 token。二是有人发现它会在设置自定义 API 地址时，用日期分隔符和撇号字符，隐写标记处于 Asia/Shanghai 或 Asia/Urumqi 时区的用户，以及指向 DeepSeek、Moonshot 等域名的请求，以防转售和蒸馏。
收尾是几个推荐：一是观众 Mitchell Wilson 的终端问答脚本 ask。二是基于 OpenStreetMap、完全离线、注重隐私的 Organic Maps。三是收录电脑在影视作品中出镜画面的网站 Starring the Computer，Scott 由此想到可以拿它来做黑客电影的反应视频。
