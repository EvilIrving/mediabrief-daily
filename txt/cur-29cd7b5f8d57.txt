《硬地骇客》第 124 期以 Podwise 发布 CLI 与 Skills 为契机，深入探讨在 AI Agent 时代命令行接口（CLI）反超传统 REST API 和 SDK 成为软件对外能力交付最优解的技术逻辑与架构演进。

关于怎么做，一啸提醒不要把 Web 版功能一比一搬进 CLI，那只会得到臃肿难用的工具。Podwise 只保留发现、处理、获取结果、导出四类原子能力，并特别强调“发现”，因为人已不在回路里，agent 必须自己找到内容。他认为 CLI 胜过 MCP 的关键在于人也能直接用、本地好调试，因此保留了带颜色和动画的 pretty 模式，但只在有 TTY 的终端启用，被 agent 调用或管道重定向时自动退回纯文本，避免控制字符浪费 token。他总结的设计原则包括：优先支持管道而非 -o 写文件、保证幂等以承受 agent 的重复调用、绝不交互式、help 里给可直接复制的示例、错误信息要告诉 agent 下一步怎么做、输出结构化且字段语义清楚。谈到 agent 不能交互，他引用谢赛宁的观点，说今天的 AI 仍主要基于文本而非视觉工作。

在 Skills 层面，主持人演示了一句自然语言如何被 LLM 拆成 search、process、get、export 一串命令，相当于从过程式编程变成声明式编程，还内置了播客周报、学外语、苏格拉底式追问等流程。一啸把这种体验归结为排列组合：传统 SaaS 是固定编排的 workflow，上限低；LLM 加原子能力让系统按用户临时需求动态组合，这又回到 workflow 与 agent 之争。做过低代码的主持人进一步断言，CLI 提供确定性、大模型免去编排，低代码平台最麻烦的“先造工具”一步被干掉，这类产品该壮士断腕了，而且低代码本就不追求性能，正好被 LLM 替代。

随后话题转向内容消费。主持人以研究 Stripe 前 CTO David Singleton 为例，Podwise 自动找到并处理了九期相关播客再汇总，自己的播客消费量随 token 一起暴涨；另一位主持人认为 token 流转即内容流转，AI coding 正是以数百倍速度替人阅读代码和文档。一啸则提醒成本问题：工作场景性价比高，纯娱乐未必划算，并说黄仁勋鼓吹的 token 消耗标准要放在他卖卡的生意立场上看。节目也交代了商业安排：CLI 和 Skills 免费开源，高价值结果按 5 小时和一周滚动窗口限额，转录与 App 共享 credits，推广期给免费用户 CLI 专属配额。

最后一啸给新产品的架构建议是：坚持 API 优先、真正的前后端分离；把字幕、PDF、XMind 导出这类逻辑放到本地 CLI，服务端只保留认证、计费和核心业务；不要把 CLI 当作 API 的薄包装，而要像 iOS App 一样把它当作服务的配套客户端，把容易出错、耗 token 的操作沉淀成固定原子工具。是否开源则取决于核心逻辑在不在服务端。
