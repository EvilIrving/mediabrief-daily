接下来我也会谈谈这类工具在认知和心理层面的一些影响。好，我们来构建 ChatGPT。这个过程分为多个阶段，依次进行。第一阶段叫作预训练。预训练的第一步，是下载并处理互联网数据。想大致了解这项工作是什么样的，我推荐大家看看这里的网址。Hugging Face 这家公司收集、创建并整理了一个名为 FineWeb 的数据集。他们在这篇博客文章里详细介绍了 FineWeb 数据集的构建过程。OpenAI、Anthropic、Google 等主要大语言模型提供商，内部都会有类似 FineWeb 的数据集。粗略来说，我们要做什么？我们要从公开来源获取大量互联网文本。我们希望拥有数量庞大、质量很高的文档，同时文档种类也要足够多样，因为我们希望模型内部包含大量知识。

因此，我们需要大量高质量且多样的文档。要做到这一点相当复杂。你可以看到，要把这件事做好，需要经过多个阶段。稍后我们会看看这些阶段具体是什么样子。现在我想先指出，FineWeb 数据集相当有代表性，跟你在生产级应用中看到的数据集差不多，但最后实际占用的磁盘空间只有约 44 TB。很容易就能买到 1 TB 的 U 盘，我想现在这批数据几乎可以放进一块硬盘里。所以，归根结底，这并不是特别庞大的数据量。互联网虽然很大，但我们处理的是文本，而且会进行严格过滤。在这个例子中，最后得到的数据约为 44 TB。接下来看看这些数据是什么样的，也看看其中一些处理阶段。许多这类工作的起点，也是最终数据的主要来源，是 Common Crawl 的数据。

Common Crawl 是一个从 2007 年起就一直在抓取互联网内容的组织。比如，截至 2024 年，Common Crawl 已经索引了 27 亿个网页，并部署了许多爬虫在互联网上运行。基本做法是先从几个种子网页开始，再沿着链接不断抓取和索引信息。随着时间推移，就会积累大量互联网数据。这通常是许多此类工作的起点。Common Crawl 的数据很原始，会经过多种方式过滤。这里有一张图，说明了各个阶段大致会进行哪些处理。首先是 URL 过滤。意思是，我们有一些黑名单，列出不想从中获取数据的网址或域名。通常包括恶意软件网站、垃圾信息网站、营销网站、种族主义网站、成人网站等。到了这个阶段，各类网站会被大量剔除，因为我们不希望它们出现在数据集中。第二步是文本提取。要记住，爬虫保存的是网页的原始 HTML。我在这里查看时，看到的就是原始 HTML。你会发现里面有列表之类的标记，还有 CSS 以及各种内容。这些基本上是网页的计算机代码。但我们真正想要的是网页上的文字，对吧？我们只要网页文本，不需要导航栏之类的内容。因此，要通过大量过滤和处理技巧，才能把网页里的优质内容提取出来。

接下来是语言过滤。例如，FineWeb 使用语言分类器来过滤数据。它会尝试判断每个网页使用的语言，然后只保留英语占比超过 65% 的网页。由此可见，不同公司可以自行决定这类设计选择：数据集中要纳入多大比例的各种语言？例如，如果我们把西班牙语内容全部过滤掉，那么可以想见，模型之后的西班牙语能力会很差，因为它几乎没见过这种语言的数据。因此，不同公司可以有不同侧重，比如对多语言能力的重视程度不同。FineWeb 很侧重英语。所以，如果他们之后用它训练语言模型，模型的英语能力会很强，但其他语言可能不那么好。语言过滤后，还会进行其他一些过滤步骤和去重等处理，最后例如进行个人身份信息（PII）清除。比如地址、社会安全号码等，要尝试检测出来，并将这类网页从数据集中滤除。这里涉及很多步骤，我不会逐一详细介绍，但数据预处理确实相当繁杂。最终我们就会得到 FineWeb 这样的数据集。点进去之后，可以看到一些数据样例。任何人都可以在 Hugging Face 网页上下载它。这里展示的是最终进入训练集的一些文本样例。这是一篇关于 2012 年龙卷风的文章。这里说的是 2012 年发生了一些龙卷风，以及当时的情况。下一个例子大概是在说：你知道吗，你体内有两个像黄色小型 9V 电池一样大小的肾上腺。好，这是一篇有点奇怪的医学文章。大家可以把这些内容理解为经过各种文本过滤后保留下来的互联网网页。

现在，我们有了大量文本，大约 40 TB。接下来就是这一阶段的下一步。我想先让你们直观了解一下我们目前的位置。我取了这里最前面的 200 个网页。要记住，我们有非常多网页；我把这些网页的文字全部取出来，直接拼接在一起。这就是最后得到的东西：一大堆原始文本，也就是原始互联网文本。光是这 200 个网页，文本就已经很多了。我还可以继续缩小视图，你会看到一大片文字数据。这些文字数据里有各种模式。现在我们要做的是用这些数据训练神经网络，让神经网络能够内化并建模这些文本的流动规律。我们有这片巨大的文本海洋，现在要训练神经网络来模仿它。

好，在把文本输入神经网络之前，我们得决定如何表示这些文本，以及如何把它们输入网络。这些神经网络的技术要求是输入一个由符号构成的一维序列，并且可用符号的集合必须有限。所以我们要决定符号是什么，再把数据表示为由这些符号构成的一维序列。目前我们有的是一维文本序列，从这里开始，接着到这里，再到这里，依此类推。虽然在我的显示器上，它当然以二维方式排版，但它从左到右、从上到下排列，对吧？所以这是一维文本序列。当然，既然是在计算机上，底层就有相应的表示。如果我对这段文本进行所谓的 UTF-8 编码，就能得到计算机中对应的原始比特。

编码后的样子就是这样。比如这里的第一条竖线代表最初的八个比特。那么这是什么呢？这就是我们要寻找的表示形式。从某种意义上说，我们只有两个可能的符号：0 和 1。目前得到的是一个非常长的序列。事实证明，在神经网络中，序列长度会是非常有限且宝贵的资源。我们不想要由两种符号构成的超长序列。相反，我们希望在符号集合（也就是我们所说的词汇表）大小和最终序列长度之间做权衡。我们不想只有两个符号和极长的序列，而是希望符号更多、序列更短。好，有一种简单的压缩方式，可以缩短序列：把连续的比特分组，比如每八个比特合为一个所谓的字节。

这些比特只有开或关两种状态，所以八个比特组合起来只有 256 种可能。这样一来，我们就能把这个序列改写成字节序列。字节序列会缩短为原来的八分之一，但现在我们有 256 种可能的符号。这里的每个数字都是 0 到 255。我要特别建议你不要把它们看成数字，而是看成独一无二的 ID，或者独一无二的符号。也许更好的想象方式是，把每一个数字都替换成一个独特的 emoji。这样就会得到类似这样的东西：一串 emoji，一共有 256 种可能的 emoji。可以这么理解。事实证明，在生产环境中，最先进的语言模型还会进一步压缩序列长度，因为序列长度依然是宝贵资源。我们愿意用更大的词汇表来换取更短的序列。

具体做法是运行一种叫作字节对编码（Byte Pair Encoding，BPE）的算法。其原理是寻找经常连续出现的字节或符号。例如，116 后面跟着 32 这个序列很常见，出现频率很高。于是我们把这一对合并为一个新符号，赋予它 ID 256，并把每一处连续的 116、32 都改写成这个新符号。随后可以根据需要反复迭代这个算法。每产生一个新符号，序列就变短，符号集合就变大。实践中，词汇表大小设为约 10 万个符号，效果相当不错。具体来说，GPT-4 使用了 100,277 个符号。把原始文本转换为这些符号，也就是我们所说的 token，这个过程叫作分词（tokenization）。

接下来看看 GPT-4 如何进行分词，也就是如何把文本转换成 token，再把 token 转回文本，实际效果是什么样的。我喜欢用一个叫作 Tiktokenizer 的网站来查看 token 表示。来到这里，从下拉菜单里选择 cl100k_base，也就是 GPT-4 的基础模型分词器。左侧可以输入文本，网站会显示分词结果。例如输入“Hello world”。结果正好是两个 token：一个是 token“Hello”，ID 为 15339；另一个是 token“ world”，ID 为 11917。所以“Hello world”就是两个 token。如果我把这两个词连在一起，比如输入“Helloworld”，结果仍然是两个 token，但变成了 token“H”，后面跟着 token“elloworld”。如果我在 Hello 和 world 之间输入两个空格，分词结果又会不同，这里出现了一个新的 token 220。

你可以试着玩一玩，看看会发生什么。还要记住，大小写会影响结果。如果把 H 改成大写或小写的另一种形式，结果会不同。如果输入“Hello World”，实际上会变成三个 token，而不是两个。你可以自己试试，直观感受 token 的运作方式。稍后我们还会再谈分词；现在我只是想给你看看这个网站，并说明这段文本最终会是什么样子。例如，这里取一行文本，GPT-4 看到的就是这个样子。这段文本的序列长度是 62，序列就在这里。每一段文本都对应这些符号。再提醒一次，一共有 100,277 种可能的符号。现在我们拥有了由这些符号构成的一维序列。之后还会回到分词的话题，但目前我们先到这里。

现在，我把数据集中的这段文本序列用分词器重新表示成了 token 序列，现在看起来就是这样。例如，回到 FineWeb 数据集，他们提到数据不仅占用 44 TB 磁盘空间，而且总共大约包含 15 万亿个 token。这里展示的只是这个数据集最前面的一两个、三个或几千个 token，但总共有 15 万亿个。再强调一次，这些 token 都代表一小段文本，是序列里的基本单位。这里的数字没有特殊含义，只是唯一 ID。好，现在到了有意思的部分：神经网络训练。训练神经网络时，大量计算工作都发生在这里。

这一步要做的是建模 token 在序列中如何彼此衔接的统计关系。我们会在数据中取一段 token 窗口。窗口从数据中相对随机地抽取，长度可以从 0 个 token 一直到我们设定的最大值。比如实际中可以使用长度为 8,000 个 token 的窗口。原则上，窗口长度可以任意设定，但处理很长的序列会非常耗费计算资源。因此我们会决定，比如 8,000、4,000 或 16,000 是个合适的长度，然后在这个位置截断。在这个例子里，我会取前四个 token，这样所有内容都能放得下。这四个 token 是 bar、view、in 和空格 single，它们对应这些 token ID。

现在我们要做的是预测序列中的下一个 token。下一个 token 是 3962，对吧？我们把这四个 token 称为上下文。它们作为输入送进神经网络。稍后我会详细介绍神经网络内部结构，现在先理解输入和输出就够了。输入是长度可变的 token 序列，长度可以从 0 到某个上限，比如 8,000。输出是对下一个 token 的预测。我们的词汇表有 100,277 个可能的 token，所以神经网络会输出同样数量的数字。每个数字对应某个 token 成为序列中下一个 token 的概率，也就是说，它在猜接下来会出现什么。训练刚开始时，神经网络的参数是随机初始化的。稍后我们会讲这是什么意思，但它本质上就是一个随机变换。

所以训练一开始，这些概率也是随机的。这里我只举了三个例子，但要记住，实际有 10 万个数字。神经网络认为，空格 direction 这个 token 的概率目前是 4%，11799 的概率是 2%，3962（也就是 post）的概率是 3%。当然，我们是从数据集中抽取的这个窗口，所以知道后面实际是什么。我们知道正确答案是 3962。这个就是标签。现在我们有一个数学过程，可以用来更新神经网络。我们有调整它的方法，稍后会再多讲一点。基本上，我们知道这里的概率只有 3%，而我们希望这个概率提高，同时让其他 token 的概率降低。因此，我们可以通过数学方法计算如何调整和更新神经网络，让正确答案的概率稍微提高。

更新神经网络后，下次再把这四个特定 token 输入网络时，网络就会稍有调整。它可能会说，post 的概率现在是 4%，case 是 1%，direction 是 2% 之类的。我们有一种方法，可以轻轻推动、稍微更新神经网络，让序列中正确的下一个 token 获得更高概率。要记住，这个过程并不只针对这里这个 token，也就是输入这四个 token 并预测下一个 token 的例子。它会同时应用于整个数据集中的所有 token。实践中，我们会抽取一批小窗口。然后对每个 token 都调整神经网络，让该 token 的概率稍微提高。这个过程会在大量 token 的批次上并行进行，这就是神经网络训练。

训练就是不断更新网络，使它的预测与训练集中的实际统计规律相符。它的概率会逐渐符合 token 在数据里彼此衔接的统计模式。现在简单看看神经网络内部是什么样的，给你一些直观认识。神经网络的内部结构。如前所述，输入是 token 序列。这里有四个输入 token，但长度可以从 0 到 8,000。原则上，token 数量可以是无限的，只是处理无限长序列的计算代价太高，所以我们会在某个长度截断，这就成为模型的最大上下文长度。这些输入 X 会与神经网络的参数，也就是权重，一起参与一个巨大的数学表达式。这里我展示了六个参数及其取值，但现代神经网络实际上会有数十亿个参数。

一开始，这些参数完全是随机设定的。你可能会想，参数随机时，神经网络也会随机预测。确实如此，开始时它完全是在随机预测。但通过反复更新网络，也就是我们所说的神经网络训练，参数会逐步调整，使神经网络的输出与训练集中的模式相符。你可以把这些参数想成 DJ 混音台上的旋钮。旋钮转到不同位置，网络对每种可能的 token 序列输入都会给出不同预测。训练神经网络，就是找到一组参数，使预测符合训练集的统计规律。给你看一个巨大的数学表达式的例子，让你了解它是什么样的。现代网络可能是包含万亿项的巨大表达式，但我这里只展示一个简单例子。

它大致会像这样。这些就是这类表达式的样子，我只是想说明它并不可怕。我们有 X 这样的输入，比如这里的两个输入 X1、X2。它们会与网络权重 W0、W1、W2、W3 等混合起来。混合操作是乘法、加法、指数、除法等简单运算。神经网络架构研究的内容，就是设计有效的数学表达式，让它具备许多有用特性：表达能力强、易于优化、可并行化等。但归根结底，这些表达式并不复杂。它们把输入和参数结合起来进行预测，我们优化神经网络参数，让预测符合训练集。现在我想展示一个实际生产级的神经网络例子。为此，我建议你去看看这个网站，它把其中一个网络可视化得很好。

这就是你在网站上会看到的东西。生产环境使用的这个神经网络有一种特殊结构，叫作 Transformer。这个特定例子大约有 85,000 个参数。顶部是输入，也就是 token 序列。信息沿着神经网络流动，最后到达输出，也就是这里的 logits 和 softmax，它们代表对下一个 token 的预测。整个表达式中间有一连串变换，会生成各种中间值，进而预测接下来会出现什么。举个例子，token 会被嵌入成一种分布式表示。每个可能的 token 在神经网络内部都有一个向量来代表它。我们先把 token 嵌入，然后这些值沿着图中的路径流动。每个数学运算单独看都很简单，比如层归一化、矩阵乘法、softmax 等。

真正重要的是要理解，这就是一个数学函数，由一组固定参数来决定，比如 85,000 个参数。它把输入转换为输出。调整参数，就会得到不同类型的预测。接下来我们要找到一组好的参数，让预测与训练集中的模式相符。这就是 Transformer。好，我已经展示了神经网络内部结构，也谈了一些训练过程。我还想介绍与这些网络有关的另一个主要阶段：推理。推理时，我们从模型生成新数据。我们想看看网络参数内化了什么样的模式。从模型生成内容相对直接：先给它一些 token 作为开头，也就是你想让它从哪里开始。

比如，我们从 token 91 开始。把它输入网络。记住，网络会给出概率，也就是这里的概率向量。接下来我们可以抛一枚有偏硬币，根据这个概率分布抽样。模型赋予高概率的 token，被抽中的可能性更大。你可以把它想成抛一枚有偏硬币。我们从这个分布中抽样，得到一个唯一的 token。比如，下一个 token 是 860。因此，在这个例子中，从模型生成内容时，860 可以成为下一个 token。860 是一个相对可能的 token，但未必是唯一可能的 token。还有许多其他 token 也可能被抽中。不过我们可以看到，860 的概率相对较高，而且在我们的训练示例中，91 后面确实接着 860。接着假设我们继续这个过程。

91 后面是 860，我们把它接上，再问第三个 token 是什么。我们抽样，假设得到 287，正如这里所示。再来一次。现在我们有了三个 token，问第四个 token 最可能是什么，然后抽出这个 token。再来一次。把四个 token 输入，抽样后得到这个 token。这里的 13659 并不是之前的 3962。这个 token 代表 article（文章）。所以，我们看到的序列是 article，而不是先前那个序列。也就是说，这次我们没有完全复现训练数据中的序列。要记住，这些系统具有随机性。我们在抽样、抛硬币。有时运气好，会复现训练集里的某一小段文本；有时抽到的 token，并不是训练数据任何文档里的原文。

所以，我们会得到训练数据的某种混合重组。每一步都可能抽到略有不同的 token，而这个 token 一旦加入序列，再抽下一个 token，等等，很快就会生成与训练文档中不同的 token 流。它们在统计特征上会相似，但并不等同于训练数据。可以说，它们受到训练数据的启发。这个例子里，我们得到的是略有不同的序列。为什么会得到 article？你可以想象，在 bar、viewing、single 这样的上下文中，article 是一个相对可能的 token。训练文档里某处可能出现过 article 跟在这个上下文后面的情况，而我们正好在这里抽到了它。推理基本上就是根据概率分布逐个预测，不断把生成的 token 输入回去，再得到下一个 token。

我们每一步都在抛硬币。根据从概率分布中抽样的运气好坏，生成的模式可能大不相同。这就是推理。在大多数常见情形下，下载互联网数据并进行分词属于预处理，一次完成。得到 token 序列之后，就可以开始训练网络。实际中，你会尝试训练许多不同网络，使用不同设置、不同排列和不同规模，因此会进行大量神经网络训练。等训练好一个神经网络，并得到一组你满意的参数后，就可以用模型进行推理，从中生成数据。你在 ChatGPT 上与模型对话时，模型可能是 OpenAI 几个月前训练好的。他们有一组效果不错的权重。

你与模型对话时，进行的全部都是推理，不再训练这些参数。参数保持固定，你只是把一些 token 提供给模型，让它补全 token 序列。这就是你使用 ChatGPT 时看到的生成内容。因此，模型此时只是在进行推理。接下来我们看一个具体的训练与推理例子，让你更清楚这些模型训练起来是什么样子。我特别喜欢用 OpenAI 的 GPT-2 作例子。GPT 的意思是“生成式预训练 Transformer”（Generative Pre-trained Transformer）。这是 OpenAI GPT 系列的第二代。当你今天和 ChatGPT 对话时，支撑这次交互所有神奇表现的底层模型是 GPT-4，也就是这个系列的第四代。GPT-2 是 OpenAI 在 2019 年发表的，相关论文就在这里。

我喜欢 GPT-2 的原因是，它是第一次把一套我们今天仍然熟悉的现代技术体系组合起来。按现代标准来看，GPT-2 的各个组成部分今天仍然认得出来，只是现在所有东西都变大了。当然，我无法详细讲解这篇论文的全部内容，因为它是一篇技术论文。但我想强调其中几点。GPT-2 是一个 Transformer 神经网络，就像你今天会接触到的神经网络一样。它有 16 亿个参数，也就是我们刚才看过的那些参数。今天它会有 16 亿个参数。现代 Transformer 的参数规模更接近一万亿，或者几千亿。GPT-2 的最大上下文长度大约是 1,024 个 token。也就是说，我们从数据集中抽取 token 窗口时，最多只取 1,024 个 token。因此，当你尝试预测序列中的下一个 token 时，上下文最多只有 1,024 个 token。

按今天的标准，这也很小。现在的上下文长度更接近几十万个，有时甚至一百万个 token。这样就能利用更多上下文，也就是更多历史 token，从而更好地预测序列中的下一个 token。最后，GPT-2 大约用 1,000 亿个 token 进行训练。按现代标准，这也相当少。如前所述，我们看到的 FineWeb 数据集有 15 万亿个 token，所以 1,000 亿确实很少。我曾经为了好玩，参与 LM.C 项目，尝试复现 GPT-2。你可以在 GitHub 的 LM.C 仓库里看我写的复现记录。特别是，2019 年训练 GPT-2 的成本估计约为 4 万美元，但现在可以做得便宜得多。这个例子耗时约一天，花费约 600 美元。

而且这还没有特别优化。我觉得现在大概能把成本降到 100 美元。为什么成本下降这么多？第一，数据集质量高得多，过滤、提取和准备数据的方法也精细得多。因此数据集本身质量更高。这是一方面。但最大的差别在于计算机硬件快了很多，我们马上会看到。用于运行这些模型、尽可能榨取硬件速度的软件也进步了很多。大家都在关注这些模型，努力让它们跑得更快。我无法详细介绍 GPT-2 的复现过程，这是一篇很长的技术文章，但我仍想让你对研究人员实际训练模型时的情况有直观认识。

他们会看什么？过程是什么样的？体验又如何？我来给你简单展示一下。好，实际过程就是这样。让我把窗口挪一下。我现在正在训练一个 GPT-2 模型。这里每一行，比如这一行，代表对模型进行一次更新。还记得我们要改善每个 token 的预测，并更新神经网络的权重或参数吗？这里的每一行都是对神经网络的一次更新，稍微改变参数，让它更擅长预测序列中的下一个 token。具体来说，这里的每一步都会改进训练集中 100 万个 token 的预测。我们从数据集中抽取 100 万个 token，同时尝试改善它们各自作为序列下一个 token 的预测。

每一步都会据此更新网络。要密切关注的数字叫作 loss（损失）。损失是一个单一数字，告诉你神经网络目前表现如何。这个数值的设计方式是越低越好。你会看到，随着我们不断更新神经网络，损失在下降，这代表它对序列中下一个 token 的预测越来越准确。所以，作为神经网络研究人员，你要关注的就是损失。你会一边等，一边转转拇指、喝咖啡，确认结果看起来正常。每次更新后，损失都在改善，网络也更擅长预测。你看到，每一步处理 100 万个 token，每一步大约花 7 秒。我们总共要进行 32,000 步优化。每步 100 万个 token，32,000 步，大约会处理 330 亿个 token。目前我们大约只完成了 420 步，也就是 32,000 步中的第 420 步。因为我只运行了十几分钟，所以还不到 2%。

我把每 20 步进行一次推理设定好了。你现在看到的是模型在预测序列中的下一个 token。我们先随机给它一些开头，再不断输入 token。这就是推理步骤，模型在预测序列中的下一个 token。每当有内容出现，就代表一个新 token。我们看一下。你会发现内容还不连贯。记住，这时训练进度只有 1% 左右。模型还不擅长预测序列中的下一个 token，所以输出看起来有些胡言乱语。

不过它仍然有一点局部连贯性。比如，“既然她是我的，这是信息的一部分，应该讨论我的父亲，伟大的伙伴。戈登让我坐在……旁边”等等。我知道这看起来不怎么样，但我们往上翻，看看开始优化时的样子。最开始是第 1 步。优化 20 步后，输出看起来完全随机。当然，因为模型只更新了 20 次参数，它还只是一个随机网络，所以输出随机文本。你可以看到，与刚才相比，模型已经开始好很多了。如果我们等到 32,000 步全部结束，模型会进步到能够生成相当连贯的英语，token 流也会更通顺，整体更像英语。训练还得再跑一两天。

此时我们只要确认损失在下降，其他指标都正常，然后等待即可。现在我来讲训练所需计算资源的情况。当然，我不是在笔记本电脑上运行这项优化，那样成本太高。我们需要运行神经网络、不断改进它，还需要大量数据等等。你的电脑可能无法很好地运行这个，因为网络太大了。所有这些任务都在云端的计算机上运行。我想谈谈训练这些模型所需的计算资源，以及这方面的情况。来看一下。好，我用来运行优化的计算机是一台配有 8 张 H100 的节点。也就是说，一台计算机里有 8 张 H100。我租用这台计算机，它在云端的某个地方。

我其实不知道它的物理位置。我常用的租赁平台叫 Lambda，但还有很多其他公司提供这类服务。往下看，可以看到他们针对配有 H100 GPU 的计算机提供按需计价。稍后我会给你看 GPU 长什么样。比如一台配备 8 张 NVIDIA H100 GPU 的机器，每张 GPU 每小时 3 美元。你可以租用这种机器，在云端获得一台计算机，然后用这些 GPU 训练模型。这就是一张 H100 GPU 的样子。它大概长这样，装进计算机里即可。GPU 非常适合训练网络，因为这项任务计算量很大，但计算过程有很多并行性。许多彼此独立的工作单元可以同时运行，一起完成神经网络训练背后的矩阵乘法。

这只是一张 H100，但实际上你会把多张 GPU 装在一起，比如把 8 张放进一台机器，再把多台机器组成一个数据中心或更大的系统。看数据中心时，就会看到类似这样的东西。这里我写不出来。看数据中心时会看到：一张 GPU，接着八张 GPU，组成一台系统，再由很多系统组成更大的集群。这就是规模更大的数据中心。当然，成本也会高得多。大型科技公司都想要这些 GPU，以便训练语言模型，因为它们的能力很强。这从根本上推动了英伟达股价达到 3.4 万亿美元，也解释了英伟达为何快速崛起。这是一场淘金热，大家争着获取 GPU、尽可能多地获取 GPU，好让它们协同完成优化。

那它们到底在做什么？它们都在协同预测 FineWeb 这样的数据集中的下一个 token。这就是计算工作流。这项工作极其昂贵。GPU 越多，就能尝试预测和改进越多 token，处理数据集也越快，迭代速度也越快，就能构建更大的网络、训练更大的网络，等等。所有这些机器做的就是这些事情。这就是为什么整个领域如此受关注。比如，这是大约一个月前的新闻。埃隆·马斯克要在一个数据中心里部署 10 万张 GPU，这件事为什么重大？这些 GPU 非常昂贵，要消耗大量电力，但它们做的事情就是尝试预测序列中的下一个 token，并借此改善网络，或许能比我们刚才看到的更快生成连贯得多的文本。

遗憾的是，我没有几千万或上亿美元来训练这样的大模型。但幸运的是，我们可以找一些大型科技公司。它们经常训练这些模型，并在训练完成后发布其中一些。它们已经投入大量算力训练网络，最后会发布训练好的网络，这很有用，因为计算工作已经由它们完成了。很多公司会常规训练这类模型，但真正发布所谓“基础模型”（base model）的公司并不多。训练结束后得到的模型叫基础模型。基础模型是什么？它是一个 token 模拟器，是互联网文本的 token 模拟器。因此它本身还没有什么实际用途，因为我们需要的是助手，可以向它提问并得到回答。这些模型做不到。它们只是生成互联网内容的混合重组。

它们会梦见互联网网页。基础模型通常不太会被发布，因为它们只是构建助手之前的第一步，还需要做其他几步。不过也有一些模型发布了。例如，GPT-2 于 2019 年发布了 15 亿参数的版本。GPT-2 是一个基础模型。那么模型发布出来是什么样的？要发布模型，基本上需要两样东西。第一，通常需要 Python 代码，详细描述模型里的一系列运算。如果你还记得 Transformer，神经网络里执行的一系列步骤，就是由这些代码来描述的。这段代码实现的是神经网络所谓的前向传播。我们需要模型如何连接神经网络的具体细节。

这就是计算机代码，通常只有几百行，不算复杂。这些内容基本都能理解，而且通常也比较标准。真正不标准的是参数，因为参数才是模型的实际取值。神经网络的参数是什么？这里有 16 亿个，我们需要正确的取值，或者一组效果很好的取值。因此，除了源代码，他们还会发布参数，在这个例子里大约是 15 亿个参数。它们只是数字：一长串 15 亿个数字，每个旋钮都被设定在精确而有效的位置，才能让 token 生成得好。要发布一个基础模型，需要这两样东西。GPT-2 已经发布，但它其实相当老了。如前所述，我们接下来要看的是 Llama 3。再说一次，GPT-2 有 16 亿个参数，用 1,000 亿个 token 训练。

Llama 3 是大得多、也现代得多的模型，由 Meta 发布和训练。它有 450 亿个参数，用 15 万亿个 token 训练，方法大体相同，只是规模大得多。Meta 也发布了 Llama 3。这是他们论文的一部分。论文里有很多细节，发布的最大基础模型是 Llama 3.1，拥有 4050 亿个参数。这就是基础模型。除了基础模型，你还会看到论文在这里提前提到了视频后面的内容：他们还发布了 Instruct 模型。Instruct 的意思是这是一个助手，你可以向它提问，它会回答。后面我们还会介绍这一部分，现在先看看这个基础模型，也就是 token 模拟器。我们来玩一玩，想想它是什么、如何运作，以及让一个很大的神经网络在大量数据上训练完成后，最终会得到什么。

我最喜欢用来体验基础模型的地方是 Hyperbolic。这家公司提供 Llama 3.1 405B 基础模型。进入网站后，你可能需要注册。请确认模型选的是 Llama 3.1 405 billion base，必须是基础模型。这里的 max tokens 表示我们要生成多少 token。把它调低一点，免得浪费算力；我们只需要后续 128 个 token，其他设置先不动。我不打算详细介绍所有设置。从根本上说，这里发生的事情与我们刚才讲的推理完全相同。它会继续你输入的前缀，接着生成 token 序列。我想先让你看看这个模型还不是助手。比如你问它“2 加 2 等于多少？”它不会回答“等于 4。还有什么我能帮你的吗？”它不会这样做，因为“2 加 2 等于多少”会被分词，然后这些 token 只会作为前缀。接下来模型只会给出下一个 token 的概率。它只是一个功能强大的自动补全器，是一种非常昂贵的自动补全器，根据它在训练文档（基本就是网页）中看到的统计规律，猜测后面会出现什么。我们按回车，看看它会接着生成什么 token。

好，它这里其实回答了问题，然后开始谈一些哲学问题。再试一次。我复制粘贴，从头再来：“2 加 2 等于多少？”好，它又开始跑题了。我还想强调一点：我觉得每次输入，它都是从头开始。它不会记住前一次。这个系统具有随机性。同样的 token 前缀，每次都会得到不同答案。原因是我们会得到一个概率分布，再从中抽样。每次抽到的样本都不同，之后的内容也会走向不同方向。这次我不知道它在说什么。再试一次。它还是继续往下写。它只是在续写自己在互联网上见过的东西，对吧？只是在复现那些统计模式。第一，它还不是助手，而是一个 token 自动补全器。第二，它是一个随机系统。关键在于，虽然这个模型本身还不能直接用于许多实际应用，但它仍然很有用，因为为了预测序列中的下一个 token，模型已经学到了很多关于世界的知识，并将这些知识储存在网络参数中。

记住，我们的文本原来是这样的，也就是互联网网页。现在所有这些信息都压缩进了网络权重里。所以你可以把这 4050 亿个参数想成互联网的一种压缩。你可以把 450 亿个参数想成一个 ZIP 文件，但它不是无损压缩，而是有损压缩。我们得到的只是一个模糊的互联网版本，现在可以从中生成内容。我们可以通过合适的提示，唤出藏在基础模型参数里的知识。例如，下面这个提示可能可以让它展示出一些知识：“这是我心目中巴黎最值得参观的十大地标。”我这样写，是为了引导模型接着列出地标。我们按回车，看看有没有效果。好，它开始列清单了，给出了一些地标。

注意，它试图提供很多信息。你可能无法完全相信其中的一些内容。记住，这只是对互联网文档的回忆。互联网数据中出现频率很高的东西，更可能被正确记住；出现频率很低的内容，则不一定如此。因此，不能完全相信这里的信息，因为这些信息并没有明确储存在任何一个参数里，只是模糊的回忆。尽管如此，它给出的内容大概是正确的。我没有足够专业知识来核实这些内容是否大致准确，但你可以看到，我们已经唤出了模型中的很多知识。这些知识并不精确，而是模糊、概率化和统计性的。经常出现的内容，更可能被模型记住。

我还想展示这个模型行为的几个例子。首先，我去了维基百科的斑马页面，复制了开头第一句话。现在我把它贴在这里。按回车后会得到什么续写？我来按回车。“现存的三种斑马……”等等。模型生成的内容，是对这篇维基百科条目的逐字复现。它纯粹靠记忆在背诵，而这些记忆储存在模型参数中。在这 512 个 token 里，模型有可能偏离维基百科条目，不过你能看到它记住了很大一段内容。让我看看，比如这句话到这里是否还出现。好，还没有偏离。再看一下。仍然一致。最后它会偏离。总之，它在很大程度上是在复述原文。

它最终会偏离，因为它不能准确记住所有内容。之所以会这样，是因为这些模型极其擅长记忆，而最终模型通常不希望它这样。这种现象叫作 regurgitation（复述、原样吐出训练内容），通常不希望模型直接复述训练过的内容。实际发生这种情况的原因是，对于很多文档，比如维基百科，如果它们被认定为非常优质的信息来源，训练时往往会优先从这些来源抽样。模型可能对这批数据训练了好几个 epoch，也就是说，它可能已经看过这个网页十次左右。这就像你反复读同一段文字，比如读 100 遍，之后就能背诵出来。模型的情况也类似。

如果它看某些内容看得太多，就能在之后凭记忆复述。只不过这些模型每次读过之后，记忆效率可能比人类高得多。它可能只看过这篇维基百科条目十次左右，但已经把文章内容准确地记在参数里了。好，接下来我想展示模型训练时绝对没见过的内容。例如，我们去论文里查看预训练数据，会看到数据集的知识截止时间是 2023 年底，因此它不可能看过那之后的文档，肯定也没有见过 2024 年大选结果。现在，如果我们用来自未来的 token 提示模型，它会继续这个 token 序列，并根据参数中现有知识尽力猜测。我们看看会是什么样。

“共和党提名特朗普……”“他于 2017 年至……担任美国总统。”看看接下来它会说什么。模型得猜副总统候选人是谁、对手是谁等等。我们按回车。这里它猜迈克·彭斯是副手，而不是 J.D. 万斯；对手是希拉里·克林顿和蒂姆·凯恩。这算是一个有意思的平行宇宙，可能是模型认为会发生的事情。我们再抽样一次。同样的提示，再来一次。这次副手是罗恩·德桑蒂斯，对手是乔·拜登和卡玛拉·哈里斯。这又是另一个平行宇宙。模型会根据它的知识，做出有根据的猜测并续写序列。我们看到的这些内容都叫作幻觉。模型只是以概率方式尽力猜测下一个 token。接下来我想展示，虽然这还是基础模型，不是助手模型，但如果提示设计得巧妙，仍然能用来做实际应用。

这就是所谓的 few-shot prompt（少样本提示）。这里有 10 个单词或 10 组对应词。每一组都是一个英文单词、冒号和它的韩语翻译。总共有 10 组。最后一栏是 teacher（老师），我们只让模型补全五个 token。这些模型具备所谓的上下文学习（in-context learning）能力。意思是，它阅读上下文时，会就地学到数据里存在某种算法模式，然后知道如何延续这个模式。这就叫上下文学习。因此它会扮演翻译者。按下补全后，我们看到 teacher 的韩语翻译是“쌤”，这是正确的。这就是你可以通过巧妙设计提示来构建应用的方式，尽管目前手里仍然只是基础模型。

它依赖所谓的上下文学习能力，通过构造 few-shot prompt 来实现。好，最后我想展示一种巧妙方法：只靠提示，就能让基础模型暂时扮演一个完整的语言模型助手。诀窍是把提示组织成一个网页，形式上像是一个 AI 助手和人类的对话，然后让模型继续这段对话。实际上，写提示时我求助了 ChatGPT 本身，这有点套娃。我告诉它，我想创建一个 LLM 助手，但手里只有基础模型，请它帮我写提示。它给出的内容相当不错：“下面是一段 AI 助手和人类之间的对话。AI 助手知识丰富、乐于助人，能够回答各种问题……”等等。光给它这样的描述还不够，设计成 few-shot prompt 效果会好得多。于是你写上几轮 human、assistant、human、assistant 对话，最后再放入你实际想问的问题。

我把它复制到基础模型提示里。现在写“Human:”，然后输入实际问题：“天空为什么是蓝色的？”接着让 Assistant 回答。天空看起来是蓝色的，是由于光的散射现象……你看，基础模型只是继续这个序列，但由于序列形式像一段对话，它就扮演起助手的角色。不过这里有个细节：它回答完之后，会继续虚构人类的下一个问题等等，于是对话会没完没了。不过你能看到，我们基本达到了目的。如果只输入“天空为什么是蓝色的？”，刷新后直接把问题放进去，当然不指望基础模型能正常回答。我们不知道会得到什么。好，它又生成了一些问题。这就是即使只有基础模型，也能创建助手的一种方法。

这就是过去几分钟讨论内容的简短总结。我们希望训练出 ChatGPT 这样的 LLM 助手。刚才讲的是其中第一阶段，也就是预训练。我们看到，归根结底，是从互联网上获取文档，把它们切分成 token，也就是一小段一小段文本构成的基本单位，再用神经网络预测 token 序列。整个阶段的产物是基础模型，也就是这组神经网络参数。基础模型本质上是一个互联网文档模拟器，工作在 token 层面。

它能生成具有互联网文档统计特征的 token 序列。我们看到，它能用于一些应用，但还不够。我们想要的是一个助手，可以向它提问并得到回答。因此我们还要进入第二阶段，也就是后训练。我们把基础模型，也就是互联网文档模拟器，交给后训练流程。现在我们来讨论几种后训练方法。后训练的计算成本低得多。绝大部分计算工作、那些庞大的数据中心和数百万美元的算力，都花在预训练阶段。但接下来是稍微便宜一些、却仍然极其重要的后训练阶段，我们要把 LLM 转变成助手。来看看怎样让模型不再生成互联网文档，而是回答问题。

换句话说，我们现在要开始考虑对话，而且对话可以包含多轮。最简单的情况是人类和助手之间的对话。比如，人类说：“2 加 2 等于多少？”助手应该回答：“2 加 2 等于 4。”人类接着问：“如果是乘法呢？”助手就可以这样回答。再看一个例子，助手可以有某种友善的个性。第三个例子展示了，当人类要求我们不希望系统协助的事情时，助手可以拒绝，说它无法帮助。换句话说，我们现在要考虑系统应该如何与人互动，并设定助手在这些对话中的行为。

由于这是神经网络，我们不会通过代码明确编写这些行为，不能像传统程序那样直接设定助手。所有事情都要通过神经网络在数据集上训练来完成。因此，我们要通过创建对话数据集，间接地设定助手行为。这里有数据集中的三个独立对话示例。实际数据集的规模会大得多，可能有数十万段多轮对话，每段对话都很长，话题也十分多样。这里我只展示三个例子。基本上，我们通过示例来训练助手。那这些数据从哪里来？比如“2 乘 2 等于 4”和“2 加 2 等于……”之类的内容是谁写的？它们来自人工标注员。我们会给人工标注员一些对话上下文，让他们写出这种情境下理想的助手回复。

人工会针对各种情境写出助手的理想回复。然后我们训练模型模仿这些回复。具体做法是：取出预训练阶段得到的基础模型。它原本是在互联网文档上训练的。现在我们把互联网文档数据集丢掉，换成新的数据集，也就是对话数据集。我们继续用这些对话数据训练模型。模型很快就会调整，并学会助手如何回应人类提问的统计模式。之后推理时，我们就能给助手一个提示，让它生成回答，模仿人工标注员在这种情况下会写的回复。希望这样说得够清楚。

接下来我们会看一些具体例子，这样就更容易理解。我还想提一句，后训练阶段基本上就是继续训练模型。预训练实际中可能要用几千台计算机训练约三个月。后训练通常短得多，比如三个小时。这是因为我们手动创建的对话数据集远小于互联网文本数据集。因此训练时间会短得多，但从根本上说，我们还是取基础模型，继续使用完全相同的算法，其他东西都不变，只是把数据集换成对话。问题是：这些对话是什么？如何表示它们？怎样让模型看到对话，而不是原始文本？这种训练会带来什么结果？从某种心理学意义上说，我们在和模型对话时，究竟是在和什么交流？

现在来回答这些问题。先谈对话的分词。模型里的所有东西都必须变成 token，因为模型处理的就是 token 序列。如何把对话转换成 token 序列？我们需要设计一种编码方式。这有点像互联网里的 TCP/IP 数据包。如果你熟悉这些概念，应该知道其中有精确的规则和协议，规定如何表示信息、如何组织各部分，使数据按一种大家都能理解的形式排布。LLM 也一样，我们需要某种数据结构，以及一套规则，将对话这样的数据结构编码成 token，再从 token 解码回来。现在我来展示如何在 token 空间里重建这段对话。

打开 Tiktokenizer，我把刚才那段对话放进去，语言模型看到的就是这种表示。这里是用户和助手在两轮对话中的交替内容。看起来有些难看，其实相对简单。最后转化成的 token 序列稍微复杂一点，但这段用户和助手的对话最终变成了 49 个 token，也就是一个由 49 个 token 组成的一维序列。这里就是这些 token。不同 LLM 会使用略有不同的格式或协议，目前这一领域有点像狂野西部。比如 GPT-4o 使用以下格式。先是一个特殊 token，叫作 im_start。它是“im”的缩写，意思是“虚构独白”（imaginary monologue），再加上 start（开始）。我说实话，不知道它为什么这么命名。然后要指定轮到谁发言，比如 user，对应 token 428。

接下来是内部独白分隔符，然后是问题的原文，也就是问题对应的 token，最后用 im_end 结束，也就是虚构独白结束。用户的问题“2 加 2 等于多少”，就变成了这一串 token。这里需要强调，im_start 不是普通文本，对吧？im_start 是一个特殊 token，是后来新增的 token，到目前为止还没有经过训练。它是在后训练阶段创建并引入的。这些特殊 token，比如 im_sep、im_start 等，会插入文本中，让模型学会：这是一个发言轮次的开始，轮到谁发言？现在轮到用户。接着是用户说的话，用户发言结束，然后是新一轮发言的开始，发言者是助手。

助手要说什么？就是这些代表助手发言内容的 token，依此类推。这样，对话就被转换成了 token 序列。具体细节并不重要。我只是想用具体例子说明，我们认为是结构化对象的对话，会通过某种编码方式转换成一维 token 序列。既然它是一维 token 序列，我们就能应用之前讲过的所有方法。现在它只是一串 token，我们可以在上面训练语言模型。我们仍然是在预测序列中的下一个 token，和以前一样，只不过现在能表示对话并在对话上训练。推理时又是什么样子？假设模型已经在这类对话数据集上训练好了，我们现在要进行推理。你在 ChatGPT 上会看到什么？

你打开 ChatGPT，和它进行对话。假设前面的对话内容已经填好，比如“2 加 2 等于多少？”“2 加 2 等于 4。”现在你接着问：“如果是乘法呢？”并加上 im_end。OpenAI 的服务器大致会这样处理：放入 im_start、assistant、im_sep，然后在这里结束。它们构造好上下文后，就开始从模型中抽样。此时服务器会向模型询问：第一个合适的 token 是什么？第二个是什么？第三个是什么？接下来就由 LLM 接管并生成回答，比如类似这样的回复。它不必与例子完全相同，但如果训练数据中有类似对话，回答就会带有类似的风格。

这大致就是协议的运作方式，虽然协议细节并不重要。再强调一次，我只是想说明，最终所有内容都是一维 token 序列。因此我们可以应用之前讲的所有方法，只不过现在训练的是对话，生成的也是对话。好，接下来看看实际的数据集是什么样。我要介绍的第一篇论文，也是这方面的早期尝试，是 OpenAI 在 2022 年发表的论文。论文叫 InstructGPT，或者说是他们开发的这项技术。这是 OpenAI 首次谈到如何在对话上微调语言模型。论文里有不少细节，我想带大家了解一下。首先看 3.4 节，他们介绍了这次聘用的人工承包人员，他们通过 Upwork 或 Scale AI 工作，负责构建这些对话。

这里有职业人工标注员，他们的工作就是创建这些对话。标注员需要提出提示，再写出理想的助手回复。以下是人们提出的一些提示。请列出五个想法，帮助我重新找回对职业生涯的热情。接下来我该读哪十本科幻小说？还有很多不同类型的提示，比如把这句话翻译成西班牙语等等。人们先提出问题，然后也会回答问题，写出理想的助手回复。那么他们怎么知道针对这些提示，理想回复应该是什么？往下看就会发现，这里节选了提供给人工标注员的标注说明。开发语言模型的公司，比如 OpenAI，会编写标注说明，告诉人工如何创建理想回复。

这里是这类标注说明的一段节选。整体原则是要求人们做到有帮助、真实、无害。你可以暂停视频查看更多内容。概括来说，就是尽量回答问题、尽量提供帮助、尽量说实话，不要回答公司不希望 ChatGPT 处理的问题。大致上，公司会编写标注说明。实际说明通常没有这么短，往往有数百页，标注员需要经过专业培训，再按照说明写出理想的助手回复。正如论文所描述，这是一个非常依赖人工的流程。OpenAI 从未发布 InstructGPT 的数据集，不过我们有一些开源复现项目，尝试遵循这种方法收集自己的数据。我熟悉的一个例子是之前的 Open Assistant 项目。

这只是许多例子之一，我只是想让大家看看其中一个。这里是网上的一位参与者，受邀创建类似 OpenAI 人工标注员所写的对话。比如有人问：“你能写一段简短介绍，说明‘垄断’这个术语在经济学中的意义吗？请举例说明。”随后同一个人或另一个人会写出助手回复。这里就是助手的回答。之后同一个人或另一个人还会继续写出理想回复。接下来可能会有人追问“现在把它讲给狗听”，于是你可以试着给出更简单的解释。这样的内容就成为标签，最后我们用它训练模型。训练时，我们当然不可能覆盖模型推理时会遇到的所有问题。

我们不可能涵盖人们未来会提出的所有问题。但如果有一些这样的示例组成的数据集，模型训练时就会逐渐形成乐于助人、诚实、无害的助手人格。整个过程都是通过示例来编程的。这些都是行为示例。如果我们有足够多这类对话，比如十万条，再用它们训练，模型就会逐渐理解其中的统计模式，形成这种助手个性。测试时，即使遇到和训练集完全相同的问题，模型也可能原样复述训练集里的回答，但更常见的情况是，它会给出风格相近的答复。我们知道这就是你想要的回答类型。我们所做的就是通过示例来设定系统行为，让系统在统计意义上形成这种乐于助人、诚实、无害的助手人格，而这也反映了公司制定的标注说明。

我想说明，自从 InstructGPT 论文发表以来的两三年里，最先进的做法已经有所进步。尤其是现在不太会再让人类独自承担所有繁重工作了，因为我们有了语言模型，它们能帮助我们创建数据集和对话。现在很少有人会从零开始逐字写出回复。更常见的做法是先用现有 LLM 生成答案，再由人修改，或采用其他类似方式。如今，LLM 已经以很多方式渗透进后训练流程，并被广泛用于创建这些庞大的对话数据集。比如 UltraChat，就是一个较新的对话数据集。我想给你看看它。它在很大程度上是合成数据，不过我认为其中也有人类参与。

我也可能记错。通常会有少量人工参与，但会有大量合成数据辅助。具体构建方式各不相同。UltraChat 只是目前众多 SFT 数据集中的一个例子。我只想指出，如今这类数据集已经包含数百万段对话。对话大多是合成的，但可能经过一定程度的人工编辑，覆盖的话题也非常广泛。如今这些数据集规模相当大。还有所谓的 SFT 混合数据集，里面混合了许多不同类型和来源的数据。它们有些是合成的，有些来自人工，整体上行业已经朝这个方向发展。不过大致来说，我们仍在使用由对话构成的 SFT 数据集，并像之前那样用它们训练。最后我想消除一些与 AI 对话所带来的神秘感。你打开 ChatGPT，提出问题并按下回车，返回的内容在统计意义上与训练数据中的内容相符，而这些训练数据追根溯源，来自遵循标注说明的人类。

所以我们在 ChatGPT 里究竟是在和什么对话？应该怎么理解它？它并非来自什么神奇的 AI。粗略地说，它来自对人工标注员的统计模仿，而这些标注员遵循的是公司编写的标注说明。模型是在模仿这些标注员。你可以把 ChatGPT 的回答想成对人工标注员的某种模拟，仿佛你在问：人工标注员在这种对话情境下会说什么？而且这些标注员并不是随便从互联网上找来的人，因为公司会聘请专家。比如你询问代码问题时，参与创建这些对话数据集的标注员通常受过良好教育，也具备专业知识。

所以你问的，某种程度上是对这些人的模拟，而不是神奇的 AI。你是在和一个平均水平的标注员对话。这个平均标注员的技能可能相当高，但你得到的是对这类受聘参与数据集制作的人进行的即时模拟。我们再看一个具体例子。比如我打开 ChatGPT，说“推荐巴黎最值得看的五个地标”，然后按回车。好，结果出来了。该怎么理解这个回答？它不是某种神奇的 AI，用无限的智慧去研究所有地标，再给它们排名。我得到的是对 OpenAI 聘用的标注员的统计模拟。大致可以这么理解。如果 OpenAI 的后训练数据集里恰好有这个具体问题，我很可能会看到一个与人工标注员为这五个地标写出的答案非常相似的回答。

人工标注员怎么想出这个答案？他们会去互联网上搜一搜，花二十分钟左右做点小研究，然后列出一份清单。如果他们写的清单进入数据集，我很可能会看到他们提交的那份助手答案。如果后训练数据集里没有这个具体问题，那么模型的表现就更像是一种涌现能力。它在统计意义上理解，训练数据里常见的地标通常是知名地标，是大家通常想看的地标，也是互联网上经常提到的地标。还要记住，模型在预训练阶段已经从互联网上获得了大量知识。它很可能看过大量关于巴黎、地标以及人们喜欢看的景点的内容。

因此，预训练知识与后训练数据集结合起来，产生了这种模仿。这大致就是从统计角度理解其幕后机制的方式。好，现在我想转向我所说的 LLM 心理学，也就是这类模型训练流程所涌现出的认知效应。首先当然要谈幻觉。你可能听说过模型幻觉：LLM 会编造东西，完全捏造信息，等等。这是助手模型面临的一大问题。多年前的早期模型中，这个问题尤其严重。我认为现在已经好了一些，稍后会谈到一些缓解方法。现在先理解幻觉从何而来。假设训练集里有下面几段对话，它们都是看起来很合理、可能出现在训练集里的对话。

比如问：“克鲁斯是谁？”答案是：“汤姆·克鲁斯是一位著名的美国演员和制片人……”再问：“约翰·巴拉索是谁？”他是一位美国参议员。再问：“成吉思汗是谁？”然后给出相应回答。这些都可能是训练数据里的对话。问题在于，人类为每种情况写出正确的助手回答时，要么本来就知道此人是谁，要么会去网上查资料，然后写出语气肯定的回答。于是到了测试时，当你问起一个人，而这个名字完全是我随机编出来的，我认为此人并不存在，至少我不知道有这个人，只是随便拼出了一个名字，那么问题就来了。你问“奥森·科瓦奇是谁？”助手不会直接告诉你“我不知道”。

即使助手或语言模型的内部特征、激活值，或者可以说它的“脑子”里，可能知道这个人并不熟悉，网络里的某些部分可能在某种意义上知道这一点，但模型不会说“我不知道这个人是谁”。因为模型在统计上模仿训练集，而训练集中“某某是谁”这种问题总是会得到肯定的正确答案。于是模型会套用这种回答风格，尽力给出统计上最可能的猜测，基本就是编造内容。再说一次，这些模型无法访问互联网，也不会做研究。正如我所说，它们只是统计性的 token 搅拌器，只是在尝试抽取序列中的下一个 token。结果就是它们会编造信息。

我们来看看实际情况。我这里打开 Hugging Face 的 Inference Playground，特意选了一个叫 Falcon 7B 的老模型。它是几年前的旧模型，因此会出现幻觉。正如我前面所说，近来的模型已经有所改善。我们问：“奥森·科瓦奇是谁？”运行 Falcon 7B Instruct。它回答：“奥森·科瓦奇是一位美国作家和科幻小说家。”这完全是假的，是幻觉。再试一次。记住，它们是统计系统，我们可以重新抽样。这次说奥森·科瓦奇是 20 世纪 50 年代电视剧里的虚构人物。完全胡扯。再试一次。它说他曾是一名小联盟棒球选手。基本上，模型不知道，所以给出了很多不同答案。它只是在从概率里抽样。模型接收“奥森·科瓦奇是谁？助手”这些 token，然后得到一组概率，再按概率抽样。

它就是这样编出内容的。这些内容在统计上符合训练集中回答的风格。你和我听起来会觉得它在提供编造出来的事实知识，但要记住，模型其实不知道。它只是在模仿回答的格式，也不会自己去查资料，因为它只是模仿回答。那么如何缓解这个问题？比如打开 ChatGPT，问“奥森·科瓦奇是谁？”，现在我问的是 OpenAI 最先进的模型。它会告诉你……这个模型似乎更聪明一些，因为你刚才可能看到它一闪而过地显示“正在搜索网络”，后面我们会讲这个。它正在尝试调用工具，同时编出某种说法。不过我想让它不调用工具。我再明确说，不要搜索网络。它回答说，似乎没有一位广为人知的历史人物或公众人物叫奥森·科瓦奇。这个模型没有编造内容。它知道自己不知道，并告诉你它不认识这样的人。

所以我们在某种程度上缓解了幻觉问题，尽管旧模型里这个问题确实很严重。如果训练集是这样的，模型给出这类答案也完全说得通。如何解决？显然，我们需要在数据集中加入一些示例，在某些事实问题上，助手的正确回答是模型不知道。但只有模型确实不知道时，才应该这么回答。问题是，我们怎么知道模型知道或不知道什么？我们可以通过实测来探测模型。比如看看 Meta 如何处理 Llama 3 系列模型的幻觉问题。

Meta 发表的这篇论文里有一节讨论幻觉，他们把它称为 factuality（事实准确性），并介绍了如何询问模型，从而判断它知道什么、不知道什么，确定其知识边界。接下来，他们会在训练集中加入一些示例：对于模型不知道的内容，正确答案就是模型不知道。原则上这听起来很容易，但大致上确实能缓解问题。之所以有效，是因为模型在网络内部可能已经对自身知识有相当不错的表征。还记得我们看过网络里的那些神经元吗？你可以想象网络中某个神经元会在模型不确定时亮起来。但问题在于，这个神经元的激活目前没有连接到模型用语言说“我不知道”这件事上。

也就是说，神经网络内部或许知道，但由于有些神经元代表了模型的不确定性，模型却不会把它表达出来，而是像训练集里看到的那样，给出最好的猜测，让自己听起来很有把握。所以我们要询问模型，并允许它在不知道时说“我不知道”。我来介绍一下 Meta 大致怎么做。举个例子，今天的维基百科特色条目是多米尼克·哈谢克，我随便点开的。他们会从训练集中随机取一份文档，选出一段，再用 LLM 根据这段文字生成问题。比如我在 ChatGPT 里做了这个操作：我给它一段文档，让它根据内容生成三个具体的事实问题，并提供问题和答案。LLM 已经足够擅长重新组织这类信息了。

只要信息在 LLM 的上下文窗口里，这种方法效果就很好。它不需要依赖记忆，因为信息就在上下文中，所以它能相当准确地改写信息。比如，它可以生成“他效力过哪支球队？”以及答案、“他赢得过几次杯赛冠军？”等等。现在我们有了问题和答案，要做的是询问模型。大致做法是拿着问题去问模型，比如 Meta 的 Llama。不过这里我们用 Mistral 7B 来做演示，它是另一个模型。这个模型知道答案吗？看看。它答的是布法罗军刀队，对吧？所以模型知道。如何用程序判断？我们取模型的回答，与正确答案比较。模型已经足够擅长自动完成这种比较，因此不需要人工。我们可以让另一个 LLM 充当裁判，检查模型回答是否符合正确答案。如果符合，就表示模型很可能知道。

我们可以重复问几次。好，它知道答案是布法罗军刀队。再问一次，还是布法罗军刀队。我们针对这个事实问题问了三次，模型似乎都知道，没问题。现在试第二个问题：“他赢得过几次斯坦利杯？”再问模型。正确答案是两次。模型说他赢了四次，这显然不对，也和答案不符。所以模型不知道，它在编造。再试一次。它还是在编。再问一次，它说他职业生涯中一次也没赢过。显然，模型不知道。程序上再次可以这么判断：问模型三次，再把回答和正确答案比较。可以问三次、五次，次数按需要设定。如果模型不知道，我们就能判断它不知道这个问题。然后把这个问题加入训练集，创建一段新的对话：问题是“他赢得过几次斯坦利杯？”，答案是“抱歉，我不知道”或“我记不清了”。因为我们已经询问并确认了，正确答案就应该是这样。

如果对不同文档提出各种问题，反复这样做，就能在训练集中给模型机会，让它在不知道时学会拒答。如果训练集中有一些这类示例，模型就可能学会把这种基于知识不足的拒答，与网络中某个内部神经元关联起来。我们假设这种神经元确实存在，而实验结果也很可能表明事实如此。模型可以学会这种关联：当代表不确定性的神经元激活较高时，自己其实不知道，于是可以说“抱歉，我不记得了”等等。训练集中有这些例子，就能大幅缓解幻觉。这大致也是 ChatGPT 能做到这一点的原因。人们已经采用这类缓解措施，逐步改善了事实准确性。好，这是缓解幻觉的第一种方法。我们还可以做得更好。除了说不知道之外，还可以用第二种方法，让 LLM 有机会基于事实回答问题。

如果我问你一个事实问题，而你不知道答案，你会怎么做？你可以去搜索、上网查资料，弄清答案再告诉我。我们也能对模型做同样的事。可以把神经网络数十亿个参数里的知识，想成模型很久以前在预训练阶段看到内容后留下的模糊回忆。把参数里的知识想成你一个月前读过的东西。如果反复读，你会记住，模型也是如此。但如果是罕见信息，你可能就记不太清了。我们会去查资料。查资料的过程，本质上是用信息刷新工作记忆，然后取回信息并讨论它。我们需要让模型刷新记忆或回忆的方法。可以通过引入工具实现。我们的思路是，不要只让模型回答“抱歉，我不知道”，而是允许它使用工具。我们可以设计一种机制，让语言模型输出特殊 token，这些都是我们新引入的 token。

比如这里我引入了两个 token，并设计了模型使用它们的格式或协议。模型不知道答案时，不必只说“我不知道，抱歉”，还可以输出特殊 token Search start。后面跟着要发送给 Bing.com（OpenAI 的例子）或 Google 搜索的查询内容。随后模型输出 search end。这时，负责从模型抽样、运行推理的程序一旦看到特殊 token search end，就不会继续抽取下一个 token，而是暂停生成。程序会打开与 Bing.com 的会话，把搜索查询提交给 Bing，然后取回所有搜索结果文本。

程序可能会用其他特殊 token 重新表示这些结果，再把文本复制到这里，也就是我用方括号表示的位置。搜索结果文本就会插入那里。文本一进来，就进入上下文窗口。也就是说，网页搜索得到的文本现在处于上下文窗口中，会作为输入送进神经网络。你可以把上下文窗口想成模型的工作记忆。处于上下文窗口里的数据可以被模型直接访问，会直接输入神经网络。它不再是模糊的回忆，而是上下文窗口中模型可以直接使用的数据。所以之后抽样生成新 token 时，模型可以很容易地引用粘贴进来的信息。这大致就是工具调用的工作方式。网页搜索只是我们接下来要看的工具之一，基本机制是引入新 token，再规定模型如何使用这些 token，调用网页搜索等特殊功能。

如何教模型正确使用这些工具，例如网页搜索的 start 和 end token？还是通过训练数据。我们需要一批数据和对话，以示例教模型如何使用网页搜索。什么情况下要搜索？搜索是什么样的？这里是如何开始搜索并完成搜索的示例。如果训练集中有几千个这样的例子，模型就会相当擅长理解工具的用法，也知道如何组织查询。当然，因为预训练数据集以及它对世界的认识，模型本来就大致理解网页搜索是什么，所以它对什么样的内容适合作为搜索查询有一定的直觉。

所以整个机制基本就能运作起来。只需要少量示例教会模型如何使用新工具，它就能靠工具取回信息并放入上下文窗口。这和我们自己查资料一样，因为信息一旦进入上下文，就是工作记忆的一部分，很容易操作和访问。几分钟前我在 ChatGPT 里搜索“奥森·科瓦奇是谁？”时，ChatGPT 语言模型判断这可能是个罕见人物。它没有从记忆中回答，而是决定抽取一个会触发网页搜索的特殊 token。我们看到屏幕上闪过“正在使用网页工具”之类的字样，等了两秒左右，它就生成了回答。你能看到它添加了参考文献，也就是引用来源。

实际情况是，它去做了网页搜索，找到了这些来源和网址。网页文本都插入了这里，只是界面没有显示。它们作为文本放在上下文中，模型看到了这些文本，于是引用它们，说可能是这些人，并附上引用；也可能是那些人，并附上引用。这就是刚才发生的事情。因此我问“奥森·科瓦奇是谁”时，也可以告诉 ChatGPT 不要使用任何工具，这足以让它不调用工具，只依靠记忆和回忆。我也问了 ChatGPT 多米尼克·哈谢克赢过几次斯坦利杯，它判断自己知道答案，有把握地说他赢过两次。它依靠自己的记忆，可能是因为它对权重、参数和激活值中的相关信息有足够信心，可以直接从记忆中取回。

当然，也可以反过来要求它进行网页搜索以确认。同一个问题，它会去搜索，找到一些来源，把这些文本复制到上下文中，然后再次回答并引用来源。它还引用了维基百科文章，那也是我们查到这一信息的来源。以上就是工具和网页搜索。模型会自行决定何时搜索。这些就是工具的运作方式，也是缓解幻觉、提高事实准确性的另一种方法。再强调一次这个非常重要的心理学观点：神经网络参数中的知识是模糊的回忆；构成上下文窗口的 token 中的知识则是工作记忆。粗略来说，它和人脑的运作方式有点相似。记忆里的东西相当于参数；几秒或几分钟前刚经历的东西，则可以想成在上下文窗口中。你可以想象，上下文窗口随着意识经验不断累积。这对你实际使用 LLM 也有不少启示。

比如我可以打开 ChatGPT，问：“你能总结《傲慢与偏见》第一章吗？”这是一个完全合理的提示。ChatGPT 的回答也还算合理。但原因是它对《傲慢与偏见》这样的名著有比较好的模糊记忆。它可能看过大量关于这本书的内容、相关论坛，也可能读过这本书的版本，所以记得一些内容。就像你读过这本书或相关评论后，也会有足够的印象来讲述它。但我实际使用 LLM 时，如果希望它准确回忆具体内容，直接把内容提供给它通常效果更好。

所以我认为更好的提示是：“你能为我总结简·奥斯汀《傲慢与偏见》第一章吗？我把章节内容附在下面供你参考。”然后加个分隔符，把章节内容贴进去。我是在某个网站上找到第一章，再复制粘贴到这里。这样做是因为内容一旦进入上下文窗口，模型就能直接访问，不必靠回忆，而是确切地看到原文。这样得到的摘要预计会比刚才那个质量更高，因为原文就在模型眼前。我认为你我也一样：如果总结之前重新读过这一章，摘要会好得多。这大致就是此处发生的事情。接下来我想简要谈另一个心理层面的怪现象：模型对自身的认知。

我经常在网上看到有人问 LLM：“你是什么模型？是谁开发了你？”这个问题多少有点不合理。正如我试图通过底层原理解释的那样，这东西不是一个人，没有任何持续存在。它会启动处理 token 的进程，然后关闭。每个用户都是如此。它建立一段对话的上下文窗口，然后一切都会被删除。所以每段对话开始时，这个实体都像是从头启动的。它没有持续的自我，也没有自我意识。它只是一个 token 搅拌器，遵循训练集里的统计规律。所以问它“你是谁？谁构建了你？”其实不太说得通。默认情况下，如果只是像我说的那样，从空白状态直接问它，得到的回答会相当随机。

比如我们来问问 Falcon 这个旧模型会怎么回答。它先回避问题，说是由才华横溢的工程师和开发者构建的。接着又说是 OpenAI 基于 GPT-3 模型构建的。这完全是编造的。很多人可能会把它说自己由 OpenAI 构建，当成模型受过 OpenAI 数据训练的证据。我不认为这一定是真的。原因是，如果你没有明确设定模型如何回答这类问题，它给出的就是统计上最可能的猜测。这个模型的 SFT 对话数据混合中有很多对话，微调时它会从这些数据中逐渐形成乐于助人的助手人格。但它不知道该怎么给自己贴标签，因为没有人明确告诉它该使用什么身份标签。它只是形成了这种助手形象。

还要记住，预训练阶段使用了整个互联网的文档，其中关于 ChatGPT 和 OpenAI 的内容非常突出。所以我认为，它很可能只是在幻觉式地给自己贴标签，把自己的身份说成 OpenAI 的 ChatGPT。之所以这么说，是因为网上有很多类似的回答，而这些回答实际上来自 ChatGPT。于是它把这个标签套用在自己身上。作为开发者，你可以覆盖这种行为。如果你有一个 LLM 模型，有几种方法可以覆盖它的自我描述。比如 Allen Institute for AI 的 OLMo 模型。它不是顶尖 LLM，但我喜欢它，因为它完全开源。OLMo 的论文和其他材料也都完全开源，这很好。现在我们看它的 SFT 混合数据集，也就是微调所用的数据混合，里面有对话数据。

他们处理 OLMo 身份问题的方法是：混合数据里包含很多内容，总共有 100 万段对话。但这里有一部分是硬编码的。点进去，可以看到 240 段对话，都是预先写好的。看看这些内容：用户问“介绍一下你自己”，助手回答“我是由艾伦人工智能研究所开发的开放语言模型……我可以帮助你……”又问“你叫什么名字？”答“OLMo 项目”。这些都是专门编写的、关于 OLMo 的问题和标准答案。如果把 240 个这样的问答或对话放进训练集并进行微调，模型之后就会复述这些内容。如果没有提供这些示例，它可能就会说自己是 OpenAI 的 ChatGPT。

有时还可以用另一种方式。在人类与助手的对话中，开头可能会有一条特殊消息，叫作 system message（系统消息）。因此，对话不只有人类和助手，还包含系统消息。你可以在系统消息里硬编码，提醒模型：“你是 OpenAI 开发的模型，你的名字是 ChatGPT-4o，你是在某日期训练的，知识截止日期是某日。”这相当于简单介绍模型，然后把这条消息插入对话中。你打开 ChatGPT 时看到的是一张空白页面，但系统消息其实隐藏在里面，那些 token 位于上下文窗口中。因此，编程模型如何介绍自己的方式有两种：通过这样的训练数据，或者通过系统消息等方式，也就是放入上下文窗口的不可见 token，提醒模型自己的身份。

不过这些身份信息都是以某种方式编造并附加上去的。它并非像人类那样真正从内在拥有的自我认知。现在我想继续下一节，讨论模型解决问题时的计算能力，或者更准确地说，模型原生的计算能力。尤其是构造对话示例时，我们得非常小心。这里有很多值得注意的棘手之处，能帮助我们理解模型如何思考。想象下面这个人类提示，它将被写成对话，放入训练集，用来训练模型解决简单数学题。题目是：“Emily 买了三个苹果和两个橙子。每个橙子 2 美元，总价 13 美元。苹果每个多少钱？”

这是道非常简单的数学题。这里左右各有一种回答，两种答案都正确，都说答案是 3。但其中一个显著比另一个更适合做助手回答。如果我是数据标注员，正在制作示例，其中一个回答会非常糟糕，另一个还可以。你甚至可以暂停视频，想想为什么其中一个明显更好。如果选错，模型的数学能力可能会很差，带来糟糕结果。编写标注文档、培训人员撰写理想助手回复时，需要考虑这一点。关键是要记住，模型训练和推理时，都是从左到右处理一维 token 序列。

我脑海里常有这样的图景：token 序列从左向右演进。为了生成序列中的下一个 token，我们把之前所有 token 输入神经网络。神经网络给出下一个 token 的概率，对吧？这里的图就是前面看过的图，来自我给你展示过的网页演示。它接收顶部的输入 token，通过网络中的神经元进行运算，给出下一个 token 的概率。重要的是，这里进行的计算层数有限。比如这个模型只有一、二、三层所谓的注意力和 MLP。现代最先进的模型可能有约 100 层。也就是说，从之前的 token 序列到下一个 token 的概率，只有约 100 层计算。因此，每个 token 所能进行的计算量是有限的。

你应该把它想成非常少的计算量。对序列中的每个 token 来说，计算量大致固定。严格来说并非完全如此，因为输入的 token 越多，神经网络的前向传播就越耗计算，但差别不大。一个好的理解方式是，每个 token 在这个计算框里都要经过大致固定的计算量。这个计算量可能不足以完成复杂计算，因为从上到下经过的层数并不多，实际发生的计算也有限。因此你不能指望模型在一次前向传播中，也就是生成一个 token 时，完成任意复杂的计算。这意味着我们必须把推理和计算分散到许多 token 中，因为每个 token 能承担的计算量有限。

我们应该把计算分摊到许多 token 上，不能期望模型在某一个 token 上做过多计算，因为每个 token 的计算量就这么多。大致上每个 token 的计算量是固定的。正因如此，这个答案明显更差。想象模型从左到右生成 token，我把这个答案复制到这里：“答案是 3……”模型一次只生成一个 token。我们预期它会说“答案是 $”，然后这里就得把整道题的所有计算都塞进一个 token 里，准确输出答案 3。接着它还要生成后面这些 token，但到这时，答案已经生成，已经放进后续 token 的上下文窗口里了。

所以后面那些内容只是在事后解释为什么答案是这个，因为答案已经生成，已经在 token 窗口里，后续内容并没有真正计算出答案。如果你让模型直接立刻回答，就等于训练模型试图用一个 token 猜出答案，而每个 token 的计算量有限，这种做法行不通。右边这个答案好得多，因为它把计算分散在多个 token 中。模型从左到右逐步得出答案，并产生中间结果。它先说橙子的总价是 4 美元，所以 13 减 4 等于 9，再得到其他中间计算。每一步单独看都不需要太多计算。因此，我们实际上是在估算模型单个 token 能承担的难度。

任何一个 token 都不能承担过多计算，否则模型在测试时就做不到。这样训练是在教模型把推理和计算分散到多个 token 中。每个 token 只处理简单问题，多个结果累加起来。接近结尾时，模型的工作记忆中已经包含之前所有结果，因此更容易得出答案是 3。这就是更好的计算标注。另一个例子会很糟糕，因为它教模型试图在一个 token 中完成所有计算。这个观点值得记住。通常你在提示里不必明确考虑这件事，因为 OpenAI 的标注员会处理，确保答案中的推理步骤充分展开，所以 OpenAI 大致会做对。

我把这道题问 ChatGPT 时，它会慢慢推理，比如先定义变量、列方程，再生成所有中间结果。这些结果不是给你看的，而是给模型自己的。如果模型不生成这些中间结果，就无法得出 3。我还想展示一下，怎样可以故意为难模型。我们可以直接要求它做某件事。比如我给它完全相同的题目，但要求“只用一个 token 回答，立即给我答案，其他什么也别说”。对于这个简单例子，它确实一次就答对了。我想这里实际用了两个 token，对吧？因为美元符号本身是一个 token。所以它不是只给了一个 token，而是两个，但仍然答对了，而且只经过一次网络前向传播。

这是因为这里的数字很简单。我再加大难度，故意为难它。我改成 Emily 买了 23 个苹果和 177 个橙子，数字变大了，我是在增加难度，要求它把更多计算塞进一个 token 里。我提出同样要求，它回答了 5，但答案不对。模型没能在一次前向传播中完成计算。它无法从输入 token 出发，仅靠一次网络计算就得出结果。接着我说，别管 token 限制，按通常方式解题。它就列出所有中间结果并逐步简化。对模型而言，每个中间结果和计算都容易得多，每个 token 承担的工作不大。

这里所有 token 都正确，最后得出答案 7。刚才它没法把所有计算压进一次网络前向传播中。我觉得这是个有趣的小例子，也能帮助我们理解模型的工作方式。关于这个话题最后一点是，如果我在日常生活中真的要解决这道题，我可能不会完全相信模型的所有中间计算都正确。因此我可能会这样做：告诉它“使用代码”。这是因为 ChatGPT 能使用代码工具。与其让它像刚才那样做心算，我并不完全信任这种心算。尤其数字很大时，模型不保证能算对。

每一步中间计算都有可能出错。我们用神经网络做心算，有点像你用大脑心算，可能会把中间结果算错。模型竟然能做这些心算，其实已经很惊人了。我不觉得我能在脑子里算出来，但模型好像能在“脑子里”算。我不信任它，所以想用工具。你可以让它用代码。我不确定刚才怎么没触发。再说一次“使用代码”。如前所述，有一个专用工具，模型可以写代码。我可以检查代码是否正确，这样就不必依赖它的心算。它可以调用 Python 解释器，这是一种简单的编程语言，用来写出计算结果的代码。相比语言模型的心算，我个人更信任 Python 程序，因为它有更多正确性保障。

所以再给你一个建议：遇到这类问题，可以直接让模型使用代码解释器。就像网页搜索一样，模型会输出调用工具的特殊 token。它不会真的把这些 token 当作普通文本生成，而是编写程序，再把程序发送给计算机的另一个部分运行，取回结果。模型随后就能访问结果并告诉你每个苹果 7 美元。这是另一种工具。实际使用时我会这么做，因为更不容易出错。因此我把这一节叫作“模型需要 token 来思考”：把计算分散到多个 token 中，让模型生成中间结果；或者尽可能使用工具，不要让模型把所有事情都放在记忆里处理。

如果模型试图全靠记忆完成，我不会完全信任它，能用工具时我更倾向于使用工具。我再展示一个类似例子：数数。模型不太擅长计数，原因也一样：你要求它在单个 token 中完成太多工作。来看一个简单例子：“下面有多少个点？”我放入一堆点，ChatGPT 说“有……”，然后试图用一个 token 解题。它需要在一个 token 里数出上下文窗口里的点数，并在一次网络前向传播中完成。正如我们说过的，一次前向传播能做的计算并不多。你可以把它想成非常有限的计算量。如果看看模型实际看到的内容，我们去 LM，再打开 Tokenizer。

模型看到的就是这些：“下面有多少个点？”结果发现，这里这一组大约 20 个点，整个是一枚 token。另一组点也构成一个 token。然后不知为何，它们又按这样的方式拆分。我不太清楚具体原因，这与分词器的细节有关。模型实际看到的是这些 token ID，诸如此类，然后要根据这些 ID 数出点的数量。先揭晓答案，不是 161，我认为实际是 177。我们可以这么做：改成告诉模型“使用代码”。你可能会问，这为什么能奏效？其中的原理有点微妙，也很有意思。我说“使用代码”时，确实预期它能成功。看看结果。好，177 是正确答案。这里发生的事情是，虽然看起来不明显，但我把问题拆成了模型更容易处理的任务。我知道模型不会计数，不会心算，但它很擅长复制粘贴。所以我说“使用代码”后，模型会在 Python 里创建一个字符串。把我这里的输入复制粘贴到那里，对模型来说很简单，因为它看到的只是这段字符串对应的四个 token 左右。因此，它很容易复制这些 token ID，并把它们展开成这里的点。然后它创建字符串，调用 Python 的 count 函数，得出正确答案。计数的是 Python 解释器，而不是模型的心算。这又是一个简单例子：模型需要 token 来思考，不要依赖它的心算。这也是模型不擅长计数的原因。如果要做计数任务，就让它使用工具。

模型还有许多其他认知上的小缺陷，这些都是这项技术需要留意的棱角。例如，模型不太擅长各种拼写相关任务。我说过会再回到分词话题。原因是模型看不到字符，只看到 token。它们的整个世界都围绕 token，也就是这些小段文本。因此它们不像我们的眼睛那样看到字符，简单的字符级任务常常会失败。例如，我给它一个单词 ubiquitous，让它从第一个字符开始，每隔两个字符输出一个字符。我们从第一个开始，然后每三个取一个，所以接下来应该是第 3 个字符 Q，依此类推。它给出的结果显然不正确。我的一个猜测是，这里心算也出了一点问题。但我认为更重要的原因是，如果去 Tiktokenizer 查看 ubiquitous，会发现它被分成了三个 token。

你我看到 ubiquitous 时，可以轻松地识别单个字母，因为我们看得到它们。它们处于视觉工作记忆中，所以我们可以很容易地每隔三个字母取一个。但模型无法访问单个字母，它看到的是这三个 token。要记住，这些模型从头开始用互联网数据训练，它们必须学会每个 token 里打包了哪些字母。我们使用 token，主要是为了提高效率。但我觉得很多人都想彻底去掉 token，改用字符级或字节级模型。只是那样会产生很长的序列，目前大家还不知道怎么处理。

所以，只要我们还处于 token 世界里，就不能指望拼写任务表现很好。既然我知道分词使拼写不是模型的强项，就可以再次让它使用工具。我只要说“使用代码”，就预期它能成功，因为把 ubiquitous 复制到 Python 解释器里很简单。接下来让 Python 解释器处理这个字符串中的字符。我说“用代码处理 ubiquitous”，它就能取出每隔三个的字符。正确结果是 u2s、uqs，我觉得看起来没错。这又是一个拼写任务表现不佳的例子。一个广为人知的例子是“strawberry 里有几个字母 r？”这个问题多次在网上走红。现在模型基本能答对，说 strawberry 里有三个 r。但很长一段时间里，所有最先进的模型都坚持说只有两个 r。

这引起了很多讨论，这个词叫什么来着，我觉得可以叫争议吧。大家会问：为什么模型这么聪明，能解数学奥林匹克题，却数不清 strawberry 里有几个 r？前面我已经逐步解释了原因。第一，模型看不到字符，只看到 token。第二，它们不擅长计数。这个问题同时结合了识别字符和计数两种难点，所以模型才会出错。虽然我觉得现在 OpenAI 可能把这个答案硬编码进去了，或者他们用了别的方法，我也不确定，但这个具体问题如今能答对了。模型不擅长拼写，还有其他不少棘手之处。我不打算一一介绍，只想举几个例子，让大家知道实际使用时要留意什么。我也不打算全面分析模型在哪些方面表现不足。

我只是想指出，模型有一些参差不齐的地方。我们刚才谈过其中几个，有些可以解释，但有些就没那么容易理解。即使你深入了解模型原理，仍然会摸不着头脑。最近一个很好的例子是，模型不太擅长回答这类非常简单的问题。这让很多人震惊，因为这些模型能解复杂数学题，回答博士级的物理、化学、生物问题，比我强得多，但有时连特别简单的问题都答不好。比如“9.11 大于 9.9 吗？”模型会试着解释，但很明显……最后它又改变了判断。我不认为这个结果每次都能复现。有时它会改变答案，有时答对，有时答错。

再试一次。好，虽然看起来可能更大……这次它最后也没有纠正自己。多问几次，有时也会答对。但为什么模型能很好地解奥林匹克级别的题目，却会在这种简单题上失败？我觉得这确实让人困惑。有一群人深入研究了这个问题，虽然我还没读过论文，但研究团队告诉我，检查神经网络内部的激活值，观察哪些特征和神经元亮起或熄灭时，会发现很多亮起的神经元通常与圣经章节有关。我猜模型因此联想到这看起来像圣经章节的标记。在圣经章节的格式里，9.11 会排在 9.9 之后。

因此，模型在认知上似乎被这种联想干扰了。它知道这里要比较数字，也在努力解释并算出答案，却还是给出了错误答案。这件事基本上说不通，也还没有完全搞清楚。还有一些类似的参差问题。所以要把模型当作它本来的样子：一个随机系统，确实很神奇，但也不能完全信任。你应该把它当作工具，而不是把问题丢给它，然后不加检查地复制结果。好，我们已经介绍了大型语言模型训练的两个主要阶段。第一阶段是预训练，也就是在互联网文档上训练语言模型，得到所谓的基础模型，本质上是互联网文档模拟器。

我们看到这是一种有趣的产物，需要在数千台计算机上训练数月，而且它是互联网的一种有损压缩。它非常有意思，但不能直接满足我们的需求，因为我们不想让模型生成互联网文档，而是想向 AI 提问并得到回答。因此我们需要助手。我们看到，可以通过后训练来构建助手，具体来说就是监督微调（SFT）。这一阶段的算法与预训练相同，其他都不变，只有数据集变了。我们不再用互联网文档，而是创建并整理一个高质量的对话数据集。我们需要数百万段涉及各种主题的人类与助手对话。归根结底，这些对话由人类创建：人类写提示，也写理想回复，并根据标注说明来完成。

不过，现代流程并非完全由人手工完成。现在人们会大量借助工具，比如用语言模型帮助创建数据集。这种做法非常普遍，但归根结底，数据仍然由人类整理。我们创建对话，把它们作为数据集，对模型进行微调或继续训练，就得到一个助手。随后我们转向讨论这个助手在认知层面的特征。比如，如果不采取缓解措施，助手就会产生幻觉。我们看到幻觉很常见，也了解了一些缓解方法。模型很强，能在内部完成很多事情，但借助工具还可以做得更好。比如使用网页搜索减少幻觉，获取更新的信息；也可以使用代码解释器，让 LLM 编写代码、运行并查看结果。这些就是目前讨论过的内容。

现在我想介绍整个流程中最后一个主要阶段：强化学习。强化学习通常仍被归在后训练之下，但它是第三个主要阶段，也是一种不同的训练语言模型的方法。通常它位于第三步。在 OpenAI 这样的公司里，各阶段由不同团队负责：有团队准备预训练数据，有团队负责预训练；另有团队生成对话，再由另一个团队做监督微调；还有团队负责强化学习。这些模型就这样逐步交接：先得到基础模型，再把它变成助手，最后进入强化学习。现在我们重点谈最后这个主要训练阶段，也就是强化学习。先解释为什么需要强化学习，以及它大致是什么样。

我想用大家熟悉的事情来说明强化学习阶段的目的，也就是上学。就像你上学是为了学会某些本领，我们也希望让大型语言模型“上学”。实际上，我们有几种传授知识和技能的方式。学校的课本里大致有三类重要内容。第一类是讲解。顺便说一下，这本书是我从网上随便找的，好像是有机化学相关的，我不太确定。重要的是，大部分文本都是正文讲解，也就是背景知识。你阅读讲解文字时，大致可以把它看作在这些数据上训练。因此，阅读背景知识和上下文信息，大致相当于预训练。通过它建立知识基础，了解一个主题。第二类是习题和详细解答。

这里的专家，也就是这本书的作者，不仅给出了题目，还完整展示了解题过程。这相当于助手的理想回复。专家向我们展示了如何完整地解题。阅读解答时，我们是在专家数据上训练，之后可以尝试模仿专家。这大致相当于 SFT 模型。也就是说，我们已经完成预训练，也了解了如何模仿专家解题。第三阶段的强化学习，则相当于练习题。有时这里可能只展示一道练习题，但通常课本每章末尾都有很多练习题。我们知道练习题对学习至关重要，因为它们让你亲自练习并摸索解题方法。练习题会给出题目描述，但不给解法，通常会在课本答案里给出最终答案。

因此你知道要达到什么最终答案，也有题目，但没有解法。你要自己练习，尝试不同方法，看哪种最容易得到最终解答。你是在发现如何解决这些问题。过程中，你会依靠预训练带来的背景知识，也可能参考对人类专家的模仿，尝试类似的解法。前两步我们已经做过了，现在这一节要练习。我们会得到提示和最终答案，但没有专家解法，必须自己练习、尝试。这就是强化学习。好，我们回到之前讨论的题目，以便在后面探讨时有一个具体例子。

我现在打开 Tiktokenizer 分词器。它有文本框，很方便；而且我想再次提醒大家，我们始终处理的是一维 token 序列。我更喜欢这个视图，因为这才是 LLM 的原生视图，也就是它实际看到的东西：token ID。题目是：“Emily 买了三个苹果和两个橙子。每个橙子 2 美元，所有水果总价 13 美元。每个苹果多少钱？”这里有四种可能的解法，它们最后都得到 3。现在请想想，如果我是一个要创建训练对话的人类标注员，我其实不知道哪一种应该加进数据集。有些解法会列方程组，有些用英语逐步讲解，有些直接跳到答案。

比如把这个问题交给 ChatGPT，它会定义一组变量，然后按步骤解题。但我们要区分两件事。解法的首要目的当然是得到正确答案。我们希望最终答案是 3，这是最重要的目的。但还有第二个目的：让回答对人类来说读起来舒服。我们假设用户想看解法和中间步骤，所以要把解答写得清楚。这里有两件不同的事：第一是面向人类的呈现，第二是实际得到正确答案。暂时先只关注得出最终答案。如果我们只关心最终答案，哪一种是让 LLM 答对的最佳解法？我想表达的是，我们不知道。我作为人工标注员，不知道哪一个最好。

例如，前面讲 token 序列和心算推理时，我们看到每个 token 能使用的计算量有限，不算很多。你可以把它理解成，每个 token 都不能跳跃太大。第一种解法的优点是 token 很少，很快就能得出答案。但这里在一个 token 里做“30 减 4，再除以 3”，要求单个 token 承担大量计算。因此这可能是一个不好的示例，会鼓励 LLM 快速跳过计算，从而在心算中出错。也许把计算展开更好，也许列方程更好，也许逐步讲解更好。我们根本不知道。因为对你我或人工标注员来说容易或困难的事情，对 LLM 来说可能不同。它的认知方式不同，token 序列对它而言也有不同难度。我觉得很简单的某些 token 序列，对 LLM 来说可能是太大的跳跃。比如这里这个 token 可能就太难了。反过来，我写的许多 token 可能对 LLM 来说轻而易举。

如果它觉得这些步骤很简单，我们却写了这么多 token，就只是浪费。既然我们只关心最终答案，并把面向人类的呈现问题分开，那么我们确实不知道该如何标注这个例子。我们不知道应该给 LLM 什么解法，因为我们不是 LLM。数学例子很明显，但这其实是普遍问题：我们的知识不等于 LLM 的知识。LLM 可能拥有大量数学、物理、化学等博士级知识，很多方面知道得比我多。我写解答时可能没有利用它已有的知识。反过来，我也可能在解答中引入模型参数里没有的知识，对模型来说就成了难以理解的跳跃。我们的认知不同。如果目标只是让模型得到最终答案并尽可能高效地做到这件事，我不知道该写什么解法。

简而言之，我们不太适合替 LLM 创建这些 token 序列。通过模仿这些数据可以初始化系统，但我们真正想要的是让 LLM 自己发现适合它的 token 序列。它需要自己找到，在给定提示时，哪些 token 序列能可靠地得到答案，并在强化学习的试错过程中发现这些序列。看看这个例子在强化学习里会是什么样。好，我们回到 Hugging Face 推理演示页面，这样可以轻松调用不同模型。右上角我选了 Gemma 2B 模型。20 亿参数很小，是一个小模型，但没关系。强化学习的做法其实很简单：我们要尝试许多种不同的解法，看看哪些有效。

我们把提示交给模型，让它生成一个解法，然后检查解法。我们知道正确答案是 3 美元，这次模型答对了，说是 3 美元。这只是一次尝试。我们删掉结果，再运行一次。第二次模型用略有不同的方式解题，对吧？每次生成都不一样，因为模型是随机系统。记住，每个 token 都有一个概率分布，我们从中抽样，于是会走上略有不同的路径。第二个解法也得到了正确答案。删掉，再试第三次。好，解法又略有不同，但也答对了。实际上可以重复很多次。

实践中，你可以针对一个提示抽取数千个独立解法，甚至数百万个。有些正确，有些不太正确。我们要做的是鼓励能得到正确答案的解法。看看这意味着什么。这里有个卡通图：有一个提示，然后并行尝试许多解法。有些解法表现不错，得到了正确答案，用绿色表示；有些解法表现不好，没有得到正确答案，用红色表示。遗憾的是，这道题不是最佳例子，因为它太简单了。正如我们看到的，2B 模型每次都能答对。所以这不是很好的示例，不过我们可以想象绿的是好解法，红的是坏解法。假设我们生成了 15 个解法，只有 4 个答对。

现在我们要鼓励那些能得到正确答案的解法。红色解法里的 token 序列显然某个地方出了问题，走错了路径。绿色解法里的 token 序列则表现不错。我们希望未来在类似提示中多采用这类做法。鼓励这种行为的方法是用这些序列训练模型。但这些训练序列不是人类专家标注的，没有人决定哪种解法正确，而是模型自己生成的。模型在这里练习，尝试了几种解法，其中四种似乎有效。接着模型会用这些解法训练自己。这就像学生检查自己的解答，发现：“这个方法很管用，我以后应该这样解题。”

当然，具体方法还有很多变体。为了说明核心思想，我们可以想象从四个正确解法中挑一个最好的，比如这个黄色标出的解法。它不仅得到了正确答案，可能还有其他优点，比如最短、写得最清楚，或符合其他标准。我们决定用这个最佳解法训练模型。更新参数后，模型未来在类似情境中采取这条路径的概率就会略微提高。不过要记住，我们会同时处理大量不同提示，涉及数学、物理等各种问题。可以想象有数万个提示，每个提示都生成数千个解法。这些事情会同时发生。

随着这个过程不断迭代，模型会自己发现哪些 token 序列能够让它得到正确答案。这不是人类标注员提供的，而是模型在这个练习场里自己摸索。它知道自己要达到什么目标，并发现对自己有效的序列。这些序列不会出现很大的思维跳跃，能可靠地利用模型已有的知识。强化学习就是这样一个过程：不断猜测、检验，尝试许多种解法，检查结果，然后增加有效做法的出现概率。这就是强化学习。联系前面讲过的内容，SFT 模型仍然有帮助，因为它能把模型初始化到正确解法附近。它让模型知道如何写解答，可能学会列方程，也可能学会逐步讲解。SFT 把模型带到正确解法附近，而强化学习会进一步把方法调到合适状态，发现真正适合模型、能答对的解法，并鼓励这些解法。模型因此逐渐变好。

好，这就是训练大型语言模型的大致过程。简而言之，训练方式有点像培养孩子。区别在于，孩子是按课本章节学习，在每章里做不同练习；训练 AI 时，我们则按阶段进行，取决于该阶段的类型。首先是预训练，相当于阅读所有讲解内容。我们同时读所有教科书的正文，建立知识基础。第二步是 SFT，也就是阅读人类专家在各本教科书中写好的解答。我们得到一个能够模仿专家的 SFT 模型，但它是盲目模仿，只是在统计意义上尽力复现专家行为。最后，强化学习阶段相当于做所有课本里的练习题，只做练习题，由此得到 RL 模型。从整体上看，训练 LLM 与训练孩子的过程非常相似。

接下来要指出，预训练和监督微调这前两个阶段已经发展多年，是标准做法，所有 LLM 提供商都会做。最后的强化学习阶段仍处于早期发展阶段，尚未成为行业标准。原因是我刚才跳过了大量细节。高层思路很简单，就是试错，但具体选择哪些解法、训练多少、提示分布如何设计、如何设置训练过程，才能真正奏效，里面有很多细节和数学上的微妙之处。核心思想虽简单，把细节做好却不容易。

例如 OpenAI 和其他 LLM 提供商，已经在公司内部尝试了很久的 LLM 强化学习微调，但没有公开谈论。相关工作都在公司内部进行。因此 DeepSeek 最近发表的论文引起了很大关注。这是中国公司 DeepSeek AI 的论文，公开谈论了大型语言模型的强化学习微调，强调它对 LLM 非常重要，也能激发模型的推理能力。稍后我们会详细讨论。这篇论文重新点燃了公众对 LLM 强化学习的兴趣，并提供了复现结果、让这阶段在大语言模型中奏效所需的许多技术细节。我来简要介绍 DeepSeek-R1 论文，看看正确地对语言模型应用强化学习会发生什么、有什么效果。

首先看图 2，它展示了模型解决数学问题能力的提升。纵轴是数学问题的准确率。我们可以打开网页，看看这些评测里具体是什么题目。这些是简单数学题，你可以暂停视频阅读，模型就是要解这些题。起初表现不太好，但经过数千步更新后，准确率持续提高。模型越来越好，解题准确率也越来越高。通过在大量这类问题上试错，模型逐渐发现如何解数学题。不过，比准确率这种定量结果更令人惊讶的，是模型达到这些结果的定性过程。

往下看，有一张有意思的图：优化后期，每个回答的平均长度似乎增加了。模型为了提高准确率，开始使用更多 token，学会生成很长的解法。为什么会这么长？我们可以看看具体例子。这里是一个问题和模型给出的回答。模型学会的行为，是优化过程中涌现出来的属性。它发现这样有利于解题，于是开始说：“等等，等等，这不对，我可以在这里标记一下。让我们一步步重新评估，确认正确的总和……”模型在做什么？它会重新评估步骤。它学会了，为了提高准确率，可以尝试许多想法，从不同角度思考。

它会追溯、重新表述、回溯。这些都是你我解决数学问题时会做的事情，但模型是重新发现了我们脑海里的思考过程，而不是写在解答里的步骤。没有人能把这些内容硬编码进助手的理想回复。这只能通过强化学习过程发现，因为我们不知道该把什么写在这里。结果表明，这种做法适合模型，能提高解题准确率。模型学会了所谓的思维链，这是优化过程中涌现出的属性。它使回复变长，也提高了解题准确率。令人惊叹的是，模型正在发现思考方式，学会我所说的认知策略：如何处理问题、从不同角度切入、借助类比、尝试不同方法、从多个角度检查结果并解决问题。

这些策略是强化学习发现的。无需任何硬编码，它们就从优化中涌现出来，令人惊叹。我们只给了模型正确答案，它只是试着解对题目，结果就学会了这些。现在回到我们一直讨论的题目，看看所谓的推理模型或思考模型会如何作答。回忆一下这道题。我把它输入 ChatGPT 4o，得到这样的回答。现在把同样的问题交给经过强化学习训练的推理模型或思考模型。论文里介绍的 DeepSeek-R1 可以在 chat.deepseek.com 使用，由开发它的公司提供。要使用 R1 模型，记得打开 DeepThink 按钮。

我们把问题贴进去运行，看看模型会输出什么。之前用 SFT，也就是监督微调方法，得到的是模仿专家解法的回答。现在来看 RL 模型的回答。它说：“好，我来试着解一下。Emily 买了三个苹果和两个橙子，每个橙子 2 美元，总价是 13 美元。我需要求……”你读着读着，不免觉得这个模型在思考，确实在尝试解题。它推断每个苹果要 3 美元，然后说：“等等，我再检查一遍计算，确保没错。”接着它换了个角度再算一次，然后说：“对，都对得上。我觉得答案就是这个，没有发现错误。我再想想有没有其他解法，比如列方程。设每个苹果 8 美元，那么……”

它又得到了相同答案：“没错，每个苹果确实是 3 美元。我确信这是正确的。”思考结束后，它会为人类写出整洁的解答。前面的部分侧重正确性，后面则侧重呈现，把过程写得清楚，最后框出正确答案。令人惊叹的是，我们看到了模型的思考过程，这来自强化学习。它让 token 序列变长，因为模型在思考、尝试不同方法。它提高了解题准确率，也让我们看到“啊哈”时刻、不同策略，以及确保答对的办法。最后一点，有些人不太放心把非常敏感的数据放进 chat.deepseek.com，因为这是一家中国公司。

因此有人会谨慎一些。DeepSeek-R1 是这家公司发布的模型，是一个开放权重模型，任何人都可以下载和使用。但你无法在 MacBook 或本地设备上以完整精度运行完整模型，因为它相当大。不过很多公司都在托管最大的完整模型。我喜欢的一家叫 Together。你可以访问 together.ai，注册并进入 Playground，在聊天模型列表里选择 DeepSeek R1。还有许多其他模型可选，都是最先进的模型。这有点像我们之前使用的 Hugging Face 推理演示页面。Together.ai 通常会托管最先进的模型。选 DeepSeek-R1，其他设置可以先不管，我觉得默认设置通常可以。输入问题即可。因为模型由 DeepSeek 发布，在这里得到的结果应该基本等同于 DeepSeek 官网。

由于抽样有随机性，结果会略有不同。但原则上，模型能力应该一样，定量和定性表现都相近。不过这个模型是通过一家美国公司提供的。这就是 DeepSeek，也就是所谓的推理模型。现在回到 ChatGPT。下拉菜单里有些模型，例如 o1、o3-mini、o3-mini-high 等，它们标注为“使用高级推理”。这指的是它们通过强化学习训练，采用了与 DeepSeek-R1 类似的技术，OpenAI 员工也公开说过这一点。这些就是经过 RL 训练的思考模型。至于 GPT-4 或免费版提供的 GPT-4o mini，应该把它们看成主要经过 SFT，也就是监督微调的模型。它们并不像 RL 模型那样进行这种思考。虽然这些模型也多少用到了强化学习，稍后会谈到，但主要还是 SFT 模型。

和刚才一样，我们可以选一个思考模型，比如 o3-mini-high。顺便说一句，除非购买 ChatGPT 订阅，否则可能无法使用这些模型，订阅价格有每月 20 美元或部分顶级模型每月 200 美元。选好思考模型运行后，它会显示“推理”，开始进行类似这样的过程。我们看到的内容和 DeepSeek 展示的不完全一样。虽然模型在底层会生成这些思维链，OpenAI 选择不在网页界面展示完整思维链，只显示简短摘要。我认为部分原因是他们担心所谓的蒸馏风险：有人可能模仿这些推理轨迹，通过模仿思维链复现大量推理能力。因此他们把完整内容隐藏起来，只展示简短摘要。所以就推理过程而言，你看到的并不完全等同于 DeepSeek 的展示。之后模型会写出解答。即使看不到底层全部细节，两者大致相当。

就表现而言，这些模型和 DeepSeek 模型目前大致相当。评测有难度，我觉得不太好判断。但如果你每月向 OpenAI 支付 200 美元，我认为目前部分模型看起来仍然更好。不过 DeepSeek R1 仍然是很可靠的思考模型，可以在这个网站或其他网站使用。因为它是开放权重模型，你也可以直接下载。这就是思考模型。到目前为止，我们讨论了什么？我们谈到了强化学习，以及在许多数学和代码问题上运行 RL 时，思考能力会在优化过程中涌现。这些问题有可验证的答案，比如答案是 3。

你可以在 DeepSeek 官网，或 Together.ai 这样的推理服务提供商上使用思考模型。ChatGPT 的 o1 或 O3 系列也有思考模型。但 GPT-4o 等模型不属于思考模型，应该把它们看成主要经过 SFT 的模型。如果提示需要高级推理，你应该考虑使用思考模型，至少试试看。但根据我的实际经验，很多时候你只是问简单问题或知识类问题，思考模型可能太大材小用。没必要为了一个事实问题思考 30 秒。因此我有时会默认使用 GPT-4o。实际使用中，我大约 80% 到 90% 的时间都用 GPT-4o。遇到非常难的数学或代码问题时，我才会用思考模型，但要多等一会儿，因为它在思考。你可以在 ChatGPT 或 DeepSeek 使用这些模型。

我还想指出，Google AI Studio 虽然看起来很拥挤、很难看，Google 在这类界面设计上确实不太行，让人搞不清楚发生了什么。但你可以选择模型，再选择 Gemini 2.0 Flash Thinking Experimental 01-21。这也是 Google 早期实验性思考模型的一种。我们输入同样的问题并运行。它也是一个思考模型，会做类似的事情并得出正确答案。所以 Gemini 也提供思考模型。Anthropic 目前还没有思考模型。不过这大致代表了 LLM 的前沿发展。我认为 RL 是一个令人兴奋的新阶段，但要做好细节并不容易。因此截至 2025 年初，这些思考模型仍处于实验阶段。不过它们代表着前沿方向：利用优化中涌现的推理能力，提升模型解决难题的表现。

我还想提到一个关联：强化学习是一种极其强大的学习方式，这并不是 AI 领域的新发现。我们已经在围棋中看到过这种现象。DeepMind 著名地开发了 AlphaGo，你可以看一部纪录片，了解它如何学习与顶尖人类棋手下围棋。看看 AlphaGo 背后的论文，往下翻会看到一张很有意思、而且看起来颇为熟悉的图。如今我们在更开放的任意问题求解领域里发现类似现象，而不是围棋这种封闭、具体的领域。论文展示了围棋 Elo 等级分的变化，以及实力极强的人类棋手李世石的水平。图中比较了监督学习模型和强化学习模型的实力。监督学习模型模仿人类专家棋手。只要给它大量专家棋局并让它模仿，水平会提高，但最终会停滞，无法超过李世石这样的顶尖棋手。

因为它只是在模仿人类棋手，单靠模仿就不可能从根本上超越人类。但围棋中的强化学习强大得多。系统尝试下棋，并根据哪些棋步在统计上能带来胜利来学习。AlphaGo 会与自己对弈，通过强化学习生成对局轨迹。这里的图示原理完全相同，只是没有提示，因为围棋是一盘固定棋局。系统尝试不同解法，也就是尝试不同棋步。最终获胜的棋局会得到强化，相关策略会变得更强。系统学习的是在统计上能带来胜利的行动序列。强化学习不受人类表现限制，因此可能做得更好，甚至超过李世石这样的顶尖棋手。

他们本来或许可以让训练继续更久，只是因为成本高而在某个时候截断了。这有力地展示了强化学习的威力。对于大型语言模型的推理问题，我们才刚开始看到类似趋势的迹象。只模仿专家不会有太大突破。我们需要建立这些小型游戏环境，让系统发现独特但有效的推理路径或解题方式。再谈谈这种独特性：强化学习不会阻止系统偏离人类下棋的分布。回到 AlphaGo 的搜索过程，有一种著名棋步叫“第 37 手”。它指的是某个时刻 AlphaGo 下出了一步人类专家不会下的棋。人类棋手下这步棋的概率据估算约为万分之一。

这步棋极为罕见，但事后看来非常出色。AlphaGo 在强化学习过程中发现了一种人类未知、但事后看来十分高明的策略。我推荐看这个 YouTube 视频：“李世石对阵 AlphaGo，第 37 手反应与分析”。AlphaGo 下出这手棋时，现场大致是这样的：“这手棋太意外了。我原以为……我看到这手棋时，以为它下错了。”大家都很震惊，因为这是人类不会下、但 AlphaGo 下出的棋。它在训练中认为这步棋是个好主意，只是人类不会这么下。这再次展示了强化学习的力量。原则上，如果我们继续扩大这种语言模型训练范式，也许会看到相似现象，但具体会是什么样，目前还不清楚。

那么，以一种连人类都无法做到的方式解决问题意味着什么？如何在推理或思考上超过人类？也许意味着发现人类想不到的类比，或找到一种新的思考策略。这很难想象。也许它会使用一种全新的语言，而不是英语。也许模型会发现自己的语言，更适合思考，因为它不必拘泥于英语。也许它会改用另一种思维语言，或创造自己的语言。原则上，系统的行为没有那么多预设限制，它可以采用任何有效的方法，也可能逐渐偏离英语训练数据的分布。但所有这些都只有在我们拥有庞大、多样的问题集时才能实现，模型才能在其中不断改进和完善策略。

这就是当前很多前沿 LLM 研究关注的方向。研究人员试图创建规模大且多样的问题分布，把它们做成模型可以练习思考的各种游戏环境。这就像编写练习题，需要为所有知识领域创建练习题。只要有大量练习题，模型就能在上面进行强化学习，产生类似的能力曲线。不过这里讨论的是开放式思考，而不是围棋这种封闭领域。强化学习这一节里，我还想介绍一个部分：在不可验证领域中的学习。到目前为止，我们讨论的都是所谓可验证领域。任何候选解法都可以与一个具体答案轻松比较。比如答案是 3，我们很容易检查这些解法是否得到 3。

我们可以要求模型把答案框起来，再检查框内内容是否与标准答案一致。或者使用所谓的 LLM 裁判，让另一个 LLM 查看解法和答案，并判断两者是否一致。根据当前模型能力的实测结果，LLM 已经足够擅长可靠地完成这类判断，因此也能使用这些方法。无论如何，我们有具体答案，可以自动检查解法，不需要人工参与。问题在于，这种策略无法应用于所谓不可验证领域。比如创意写作任务：写一个关于鹈鹕的笑话、写一首诗、总结一段文字。在这些领域里，很难给不同解法评分。

例如，我们可以生成很多关于鹈鹕的笑话，这当然没问题。我们可以打开 ChatGPT，让它写一个笑话。它说：“鹈鹕为什么把那么多东西装进嘴里？因为它们的背包里装不下。”什么？再试一个：“鹈鹕为什么从不付饮料钱？因为它们总把账单推给别人。”哈哈。这些模型显然不太擅长幽默。我觉得这很有意思，因为幽默其实非常难。不过模型也许有能力做到。总之，我们可以想象生成很多笑话，问题是如何评分。原则上，我们当然可以让人类来评价所有笑话，就像我刚才做的那样。但如果要进行强化学习，我们会做数千次更新。每次更新要看数千个提示，每个提示可能要看数百或数千种不同生成。

数量实在太多了。原则上，可以让人类逐个检查、评分，判断哪个笑话好笑，再用它们训练模型，让模型至少更擅长写关于鹈鹕的笑话。但这会耗费太多人工时间，无法扩展。我们需要自动化方法。一个解决思路出现在提出“基于人类反馈的强化学习”（RLHF）的论文中。这是一篇当时由 OpenAI 发表的论文，其中许多人后来成了 Anthropic 的联合创始人。这篇论文提出了一种在不可验证领域进行强化学习的方法。我们来看看具体做法。下面是核心思想的卡通图。如前所述，如果人类时间无限，我们可以直接在这些领域运行 RL。

比如可以像平常那样运行 RL。图里的数字只是示意：假设做 1,000 次更新，每次更新用 1,000 个提示，每个提示生成 1,000 个候选结果并评分。这样的 RL 可以运行。但过程中需要人类总共评估 10 亿次笑话。这意味着要有很多人看非常糟糕的笑话，所以行不通。我们要采用 RLHF。核心诀窍是“间接”。只让人类少量参与。我们训练另一个独立的神经网络，称为奖励模型，让它模仿人类打分。

我们让人类给候选结果打分，再用神经网络模仿这些评分。这个神经网络就会成为人类偏好的模拟器。有了这个模拟器，就可以用它进行强化学习。比如，不再让真实人类评价笑话，而是询问模拟出来的人类评分。得到模拟器后，我们可以随意调用它，因为查询次数不受限，而且整个过程自动化。然后就可以对这个模拟器进行强化学习。它不会是完美的人类，但只要在统计上与人类判断相似，就可能奏效。实践中确实有效。我来用卡通图简单说明流程。具体细节并不特别重要，核心思想是这样。

这里是一个假设的奖励模型训练示例。提示是“写一个关于鹈鹕的笑话”，然后有五个候选结果，也就是五个不同笑话。首先，我们让人类把这些笑话从最好排到最差。这个人认为第二个笑话最好笑，所以排第一；接下来是第二名、第三名、第四名、第五名。第五个最差。我们要求人类排序而不是直接打分，因为排序更容易。人类更容易比较高低，而不是给出精确分值。这就是监督信号。人类完成排序后，接下来单独询问奖励模型对这些笑话的评分。

奖励模型是一个完全独立的神经网络，很可能也是 Transformer，但它不是生成多样语言的语言模型，而是评分模型。奖励模型的输入有两个：提示，以及一个候选笑话。比如，它会接收提示和这个笑话。输出是一个数字，可以看成分数，范围可能是 0 到 1，0 最差，1 最好。这里是训练过程中某个阶段，假设的奖励模型给这些笑话打出的分数。0.1 很低，0.8 很高，等等。现在我们要比较奖励模型给出的分数与人类排序。

有精确的数学方法可以计算两者的对应程度，设置损失函数并据此更新模型。但我只想说明直觉。比如第二个笑话，人类认为它最好笑，模型也大致认同，因为 0.8 是相对高分，但分数还应该更高。更新网络后，分数可能会涨到 0.81。这里人类和模型意见严重不一致：人类认为它排第二，但模型只给了 0.1。因此这个分数需要提高，更新后可能涨到 0.15 左右。人类认为最后一个笑话最差，但模型给它的分数相当高。更新后，这个分数可能会降到 0.35 左右。

基本上，我们还是像之前一样，通过神经网络训练稍微调整模型预测，让奖励模型的分数与人类排序一致。用人类数据更新奖励模型后，它会越来越擅长模拟人类提供的评分和排序，进而成为人类偏好的模拟器，供我们进行强化学习。关键是，我们不需要让人类看十亿次笑话。我们可能只让他们看一千个提示、每个提示五个候选结果，总共五千个笑话。人类只需排序，然后我们训练模型与排序一致。我略过了数学细节，只希望大家理解大致思想：奖励模型提供分数，我们有办法训练它，使其符合人类排序。这就是 RLHF 的工作方式。

大致来说，我们训练人类偏好的模拟器，再针对模拟器进行强化学习。先谈 RLHF 的好处。第一，它让我们能在各种领域运行强化学习，而强化学习是一套极其强大的技术，包括不可验证领域，比如摘要、写诗、写笑话，以及数学和代码以外的创意写作任务。实际使用 RLHF 时，我们发现它能提升模型表现。我有一个对其原因的猜测，但我不确定是否已有充分确立的解释。通过实测可以观察到，正确使用 RLHF 会让模型变得好一些。至于为什么，我觉得还没有特别清楚。

我最好的猜测是，这主要可能来自“判别与生成的差距”。很多情况下，人类判断好坏比自己生成内容容易得多。例如监督微调 SFT 要求人类写出理想的助手回答。我刚才展示的例子里，理想答案很容易写，但很多任务并非如此。比如写摘要、诗歌或笑话，人工标注员怎么写出理想答案？这需要人类进行创造性写作。RLHF 绕过了这个难点，因为我们可以给人类一个容易得多的问题。标注员不需要直接写诗，只需从模型生成的五首诗里排序。因此这对人工标注员来说容易得多。

我认为，这样可以得到准确度更高的数据，因为我们不要求人类完成特别难的生成任务，例如创意写作。我们只要求他们区分不同作品，挑出最好的。人类提供的信号只是排序，然后系统通过 RLHF 找到那些会被人类评为较好的回复。因此这种间接方式让模型变得更好一些。这就是 RLHF 的好处：它让我们可以运行 RL；实测中能提升模型表现；也让人们能够提供监督信号，而不必完成写理想回复这类很难的任务。遗憾的是，RLHF 也有明显缺点。主要问题是，我们进行强化学习时，并非依据真实人类判断，而是依据人类的有损模拟。

这个有损模拟可能会误导我们，因为它毕竟只是一个模拟，只是一个输出分数的语言模型，无法在所有可能情境下完美反映真实人类的意见。还有一个更微妙、更棘手的问题，大幅限制了 RLHF 扩展到更聪明系统的能力：强化学习极其擅长找到办法来利用奖励模型的漏洞。我们构建的奖励模型是一个巨大的 Transformer，有数十亿参数，模仿人类并输出分数。但问题是，它是一个复杂的大系统，有数十亿参数，最后只输出一个分数。事实证明，可以找到方法“欺骗”这些模型，找到训练集中没有出现过、却能得到极高分的输入。

如果 RLHF 运行很久，比如做 1,000 次更新，你可能会以为关于鹈鹕的笑话会越来越好，甚至会出现真正绝妙的笑话，但实际并非如此。前几百步里，笑话可能确实有所改善，然后就会急转直下，出现极其荒谬的结果。比如关于鹈鹕的最佳笑话可能变成“The the the”。这毫无道理，对吧？但你把“The the the”输入奖励模型，它本来应该得零分，结果奖励模型非常喜欢它，会给它 1 分。这完全说不通，因为这些模型只是人类的模拟器，是庞大的神经网络。你能在输入空间的边角找到一些奇怪输入，让它们得到荒谬的高分。这些例子叫作对抗样本。我不打算详细介绍这个话题。对抗输入是一些特殊输入，钻进模型内部的缝隙里，从而在输出端得到荒谬结果。

你可能会想：显然“The the the”不该得 1 分，那我们把它加入数据集，给它极低的排序或分数，比如排第五。这样模型确实会学会给“The the the”很低分，甚至给零分。问题是，奖励模型里总会藏着无穷多荒谬的对抗样本。如果你反复迭代，把各种荒谬内容加入奖励模型并给低分，永远无法赢过它。你可以进行很多轮，但强化学习只要运行得够久，就总会找到办法利用模型，发现对抗样本，用荒谬结果得到高分。从根本上说，这是因为评分函数是一个巨大的神经网络，而 RL 极其擅长找到欺骗它的方法。

简而言之，RLHF 通常只能运行几百步。模型会先变好，然后你得截断训练并结束。不能对这个奖励模型训练太久，否则优化就会开始利用漏洞。你只能停下来发布模型。虽然可以改进奖励模型，但最终还是会遇到这类情况。所以我常说，RLHF 不是 RL。我的意思是，当然它确实是强化学习，但不是那种具有神奇效果的 RL。你不能无限期运行它。这和有标准答案的问题不同，后者不容易被钻空子。你要么得到正确答案，要么没有，评分函数也简单得多，只需检查答案框里的结果是否正确，因此很难利用评分函数。但奖励模型可能被钻空子。

在可验证领域里，你可以无限期进行强化学习，训练数万、数十万步，让模型发现各种我们可能想都想不到的策略，从而更好地解决问题。围棋里也没有办法钻空子，利用输赢判定。我们有一个完美模拟器，知道棋盘上每颗棋子的位置，可以判断谁赢谁输，因此无法欺骗它，可以无限期进行 RL，最终甚至超过李世石。但对于这种可被利用的奖励模型，不能无限重复这个过程。所以我认为 RLHF 不是真正意义上的 RL，因为奖励函数可以被钻空子。它更像一种小幅微调，只能略微改进模型，无法像真正设置良好的 RL 那样投入更多计算、延长训练，就获得更强、更神奇的结果。它不是那种意义上的 RL，也没有那种神奇力量。它可以找到模型中的一些问题并提升表现。回到 ChatGPT，GPT-4o 经过了 RLHF，因为这种方法有效，但它不是同一种强化学习。可以把 RLHF 看作一种小幅微调，让模型稍微变好。

这就是我想讲的大部分技术内容。我介绍了训练模型的三个主要阶段和范式：预训练、监督微调和强化学习，也说明了它们大致对应人类教育孩子的过程。预训练相当于通过阅读讲解获得基础知识；监督微调相当于阅读大量完整示例、模仿专家；强化学习相当于做练习题。唯一不同的是，我们要为 LLM 和 AI 编写涵盖人类知识各个学科的“教科书”，也要覆盖它们需要处理的代码、数学以及其他领域。我们正在为它们编写教科书，改进刚才高层次介绍的算法，并有效、大规模地训练这些模型。我没讲太多细节，但这些都是极其庞大、复杂、分布式的训练任务，需要数万甚至数十万张 GPU。

这类规模下的工程技术处于计算机能力的前沿。我没有详细讲这一面，但它非常严肃。所有这些复杂工程都支撑着看似简单的算法。最后我也谈了一些模型的心智理论。希望大家记住，这些模型非常强大，但最适合当作工作工具。不要完全信任它们，我已经展示了一些例子。即使有缓解幻觉的方法，模型也不完美，仍会产生幻觉。随着时间推移情况有所改善，也会继续改善，但幻觉依然会发生。此外，我还介绍了我所谓的 LLM 能力“瑞士奶酪模型”：模型在许多学科都极其出色，却会在某些独特情形下随机失败。

比如，9.11 和 9.9 哪个更大？模型可能不知道，但转头就能解奥林匹克题目。这就是瑞士奶酪上的一个洞，而且有很多洞，你不想撞上它们。不要把模型当成不会出错的权威。检查它的工作，把它当作工具和灵感来源，用来起草初稿，但要由你对最终成果负责。这大致就是我想说的内容：模型如何训练，以及它们是什么。接下来谈谈这些模型未来可能具备什么能力，以及接下来可能出现什么，还有到哪里可以找到这些模型。我对未来可能出现的事情有几点看法。首先，你会发现模型很快会变成多模态。前面讲的所有内容都围绕文本。

但很快，LLM 将不仅能处理文本，还能原生处理音频和图像：听和说，也能看和绘图。我们已经看到这些能力的开端，但未来这些功能都会在语言模型内部原生实现，从而支持自然对话。粗略来说，这与前面讲的内容没有本质区别，因为我们可以把音频和图像分词，再用相同方法处理。并不是根本性变化，只是要增加一些 token。例如，音频分词可以查看音频信号的频谱图切片，再将它们转成 token，加入表示音频的新 token，然后放进上下文窗口训练。图像也一样，可以切成图像块，分别进行分词。这样图像就是一串 token。这种方法已经初步奏效，也有许多早期研究。我们可以创建表示音频、图像和文本的 token 流，把它们交错排列，在同一个模型里同时处理。这就是多模态的一个例子。

第二，人们非常关注的一点是：目前大多数工作都是把一个个独立任务直接交给模型，比如“请替我完成这个任务”。模型完成这个小任务后，仍然由我们负责组织任务，形成连贯的工作流程。模型还不具备在较长时间内连贯执行任务并纠正错误的能力，无法把多个任务串联起来，完成持续时间较长的工作。不过它们正在进步。未来可能会出现所谓的 agent（智能体），可以持续执行任务。你监督它、观察它的工作，它会时不时向你汇报进度。我们会看到更多长时间运行的智能体任务，不再只是几秒钟的回答，而是持续几十秒、几分钟，甚至几小时。但正如前面谈过的，模型不会永远正确，整个过程都需要监督。工厂自动化领域有人会讨论“人机比例”，我认为数字领域也会出现类似概念，讨论人和智能体的比例。人类会更多地监督数字领域里的智能体任务。

接下来，我认为 AI 会变得更加普遍、更加隐形，融入各种工具中。此外还有计算机操作能力。目前模型还不能替你采取行动，但这是另一个独立的发展方向。如果你看到 ChatGPT 推出的 Operator，它就是早期例子之一。你可以把控制权交给模型，让它代你操作键盘和鼠标。这也很有意思。最后一点是，这个领域仍有大量研究空间。例如测试时训练（test-time training）。记住，前面讲的训练过程有两个主要阶段：先训练并调整模型参数，让它完成任务；得到参数后，就把参数固定，然后部署模型进行推理。从那以后，模型参数不再变化，也不会从测试时做的事情中学习。它的参数数量固定。

唯一变化的是上下文窗口里的 token。因此模型能在测试时学习的方式，只有上下文学习，也就是动态调整上下文窗口。可是我觉得这与人类不同。人类确实会根据正在做的事情学习，尤其睡眠时，大脑会更新参数之类的，对吧？目前这些模型和工具没有类似机制。我觉得还有许多更不寻常的想法值得探索。尤其是，上下文窗口是有限且宝贵的资源。一旦我们开始处理很长时间的多模态任务，把视频放进上下文，token 窗口就会变得非常庞大，不只是几千或几十万个，可能远超这个规模。

现在唯一的办法就是让上下文窗口变得更长，但我认为仅靠这种方法无法扩展到真正长期运行的多模态任务。对于那些需要非常长上下文的任务，我们需要在一些领域提出新想法。以上是未来可能出现的一些发展。现在谈谈到哪里关注这些进展，如何跟上领域最新动态。我长期以来主要使用三种资源。第一是 LM Arena。来看一下 LM Arena。这基本是一个 LLM 排行榜，模型排名根据人类比较结果得出。人类向模型提问并评判哪个回答更好，而且不知道哪个回答来自哪个模型，只看哪个更好，然后计算排名。这里可以看到 Google Gemini 等不同机构发布的模型。点击某个模型，会跳转到提供该模型的网站。现在 Google 排在前面，OpenAI 紧随其后，DeepSeek 排第三。

这件事有意思的地方在最后一列：DeepSeek 使用 MIT 许可证，属于开放权重模型。任何人都可以使用这些权重、下载它们、托管自己的 DeepSeek 版本，并以自己喜欢的方式使用。所以它不是你无法接触的专有模型，而是开放权重发布。如此强大的模型采用开放权重发布，前所未有，团队做得很棒。后面还有 Google 和 OpenAI 的模型。再往下看，会看到一些熟悉的公司：xAI、Anthropic 的 Sonnet 排第 14，还有 Meta 的 Llama。Llama 和 DeepSeek 一样是开放权重模型，但排名在下面，不在上面。

我得说，这个排行榜很长一段时间都很有用。但过去几个月里，我觉得它有点被操纵，不像以前那么可信。根据我的实际使用，很多人在用 Anthropic 的 Sonnet，我觉得它是个很好的模型，但它排在第 14。反过来，我觉得使用 Gemini 的人没那么多，但它的排名却很高。因此把这个榜单当作初步参考，再针对自己的任务试试几个模型，看看哪个表现更好。第二个资源是 AI News Newsletter。AI News 这个名字不太有创意，但这是 swyx 和朋友们制作的一份很好的新闻简报。感谢他们维护这份简报。它对我很有帮助，因为内容非常全面。点开存档，会发现它几乎隔天发布一次，内容也很全面。有些内容由人工撰写和整理，很多则由 LLM 自动生成。因此你大概不会漏掉什么重要内容。当然，你可能不会逐篇读完，因为实在太长了。但我觉得顶部的摘要做得不错，而且应该有人审核过。它对我很有帮助。最后一个资源是 X，也就是 Twitter。很多 AI 领域的讨论都在 X 上。关注你喜欢、信任的人，就能在 X 上获取最新消息。

这些是我长期以来觉得有用的主要渠道。最后简单说说在哪里找到和使用模型。首先，最强的专有模型通常要去模型提供商的网站。比如 OpenAI 的 ChatGPT。Gemini 的话，我想是 gem.google.com 或 AI Studio。Google 不知为何有两个，我不太明白，我想没人明白。对于 DeepSeek、Llama 这类开放权重模型，你需要找 LLM 推理服务商。我最喜欢 Together.ai。前面给你看过，在 Together.ai 的 Playground 里可以选择许多不同模型，这些都是不同类型的开放模型，也可以直接和它们对话。

如果你想用基础模型，比如前面提到的基础模型，推理服务商通常不太常见，因为它们都面向助手和聊天模型。我觉得这里也找不到基础模型。基础模型的话，我一般去 Hyperbolic，因为他们提供 Llama 3.1 基础模型。我很喜欢这个模型，可以直接在那和它对话。据我所知，这是体验基础模型的好地方。我希望有更多人托管基础模型，因为有些情况下它们很有用，也很有意思。最后，有些较小的模型可以下载到本地运行。例如，你无法在 MacBook 上本地运行最大的 DeepSeek 模型，但有较小版本的 DeepSeek 模型，叫作蒸馏模型。你还可以用较低精度运行它们，而不是 DeepSeek 的原生 FP8 或 Llama 的 BF16 精度，而是更低精度。细节不懂也没关系，你可以运行蒸馏后的小模型，再进一步降低精度，就能放进自己的电脑里，因此在笔记本上也能运行表现不错的模型。

我最常用的平台可能是 LM Studio，它是一个可以安装的应用。我觉得它界面很难看，不喜欢。它展示的很多模型也没什么用，大家其实都想跑 DeepSeek，我不知道为什么要给你看五百种不同模型。搜索起来非常复杂，还得选择不同蒸馏版本和精度，容易让人困惑。不过理解它的使用方法是另一支视频的内容。弄懂后，你就可以载入模型。例如这里我载入了 Llama 3.2 Instruct 1B，然后可以直接和它对话。我让它讲鹈鹕笑话，又让它再讲一个，它就给了另一个。这里发生的一切都在本地计算机上运行。

数据不会发送给其他地方。这是 MacBook Pro 的 GPU 在运行。很好。用完后可以卸载模型，释放内存。LM Studio 大概是我最喜欢的工具，虽然我觉得它在 UI/UX 上有不少问题，而且几乎是为专业人士设计的。不过你可以看一些 YouTube 视频，学会使用这个界面。这就是一些寻找模型的方式。现在回到最初的问题：我们打开 ChatGPT，输入问题并按下发送，到底发生了什么？我们看到了什么？我们在和什么对话？它如何运作？希望这个视频让你了解了模型训练的一些底层细节，以及返回的内容是什么。

具体来说，我们现在知道，输入的问题会先被切分成 token。打开 Tiktokenizer，看看用户问题会插入对话协议的什么位置。它会被放进我们之前讨论的对话协议格式中，也就是维护对话对象的方式。然后整个内容就变成一维 token 序列。ChatGPT 接收到这个 token 序列。我们按下发送后，它会继续把 token 添加到序列里，也就是续写序列，像 token 自动补全器一样。它给出了这样的回答。我们可以把回答放进这里，看到它续写的 token 大致是什么。接下来问题是：模型为什么会返回这些 token？这些 token 是什么？从哪里来的？我们究竟在和什么对话？如何设定这个系统？

于是我们转向讨论其底层组成。这个过程的第一阶段有三个阶段，叫作预训练，基本上是把互联网上的知识吸收到神经网络参数中。神经网络从互联网内化大量知识。但模型的个性主要来自监督微调阶段。OpenAI 这样的公司会整理一个大型对话数据集，比如涵盖不同主题的 100 万段对话。对话发生在人类和助手之间。虽然整个流程中使用了大量合成数据生成、LLM 辅助等方法，但从根本上说，这仍然是人类整理数据的工作，有许多人参与。具体来说，这些人是 OpenAI 聘用的数据标注员，他们会学习标注说明，任务是针对任意提示写出理想的助手回复。

他们通过示例教神经网络如何回应提示。那么我们收到的回答该如何理解？我认为，正确的理解方式是：它是对 OpenAI 数据标注员的神经网络模拟。就好像我把这个问题交给 OpenAI 的数据标注员，他们先阅读所有标注说明，再花两个小时写出理想的助手回答给我。实际上我们并没有这么做，因为没有等两个小时。我们得到的是对这个过程的神经网络模拟。要记住，神经网络并不像人类大脑，它们有所不同。对人类容易或困难的事情，对模型可能恰好相反。我们得到的确实只是模拟。这里展示的是 token 流，中间有许多激活值和神经元。这是一个固定的数学表达式，把 token 输入与模型参数混合，产生序列中的下一个 token。但每个 token 能进行的计算量有限。因此这只是人类行为的一种有损模拟，并受到这种限制。无论人类写了什么，语言模型都只是在 token 层面模仿，而且每个 token 的计算量有限。

我们还看到，认知差异会造成各种问题，使用时需要小心。比如模型会产生幻觉。我们也有一个“瑞士奶酪式”的 LLM 能力模型：奶酪上有许多洞。模型有时会莫名其妙做出很愚蠢的事。它们能完成许多神奇任务，但有时就是做不到。也许是你给它的 token 不够，让它来不及思考；也许它会编造内容，因为心算出错；也许它数不清字母；也许它分不清 9.11 小于 9.9，显得很蠢。这就是瑞士奶酪式能力。我们要小心使用，也了解了这些问题的原因。但归根结底，我们可以把返回的内容看成神经网络对遵循 OpenAI 标注说明的数据标注员的模拟。

但我认为使用思考模型，比如 o3-mini 时，情况会有些不同。原因是 GPT-4o 基本上没有进行强化学习。它确实进行 RLHF，但我说过 RLHF 不等于真正的 RL，没有多少神奇之处，只是小幅微调。但思考模型使用了 RL。它们经历了第三阶段，完善思考过程，发现新的思考策略和解题方法。这些方法有点像你脑海中的内心独白。模型会在公司创建和整理的大量练习题上练习，然后这些题目提供给 LLM。现在我用思考模型处理这个问题时，看到的不再只是对数据标注员直接的模拟，而是某种新颖、有趣的东西。当然，OpenAI 不会展示推理背后的完整思维链，但我们知道它存在，这里展示的是摘要。我们看到的不只是模仿人工标注员，而是从强化学习过程中涌现出来的思考功能。

当然，这里没有给模型展现能力的机会，因为这不是数学或推理问题，而是某种创意写作问题。思考模型在可验证领域里形成的策略，能否迁移并泛化到创意写作等不可验证领域？这是个开放问题。我认为业内还不知道这种迁移能在多大程度上发生。所以我们不确定，在所有可验证问题上进行 RL，是否能让模型在这种不可验证的提示上也受益。这仍是一个开放问题。另一个有意思的地方是，这种强化学习仍然非常新，处于萌芽阶段。我们才刚看到推理问题上的一点潜力。原则上，这种方法有能力产生相当于 AlphaGo 第 37 手的成果，只不过不是围棋，而是开放领域的思考和问题求解。原则上，这种范式可能带来新颖、令人兴奋的成果，甚至是人类从未想到过的东西。

原则上，模型可能发现人类从未有过的类比。所以我觉得这些模型的出现非常令人兴奋。但这还只是早期阶段，目前还是萌芽中的模型。它们主要会在数学和代码等可验证领域表现出色。非常值得体验、思考和使用。大致就是这样。这些是目前可用能力的大致情况。总体而言，我认为现在是身处这个领域的激动人心的时刻。我每天都会用这些模型几十次甚至上百次，因为它们大大加快了我的工作。我想很多人也有同样感受。我认为这些模型会创造大量财富。与此同时，也要留意它们的不足。即使使用 RL 模型，它们仍会有这些问题。把它们当作工具箱里的工具，不要完全信任。

它们会随机做出愚蠢的事，会随机产生幻觉，会跳过心算步骤而算错，会突然数不清东西。所以把它们当工具，检查结果，对自己的工作成果负责。但可以用它们获取灵感、起草初稿、回答问题。始终检查和核实，你就能在工作中做得很好。希望这个视频对你有用，也让你觉得有意思。视频已经很长了，抱歉。不过希望内容确实有帮助。再见。
