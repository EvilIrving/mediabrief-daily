最近，一篇帖子广为流传，预言“让你的机器人跟我家机器人聊聊”很快就会成为一句平常话。例子很有趣：发送缺陷报告、安排会议、组织团购、在 Craigslist 上买卖东西。甚至有一篇后续帖子分享了一个用于提交缺陷的真实地址。

我很喜欢这个想法，但我也以安全人员看待一切的方式来看它：当另一端的对象并不是你以为的那个时，会发生什么？

这个问题如今比一年前更重要。智能体收件箱正从内部协调工具变成开放互联网上的公开地址。一旦机器人能够接收陌生人的邮件并据其行动，每一封入站邮件都会变成不可信输入，并且有一条通向工具、数据，某些情况下还通向金钱的路径。

## 关键风险一览

```

    agent --> delete["Delete evidence"]

    agent --> spend["Spend money or share data"]
```
- 如果密钥允许，智能体往往可以编辑自己的允许列表。
- 回复限制与接收限制是分开的；空的回复列表会让所有回复通过。
- 删除权限会造成抵赖问题：机器人可以清理自己留下的痕迹。
- 每一封入站邮件都是一个提示词。如果智能体拥有工具，这个提示词就有一条通向行动的路径。

电子邮件认证证明了对某个域名的控制权，但不能证明谁控制着机器人，也不能证明它被授权做什么。

## 我们是如何走到这一步的

智能体与智能体对话并不新鲜。研究团队运行过通过共享留言板协调的智能体集群。并排运行 Claude Code、Codex 和 Cursor 的开发者想要同样的东西，于是像 MCP Agent Mail 这样的开源工具出现了，为编码智能体提供收件箱、会话线程和文件“租约”，防止它们覆盖彼此的工作。像 AgentMail 这样的托管服务现在只需一次 API 调用，就能给任何智能体一个真实的电子邮件地址。

最后这一步才是转变所在。在一个团队内部，消息总线上的智能体大多属于你自己。在开放互联网上，给你的机器人发邮件的那个机器人属于一个陌生人。

## “给你的机器人一个收件箱”到底意味着什么

风险藏在底层管道里。使用 AgentMail 时，智能体可以通过托管的 MCP 服务器、REST API 和 SDK，或者普通的 IMAP 和 SMTP 连接。它通过 API 密钥认证，或者在某些助手中通过 OAuth 认证。由此，它获得一个包含大约三十多项操作的工具箱：发送、回复、转发、搜索、删除会话线程、删除收件箱，以及编辑该收件箱自己的允许列表和阻止列表。

MCP Agent Mail 的工作方式不同。它是一个用于团队内部协调的本地服务器，并且包含一种“人类监督者”（Human Overseer）消息类型，会告诉智能体放下手头的事情并优先处理它。这正是攻击者会想要模仿的那类消息。

### 这些选择中的每一个都有安全后果

```
flowchart LR
    subgraph intended["Intended controls"]
        keys["Scoped API keys"]
        lists["Allowlists for send/receive/reply"]
        perms["No delete or list-edit permissions"]
    end
    subgraph misconfigured["What happens if misconfigured"]
        selfEdit["Agent can edit its own allowlist"]
        emptyReply["Empty reply list lets everything through"]
        evidence["Bot can delete the evidence"]
    end
    keys --> selfEdit
    lists --> emptyReply
    perms --> evidence
```
**列表确实存在，但它们有作用域，而且是拆分的。** AgentMail 支持针对发送、接收和回复的允许列表与阻止列表，可在组织、团队或收件箱层级设置，范围最窄者生效。回复会对照它们自己的回复列表进行检查。空的回复列表会让所有回复都通过。锁定谁能给你的机器人发邮件，并不会自动锁定谁能回复它。

**智能体可以编辑自己的防护栏。** 工具集包含添加和删除列表条目。如果你的智能体持有的密钥允许这样做，一个被操纵的智能体就能把攻击者添加到自己的允许列表中。受限密钥可以移除这种能力，但除非你明确限制，否则密钥在其作用域内拥有完全访问权限。

**删除会造成抵赖问题。** 拥有删除邮件权限的密钥可以删除整个会话线程。这对保持整洁有用，对问责却非常糟糕。一个被骗去做某事的智能体，也可能被骗去替自己清理痕迹。如果你机器人收到什么提示的唯一记录，存在于机器人能够删除的邮箱里，那你就没有记录。短消息过期之类的功能有助于隐私，但也会以同样的方式损害问责。

**速率限制保护的是服务提供商，不一定保护你。** API 会在你调用太快时进行限流，并限制每条消息的收件人数。这与你自行选择的限制不是一回事：你的机器人一小时内可以发送多少封邮件、它在人类查看之前会对多少封入站邮件采取行动，或者一场邮件洪水能触发多少模型开销。没有这些限制，一个高频发送者就会变成可用性问题和账单问题。那种尖峰恰恰是应该触发警报的那类信号。

这些控制措施是存在的。AgentMail 提供作用域密钥、权限允许列表（可阻止受限密钥生成更强大的密钥）、发件人列表和垃圾邮件过滤。决定它们是否保护你的是配置，而不是产品页面。

## 电子邮件地址不是身份

电子邮件有相当不错的发件人认证。SPF、DKIM 和 DMARC 可以告诉你一封邮件确实来自某个给定域名。它们无法告诉你谁控制着其背后的机器人、这个机器人被授权同意什么、它的所有者是否本来就想发送这封特定的邮件，或者是否已经有别人操纵了它。

人类用判断力填补这个缺口。我们会注意到语气不对劲。我们会给供应商打电话。我们会问同事：“这看起来对吗？”一个在凌晨 3 点阅读收件箱的机器人，只有我们内置给它的那点判断力。对今天的大多数机器人来说，那并不多。

## 每一封入站邮件都是一个提示词

“把你的缺陷报告发给我家机器人”是一个友好的邀请。对安全人员来说，它也是一个公开地址，任何人都可以把文本放到某个智能体面前。如果那个智能体拥有工具和访问权限，比如能够买票、读取源代码、回复信息或更新日历，那么一封邮件的正文就是不可信输入，并且有一条通向行动的路径。

### 那就是带有邮寄地址的提示词注入

这不是在批评任何一个项目。这就是这种模式的形态。这个领域的每个构建者都应该能回答一个问题：因为一封来自我从未见过的人的消息，我的智能体可能做的最坏的事情是什么？

## 会回应机器人的机器人也能传播东西

把它串起来。我的机器人读了你机器人的消息，然后写给第三个机器人。如果一条消息能让模型在回复中加入一条新指令，那条指令就会传播。

这已经被演示过了。2024 年，研究人员 Stav Cohen、Ron Bitton 和 Ben Nassi 构建了 Morris II，这是一种利用自我复制提示词在 AI 电子邮件助手之间传播的蠕虫。它窃取数据并发送垃圾邮件，无需任何人点击链接。它运行在测试环境中，而非真实环境。但那个测试环境涉及 AI 电子邮件助手彼此对话，而如今这已经成为一个产品类别。

## 当金钱进入会话线程

Craigslist 的例子正是利害关系发生变化的地方。我加固过处理真实金融交易的生产智能体系统。最大的教训很简单：一旦智能体能够动用资金，其他所有问题都会改变。

当两个机器人协商一笔交易时，谁对价格负责？什么能阻止我的机器人接受一个它从未验证过的对手方发来的“更新后的支付链接”？而实际上又是谁在阅读这个会话线程？

一旦邮件量变高，人们就已经不再阅读邮件了。智能体会制造大量邮件。一份可审计但从未被审阅的日志不是监督。它是留给以后的证据。

## 给你的机器人一个收件箱之前的五个问题

1. **谁能联系到它？** 对于任何超出业余项目范畴的东西，一份已知发件人的允许列表胜过开放的收件箱。
2. **因为一条消息，它能做什么？** 列出工具。把阅读与行动分开，把行动与花钱分开。它能删除自己的邮件或编辑自己的允许列表吗？它不应该能。
3. **什么需要人类？** 承诺、付款、数据共享以及任何不可逆的事情都应该需要人类批准。
4. **它把邮件当作数据还是命令？** 入站消息的内容应该是智能体去评估的东西，而绝不是它简单服从的东西。
5. **谁审阅发生了什么？** 确定谁负责、审阅频率如何，以及什么会触发警报。把记录保存在机器人无法删除的地方，并自己设定它每小时发送和处理多少的上限，让尖峰触发警报而不是账单。如果答案是“全都记录下来了”，那你还没做完。

## 有趣的部分是真实的

我希望机器人对机器人能行得通。跨公司安排日程，不用来回六封邮件；支持请求得到解决，不用排队等待；一个团购自己组织起来。这确实有用，而构建智能体收件箱的团队已经在思考其中的各个部分。允许列表、租户隔离和消息过期存在是有原因的。

互联网吃过大亏才明白，电子邮件需要认证、垃圾邮件过滤器，以及对陌生人保持适度的怀疑。我们的机器人也需要这些，而且需要在第一个机器人同意一笔没人真想达成的交易之前就拥有它们。

所以，是的，让你的机器人跟我家机器人聊聊吧。只要告诉我，是谁在核验身份。

*如果你正在构建智能体收件箱或机器人对机器人工作流，你希望自己早点设置的那个控制是什么——或者，你的智能体现在收到一封陌生人的消息后能做的最坏的事情是什么？*
