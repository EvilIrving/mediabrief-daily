712: Lazy Loading the Web with Scott Jehl ｜ ShopTalk Show ｜ 65分钟 ｜ https://shoptalkshow.com/712/

这一期 ShopTalk Show 只有 Chris Coyier 主持，Dave Rupert 缺席。嘉宾是响应式设计和 Web 性能领域的老将 Scott Jehl，他现在在 Squarespace，刚刚把 video 和 audio 的原生懒加载推成了 HTML 标准。整期从这个特性本身聊起，讲到响应式视频的来龙去脉，再到普通 Web 开发者怎样参与标准制定。

懒加载的意思是把资源的获取推迟到它真正和视口相交的时候，轮播里没翻到的那一页也算。图片和 iframe 早就支持 loading="lazy"，视频以前只能靠脚本在滚入视口时再把 video 元素或 src 写进去，既麻烦又会弄坏 RSS。现在静态 HTML 里放上千个视频，也只会在可见时才去下载。各浏览器提前加载的距离不同：Firefox 大约 800 到 1200 像素，更看重省带宽；Chrome 提前得更多，更看重滚到时已经显示好。图片、iframe、视频用的是同一套距离。在此之前，video 只有 preload 属性可以控制：auto 让浏览器自己决定，通常会下很多；metadata 只取够画封面帧的数据；none 完全不加载，要配合 IntersectionObserver 才能模拟懒加载。新的 loading="lazy" 还会推迟自动播放，这对用 video 取代 GIF 的场景很有用。用流媒体时，video 指向一份分片清单，懒加载同样有效。

接着是响应式视频的历史。当年响应式图片社区小组设计 picture 时，拿 video 的 source 加 media 属性当先例，结果这项能力恰好在那段时间从规范里被删了，理由大概是流媒体被视为更好的方案。Scott 认为流媒体常常确实更好，但只靠一份 HTML、不需要服务器配合就能按屏幕方向或尺寸换视频源，门槛低得多，值得保留。他也重申了两种机制的区别：media 是浏览器必须执行的规则，srcset 加 sizes 只是给浏览器的建议，网速慢时浏览器可以自己挑小图。后来 Mozilla 的 Simon Pieters 和 Apple 方面都表示支持，规范恢复了这一能力。Scott 从 Firefox 的 git 历史里把旧实现找了回来，WebKit 也恢复了，进展很快。

懒加载视频起源于 Squarespace 每半年一次的黑客周。Scott 一年前就在 HTML 标准的跟踪器里提了 issue，一直没人动。四人小组分头推进：Scott 写规范，有人写 Web Platform Tests，有人改 WebKit 和 Firefox 的构建，几条线互相校正。标准流程包括：三家浏览器厂商里至少两家表态支持（WebKit 和 Firefox 有专门征询立场的 GitHub 仓库），PR 模板里列着全部步骤，要补齐测试，还要在 WHATWG 每周例会上演示，逐级推进各个阶段。Scott 特别推荐把 Web Platform Tests 当作参与标准的第一步：只要懂原生 JavaScript 就能写，写测试的过程本身就能让人吃透一个特性，比如先验证 display:none 的懒加载视频没有发起请求，再改成可见，看它是否触发加载事件。测试可以先标成 tentative 合并，等标准落地再去掉。正因为测试是共享的，第三方开发者 Helmut Januschka 一两天内就在 Chromium 里写出了完全符合规范的实现，现在已经进入 Chrome 稳定版，但要用命令行参数开启。Firefox 和 WebKit 的补丁还在审核。Scott 也感谢了 Mozilla 的 Keith Cirkel 一路帮忙。两人还吐槽 HTML 规范是用一种自有的源格式写成，再生成标准 HTML，全文约 8 MB。

下一个提案针对 poster 属性：它只能指定一张图，不能响应式，也没有 alt 那样的可访问名称，更不支持 fetchpriority、decoding 这类图片早已有的控制。Scott 团队的设想是让 video 的直接子元素 img（可以放在 picture 里，带 srcset 和 sizes）充当封面，与 source、track 并列。如果它和 poster 属性同时存在，以 img 为准，旧浏览器则自然回退到 poster。封面默认继承 video 的懒加载设置，也可以单独覆盖，比如让封面优先加载。吸取上次规范 PR 被要求大量修改的教训，这次他们先在跟踪器里贴出设计思路征求意见，再动手写代码，因为标准一旦定下就很难再改，值得多花时间讨论。

中间还穿插了一些闲聊：Chris 刚加入 CSS 工作组，两人都推崇侧边标签页和分屏标签页；Chris 开玩笑说要请 MrBeast 来为响应式封面站台。节目最后，Scott 让听众到 scottjehl.com 关注他的博客。
