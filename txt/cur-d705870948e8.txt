TypeScript 7：十倍性能的升级之外，为什么选 Go？ ｜ AsyncTalk ｜ 13分钟 ｜ https://www.ximalaya.com/sound/1014896982

这是 AsyncTalk 主播的一期单人节目，先讲 TypeScript 7 的实际升级体验，再谈 TypeScript 团队为什么用 Go 而不是 Rust 重写编译器。他引用 VS Code 的类型检查从 78 秒降到 7.5 秒，又拿公司一个 58 万行的项目举例：tsc 检查从约 64 秒降到约 3 秒。只用 tsc 命令行的普通项目几乎可以无痛替换。对他来说更大的收益在编辑器里：原先 TypeScript 语言服务一天要崩溃好几次，升级后不再崩溃，类型提示也更快，代码库越大越明显。不过，依赖 TypeScript API 的工具（较早版本 Next.js 的 lint、Hey API 等）暂时还不支持，他建议这类项目等 7.1。

后半段是他的个人立场。他写了七八年 Go，也用 Rust 写过几万行，换作是他也会选 Go。理由是 Go 在性能和克制之间平衡得好：作为编译成机器码的静态语言，性能并不差；显式返回 error 比 try-catch 的"意外抛错"更利于维护大型系统；不提供三目运算符，泛型也引入得很谨慎，可读性优先，他甚至认为类型体操既不该是人的思维，也不该让 AI 去理解。Rust 性能极致，但生命周期、Pin 等概念太难。他承认用 AI 两周内拿 Rust 重写 TypeScript 是可能的，但从可读性和长期维护看，Go 更适合人类维护。最后他建议推崇 Rust 的人先亲手写一个万行级项目再下结论。
