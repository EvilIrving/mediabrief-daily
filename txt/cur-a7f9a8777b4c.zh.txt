前端开发的终结

过去几个月里，我和许多刚入行的开发者聊过，他们对 AI 越来越焦虑。他们看到了 GPT-4 等工具越来越令人印象深刻的演示，担心等到自己熟练掌握 HTML/CSS/JS 的时候，已经没有工作留给他们了。

这种情绪眼下在社交媒体上随处可见：

我完全不同意。我不认为前端开发者的工作会消失。而且我已经相当厌倦网上散播的恐惧、不确定和怀疑（FUD）了。

所以，在这篇博文里，我要分享我对将会发生什么的推测。事情确实会变，但不是人们所说的那种可怕的方式。

又来了

CSS 语言于 1996 年首次发布，随 Internet Explorer 3 一起问世。不到两年，第一个“无代码”网站构建工具 Homestead 就上线了。

Homestead 让人们不用写一行代码就能构建自定义网页：

几乎从一开始，人们就担心 Web 开发者会因为某种新技术而变得多余。2000 年代是 WordPress，2010 年代是 Webflow，2020 年代初是各种“无代码”工具。

而且在某种程度上，Web 开发者确实已经被淘汰了！如今，如果一家本地面包店、一位牙医或一位艺术家需要一个网站，他们大概不会雇一个开发者、花几万美元从零开始做。他们会上 Squarespace，挑一个喜欢的模板，每月花 20 美元。

然而，Web 开发者依然存在。

上周，OpenAI 举办了 GPT-4 的展示会。其中有一个相当惊人的演示：GPT-4 可以把一张手绘的网站草图变成一个功能齐全的网站，甚至包括一点用来连接“揭晓笑点”按钮的 JS。

这很了不起，我认为它在制作原型方面有很大潜力……但我们要说清楚：几十年来，我们早就不需要 Web 开发者来构建这类页面了。这个 HTML 文档和如今前端开发者所写的代码之间，有着巨大的差别。

展望未来

到目前为止，我看到的大多数演示范围都相当有限：一个简单的 HTML 页面，或者一个 JavaScript 函数。一个开发者一个下午就能做完的那种东西。

但现在还是早期！如果事情继续以同样的速度加速，几年之内它就能构建完整的应用了，对吧？

说到大语言模型（为 GPT-4 等工具提供动力的机器学习模型），我远远算不上专家，但我确实在宏观层面上理解它们是如何工作的。

从根本上说，LLM 是超级强大的文本预测器。给定一个提示，它们用机器学习尝试得出最有可能跟在提示后面的一串字符。

像 OpenAI 这样的公司花费大量时间和精力调整模型，以改进输出。一大批人工标注员给模型的输出“打分”，模型据此学习和进化。

如果你试过 ChatGPT 或必应的 AI 搜索之类的工具，你大概注意到它们的回答也许八成是正确的，但说出来时带着绝对的、不可动摇的自信。

LLM 无法验证自己的假设，也无法检验自己的猜想。它们无法确认自己说的是真是假。它们在玩一场概率游戏，估计这串字符似乎与提示中的那串字符相契合。

有时，回答的某些部分是毫无意义的。OpenAI 团队把这些称为“幻觉”。

随着技术进步，我们可以预期一些粗糙之处会被磨平，但从根本上说，总会存在一定程度的不准确。这些工具根本没有任何机制来客观地验证自己的回答。

所以，准确率会提高，但永远不会完美。而如果我们谈论的是让 Web 开发者被淘汰，这就是个问题。如果你不是程序员，你将无法分辨哪些部分是准确的，哪些不是。你将无法发现幻觉。

但等等，在 GPT-4 的演示中，我们看到了 AI 如何自我修复！把错误信息复制粘贴过去，它就会找到并修复问题。

不过，嗯，并不是所有的幻觉都会导致明确的错误。例如，我最近用 GPT-4 生成了一个基于 React 的 <Modal> 组件，虽然输出确实出奇地好，但它仍然犯了几个无障碍方面的错误。构建应用的人可能不会注意到这些问题，但终端用户一定会注意到！

无障碍只是一个例子。代码中的安全漏洞呢？当事情出了严重差错时，谁来承担责任？

还有一点：生成一个 50 行的 HTML 文档，和吐出一个可以上线生产的 Web 应用，两者之间有着巨大的差别。像这个博客这样一个小型 JS 应用，就有大约 6.5 万行代码，分布在 900 多个文件里。这还不包括文字内容，只算 TypeScript/JavaScript。

即使准确率达到 95%，调试起来也会极其困难。这就像一个开发者花几个月构建一个庞大的项目，在百分之百完成之前从来没有真正尝试运行过任何代码。这简直是噩梦。

AI 不是魔法。它只和它的训练数据一样好。代码片段在互联网上到处都是，而且往往是通用的。相比之下，每个代码库都是独一无二的。大型开源代码库非常少。AI 要怎么学会构建大型的真实项目呢？

我们正在非常迅速地接近这样一个时刻：非开发者可以坐下来和聊天机器人一起，做出一个小型的独立项目，也就是人们目前用 Webflow 之类的工具构建的那种东西。这太棒了！

但我认为，距离大型科技公司辞退开发人员、用提示工程师取而代之，我们还有非常远的路要走。在我看来，横在这一切成为现实之前的，有几个可能无法解决的问题。

增强，而非取代

从这篇文章里你可能看不出来，但我其实对 AI 相当乐观。😅

我认为最有可能的情况是，GPT-4 这样的工具会被集成到开发者工具中，用来放大熟练开发者的能力。

木匠没有被电动工具取代，会计没有被电子表格取代，摄影师没有被数码相机/智能手机取代（信不信由你，职业摄影师的数量一直在逐年增加。美国劳工统计局预计，未来十年这类岗位将增长 9%。作为对比，所有行业的平均水平是 5%），我也不认为开发者会被 LLM 取代。

我确实想过，也许开发者岗位的总数会下降；毕竟，如果每个开发者的效率都大大提高，我们需要的开发者不就少了吗？

不一定。就目前而言，软件开发者的需求远远大于供给。在我工作过的每家公司，我们都有一大堆想做的事情，但受限于手头开发者的数量。

如果开发者的生产力突然提高一倍，会发生什么？更多的 bug 会被修复，更多的功能会被发布，更多的利润会被创造出来。要构建的东西永远不缺，所以我们并不会没活给开发者干。

我其实认为，这可能会增加开发者岗位的总数。

如今，有非常多的公司根本不雇软件开发者。我以前在一家叫 Konrad Group 的公司工作，那是一家为其他公司构建 Web 应用的代理机构，其中许多客户都是家喻户晓的品牌。由于开发成本太高，对这些公司来说，把开发需求外包出去，比在内部雇开发者更合算。

那些财富 500 强公司是根据当前的软件开发成本来算账的。我们编几个数字：假设他们需要 4 个开发者，每人年薪 15 万美元，一年总共 60 万美元。那么付 50 万美元让一家代理机构替他们打理会更合算。但如果 LLM 真的能放大开发者的生产力，他们也许只需雇 2 个年薪 15 万美元的开发者，就能完成同样多的工作。突然之间，这笔账就有吸引力多了！

经济学家对这种现象有一个术语：杰文斯悖论（Jevons Paradox）。它可以一直追溯到 1865 年！感谢 Tim Grant 告诉我这个概念。

我要说清楚：我不是经济学家，这全都是天马行空的猜测。我不是说我确定事情一定会这样发展。我想说的是，这对软件开发者来说是坏事，并不是一个已成定局的结论。没人知道事情会如何发展，而我有点厌倦了人们表现得好像最坏的情况已成定局。

进行这场讨论的不只是我们

Aaron Blaise 是一位资深的动画师和插画师。他在迪士尼工作了将近 20 年，参与过《美女与野兽》（1991）、《阿拉丁》（1992）、《风中奇缘》（1995）等迪士尼经典影片。

几周前，他在 YouTube 上发布了一个视频：《迪士尼动画师回应 AI 动画》。读完这篇博文后，你会觉得他的观点很耳熟：他不把这些工具视为威胁，而是视为能提高动画师生产力、带来更多动画师岗位的东西。

此刻，几十个行业的艺术家和知识工作者都在进行同样的讨论。人们担心自己的工作即将被 GPT-4、DALL-E 2 和 Midjourney 这样的 AI 吞掉。

GPT-4 可以通过模拟的律师资格考试（有志成为律师的人必须通过这项考试，才能获得执业许可），成绩排在应试者的前 10%。许多律师也在进行一模一样的讨论。

我个人的看法是，在大多数情况下，在职的专业人士会找到办法把这项技术融入自己的工作流程，提高自己的生产力和价值。某些任务也许会交给 AI，但不会有很多岗位被交出去。

但如果我错了，事实证明 LLM 完全可以取代软件开发者呢？如果真是那样，我猜 LLM 会取代绝大多数知识工作者。

这不是那种你换个领域就能躲开的海啸。没有更高的地方可以躲。所以，与其试图赌未来会带来什么，为什么不专注于你热爱的、你感兴趣的、你擅长的事情呢？

用 LLM 帮助你学习

我听一些人说，ChatGPT 在学习技术技能方面帮了他们很大的忙。如果你对教程里的某个地方感到困惑，可以让 AI 给你解释！

我觉得这是一个非常有意思的用例。本质上，ChatGPT 就像一个结对编程的伙伴，一个能帮你弄懂你不理解的东西的人。你可以问它具体的问题，得到具体的回答。

但我确实认为你需要小心。用这类工具帮助学习，有正确的方式，也有错误的方式。

错误的方式是把它当作 GPS 导航。当我要开车去某个地方时，我把地址输入 GPS，然后不加分辨地照着它的指示走。我通常确实能到达目的地，但这需要我付出的脑力为零。结果，我的方向感完全退化了。现在没有一个合成的声音告诉我在哪里转弯，我哪儿也去不了。😬

与其把它当作 GPS，我建议你把自己当作陪审团的一员，而 LLM 是检方传唤、走上证人席的证人。

你会听他们说什么，但不会把它当作事实。你会保持怀疑，对每个字都进行批判性思考。

不要盲目地复制粘贴 ChatGPT 生成的代码，而是逐行读一遍，确保自己理解。让它澄清。对看起来可疑的地方，用权威来源（例如官方文档）再核实一遍。记住，LLM 是百分之百自信的，但不是百分之百准确的。

如果你遵循这个策略，我认为 LLM 能提供很大的价值。😄

给有志成为开发者的人的话

我想写这篇博文，正是为了对那些正在学习 Web 开发、感到焦虑和沮丧的人说几句话，他们觉得既然整个领域即将被淘汰，花这么多时间和精力培养这些技能毫无意义。

我不能保证事情会一成不变。我确实猜测 AI 会影响我们的工作方式。我从 2007 年开始摆弄 HTML/CSS/JS，从那以后事情已经变了太多太多。开发者向来都必须适应变化，随着技术一同进化。

但到目前为止，我看到的任何东西都不表明我们的工作有危险。我试着想象，如果非开发者能够在不理解 Web 技术的情况下构建完整的 Web 应用，那会是什么样子，结果我想出了那么多行不通的理由，即使未来版本的 GPT 不再那么频繁地产生幻觉。

我可能是错的。我没有水晶球 🔮。说不定明天太阳就爆炸了。但我真的不相信我们正处在 Web 开发者被淘汰的边缘。我担心许多想成为开发者的人毫无理由地松开了油门。

我不希望五年后，如果软件开发者变得更加抢手，你回头看时后悔自己停止了追逐梦想。❤️
