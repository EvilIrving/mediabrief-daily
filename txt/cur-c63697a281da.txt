EP126 Agent Harness 🏇 ｜ 硬地骇客 ｜ 50分钟 ｜ https://www.xiaoyuzhoufm.com/episode/6a0358b3e1eb34a939468885?utm_source=rss

这期硬地骇客由三位主持人对谈，主题是 agent harness。开场提出的问题是：同一个模型放在聊天框里只能给建议，放进 Claude Code 却能读文件、改代码、跑测试，而放在 Claude Code 和 OpenCode 里表现也不一样，差别来自模型周围的那套工作环境。

关于 harness 是什么，节目里有两种理解。归归认为大模型、agent、harness 是三层：agent 赋予模型角色和人格，harness 提供工具、环境和权限，是一个硬编码、确定性的工程层。他借“挽具”的本义和早已有之的 test harness 来说明：没套 harness 的 agent 什么都敢做，删库事故就该由 harness 拦下。另一位主持人则把 harness 定义为“大模型之外的一切工程实现”，认为 agent 与 harness 的边界本来就模糊。他不赞成“控制反转”的说法，认为工具调用、编译检查和 skills 本质上都在约束模型，外部控制是和模型智能并行的另一条腿，从 prompt 工程一路发展到 context 工程和 harness 工程。

具体职责方面，他们列出了 prompt、上下文压缩与重置（以 Anthropic 博客提到的“上下文焦虑”为例）、工具调用、记忆、可扩展的权限模型，以及 CLAUDE.md、rules 这类用户接口。另外还有沙箱和 worktree，按任务类型组装上下文（比如测试失败时附上失败行和历史 diff），以及靠日志、浏览器和 computer use 获得可观察、可验证的结果。归归还用记忆举例：harness 提供记忆机制并控制它能否在多个 session 或 agent 之间共享，而调取哪些记忆、什么值得长期保存，由 agent 自己决定。他判断随着模型变强，agent 和 harness 都会越来越薄，最后只剩下控制、环境和能力供给。权限方面，主持人认为 Claude Code 现有的修改、确认、直接运行等几档权限只覆盖了本地文件，还可以继续扩展到数据库的只读、读写和管理员权限，整个数字世界都还没有被完整抽象。他们特别看好一种做法：在 Claude Code 外面再包一层，做成企业专属的工作流产品。

为什么现在爆发？他们引用罗福莉的观点：OpenClaw 让人看清了框架的威力，换别的模型效果也不错。由此认为训练模型与做工程是两拨人、两条路，并拿当年算法和工程互不交集、字节模型泄露事件，以及 Claude Code source map 泄露后业界 harness 水平跟着提升来佐证工程层容易复刻。主持人认为 AI coding 是最好的练兵场，软件工程积累的大量工具让 harness 积累到一定程度后“突然生效”。他把 Cursor 看作让人来充当 harness 的弯路，Claude Code 则直接走了自动化路线。

谈到好 harness 能否抹平模型差距，主持人的经验是：模型降一档时，把任务拆细、多投入人力也能顶住。但他强调，模型变强会让 harness 越来越简单，并以 Manus 半年重写五次、Podwise 自身的重写为例，认为两者是相辅相成的。归归补充说，可验证的任务上 harness 能补足智力差距，大不了多跑几轮；创造性任务则仍主要靠模型。主持人 A 用 Grok 激进搜索 X 的体验说明上下文的重要性。他们还认为，通用 agent 的门槛是 coding agent：数字世界里的大多数问题都能靠写代码解决，过去传统代码做不到的意图理解，现在有模型来补，所以不会写代码的 agent 成不了真正的通用 agent。主持人也提醒，与其争论模型和 harness 谁更重要，不如想一想自己的工作流和业务能不能打造一套专属 harness，就像给最烈的野马套上自己的马鞍。

最后，他们把 harness 比作操作系统，判断未来会像 iOS 和安卓那样，在几个通用底座之上长出大量专属 agent 和领域能力包（比如 CRM、ERP），甚至出现 harness 市场，不会被少数产品吃掉。主持人 B 回顾说，他们早年曾断言大模型成不了操作系统，现在却觉得 agent 已经有点操作系统的意思了；他也不相信会有一个 agent 能同时写代码、画图、做音乐、管客户，所谓“通用”应该指通用的平台框架。归归补充，领域能力太多时会出现能力发现的问题，可以把任务限定在某个能力包的范围内来解决。他们也承认这个概念出现还不到半年，仍在演变。
