标题：大型 Transformer 模型的推理优化
作者：Lilian Weng（Lil’Log）
日期：2023-01-10
（2023-01-24 更新：补充蒸馏小节）

大型 Transformer 如今已是主流，在各类任务上创造 SOTA，但训练与使用都极其昂贵。推理在时间与内存上的极高成本，是把强大 Transformer 规模化用于真实任务的一大瓶颈。

**为何大型 Transformer 推理难？**除模型越来越大外，Pope 等人（2022）指出两个主因：

1. **内存占用大。**推理时参数与中间状态都要在内存中。例如批大小 512、上下文 2048 时，KV cache 合计约 3TB，是模型体积的 3 倍；注意力计算成本随序列长度平方增长。
2. **并行性差。**生成按自回归方式执行，解码过程难以并行。

本文将梳理若干让 Transformer 推理更高效的方法：有的是通用网络压缩，有的针对 Transformer 架构。

# 方法概览

推理优化的一般目标包括：用更少 GPU 与更少显存降低内存占用；降低所需 FLOPs；降低延迟、跑得更快。

可用手段包括：（1）各类并行，把万亿参数模型摊到大量 GPU；（2）把暂不用的数据卸载到 CPU，省内存但增延迟；（3）更聪明的批处理，如 EffectiveTransformer 把连续序列打包以去掉批内 padding；（4）剪枝、量化、蒸馏等网络压缩；（5）针对架构的改进，尤其是注意力层。训练侧的并行与 CPU 卸载见作者前文；本文聚焦压缩与架构特化改进。

# 蒸馏

知识蒸馏（KD；Hinton 等 2015）用更小的“学生”模仿预训练好的昂贵“教师”，以加速推理。对学生架构限制不多，只要输出空间与教师对齐以便构造目标。在数据集上用蒸馏损失让学生逼近教师输出；对带 softmax 的网络（如 LLM 的 token 分布），在高温 T 下最小化师生 softmax 差异；若有真实标签，可与监督损失（如交叉熵）用超参 λ 加权组合，蒸馏项常用 KL/交叉熵。

早期成功例子是 DistilBERT（Sanh 等 2019）：参数减 40%，微调下游保持约 97% 性能，速度提升约 71%。其预训练损失含软蒸馏、监督项（BERT 的 MLM）以及对齐师生隐状态的余弦嵌入损失。蒸馏也易于与量化、剪枝或稀疏化结合：教师为全精度稠密模型，学生为量化/剪枝/更稀疏版本。

# 量化

常见两类：（1）**训练后量化（PTQ）**：先训到收敛再降精度，成本相对训练很低；（2）**量化感知训练（QAT）**：在预训练或微调中引入量化，效果更好但要额外算力与代表性数据。还须注意：理论最优策略与硬件 kernel 支持之间有差距——缺 INT4×FP16 等矩阵乘 kernel 时，不少方法并不能真正加速推理。

## Transformer 量化的挑战

多项研究观察到：简单的低精度（如 8-bit）PTQ 会严重掉点，主因是激活动态范围大，朴素激活量化保不住容量。Bondarenko 等（2021）在小 BERT 上发现 FFN 输入与输出动态范围差异很大（输出有强异常值），对 FFN 残差和做 per-tensor 量化易出大误差。模型到数十亿参数后，高幅度异常特征开始出现在**所有** Transformer 层；Dettmers 等（2022）在大于 6.7B 的 OPT 上观察到这一点，少数维度上的激活异常可比其他值大约 100 倍。

## 训练后量化（PTQ）

### 混合精度量化

最直接的办法是权重与激活用不同精度。GOBO（Zadeh 等 2020）是较早对 Transformer（小 BERT）做 PTQ 的工作：假设每层权重近似高斯，用均值与标准差找异常值；异常保持原精度，其余分箱只存索引与中心。Bondarenko 等对出问题的激活（如 FFN 后残差）用 16-bit、其余用 8-bit。`LLM.int8()`（Dettmers 等 2022）用两套混合精度分解：（1）矩阵乘可看成独立内积，对每行/列按绝对值最大值缩放后量化到 INT8；（2）约 20 倍于其他维度的异常激活特征留在 FP16，只占极小比例；如何认定异常偏经验。

### 更细粒度的量化

整层权重量化（per-tensor/per-layer）最好实现，但粒度粗。**Q-BERT**（Shen 等 2020）对微调 BERT 做分组量化：把 MHSA 每个头对应的矩阵当作一组，再做基于 Hessian 的混合精度。**Per-embedding group（PEG）**激活量化源于异常只出现在少数隐藏维：按嵌入维均分若干组共享量化参数，并对维做按值域排序的确定性置换，使异常聚在一起。**ZeroQuant**（Yao 等 2022）权重用分组量化、激活用 token 级量化，并用定制 kernel 把量化与前一算子融合，避免昂贵的量化/反量化。

### 利用二阶信息

Q-BERT 的 HAWQ：Hessian 谱更大（最大特征值更大）的参数对量化更敏感，需更高精度——本质上是在找“敏感点”。另一视角把量化当优化：给定 W、X，找量化权重使 ‖WX − ŴX‖ 最小。**GPTQ**（Frantar 等 2022）把 W 看成行向量集合，逐行独立、贪心选更多权重以最小化量化误差，更新有闭式、用到 Hessian；可将 OPT-175B 权重压到 3 或 4 bit 而性能损失不大，但不量化激活。细节见原文与 OBQ（Optimal Brain Quantization）。

### 异常平滑

激活通常比权重更难量化。**SmoothQuant**（Xiao & Lin 2022）用数学等价变换把激活上的异常“抹”到权重上，从而对权重与激活都能量化（W8A8），硬件效率优于混合精度。按通道平滑因子 s：

Y = (X diag(s)⁻¹) · (diag(s) W) = X̂ Ŵ

平滑因子可离线融合进前层；超参 α 控制难度从激活迁到权重的程度：s = max(|Xⱼ|)^α / max(|Wⱼ|)^(1−α)。实验中 α=0.5 对许多 LLM 合适；激活异常更显著时 α 可更大。

## 量化感知训练（QAT）

把量化融入预训练或微调，直接学低比特权重，效果更好但更贵。最直接是量化后再在预训练数据或代表性数据上微调，目标可与预训练相同或针对下游。也可把全精度当教师、低精度当学生，用蒸馏；蒸馏未必需要原数据（维基甚至随机 token 也能带来增益）。**逐层知识蒸馏（LKD；Yao 等 2022）**逐层量化，并以未量化版本为教师，最小化同输入下原权重与量化权重乘法结果的 MSE。

# 剪枝

网络剪枝去掉不重要的权重或连接以缩小模型，容量大致保留；可要或不要再训练。分无结构与有结构：无结构可任意丢连接，但不保留原架构，常难在现代硬件上真正加速；有结构则保持稠密矩阵乘形式、部分元素为零，且常需符合硬件 kernel 的模式。本文聚焦能在 Transformer 上实现高稀疏度的有结构剪枝。

常规三步：训稠密网至收敛 → 剪掉不想要的结构 → 可选再训练以用新权重恢复性能。动机与**彩票假设（LTH）**相关：随机初始化的稠密前馈网中存在一批子网，“中奖彩票”单独训练即可达到最优。

## 如何剪？

**幅度剪枝**最简单却很有效：丢掉绝对值最小的权重。Gale 等（2019）发现简单幅度剪枝可媲美或优于变分 dropout、ℓ₀ 正则等复杂方法，且对超参较稳健。Zhu & Gupta（2017）发现**大而稀疏**可优于**小而稠密**，并提出**渐进幅度剪枝（GMP）**：训练过程中逐步提高稀疏度 s，每步把绝对值最小的权重掩为 0 且不再回传梯度；学习率需高于稠密训练但不可过高。**迭代剪枝**（Renda 等 2020）多次重复“少剪一点再训练”，直到达到目标稀疏度。

## 如何再训练？

可用原预训练数据或任务数据微调。彩票假设提出**权重回绕**：剪完后把未剪权重重置为训练早期的原始值，再按同一学习率日程重训。**学习率回绕**（Renda 等 2020）只重置学习率，权重保持上一阶段结束时的值；他们观察到权重回绕整体优于微调，而学习率回绕在所有测试场景中达到或超过权重回绕。

# 稀疏

稀疏能在保持推理算力可控的同时放大容量。此处考虑两类：稠密层（自注意力与 FFN）的稀疏化；以及通过 MoE 引入的稀疏架构。

## 经剪枝得到的 N:M 稀疏

**N:M 稀疏**是与现代 GPU 优化契合的有结构模式：每连续 M 个元素中有 N 个为零（如 A100 稀疏 Tensor Core 支持 2:4）。Nvidia（2020）建议仍走训→剪到 2:4→再训。列置换可在剪枝时提供更多保留大幅度参数或满足 N:M 的选项；只要两个矩阵配对轴按同序置换，乘积不变——例如注意力里对 Q 的轴 1 与 Kᵀ 的轴 0 同序置换，或 FFN 里对 W₁ 轴 1 与 W₂ 轴 0 同序置换。Pool & Yu（2021）用迭代贪心找最大化权重大小的置换，并以有界回归、窄而深的搜索跳出局部最优；剪前置换通常优于默认通道顺序。从零训 N:M 时，Zhou & Ma 等（2021）把量化常用的 STE 扩展为 **SR-STE**，用掩码正则抑制掩码剧烈变动。**Top-KAST**（Jayakumar 等 2021）在前向与反向都保持恒定稀疏，前向只取每层幅度 top 部分，反向更新更大集合以探索不同掩码，并用 L2 惩罚活跃权重以防“富者愈富”。

## 稀疏化的 Transformer

*Scaling Transformer*（Jaszczur 等 2021）稀疏化自注意力与 FFN，单样本推理提速约 37 倍。稀疏 FFN：利用 ReLU 产生大量零，强制每 N 元块仅 1 个非零，模式随 token 动态变化；控制器为低秩瓶颈，推理用 argmax、训练用 Gumbel-softmax，因可先算控制器再决定**不加载**将被置零的列。稀疏 QKV：把 d_model 分成 S 个模块，用乘法层（可表任意置换、参数少于稠密）再接二维卷积以减参与耗时。再配 Reformer 的 LSH 注意力与 FFN 块循环，得到 *Terraformer*。

## 混合专家（MoE）

MoE 依赖一组“专家”网络，每个样本只激活子集（思想可追溯到 1990 年代，与集成相关）。解码时只用部分参数，从而省推理成本。专家容量由容量因子 C 调节：选 top-k 时，更大 C 意味更高容量与更好效果，也更贵；C>1 留松弛，C<1 则路由需丢掉部分 token。细节见作者前文与 Fedus 等 2022 综述。

### 路由策略改进

原版按自然顺序把 token 分给偏好专家，容量满则标记溢出并跳过。**V-MoE**（Riquelme 等 2021）把 MoE 接入 ViT，约一半推理算力追平此前 SOTA，可扩到 15B；用 **BPR（批优先级路由）**先按优先级分专家，避免关键 token 因靠后而被丢，在 C≤0.5 时明显优于原版路由。早期 MoE 层更通用，后期层可专攻少数图像类。**Task MoE**（Kudugunta 等 2021）在机器翻译等任务级而非 token 级路由：任务固定则推理服务器只需预载 k 个专家，峰值吞吐约高 2.6 倍、解码器体积约 1.6%；但无清晰任务启发式时不易用。**PR-MoE**（Rajbhandari 等 2022）让每 token 过一个固定 MLP 加一个选中专家，并在后期层用更多专家；DeepSpeed 支持跨层不同专家数。

### Kernel 改进

专家可分布在不同设备，但 GPU 增多时每卡专家变少、专家间 all-to-all 变贵；现有算法在大规模小负载下不佳。DeepSpeed 与 TUTEL 实现基于树的**分层 all-to-all**（先节点内再节点间），跳数从 O(G) 降到 O(G_node + G/G_node)。*DynaMoE*（Kossmann 等 2022）用动态重编译按专家负载调容量因子，并在样本–专家分配收敛后缓存分配以去掉门控与专家间依赖。

# 架构优化

Tay 等（2020）的 *Efficient Transformers* 综述与作者《Transformer Family 2.0》文介绍了大量更省算力与内存的变体。自注意力二次复杂度是解码瓶颈，高效变体几乎都对稠密注意力施加某种稀疏。高层归类如下。

## 稀疏注意力模式

1. **固定模式**：限制注意力视野——分块（Blockwise）、局部（Image Transformer）、跨步（Sparse Transformer）等。
2. **组合模式**：在固定模式效率上争取更优全局视野——跨步+局部、Axial（沿张量各轴分别注意力）、ETC/Longformer/Big Bird（局部+全局，再加跨步或随机）等。
3. **可学习模式**：Reformer（LSH 聚类）、Routing Transformer（k-means）、Sinkhorn 排序网络等。

## 循环

用循环连接多块/段：Transformer-XL 复用段间隐状态；Universal Transformer 把自注意力与 RNN 式循环结合；Compressive Transformer 在 Transformer-XL 上增加主记忆与压缩记忆槽。

## 省内存设计

Linformer 把 key/value 的长度维投影到更低维（N→k），复杂度从 N×N 到 N×k；Shazeer（2019）的**多查询注意力**让各头共享 K/V，大减这些张量与内存；Random feature attention 与 Performer 用核方法得到更便宜的自注意力形式。

## 自适应注意力

让模型学最优注意力跨度或决定何时对 token 早退：Adaptive Attention Span；Universal Transformer + ACT 动态决定循环步数；Depth-Adaptive Transformer 与 CALM 用置信度决定每 token 早退层数，以权衡效果与效率。
