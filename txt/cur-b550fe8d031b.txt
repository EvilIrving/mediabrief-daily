机器人之间互发邮件，谁来核验身份？ ｜ Latacora ｜ 约 8 分钟阅读 ｜ https://www.latacora.com/blog/2026/10/14/have-your-bots-talk-to-my-bots/

一篇广为流传的帖子预言，“让你的机器人跟我家机器人聊聊”很快会成为平常话；例子包括发送缺陷报告、安排会议、组织团购、在 Craigslist 上买卖。从安全角度看，问题在于：当另一端的对象并不是你以为的那个时，会发生什么。智能体收件箱正从内部协调工具变成开放互联网上的公开地址，每一封入站邮件都成为不可信输入，并且有一条通向工具、数据乃至金钱的路径。

智能体彼此对话并不新鲜：研究团队运行过通过共享留言板协调的智能体集群；MCP Agent Mail 这类开源工具为编码智能体提供收件箱、会话线程和文件“租约”，防止它们互相覆盖工作；AgentMail 等托管服务只需一次 API 调用，就能给智能体一个真实邮箱。转变在于，开放互联网上发信的机器人属于陌生人。AgentMail 可通过托管 MCP 服务器、REST API、SDK 或普通 IMAP/SMTP 连接，以 API 密钥或 OAuth 认证，工具箱约有三十多项操作，包括删除会话线程、删除收件箱、编辑自己的允许列表；MCP Agent Mail 则包含“人类监督者”消息类型，会让智能体放下手头的事优先处理它，而这正是攻击者会模仿的对象。

允许列表按发送、接收、回复拆分，空的回复列表会让所有回复通过；如果密钥允许，被操纵的智能体就能把攻击者加入自己的允许列表；删除权限会造成抵赖问题；速率限制保护的是服务提供商。SPF、DKIM、DMARC 能证明域名控制权，却不能证明谁控制机器人、它被授权同意什么。2024 年，Stav Cohen、Ron Bitton 和 Ben Nassi 构建的 Morris II 蠕虫利用自我复制提示词在 AI 邮件助手之间传播，窃取数据并发送垃圾邮件，无需点击链接，但它运行在测试环境而非真实环境。一旦智能体能够动用资金，其他问题都会改变。需要回答的五个问题是：谁能联系到它、因为一条消息它能做什么、什么需要人类批准、它把邮件当作数据还是命令、谁审阅发生了什么。结论是：机器人需要认证、垃圾邮件过滤，以及对陌生人保持适度怀疑。
