训练大型神经网络的技术

作者：Lilian Weng、Greg Brockman（OpenAI）

大型神经网络是近期许多 AI 进展的核心，但训练它们是困难的工程与研究挑战：需要编排一整个 GPU 集群来完成一次同步计算。随着集群与模型规模增长，从业者发展出越来越多把训练并行到多块 GPU 上的技术。乍看吓人，但只要对计算结构做少量假设，这些技术就会清晰许多——那时你不过是像网络交换机搬运数据包一样，把不透明的比特从 A 运到 B。

无并行时，训练是迭代过程：每轮对一批数据前向穿过各层算输出，再反向传播、对每个参数算梯度；批平均梯度、参数与一些逐参数优化状态交给如 Adam 的优化算法，算出下一轮参数与新的优化状态。数据一批批迭代，模型输出越来越准。

各种并行技术从不同维度切开这一过程，包括：数据并行——在不同 GPU 上跑批次的不同子集；流水线并行——在不同 GPU 上跑模型的不同层；张量并行——把单次运算（如矩阵乘）的数学拆开跨 GPU；混合专家——每个样本只由每层的一部分处理。（本文假定用 GPU 训练，同样想法也适用于其他神经网络加速器。）

数据并行

数据并行训练意味着把同一套参数复制到多块 GPU（常称 worker），并给每块分配不同样例同时处理。仅靠数据并行仍要求模型装进单卡显存，但能利用多卡算力，代价是存储多份参数副本。也有策略增大 GPU 有效 RAM，例如在两次使用之间暂时把参数卸载到 CPU 内存。

各 worker 更新各自参数拷贝时需要协调，以保证参数继续相近。最简单做法是引入阻塞通信：（1）各 worker 独立算梯度；（2）跨 worker 平均梯度；（3）各 worker 独立算出相同的新参数。第（2）步是阻塞平均，传输量很大（与 worker 数乘参数规模成正比），可能伤吞吐量。有各种异步同步方案去掉这开销，但会伤学习效率；实践中人们一般坚持同步做法。

流水线并行

流水线并行训练把模型的连续块划分到各 GPU。每块 GPU 只持有一部分参数，因而同一模型每卡消耗的显存按比例下降。

把大模型切成连续层块很直接，但层的输入输出有顺序依赖，朴素实现会在等待上一机输出时产生大量空闲，这些等待时段叫"气泡"。可借用数据并行的想法：每 worker 一次只处理一部分数据元素，把一批拆成多个 microbatch，有足够 microbatch 时 worker 大部分时间都在忙，步骤首尾只有很小气泡。梯度跨 microbatch 平均，参数只在全部 microbatch 完成后更新一次。模型被切到的 worker 数常称流水线深度。

前向时 worker 只需把本块层的输出（激活）送给下一 worker；反向时只需把对这些激活的梯度送给上一 worker。如何调度这些 pass、如何跨 microbatch 聚合梯度有很大设计空间。GPipe 让每 worker 连续做前向与反向，再在结束时同步聚合多个 microbatch 的梯度。PipeDream 则调度每 worker 交替做前向与反向（图示对比中，PipeDream 用部分陈旧参数换取更高效率）。

张量并行

流水线并行按层把模型"纵向"切开。张量并行则把单层内的大运算（尤其矩阵乘法）切到多卡上，使单卡装不下的巨大层也能算。通信模式与具体切法取决于运算如何分解。

混合专家（MoE）

在混合专家方法中，对任一输入只用网络的一部分来算输出。一个例子是有多套权重，网络可在推理时经门控机制选择用哪一套，从而在不增加计算成本的情况下拥有多得多的参数。每套权重称为"专家"，希望网络学会给每个专家分配专门计算与技能。不同专家可托管在不同 GPU 上，提供清晰的扩卡方式。

其他省显存设计

还有许多计算策略让训练越来越大的网络更可行。例如：算梯度需要保存原始激活，可能消耗大量设备 RAM；检查点（亦称激活重算）只存激活的任一子集，反向时即时重算中间值，以至多一次额外完整前向换大量显存；也可通过选择性激活重算在算力与显存间持续权衡。混合精度训练用更低精度数（最常见 FP16），现代加速器在低精度上 FLOP 更高，也省设备 RAM，妥善处理时精度几乎不损失。卸载是把暂不用的数据临时卸到 CPU 或不同设备，需要时再读回；朴素实现会严重拖慢训练，精致实现会预取使设备无需等待——ZeRO 即把参数、梯度与优化器状态切到全部可用硬件并按需物化。还有人提出省内存优化器以缩小优化器维护的运行状态，如 Adafactor。压缩也可用于存网络中间结果，例如 Gist 压缩为反向保存的激活；DALL·E 在同步前压缩梯度。
