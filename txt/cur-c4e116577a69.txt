实用循环工程（Practical Loop Engineering） ｜ Addy Osmani ｜ 文章 ｜ https://addyosmani.com/blog/practical-loop-engineering/

Addy Osmani 平时同时开五到十个 agent：停止条件和约束清楚的任务（写文档、补测试）就完全放手，涉及权限、认证、安全或财务的就盯紧审代码。循环是 agent 反复行动、检验、调整直到达成目标；早年靠手写 bash 循环（如 Geoff Huntley 的 Ralph 循环），如今 Claude Code 和 Codex 已内置 goal 和 loop 两个原语，但目标和约束没定义清楚就放任它跑照样出事，新项目和银行式的棕地代码库要区别对待。

他借 Claude Code 团队的分级说明：/goal 定义"完成"的样子，agent 想停时由评估模型检查条件、不满足就打回，所以测试通过数这类确定性标准最有效；/loop 按间隔重跑同一提示，像本机的 cron；更高一级是事件触发、无人实时参与的主动循环。他的经验是给 goal 写明工具和硬指标，并设"连续两轮无改进就中止"之类条款；验证交给另一个子 agent；只委托任务，不委托品味和判断。他曾差点推上一组 agent 写的补齐竞品差距的 PR，后来才发现它们给用户增加大量复杂度、收益却很小。

实际用法上，他用 loop 给 8 万星的 Agent Skills 仓库做 issue 分级和 PR 初审，也把两者组合：loop 每天查 bug 标签，有就用 goal 修到测试全过再推分支。标准模糊、靠审美的任务（"把 UI 改好看"）不适合循环。他的建议是：你每天早上手动做的那项检查，就是你的第一个循环。
