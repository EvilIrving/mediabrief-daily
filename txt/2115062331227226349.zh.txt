我是 Anthropic 的产品工程师，手上的事情很杂：针对特定任务改进我们的模型、搭建智能体运行框架（agent harness）、和我们一些最大的客户一起把智能体用例真正落地，还有其他各种各样的事。所以我每天的工作就是个大杂烩。

今天我想讲讲我们看到的智能体界面（agentic surfaces）是怎么演变的，特别是大家熟悉的那些构建智能体的接口如何一步步演进，最终发展成我们最近做出来的 Claude Managed Agents（Claude 托管智能体）。它是一款产品，但我更想谈演变过程，以及各种用例之类的内容。很高兴跟大家分享。

我们会讲核心概念，比如 Managed Agents 是怎么运作的。本来有一部分是动手工作坊，但今天不做了——我觉得时间不够——所以我只讲讲它会怎么进行。然后我们会讲基础之外的内容，以及之后可以从哪里入手。

先说起点：我知道大家都做过智能体。在大语言模型和 AI 刚刚兴起的时候，我们推出了一个叫 Messages API 的服务，相信这里很多人都熟悉。我们提供的只是 token 进、token 出。也就是只有 Claude 本身：你给它输入，然后得到下一个 token 的预测。这就是 Messages API。

后来事情越来越复杂，你得搭更复杂的智能体、循环和工作流，但这时你仍然需要自己管理和搭建智能体循环、管理上下文、执行工具、处理会话状态和故障恢复、处理鉴权、可观测性、自定义工具逻辑——这些都还得你自己来做。所以管理这一切仍然是个难题。

接着出现了 Claude Code，这是我们对智能体运行框架的理解和实现，我们又把它封装成了 Claude Agent SDK。这个 Agent SDK 基本上提供了那套智能体循环和运行框架，提供了上下文管理、内置的工具执行、沙箱和文件系统能力，底层仍然用 Messages API 做 token 进、token 出，对吧？但你还是得自己管托管和扩容、会话状态、可观测性、自定义工具逻辑等等。要把智能体推到生产环境，你还有很多工作要做。

第三次迭代——这也算是智能体界面演变的结果——就是我们说的 Claude Managed Agents。思路是：你只需带上你的任务和智能体配置，再带上你的自定义工具逻辑，其余由 Anthropic 负责：专门打造的运行框架、工具运行时和沙箱、会话状态、持久化和检查点、鉴权、凭据保险库（credential vault）以及为其他服务安全存放 API 密钥，当然还有托管、扩容和可观测性。这些你都不用操心，开箱即用。当然，底层依然是 token 进、token 出。这就是我们看到的开发者构建智能体所用接口的演变过程。

所以说，Claude Managed Agents 是个相当新的东西，是我们构建和交付变革性智能体产品的最快方式。如果你想从一个想法走到在产品里真正拥有一个功能非常丰富的智能体，我建议从 Claude Managed Agents 入手。我会演示怎么很快上手，这也能说明你能多快把东西推到生产环境。因为我们经常发现，客户花几个小时就能做出原型，但要花几周才能把智能体真正上线，因为围绕智能体产品本身要处理的事情太多了。

Claude Managed Agents 有三种主要资源。第一种是人设和能力：你的智能体是什么、用哪个模型、提示词、工具、MCP 服务器、技能（skills）。这些全都有版本且不可变，所以你可以反复迭代，必要时回滚。第二种是基础设施和护栏：你的模型运行在什么容器里？这个容器的网络边界怎么定义？允许访问哪些主机，哪些不允许，诸如此类。也就是你的智能体所处的环境——这是我们提供的第二种资源。第三种是会话资源本身：你拿智能体配置，再拿你配好的环境，然后启动会话，对吧？就这三种简单的资源。还有几种更丰富的 API 功能，我稍后再讲，但这些是核心，用它们就能配置智能体，并以极快的速度上线。

再提醒一下，在 Claude Managed Agents 里，智能体循环运行在服务端。也就是说，智能体的编排和执行发生在云端，你做的基本上是在操控和引导云端的这个智能体循环。你把事件发进去，按需把智能体往不同方向推，你可以合上笔记本电脑，智能体仍在云端运行。打个比方就是这样。

这里发生了一个关键的架构变化。以前，智能体循环和工具执行都发生在托管智能体的同一个容器里。这意味着每次启动智能体都有很高的延迟代价，而且存在单点故障：容器一挂，智能体循环就跟着挂。在 Claude Managed Agents 中，智能体循环和实际的沙箱是分开的——大脑，也就是模型，和双手，也就是工具、沙箱，是分开的——因为并非每个智能体用例都需要沙箱，沙箱可以只在需要时才启动。这是一个关键的架构差异，因为它让我们能更快地扩容，也让你获得低得多的延迟和更高的可靠性。

本来有个动手工作坊，但这是闪电演讲，还是没时间展开。我在 Code with Claude——我们的开发者大会——上讲过这个，大家可以去看看。GitHub 上 Anthropic 组织下有个开源仓库，叫 CWC workshops，里面有个文件夹演示怎么上线你的第一个托管智能体。那是一个 SRE（站点可靠性工程）智能体，我现在就过一遍。

假设你遇到一起事故，你的结账服务报错高于基线水平。要是有个功能齐全的 SRE 智能体能去排查、找出问题所在，岂不是很好？在这个工作坊里，我们就演示了怎么实现它，而且相当简单。

如前所述，第一步是定义你的智能体是什么。你写一小段代码——当然 Claude 会替你写——描述智能体拥有的工具、要用的模型和它的名字，一用上它就会立即持久化到云端。然后定义你的容器在哪里：定义网络边界，比如模型有多大的联网权限之类，把它持久化到云端，你会得到一个唯一 ID。然后挂载你想要的任何数据：想上传一个日志文件供智能体排查时使用，可以上传；想上传技能，也可以；这些全都持久化在云端。接着用我说的智能体和环境启动会话，对吧？用智能体 ID 和环境启动会话，云端的这个智能体就有一个真正的沙箱可用，带 grep 和 glob 能力，用来找出你遇到的问题的根本原因。

而你写的这些代码都是生产级别的。所以当你对智能体满意时，可以用同一个智能体 ID、同一个环境，把它放进你的产品，作为一个真正的智能体在你的平台上发布。扩展能力是内置的，所以智能体原型一旦就绪，只需极少改动就能提供给你的用户。

再提醒一下，会话是用事件来通信的。当然其中一些东西可能会变，所以使用 Managed Agents API 时请再核对一下，但思路是：你会从云端收到关于智能体在做什么的事件，你再把事件发回去，控制它、改变它的方向。举例说明：Claude 智能体实际在云端运行，如果有本地需求，你会收到自定义工具调用；如果只是 MCP 服务器，它会直接去连；你可以在自己的产品里操控和编排这个智能体。你不用操心托管智能体之类的事，只需在需要时给它提供正确的上下文和正确的任务。这只是一段打开流、发送消息的代码片段，不一定有什么关系。

再提醒一下，对话存在云端——这里有些代码写着 beta，它已经不是 beta 了，忽略就好——所以会话基本上是持久化的。你可以做多会话持久化，用一条简单命令就能列出你在云端的所有会话。不用操心怎么持久化对话记录、存储、读取等等。

功能还多得多。有子智能体或多智能体，可以按层级派生出多个智能体。有记忆，能从会话中学习、长期记住东西，让智能体越来越好。还有“做梦”（dreaming），这里没列出来，它会随时间从对话记录中学习，形成技能、改进记忆库，以便将来表现更好。有 Outcomes，会对一个产物反复迭代多次——有点像 Ralph Wiggum 循环——以得到高质量的输出。有 Vaults（保险库），这非常重要，因为它能以高度安全的方式存放你的凭据。还有 MCP 服务器、webhook、权限策略、中断。甚至还有一个控制台智能体构建器，你可以进入 Anthropic 控制台，用纯文本描述你想要什么样的智能体，就能得到一份可以直接用在产品里的生产级配置。还有定时和触发式智能体：比如你想让智能体每天凌晨 1 点自动运行，或者想每天早上 8 点给用户发一份每日摘要——定时和触发式智能体能让你像 cron 定时任务一样按计划运行智能体。

那么，今天希望大家建立起了对 Managed Agents 及其演变的心智模型。我们还没真正上线一个能用的智能体，但你可以通过提供的链接去做，也知道接下来去哪儿了。功能还多得多，非常丰富。如果有任何问题，随时给我发邮件或在 LinkedIn 上联系我——我就在 Anthropic——有什么功能需求我们也可以看看。好，期待大家上手，也期待跟在座各位交流。谢谢大家抽出时间。
